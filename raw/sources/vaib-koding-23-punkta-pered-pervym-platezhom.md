Совет: прежде чем ваше вайб-кодинг приложение примет первый платёж, попросите агента проверить эти 23 пункта:

1. Единый документ с дизайн-системой, которому соответствуют все цвета, размеры шрифтов и отступы.
2. Отдельные экраны для каждого состояния: загрузка, отсутствие данных и ошибка.
3. Приватные ключи хранятся только на сервере. Файлы фронтенда и история Git проверены на утечки, а все когда-либо раскрытые ключи заменены.
4. Каждый API-эндпоинт проверяет авторизацию и права доступа на сервере. В базе данных включена RLS.
5. Для всех сервисов с оплатой по факту использования (ИИ, SMS, электронная почта) настроены лимиты расходов или уведомления.
6. Платёжные вебхуки проверяют подпись, а повторное получение уведомления об одном и том же платеже не приводит к его повторному учёту.
7. Возвраты, отмены и неудачные списания проверены в тестовом режиме. Каждый сценарий выполняется один раз и завершается установкой правильного статуса.
8. После окончания пробного периода или подписки доступ отзывается вовремя.
9. При переключении платежей из тестового режима в рабочий заново настраиваются рабочие API-ключи и секрет подписи вебхуков.
10. Денежные суммы хранятся как целые числа в минимальных единицах валюты, как в Stripe. Никаких чисел с плавающей точкой: в JavaScript `0.1 + 0.2` не равно `0.3`.
11. Двойное нажатие пользователем кнопки отправки создаёт только один заказ.
12. Налог с продаж или НДС настроен для стран, в которых вы продаёте продукт.
13. Условия использования и политика конфиденциальности соответствуют тому, как приложение действительно работает.
14. Настроено ежедневное автоматическое резервное копирование. На бесплатном тарифе Supabase его нет, поэтому необходимо перейти на Pro или настроить собственное создание дампов. Также нужно один раз проверить восстановление данных в новой базе.
15. Для каждой миграции схемы базы данных подготовлен SQL для отката. Миграция и её откат проверены на копии продакшен-данных.
16. Списки, содержащие более 1000 записей, не обрезаются незаметно. По умолчанию API Supabase возвращает максимум 1000 строк.
17. Время хранится в формате `timestamptz`, а часовой пояс каждого пользователя записывается в отдельный столбец, чтобы напоминания приходили по местному времени.
18. Сначала используется мягкое удаление (soft delete), причём RLS скрывает и удалённые записи. При удалении аккаунта данные пользователя удаляются окончательно.
19. Пользователи могут экспортировать собственные данные.
20. Имена с апострофами, эмодзи или текстом справа налево не вызывают ошибок в полях ввода.
21. Изображения используются в форматах WebP или AVIF, а всё, что находится ниже видимой области экрана, загружается по мере прокрутки.
22. Для полей, по которым чаще всего выполняется фильтрация, созданы индексы. На нескольких десятках тестовых записей всё работает быстро, но на реальных объёмах данных начинаются замедления.
23. Подключён мониторинг ошибок, чтобы вы первыми узнавали о возникающих проблемах.


Отправьте весь этот список вашему агенту и добавьте в конце следующий промпт. Агент проверит каждый пункт и представит результаты в таблице:
«Распредели проверку между пятью субагентами по следующим направлениям:

1. Дизайн и производительность.
2. Безопасность.
3. Платежи.
4. Данные.
5. Работа приложения после запуска.

Проверь все пункты, ничего не изменяя. Для каждого пункта укажи, пройдена проверка или нет, а также файл, в котором обнаружена проблема.

Если что-то можно проверить только через панель управления сервиса, отметь пункт статусом "Требуется моё подтверждение" и предоставь пошаговую инструкцию для самостоятельной проверки.

Резервное копирование и восстановление данных тестируй только на тестовой базе данных, платежи — исключительно в тестовом режиме. Не изменяй продакшен-данные.

Сначала покажи мне таблицу с результатами и ничего не исправляй, пока я не дам подтверждение».
