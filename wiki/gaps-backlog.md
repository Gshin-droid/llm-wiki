# Бэклог пробелов вики

Living-чеклист для ежедневного автономного процесса закрытия пробелов (см. `CLAUDE.md` → «Рутина 3 — хвосты: закрытие пробелов»). Каждый день агент берёт 1-2 пункта со статусом "не начато", закрывает через проверенные/первичные источники, отмечает результат здесь же с датой и ссылкой на источник. Если автономно закрывать нечего — работает по приоритетному списку fallback'ов из `CLAUDE.md` (допроверка флагнутых страниц по первоисточнику → углубление старой concept-страницы), и список пополняется заново находками.

Формат пункта: **Тема** — почему это пробел. *Статус: не начато / в работе / закрыто (дата, источник)*.

## Важно для всех пунктов ниже: сетевой фильтр стоит на стороне рутин, а не на стороне сайтов

Найдено 2026-08-18 в обычной сессии с пользователем. `arxiv.org` открылся напрямую без затруднений — тогда как автономные рутины упираются в `EGRESS_BLOCKED` на нём начиная с 08-12 и с тех пор потратили на повторные попытки как минимум пять прогонов (08-12, 08-13, 08-14, 08-15, 08-17). То же касается доменов из других пунктов: блокировка живёт в облачном окружении, где исполняются рутины, а не на стороне arXiv, Cursor или Meta.

Практические следствия:

1. **Пункт, который рутина не смогла закрыть из-за `EGRESS_BLOCKED`, не безнадёжен — он адресован не рутине.** Такие пункты закрываются из локальной сессии, и это единственный способ их закрыть, пока фильтр стоит.
2. **Рутине не следует биться в один и тот же заблокированный домен каждый прогон.** Один заход, отметка в логе, переход к следующему пункту — иначе прогон уходит в ноль, как уже было пять раз.
3. Помечать такие пункты явным словом «локально» ниже, чтобы было видно, кому пункт по силам.

## Открытые пункты

- **Связка «ИИ + CAD» под 3D-печать: выбрать путь и проверить печатью** — заведено 2026-08-24 по запросу пользователя, в тот же вечер, что рутина разобрала [[makeform-freecad-mcp-tutorial]]. Направление взято в работу: интересна не демонстрация MCP, а **деталь, которую печатают и которая подходит по размеру**. Критерий поэтому другой: цепочка целиком, промпт → геометрия → экспорт STL/3MF → слайсер → печать. По туториалу проверен только первый шаг, дальше него материал не идёт.

  **Что проверять, по порядку:**
  1. **Допроверить сам сервер** `neka-nat/freecad-mcp` по репозиторию: автор, живость, открытые issues, дата последнего коммита. Ни рутина, ни сессия его не смотрели. Известен один конкретный дефект — «закрыть все документы» уносит несохранённое без подтверждения; проверить, есть ли у сервера режим подтверждения деструктивных вызовов вообще.
  2. **Сравнить три пути на одной задаче**, а не выбирать по чтению: FreeCAD+MCP; генерация кода (OpenSCAD или CadQuery) с последующей компиляцией в STL; генераторы меша. Третий, судя по обзорам, отпадает для функциональных деталей — у меша нет размерных ограничений; но проверить стоит на своей задаче, а не поверить обзору.
  3. **Эталонная задача для замера** — одна и та же простая деталь с посадочным размером (то, что должно на что-то надеться или во что-то влезть). Оценка не «похоже ли», а попал ли размер и печатается ли без ручной правки в слайсере.
  4. **Печать как приёмка.** Успех — напечатанная деталь, а не картинка в окне редактора. Это тот же принцип, что «успех только с доказательством»: модель в CAD — это ещё не результат.

  Оговорка про среду: связка из туториала завязана на Claude Desktop, а не на Claude Code; путь через генерацию кода такой привязки не имеет. Что именно ставить и куда — решать после пункта 1, до установки чего-либо стороннего.

  **Шаг 1 закрыт 2026-08-25 (ежедневный процесс закрытия пробелов).** Прямая проверка `github.com/neka-nat/freecad-mcp` (README ветки `master` + список открытых issues). Живость подтверждена: 1.9k★, MIT, 147 коммитов, последний issue 12.08.2026, 6 открытых, ни одного про подтверждение деструктивных действий. Находка отличается от того, что записал туториал: официальный список из 12 тулов не содержит отдельного тула закрытия документа — команда «close all documents» из видео шла через `execute_code` (произвольный Python FreeCAD API), то есть риск не в одной команде, а в том, что `execute_code` вообще не имеет механизма подтверждения ни для одного деструктивного вызова. Деталь и правка риска — на странице [[freecad]], раздел «Допроверка сервера 2026-08-25». **Статус: в работе, шаг 1/4 сделан, шаги 2–4 (сравнение трёх путей на эталонной детали, печать как приёмка) не начаты.**

[[ai-security-by-design]]).

Порядок: **раз в месяц один короткий заход** — вышел ли из preview, живы ли плагины, появились ли границы прав; ответ «всё ещё рано» записывается строкой в лог и стоит одного прогона, а не пяти.   **Context rot — закрыто частично 2026-08-08** (ежедневный процесс закрытия пробелов). Полный техотчёт на `research.trychroma.com` заблокирован сетевым прокси окружения на уровне домена (`EGRESS_BLOCKED`), но официальный репозиторий авторов `github.com/chroma-core/context-rot` прочитан напрямую через `git clone` — методология трёх экспериментов (NIAH extension/LongMemEval/Repeated Words), точная библиография, и пример реальных данных прогона GPT-4.1 (не синтетика для вики, посчитано из бандл-CSV репозитория): точность 100%→18% на переходе 5 000→10 000 токенов, дальше нелинейно. Не подтверждено первоисточником: точное число моделей отчёта (18 — только по вторичным пересказам) и явная формулировка «context rot отдельно от lost-in-the-middle» (её не нашлось в доступных файлах репозитория).   **MINJA — закрыто частично 2026-08-09** (ежедневный процесс закрытия пробелов). Сама статья (arXiv:2503.03704, NeurIPS 2025) недоступна — не только `arxiv.org`, но и все проверенные зеркала/индексы (`openreview.net`, `neurips.cc`, `researchgate.net`, `semanticscholar.org`, `huggingface.co`, `alphaxiv.org`) вернули `EGRESS_BLOCKED` на уровне сетевого прокси окружения. По прецеденту context rot — прочитан официальный GitHub-репозиторий авторов (`github.com/dsh3n77/MINJA`) напрямую: подтверждён механизм indication prompt + progressive shortening реальными промпт-шаблонами атаки (не пересказ, а сам код), поимённо подтверждены три агента эксперимента (RAP/EHR/QA — EHR и есть «медицинский» агент из видео на слух). Не подтверждено первоисточником: точные цифры ISR/ASR (98.2%/76.8% — только по повторяющимся вторичным пересказам) и ключевое утверждение источника «на пустой памяти успех почти всегда, на заполненной резко ниже» — код основного эксперимента параметризует число benign-записей, подмешиваемых в память ДО замера успеха (50 для RAP/EHR, 30 для QA), то есть метрики считаются не на пустой памяти; возможно, относится к отдельной абляции в недоступном полном тексте. Создана [[minja-memory-injection-attack]], дополнена [[ai-security-by-design]] (раздел «Память как attack surface», новый подраздел «Не подтверждено первоисточником»).
