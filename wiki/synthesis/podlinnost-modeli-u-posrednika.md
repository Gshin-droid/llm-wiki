# Подлинность модели у посредника: как проверить, что подают ту модель, за которую платишь

Вопрос пришёл наводкой 2026-11-09: в обсуждении практиков (`raw/inbox-assistant/2026-11-08-дешёвые-api-посредники-как-проверить,-что-модель-настоящая`, `ai-assistant #394`) участник доволен дешёвым доступом к GLM, но признаёт, что подлинность модели проверить нечем; советуют «спросить саму модель» и «прогнать бенчмарк». Сводка обсуждений — наводка, поэтому ответ собран по первоисточникам, а не по ней.

**Короткий ответ.** Оба совета из обсуждения первоисточники опровергают. Спросить модель «кто ты» — ненадёжно; типовой бенчмарк посредник может узнать и отправить на настоящую модель, а обычный поток — на подмену. Подмена бывает не только «другая модель», но и **та же модель в сжатом виде** (квантизация) или с дефектами обвязки у исполнителя — у производителя Kimi разрыв доходил до 20+ процентных пунктов. Работают три вещи: закрепить исполнителя, сравнивать на **своих** эталонах, где можно — по вероятностям токенов.

## Что говорят первоисточники

**Berkeley, «Are You Getting What You Pay For? Auditing Model Substitution in LLM APIs»** ([arXiv 2504.04715](https://arxiv.org/abs/2504.04715), код [sunblaze-ucb/llm-api-audit](https://github.com/sunblaze-ucb/llm-api-audit)). Систематически проверены способы поймать подмену — статистика по тексту ответов, бенчмарки, вероятности токенов — против реалистичных атак: квантизация, случайная подмена части запросов, уклонение от бенчмарка. Выводы:

- проверки только по тексту ответов не ловят тонкую и подстраивающуюся подмену;
- вопрос модели «кто ты?» — *«highly unreliable»* (крайне ненадёжен);
- **уклонение от бенчмарка**: посредник узнаёт типовые проверочные вопросы (MMLU, GSM8K) и отправляет их на настоящую модель;
- вероятности токенов (logprobs) дают самую сильную гарантию, но доступны редко;
- доказуемая подлинность — только аппаратно, через защищённую среду исполнения (TEE).

Продолжения той же линии: ранговый тест RUT ([arXiv 2506.06975](https://arxiv.org/abs/2506.06975)) — для посредников с открытыми моделями, один вызов на запрос; AgentProv (2026) — сравнение распределения вызовов инструментов, для агентских API, которые отдают только вызов, без текста. Оба — по описаниям в поиске, статьи целиком не читались.

**Moonshot, K2 Vendor Verifier и Kimi Vendor Verifier** ([анонс K2VV](https://medium.com/@kimi_moonshot/announcing-the-k2-vendor-verifier-ensuring-consistent-toolcall-performance-for-kimi-k2-04c568f4a1dd), репозитории в [github.com/moonshotai](https://github.com/moonshotai)). Производитель модели сам сравнивает ответы сторонних исполнителей с официальным API. Повод — жалобы на ненадёжные вызовы инструментов, причина — разные способы запуска модели у разных исполнителей. По данным Moonshot, у части сторонних исполнителей точность ниже на 20+ п. п. ([заявление](https://x.com/Kimi_Moonshot/status/1987892275092025635)). Ограничение метода, замеченное в [обсуждении на Hacker News](https://news.ycombinator.com/item?id=47838703): исполнитель может пройти проверку на пустом кластере и деградировать под нагрузкой — проверка одномоментна.

**Anthropic, FlashProve — второй доказуемый путь, криптографический** ([исследование «Provable inference»](https://www.anthropic.com/research/provable-inference), 02.11.2026; код [anthropics/FlashProve](https://github.com/anthropics/FlashProve), Apache 2.0; наводка `ai-assistant #331`). Доказательство с нулевым разглашением (zkSNARK): исполнитель заранее публикует «отпечаток» весов, а к ответу прикладывает доказательство, что его выдала именно эта модель; веса не раскрываются. Статус — *«intermediate progress»*, исследовательский прототип; внедрения в продукты и API **не объявлено** (пересказ канала «Anthropic готовится внедрить» источником не подтверждается). Ограничения по самой статье: контекст 1024 токена; в 72–94 раза больше вычислений на видеокарте, чем обычный запуск; доказательство ~19 МБ, проверка ~17 с; только детерминированный выбор токенов. Для проверки посредника сегодня неприменим — вывод страницы не меняется.

## Что из этого берём себе (логика, не инструмент)

Инструменты Moonshot проверяют только модели Kimi — ставить незачем. Переносимы три механизма:

1. **Закрепить исполнителя.** У [[openrouter]] в запросе есть объект `provider` (документация provider routing, сверено 09.11): `order` — список исполнителей по порядку, `allow_fallbacks: false` — не уходить к другим, `only`/`ignore`, `quantizations` — допустимые уровни сжатия (`fp8`, `bf16`, `int4` и др.), `data_collection: "deny"` — только исполнители, которые не хранят и не учат на данных. Без этого агрегатор сам выбирает исполнителя за моделью, и «замер модели» становится замером случайного исполнителя. Замер судьи 05.11 исполнителя закреплял ([[delegirovanie-deshevym-modelyam]]); обычные вызовы шлюза `llm.py` на 09.11 — нет.
2. **Сравнивать на своих эталонах, а не на бенчмарке.** Эталонные задачи шлюза — не типовой набор, посредник их не узнает. Те же эталоны через официальный API и через посредника — и сравнить долю принятых машинной приёмкой. Дорого раз, потом — по событию (смена посредника, жалоба на качество).
3. **Вероятности токенов там, где их отдают.** Механизм уже освоен на судье с уверенностью ([[llm-as-a-verifier-stanford]]): Ollama их отдаёт. Сторонний посредник, отдающий logprobs, проверяется сильнее остальных.

Отдельно от подлинности, но из той же наводки: у посредника своя **политика хранения данных** и своё **кэширование** — по отзывам участников, у одного из посредников реже попадание в кэш, чем у оригинального API (не проверено). Первое — вопрос корзины материала (жёлтое — только локально), второе — вопрос цены.

## Фильтр для посредников

Применять при разборе любого дешёвого доступа (группа «дешёвый доступ» инбокса: Alibaba Model Studio, OpenCode Go, MiniMax через NVIDIA и т. п.):

- можно ли закрепить исполнителя и уровень сжатия — или посредник сам решает, кто ответит;
- отдаёт ли вероятности токенов;
- что написано о хранении и обучении на запросах;
- есть ли официальный API той же модели, чтобы прогнать свои эталоны рядом.

Нет ни одного из первых двух — посредник годится только для зелёного материала и задач, где ответ дёшево проверить машинной приёмкой.

## Противоречия

Нет — обсуждение и первоисточники расходятся только в советах, а не в фактах.
