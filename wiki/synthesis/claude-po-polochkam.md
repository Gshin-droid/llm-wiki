# Claude по полочкам: путеводитель по Claude Code и соседним продуктам

Ответ на вопрос «как всё устроено и как что включать». Страница — **путеводитель, а не источник**: здесь только «что это, как включить, как выключить» и ссылка, где подробно. Цифры, версии и лимиты сюда намеренно не переносятся — они живут на страницах-источниках и протухают за недели; две копии одного факта разъедутся (правило «представление не поддерживают параллельно с источником»). Нужна цифра — открыть ссылку.

Собрано 2026-11-09 из [[claude-code]] и ~20 соседних страниц: выписки сделал субагент только на чтение, каждая сверена с исходным разделом (заголовки и дословные опоры — скриптом, смысл «включить/выключить» — выборочно вручную). Чего нет на страницах вики, нет и здесь: такие места помечены «в вики не описано».

Раздел «Что-то» в ссылке — заголовок раздела на той странице (у [[claude-code]] заголовки — даты обновлений, поэтому ищется по началу заголовка).

## 1. Где работает

| Что | Как попасть | Подробно |
|---|---|---|
| Терминал (CLI) | команда `claude` | [[claude-code]], «Что это» |
| Расширение VS Code | панель со строкой ввода и картой агентов; `claudeCode.useTerminal` открывает его во вкладке терминала VS Code (там работает сжатие при простое) | [[claude-code]], «Интерфейс расширения VS Code»; [[prompt-cache-control-mod]] |
| Claude Desktop | три вкладки: Chat, Cowork, Code; `claude --desktop` открывает приложение на текущей папке | [[claude-desktop-automation-modes]] |
| Веб и мобильное | там начинаются сессии Cowork; плагины там, по записи вики, не работают | [[claude-cowork]] |
| Облачная сессия | `claude --cloud "<задача>"` — сессия в изолированной виртуалке Anthropic, переживает закрытие ноутбука; обратно в терминал — `claude --teleport`. Ест те же лимиты подписки | [[claude-code]], «Облачные сессии вышли из research preview» |
| Свой исполнитель облачных сессий | `claude self-hosted-runner setup`; только Team/Enterprise, выключен по умолчанию | [[claude-desktop-automation-modes]], «Пятый способ» |
| Remote Control | `claude remote-control`; как включить — в вики не описано | [[claude-artifacts]] |

**Ловушка двух версий:** расширение VS Code и программа в терминале обновляются отдельно, номер версии у них может различаться.

## 2. Режимы разрешений

| Режим | Что делает | Как включить / выключить | Подробно |
|---|---|---|---|
| default (Manual) | спрашивает перед каждым действием | в вики не описано отдельно | [[claude-code]], «Permissions и .claudeignore» |
| acceptEdits | назван, смысл в вики не объяснён | — | [[claude-code-critical-path-rm-docs]] |
| plan | режим планирования; отдельного описания нет, есть `/model opusplan` и тиммейты в plan mode | в вики не описано | [[claude-code]], «Модели и Effort»; [[agent-teams]] |
| auto | модель-классификатор проверяет действие перед выполнением; дефолт новых сессий | `"permissions": {"defaultMode": "auto"}` в `~/.claude/settings.json` (не в проектном); после серии блокировок сам возвращается к ручным подтверждениям. «Не гарантирует безопасность» — слова вендора | [[claude-code-auto-mode-default]] |
| bypassPermissions | без вопросов вообще | `claude --permission-mode bypassPermissions`; `--restricted` с ним запускаться отказывается | [[claude-code]], «Permissions…» |

**Правила `allow` / `ask` / `deny`** — в `settings.json`; подхватываются только при старте новой сессии. **`permissions.denyInsteadOfPrompting`** — вызов, который ждал бы ответа, сразу отказывает (полезно для фона и субагентов); по умолчанию выключено. Подробно — [[claude-code]], «Permissions…» и «Обновление 2.1.319».

## 3. Модели и уровень усилий

- **Выбор модели** — `/model` в сессии (запоминается), `--model` при старте, `ANTHROPIC_MODEL` или `model` в settings. Порядок старшинства — [[claude-code-model-config-docs]].
- **`opusplan`** — Opus планирует, Sonnet исполняет: `/model opusplan`. [[claude-code]], «Модели и Effort».
- **Резервная модель** — `fallbackModel` в settings или `--fallback-model`: при перегрузке сессия пробует следующую. Там же.
- **Смена модели при пометке сообщения** — включена по умолчанию; `/config` → «Switch models when a message is flagged» или `switchModelsOnFlag: false` — тогда помеченный запрос ставит сессию на паузу с выбором. [[claude-code]], «Смена модели при пометке сообщения и `/fast`».
- **Effort (уровень усилий)** — `/effort low…max`; хранится отдельно для каждой модели; потолок — `maxEffortLevel`; у субагента — поле `effort` в описании. Названия уровней у разных моделей не сопоставимы. [[claude-code]], «Модели и Effort».
- **`ultrathink`** — слово посреди хода поднимает усилия до `xhigh` до конца хода; выключить слово — `CLAUDE_CODE_DISABLE_ULTRATHINK`. Дорого по лимиту — точечный инструмент. [[claude-code]], «`ultrathink` посреди хода и Message Threads».
- **`ultracode`** — слово в промпте или `/effort ultracode`: Claude сам решает, запускать ли workflow. [[dynamic-workflows]].
- **`/fast`** — та же модель, текст быстрее, токен дороже; требует включённого дополнительного расхода. Как выключить — в вики не описано. [[claude-code]], «…и `/fast`».

## 4. Контекст и лимиты

- **Ручное управление** — `/compact` (сжать, можно с уточнением, что сохранить), `/clear` (с нуля), `/new`, `/resume`. Один диалог — одна задача. [[claude-code]], «Контекстное окно и сессии».
- **Порог автосжатия** — `/autocompact <значение|auto>`; `auto` возвращает подобранное. [[claude-code]], «Порог автосжатия»; [[kontekst-szhat-ili-nachat-zanovo]].
- **Сжатие при простое** — долго простоявший большой разговор сжимается до истечения кэша; включено по умолчанию, выключить — `"idleCompaction": false`. Где именно работает полноценно — см. «Где вики сама не уверена». [[prompt-cache-control-mod]]; [[kontekst-szhat-ili-nachat-zanovo]].
- **Кэш промпта** — срок жизни задаётся `promptCacheTtl` / `subagentPromptCacheTtl` (или переменными окружения); проверка — `/usage`, строка `Prompt cache (main)`. [[prompt-cache-control-mod]].
- **Message Threads** — повторные запросы шлют только новые сообщения; в Claude Code включено по умолчанию. Экономит время, **не лимит**. [[claude-code]], «`ultrathink`… и Message Threads».
- **Возобновление после сброса лимита** — настраивается в `/config`. [[claude-code]], «Обновление 2.1.234–2.1.235».
- **Автопамять (auto-memory)** — индекс `MEMORY.md`, грузится в каждую сессию; включена по умолчанию; тумблер `/memory`, ключ `autoMemoryEnabled` или `CLAUDE_CODE_DISABLE_AUTO_MEMORY=1`. Не путать с memory tool из API (полка 9). [[claude-memory-tool]].

## 5. Агенты

- **Субагенты** — изолированный контекст, отчитываются главному. Описание агента: `tools` (белый список — единственная настоящая стена), `maxTurns`, `effort`, `isolation: worktree`. [[claude-code]], «MCP, Skills, Subagents…» и «Описание субагента»; [[zabor-i-stena-prava-agenta]].
- **Вложенность и параллелизм** — по умолчанию субагент не порождает субагентов; включается `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`; число одновременных — `CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`. [[claude-code]], «Обновление 2.1.216–2.1.217».
- **`/fork`** — копия диалога отдельной фоновой сессией. [[claude-code]], «Обновление 2.1.211–2.1.214» и «2.1.232–2.1.233».
- **Worktree** — `claude --worktree`: отдельная рабочая копия репозитория, чтобы параллельные диалоги не портили файлы друг другу. Не граница безопасности. [[claude-code]], «Автономный режим и параллельная работа».
- **Фоновые сессии** — `claude agents`. Там же.
- **Команды агентов (agent teams)** — экспериментально, `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS=1`; тиммейты наследуют режим разрешений ведущего. [[agent-teams]].
- **Связь между сессиями** — `SendMessage` / `ListAgents`; к сессиям без подтверждений входящие по умолчанию ждут подтверждения (`crossSessionInbound`). [[claude-desktop-automation-modes]], «Межсессионная связь».
- **Managed Agents** — полка 9.

## 6. Автоматизация

| Что | Где идёт | Как включить / выключить | Подробно |
|---|---|---|---|
| Cloud Routines | на серверах Anthropic, компьютер не нужен | создаются в claude.ai (пошаговой инструкции в вики нет); частые — на паузу при долгом отсутствии. Триггер не равен живому согласию пользователя | [[claude-desktop-automation-modes]], «3. Cloud Routines»; [[claude-code-routines-docs]] |
| Cowork Scheduler / Local Routines | на своей машине, пока она и приложение включены | в приложении | [[claude-desktop-automation-modes]], «1» и «2» |
| `/loop` | внутри текущей сессии | `/loop`; остановить — `ScheduleWakeup(stop: true)` | [[claude-desktop-automation-modes]], «4. `/loop`» |
| `claude -p` | без интерфейса, для фона и расписания | `claude -p "задача"`, с `--max-turns`, `--max-budget-usd` | [[claude-code]], «Автономный режим…» и «Подписка в автоматизации» |
| `/goal` | цель с критерием завершения на много сессий | `/goal` | [[claude-code]], «Долгоживущие агенты» |
| Режим «без присмотра» | бесконечные повторы при перегрузке и лимите | `CLAUDE_CODE_RETRY_WATCHDOG=1` + две переменные-потолка; глобально не ставить | [[claude-code]], «Режим «без присмотра»…» |
| Dynamic workflows | скрипт-оркестратор в фоне | слово `ultracode` или «используй workflow»; размер — `workflowSizeGuideline` в `/config` | [[dynamic-workflows]] |

**Хуки** — команды на события (`PreToolUse`, `Stop`, `SubagentStart`/`SubagentStop` и др.). Единственный способ гарантированно исполнить правило: текст правила — забор, хук ближе к стене. `onFailure: "block"` — упавший хук блокирует действие, а не пропускает. Синтаксиса записи хуков в вики нет. [[claude-code]], «Практическая механика» и «Обновление 2.1.293–2.1.296»; [[zabor-i-stena-prava-agenta]].

## 7. Расширения

- **Скиллы** — папка с `SKILL.md`: личные в `~/.claude/skills/`, проектные в `.claude/skills/`, или из плагина. Перечень скиллов сам стоит токенов; спрятать из перечня — статус `user-invocable-only` (скилл из плагина так не скрыть); диагностика — `/skill-doctor`. [[claude-skills]].
- **Плагины** — установка `claude plugin install` (можно `--marketplace`), тест-раннер eval. Общего определения в вики нет. [[claude-code]], «Обновление 2.1.268–2.1.270», «2.1.284–2.1.286», «2.1.289–2.1.292».
- **MCP** — подключение внешних систем: `claude mcp add --transport http <имя> <адрес>`, убрать — `claude mcp remove <имя>`, вход — `claude mcp login`. У подключённого сервера постоянная цена в контексте; редкое — скиллом. [[mcp-model-context-protocol]]; пример — [[inspo]].
- **Моды** — плагины, меняющие поведение самого Claude Code; исполняются с правами пользователя без песочницы. Пример — «You should know»: `/plugin enable cc-plugin-you-should-know@builtin` или `enabledPlugins` в settings, выключить — `false`; тратит лимит незаметно. [[claude-code]], «Обновление 2.1.287–2.1.288» и «You should know»…».
- **Строка состояния** — поле `statusLine` в `settings.json`; готовый скрипт — [[claude-statusline]]. В панели расширения VS Code не отображается.

## 8. Безопасность

- **Песочница** — `sandbox.enabled`; из настроек проекта не включается, только пользовательские или управляемые. На чистой Windows её нет — только через WSL2. `sandbox.filesystem.disabled` снимает только файловый слой. [[zabor-i-stena-prava-agenta]]; [[claude-code]], «Permissions…».
- **`permissions.deny`** — закрыть чтение `.env` и секретов. [[claude-code]], «Permissions…».
- **`blockWritesOutsideWorkingDirectories`** — Write/Edit не пишут вне рабочих папок в любом режиме; нужно задать явно; **Bash и PowerShell не покрывает** — для них нужна песочница. [[zabor-i-stena-prava-agenta]], «Дополнение (2026-11-04)».
- **Управляемые настройки** — `/etc/claude-code/managed-settings.json` (Linux, WSL), пишет root; сильнее пользовательских, агент их не перебьёт. [[zabor-i-stena-prava-agenta]], «Проверено на практике 2026-10-14».
- **`--restricted`** (`CLAUDE_CODE_RESTRICTED=1`) — режим без инструментов исполнения команд и `WebFetch`. **`CLAUDE_CODE_DISABLE_WEB_FETCH`** — выключить веб-запросы. [[claude-code]], «Обновление 2.1.246–2.1.250» и «2.1.284–2.1.286».
- **Защита критических путей от `rm`** — встроенная, правилом не снимается; переменная `CLAUDE_CODE_EVEN_MORE_DANGEROUSLY_SKIP_PERMISSIONS` снимает её только при ряде условий. [[claude-code-critical-path-rm-docs]].
- **Контрольные точки** — создаются перед каждой правкой файла; откат — `/rewind`. [[claude-code]], «Safety net».
- **Обходы проверки прав** закрываются почти в каждом обновлении — `allow`-правила перепроверять, а не считать вечными. Инциденты (поддельное расширение, Plugin4Shell, уязвимость Agent SDK) — [[claude-code]] и [[ai-security-by-design]].

## Где вики сама не уверена

Разведка нашла места, где страницы вики расходятся между собой. Справочник на них не опирается; разбирать — через [[gaps-backlog]], первоисточниками.

- **Сжатие при простое** — где работает полноценно (терминал, панель VS Code, Desktop) и с какой версии: снимки журнала изменений и запись трекера дают разные ответы.
- **Лимит субагентов на сессию** — помечен устаревшим в [[claude-code]], но подаётся как действующий в [[dynamic-workflows]].
- **Публичная ссылка на артефакт с коннекторами** — [[claude-code]] говорит «нельзя ни на одном тарифе», [[claude-artifacts]] по документации — «можно, как позволяют тариф и организация».
- **`onFailure: "block"`** — одна функция для хуков Claude Code и Agent SDK или две разные: страницы не сверены.
- **Число запусков Cloud Routines в сутки** — внутри [[claude-desktop-automation-modes]] и подано цифрами, и помечено неподтверждённым.
- **Песочница на Windows** — в [[zabor-i-stena-prava-agenta]] осталась ранняя формулировка «не проверено» выше раздела, где проверено.

## Пробелы: в вики этого нет

Plan mode, `acceptEdits` и `dontAsk` как самостоятельные режимы; синтаксис хуков и полный список событий; что такое плагин и как устроен `/plugin`; установка расширения VS Code и Claude Desktop; пошаговое создание Cloud Routine; как включить Remote Control; как выключить `/fast`, Message Threads, команды агентов, Cowork. Закрывать — по первоисточникам, по мере надобности, а не скопом.
