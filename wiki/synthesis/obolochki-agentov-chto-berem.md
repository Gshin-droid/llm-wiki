# Оболочки для агентов: что берём, а что нет (ноябрь 2026)

**Актуально на:** 2026-11-18
**Вопрос:** в обсуждениях практиков всплыл десяток оболочек вокруг агентов для кода — ThinkRail, Hermes, Pi, OMP, OpenCode, T3 Code, Kilo Code, ACP. Что из них ставить, а что взять как механизм в свою связку на Claude Code?

Повод — наводки из инбокса ассистента #400, #186, #192, #499 (сводки обсуждений, 28.10–14.11). Каждый факт ниже сверен с первоисточником — репозиторием и документацией проекта, `gh api` 17–18.11.2026; опыт участников обсуждения не проверялся. Разбор шёл с пользователем по одному материалу, итог — один план внедрения.

## Короткий ответ

**Не ставим ни одну.** Причины повторяются: установка через `irm … | iex`, работа без вопросов по умолчанию, телеметрия по умолчанию, доступ к файлу входа Claude Code, ночные сборки. Подписка Claude у чужих оболочек — отдельный риск, см. [[opencode]] и раздел о пятичасовом окне в [[claude-code]].

**Берём механизмы** — они переносятся на встроенные средства Claude Code (хуки, субагенты, скиллы) без чужой программы.

## Механизмы подробнее

**Спящие правила (из OMP).** В OMP регулярное выражение по выводу модели прерывает поток, вставляет правило и повторяет с той же точки. Claude Code прерывать посреди ответа не умеет, но умеет подложить текст модели **на границе действия** — хук перед вызовом инструмента (`PreToolUse`) с `additionalContext`. Это даже ближе к правилу «проверка стоит перед действием». Наша форма: строку инструкций «по поводу X — прочитай Y» превратить в хук, где повод замечает код, а не память модели. Подходит, когда повод **механический** (команда, путь, имя инструмента), правило длинное и редкое, а хук только подсказывает и не запрещает — тогда ложное срабатывание стоит одного лишнего абзаца, и эвристика допустима (фильтр «инвариант или эвристика» — [[verification-three-levels]]). Не подходит для смысловых поводов и для частых срабатываний: подсказку на каждую третью команду модель перестаёт читать. До включения — прогон по истории сессий: сколько раз повод был и сколько раз правило не прочли.

**«Предлагает, а не пишет» (из Hermes).** У Hermes запись скиллов и памяти можно поставить в очередь на утверждение. Но их ворота не покрывают правку теми же файлами обычными инструментами — это забор, а не стена ([[zabor-i-stena-prava-agenta]]). Переносимая форма: агент, читающий журналы сессии, вообще без права записи; предложения — в файл-очередь с цитатой из журнала; утверждает человек.

**Жёсткий лимит памяти (из Hermes).** У Hermes память ограничена 2200 знаками, переполнение — ошибка, и агент сам ужимает. Переносим как предупреждение, а не отказ: ложный отказ при записи памяти потерял бы данные.

**Сжатие до истечения кэша (из T3 Code).** T3 шлёт `/compact` незадолго до конца часового кэша промпта подписки, пока история ещё в кэше, и показывает выбор «сжать / оставить» при возврате к большой ветке (`docs/user/providers-claude.md`). Проба: можно ли так же подать `/compact` в сессию извне.

## Что сделано (18.11)

- **Спящие правила** — хук перед вызовом Bash на три повода: публикация в чужой репозиторий и установка чужого кода (стоп один раз за сессию с текстом правила), ssh (подсказка). Замер по истории и находка «подсказка не останавливает команду» — [[claude-code-practices]], п. 18.
- **Форма сводки из Pi** — четвёртый вопрос итога сессии «с чего продолжить»: цель, ограничения, сделано, в работе, заблокировано, решения, дальше, файлы.
- **Лимит памяти** — обходчик машины предупреждает, когда индекс памяти подходит к 80% того, что Claude Code грузит в сессию (200 строк или 25 КБ); остальное там режется молча.
- **`claude -p` и пятичасовое окно** — сверено расписание: тяжёлых задач на рабочих часах нет.
- **Сжатие до истечения кэша — своё не нужно:** с 2.1.314 панель VS Code сама готовит сводку при простое и применяет к следующему сообщению; по своим журналам сработало в 7 из 9 подходящих пауз — [[prompt-cache-control-mod]], дополнение 18.11.
- **Вложенный CLAUDE.md** (опыт 18.11, три свидетеля): у `claude -p` подгружается при чтении файла из его папки; у субагента и у основной сессии в панели VS Code — нет. Папка-ссылка (junction) наружу проекта не годится даже для основной сессии: Claude Code видит настоящий путь вне проекта. Правило субагенту — только нарядом или полем `skills`.
- **Сбой субагента не бывает тихим — своё не нужно** (разбор 18.11). Claude Code помечает сам: упавший на ошибке API — статус «failed» с причиной, а субагент без текста — ошибка «Agent terminated early»; обрыв на полуслове и исчерпанный `maxTurns` — ответ с пометкой «частичный»; зависание ловит `CLAUDE_ASYNC_AGENT_STALL_TIMEOUT_MS` (по умолчанию 10 минут) — первоисточник: документация Claude Code, страницы sub-agents, hooks и env-vars. По журналам одной машины: из 248 фоновых субагентов провалились 11, все громко (лимит сессии); среди 57 завершённых с текстом пустых и оборванных нет; «короткие» ответы оказались ссылкой на отчёт, переданный отдельным сообщением. Сторож «короткий ответ = провал» был бы эвристикой с законными исключениями («находок нет»), поэтому в код не идёт ([[verification-three-levels]]). Опасный тихий провал — длинный уверенный отчёт без работы за ним — ловится по смыслу: доказательство к каждому пункту и сверка ссылок отчёта с файлами. Не проверено: что делает сторож зависания при срабатывании и что видно, если субагент закончил, не передав отчёт.
- **CLAUDE.md против кода** (механизм из ThinkRail, 18.11): обходчик машины раз в сутки сверяет пути и имена из кода, упомянутые в CLAUDE.md и AGENTS.md в обратных кавычках, с файлами git и текстом кода; при старте сессии хук показывает расхождения по своему проекту. Прототип на семи CLAUDE.md двух проектов: 116 путей и 250 имён, из них после отсева шума — одна настоящая находка: инструкция три месяца описывала вкладку интерфейса, удалённую из кода. Шум трёх видов: отрицание («не `X`», «без `X`» — инструкция законно называет то, чего быть не должно), окончания имён (`.check.ts`), прочее законное (имя задачи планировщика, пакет, суффикс поля) — первые два отсекаются кодом, третье списком глушения. Поэтому это эвристика и только отчёт, а не запрет ([[verification-three-levels]]). Готового инструмента не нашлось: проверяльщики ссылок Markdown смотрят ссылки `[текст](путь)` и адреса, а не упоминания в кавычках и имена из кода.

## Что не берём и почему

- **Советник на каждом ходу (OMP)** — вторая модель читает каждый ход; дорого, а проверка моделью другого семейства и так ставится отдельной пробой.
- **Граф описаний модулей (ThinkRail)** — на наших объёмах дороже, чем полезен.
- **Подмена метки точки входа ради лимита** — обход учёта, см. [[claude-code]].
- **Карточки-агенты на полотне (#499)** — свой проект участника без ссылки; механизм «главный агент сам строит цепочку» уже есть во встроенных workflow Claude Code ([[dynamic-workflows]]).
- **Минимальный харнесс + cron (#192)** — у нас то же самое уже стоит: `claude -p` по расписанию и облачные рутины.
