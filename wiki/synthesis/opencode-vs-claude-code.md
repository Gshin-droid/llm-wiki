# OpenCode vs Claude Code

**Дата:** 2026-07-29
**Вопрос:** чем OpenCode отличается от связки «редактор + Claude Code» и стоит ли переходить.

## Рамка: агент — не редактор

Первое, что путается в самой постановке вопроса. [[opencode]] и [[claude-code]] — **агенты**: они читают репозиторий, правят файлы, гоняют команды. VS Code (как и [[cursor]] с его форком) — **редактор**, среда, где человек сам смотрит и правит код.

Поэтому «OpenCode вместо VS Code» — сравнение разных категорий. Реальная замена: **OpenCode вместо Claude Code**, редактор при этом остаётся тем же. Дальше — только про агентов.

## Сравнение

| | **Claude Code** | **OpenCode** |
|---|---|---|
| Лицензия | проприетарный, Anthropic | open source (MIT), SST |
| Модели | только Anthropic (Claude), напрямую или через Bedrock/Vertex/Foundry | ~75–100 провайдеров (цифра расходится по источникам), включая локальные Ollama/LM Studio/Hugging Face |
| Локальные модели | нет | да — код не покидает машину |
| Оплата | подписка (OAuth через claude.ai) **или** API-ключ по токенам | всегда через провайдера; для Claude — только API-ключ по токенам (см. ниже) |
| Файл-инструкция | `CLAUDE.md` | `AGENTS.md` |
| Конфиг проекта | `.claude/settings.json` | `opencode.json` |
| Интерфейсы | терминал, расширения VS Code/JetBrains, десктоп, веб, Remote Control | терминал (TUI), десктоп, веб на localhost |
| MCP | да | да |
| Skills | да, плюс plugins/marketplace | да, совместимая структура |
| Режимы работы | permission-режимы (Manual/Auto/Bypass), Plan Mode | Plan/Build, `ask` на правки и bash |
| Оркестрация | субагенты, [[agent-teams]], [[dynamic-workflows]], hooks, `/goal`, cron-рутины | базовые сессии, без сопоставимого слоя оркестрации |
| Safety net | checkpoints + `/rewind`, сэндбокс (файловый и сетевой слой) | подтверждения на действия, `git` как единственный откат |

## Ключевой факт: подписка не переносится

Февраль 2026 — Anthropic обновила Terms of Service и явно запретила использование subscription-OAuth-токенов (Pro/Max/Team) в сторонних инструментах, включая Agent SDK. В тот же день OpenCode вырезал из кодовой базы Claude-OAuth; к марту исчезли встроенный auth-плагин и подсказки провайдера в UI логина.

Практический вывод: **Claude в OpenCode — только по API-ключу, с оплатой по токенам.** При интенсивной работе (длинные автономные прогоны, большие рефакторинги) это существенно дороже фиксированной подписки. Сторонние плагины, возвращающие OAuth-логин, существуют, но делают ровно то, что ToS запретил — риск блокировки аккаунта.

Это же обстоятельство меняет и позиционирование OpenCode как «бесплатной альтернативы»: бесплатен сам инструмент, не работа модели. Бесплатной она становится только на локальных моделях.

## Плюсы и минусы

### OpenCode

**+**
- Мультипровайдерность: не заперт в одном вендоре, модель меняется под задачу и под цену.
- Локальные модели — единственный вариант, когда код в принципе не должен уходить наружу (NDA, закрытый контур).
- Полностью открытый код: можно читать, форкать, править поведение агента.
- Дешёвые модели на рутину, дорогие — только на сложное.
- Клиент-серверная архитектура: к сессии можно подключиться с другого устройства.

**−**
- Подписка Anthropic не работает — Claude только за токены.
- Промпты и тулинг универсальны, а не заточены под конкретную модель: на том же Claude результат обычно чуть слабее, чем у нативного агента.
- Слой оркестрации беднее: нет аналога agent teams, workflow-скриптов, хуков, долгоживущих харнессов.
- Нет checkpoints/`/rewind` и сэндбокса — страховка сводится к git и подтверждениям.
- Молодой проект, быстро меняется, документация местами отстаёт.

### Claude Code

**+**
- Заточен под модели Anthropic — промпты, инструменты и дефолты собраны под них.
- Подписка с фиксированной ценой вместо счётчика токенов.
- Богатая обвязка: hooks, plugins, субагенты, [[agent-teams]], [[dynamic-workflows]], [[long-running-agent-harness|харнессы долгоживущих агентов]], фоновые агенты, cron-рутины.
- Нативная интеграция с редакторами: диффы в окне, контекст выделения.
- Безопасность как отдельный слой: permission-режимы, сэндбокс (файловая и сетевая изоляция настраиваются раздельно), checkpoints.

**−**
- Vendor lock-in: только Claude. Ни локальной модели, ни выбора по цене.
- Закрытый код — поведение агента меняется релизами Anthropic, влиять нельзя.
- Код всегда уходит в облако Anthropic (Bedrock/Vertex меняют юрисдикцию, но не суть).
- Лимиты подписки: упираешься в потолок прогонов, а не в счёт.
- Быстрый темп релизов ломает привычки — см. историю изменений на [[claude-code]].

## Когда что

- **Нужна локальная модель или свобода выбора провайдера** → OpenCode. Здесь у него монополия, остальные аргументы вторичны.
- **Нужна автономность и оркестрация** (многосессионные задачи, команды агентов, воспроизводимые workflow-скрипты) → Claude Code, у OpenCode сопоставимого слоя нет.
- **Оба сразу** — рабочий вариант: агенты не конфликтуют, живут в разных конфигах (`CLAUDE.md` / `AGENTS.md`) и запускаются из одного репозитория. OpenCode берут под задачи, где важна цена токена или закрытость контура.

Стоимость перехода при этом односторонняя: настройки Claude Code (hooks, skills, permissions, память, регулярные рутины) на `opencode.json` не переносятся — переизобретаются руками.
