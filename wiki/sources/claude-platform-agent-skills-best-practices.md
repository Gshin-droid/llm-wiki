## Саммари

Руководство Anthropic по написанию Skills — заметно полнее и конкретнее того, что в вики уже было собрано из трёх разных официальных источников ([[anthropic-official-skills-docs]], [[agentskills-best-practices]]) и синтезировано в [[skill-authoring-practical-rules]]. Примерно треть материала (progressive disclosure, правило 500 строк, description как единственный триггер, `scripts/` для повторяющейся логики, вариант по умолчанию вместо списка равных) уже есть на той странице на той же глубине. Новое — семь практических блоков, каждый с конкретным механизмом или проверяемым правилом, не сводимым к уже записанному.

## Что взято в вики

Всё → [[skill-authoring-practical-rules]], дополнение 2026-11-09:

- **Степени свободы инструкции** (framework, ранее в вики не было): высокая/средняя/низкая степень свободы инструкции калибруется по хрупкости и вариативности задачи, с аналогией «робот на мосту» (узкий мост с обрывами — точный скрипт без права на отклонение; открытое поле — общее направление, Claude сам найдёт путь). Низкая свобода — конкретный скрипт без параметров («не меняй команду, не добавляй флаги»); средняя — псевдокод/шаблон с параметрами; высокая — текстовые инструкции-эвристики. Раздел «жёсткость калибруется по частям» уже был в вики интуитивно, но без названного механизма принятия решения и без явной лестницы из трёх уровней.
- **Вложенные ссылки режутся частичным чтением — назван механизм, а не только правило.** В вики уже было правило «references одним уровнем», но без объяснения, *почему*: когда файл A ссылается на файл B, который ссылается на файл C, Claude может прочитать промежуточный файл командой типа `head -100` вместо полного чтения — и собрать неполную картину. Отсюда следствие, которого не было: референс-файлы длиннее 100 строк должны начинаться с таблицы содержания, чтобы частичное чтение всё равно показывало полную карту разделов.
- **Разработка через Claude A / Claude B** — итеративный метод написания скилла, которого в вики не было вовсе: один экземпляр Claude («А») помогает спроектировать и отредактировать `SKILL.md` по итогам обычной сессии без скилла, второй свежий экземпляр («Б») тестирует скилл на реальных задачах; наблюдения за поведением Б (неожиданные пути чтения файлов, пропущенные связи, файл, который Б никогда не открывает) возвращаются к А для правки. Явно: не нужен отдельный «скилл написания скиллов» — Claude и так умеет формат.
- **Solve, don't defer + «воодушевлённые константы» (Ousterhout's law).** Скрипт скилла обязан сам обрабатывать предсказуемые ошибки (файл не найден → создать с дефолтом, нет прав → подставить альтернативу), а не перекладывать на Claude решение по месту. Отдельное правило: любая числовая константа в скрипте (таймаут, число попыток) комментируется тем, почему выбрано именно это число — необъяснённое число модель не сможет ни проверить, ни скорректировать.
- **Установка пакетов зависит от среды выполнения — платформенное расхождение, которого не было.** `claude.ai` умеет ставить пакеты из npm/PyPI и тянуть с GitHub во время выполнения скилла; у Claude API **нет сетевого доступа и нет установки пакетов в рантайме**. См. «Противоречия» ниже — это сужает уже записанное в вики правило про `dependencies` в frontmatter.
- **Полные имена MCP-инструментов в тексте скилла.** Если скилл ссылается на инструмент MCP-сервера, писать `ServerName:tool_name` (например, `BigQuery:bigquery_schema`), а не короткое имя — без префикса Claude может не найти инструмент при нескольких подключённых серверах.
- **Третье лицо в description — обязательно, не стилистика.** Description вставляется прямо в системный промпт; несогласованное лицо («I can help...», «You can use this to...») мешает механизму отбора. Формулировка должна звучать как «Processes Excel files…», а не как реплика ассистента.
- **Gerund-форма имени скилла** (`processing-pdfs`, а не `pdf-helper`) — конвенция именования для единообразия в библиотеке из многих скиллов; в вики не было вовсе.
- **Evaluation-driven development — порядок, а не просто «сделай evals.json».** В вики уже была цифра «2–3 сценария», но не сам порядок: сначала прогнать Claude на задаче **без** скилла и зафиксировать конкретные провалы, из них собрать 3 evaluation-сценария, замерить baseline без скилла, написать только минимум текста, закрывающий именно эти провалы, и только потом итерировать. Не писать документацию по воображаемым требованиям — ровно обратный порядок тому, как скиллы обычно пишут («сначала описал всё, что знаю о теме»).
- **Чеклист готовности скилла** — три блока (качество контента / код и скрипты / тестирование), включая «протестировано на Haiku, Sonnet и Opus» — тестирование на всех целевых моделях уже называлось в вики абстрактно, здесь — с конкретным «что проверять на каждой»: Haiku — хватает ли инструкции без неё агент теряется; Opus — не раздута ли инструкция объяснениями, которые Opus и так знает.

## Противоречия

Страница [[skill-authoring-practical-rules]] утверждает без оговорки на среду: «скрипту нужны внешние пакеты — объявляет их `dependencies` во frontmatter, Claude ставит пакеты из PyPI/npm при загрузке скилла». Этот официальный источник это сужает: установка пакетов в рантайме доступна только в `claude.ai`; у Claude API (а значит, и у любого собственного агента на Agent SDK, подключающего Skills через API, а не через `claude.ai`) сетевого доступа и установки пакетов нет вовсе — зависимости нужно закладывать в образ среды заранее. Для Claude Code это не относится напрямую (другой механизм — `/plugin` и собственные скрипты), но формулировка на странице вики звучала как общее правило Skills, а не частность одной платформы. Дополнение на странице концепта помечает это явно.

## Берём инструмент или логику

**Инструмента нет** — это сама методология Anthropic по написанию скиллов, уже применяемая вики (скиллы `wiki-ingest`/`wiki-lint`).

**Логика — все девять пунктов выше.** Два особенно применимы к собственным скиллам репозитория:
- «Степени свободы» прямо объясняет, почему `wiki-ingest` местами жёсткий скрипт (`ingest.py check` — низкая свобода, нельзя обойти), а местами текстовая эвристика («что считать дублем» — высокая свобода, решает модель).
- Таблица содержания для длинных референс-файлов — прямое указание на `references/source-evaluation.md` этого же скилла (хорошо под 100 строк, но будет расти) и на `page-conventions.md`: как вырастут, добавить `## Contents` в начало.
