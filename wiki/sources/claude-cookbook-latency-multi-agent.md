## Саммари

Официальный notebook Claude Cookbooks, добавлен 2026-09-22 — внутри окна поиска этого прогона (прошлый прогон разведчика практики — 09-21, [[claude-cookbook-admin-api]]). Разбирает конкретную проблему: команда «lead + helpers» (см. [[agent-teams]]) по умолчанию оптимизируется на тщательность, а не на скорость — ни у одного агента в контексте нет сигнала, сколько времени уже прошло и сколько человек готов ждать. Дословно: *«Left to itself, a team optimizes for thoroughness, not speed: nothing in any agent's context says how long the person asking has been waiting, or how long they are willing to wait»*.

Собран не на Claude Agent SDK и не на встроенных Agent Teams Claude Code, а на **сыром Messages API** — то есть показывает механизм с нуля, тот же класс задачи, что решают встроенные функции продукта, но в виде переносимого кода, который можно вставить в любую самописную мультиагентную систему.

## Что взято в вики

- **Архитектура**: `TeamClock` — общий секундомер с опциональным бюджетом на всю команду; `Hub` — центральная координация (инбоксы агентов, события, счётчик вызовов тулов, лог прогона); agent loop — обычный tool-use цикл с двумя добавками (штамп времени перед каждым вызовом API, автоматический репорт helper → lead по завершении); инструменты координации `send_message`/`wait_for_message`/`create_subagents` для параллельной работы.
- **Механизм штампа времени**: перед каждым вызовом API в конец последнего user-сообщения дописывается одна строка вида `[elapsed 252s]` (с бюджетом — `[elapsed 252s / 600s]`); helper видит уже прошедшее время команды на первом же ходу, а не с нуля. Прямая функция `stamp_elapsed(messages, clock)`. Кэш не ломается сменой строки — `cache_control={"type": "ephemeral"}` применяется так, что растущая часть остаётся за пределами закэшированного префикса.
- **Два независимых рычага, не смешивать**: (1) **pressure** — одна фраза в промпте: *«Time matters here: do not spend time that can be avoided, and the earlier a correct result is obtained, the better»*; (2) **budget** — только цифры на строке часов, без единого слова текста: *«No prompt text comes with it: the second number is all any agent is told about the budget»*. Разница важна: pressure убеждает торопиться всегда, budget сообщает только остаток, оставляя агенту решать, что с этим делать.
- **Вывод авторов (дословно)**: *«We gave a lead-and-helpers team one shared clock and showed it to every agent before every turn. One sentence of latency pressure, or a budget on the clock line, is then what changes how the team paces itself»*. Рекомендация: pressure — когда «раньше просто лучше», budget — когда есть конкретный целевой лимит времени.
- **Честно названные границы**: бюджет не подходит коротким задачам — *«A budget suits longer tasks better than brief ones. When the whole task takes a minute or two, half of that leaves little room to do any of the work, and Claude may overrun the budget»*; авторы прямо просят проверить качество ответов на своей задаче, прежде чем включать более быструю конфигурацию — *«Before acting on a faster arm, check that its answers are still good enough for your task»*; техника **не протестирована полностью на Claude Opus 5 и более старых моделях**, демо по умолчанию использует `claude-fable-5-1` (с переопределением через `COOKBOOK_MODEL`).

## Берём инструмент или логику

**Логика, не инструмент.** Ставить нечего — это код-пример на 100–200 строк, не библиотека и не сервис. Переносимый механизм — три штуки: (1) единая строка с прошедшим временем/бюджетом, дописываемая к последнему сообщению перед каждым вызовом модели, без порчи промпт-кэша; (2) осознанный выбор между «фразой давления» (действует всегда) и «голыми цифрами бюджета» (действует только когда агент сам решает, что с ними делать) — два разных рычага, а не один; (3) обязательная проверка качества на своей задаче перед тем, как довериться более быстрой конфигурации — иначе экономия времени объясняется недоделанной работой, а не эффективностью.

Прямое применение к этой же вики: [[dynamic-workflows]] и [[agent-teams]] — оба механизма Claude Code, где агенты не знают, сколько времени уже потрачено на прогон; ни одна из трёх автономных рутин вики сейчас не многоагентна, но при первом же случае, где рутина заспавнит несколько параллельных субагентов с бюджетом токенов (например, воскресный механический проход + сверка с сырьём внутри одного прогона), штамп времени — готовый к переносу приём без своей реализации с нуля.

## Что не взято / лиды

- Количественных замеров (время базового прогона против pressure/budget, токены, качество ответов) в ноутбуке нет — только один smoke-тест на 9 секунд с 4 спавненными helper'ами, без сравнения веток. Не заносится как цифра, потому что цифры не измерено самим источником.
- Полный код ноутбука (классы `TeamClock`/`Hub`, инструменты координации) прочитан пересказом через `WebFetch`, не побайтово построчным чтением JSON — сигнатуры функций не сверены буква-в-букву. Если понадобится точная реализация — отдельный заход с прямым построчным чтением `.ipynb`.
