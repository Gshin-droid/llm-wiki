# Claude Agent SDK — впрыск аргументов командной строки через `resume` (CVE-2026-96620)

**Дата загрузки:** 2026-10-19 (ярус 2 рутины 1, вслед за [[novosti-2026-10-19]])
**Опубликовано:** 2026-09-12 (раскрытие мейнтейнером на GitHub), 2026-10-16 (регистрация в GitHub Advisory Database)
**Тип:** официальная security-карточка GitHub Advisory Database (CNA-запись, издана самой Anthropic как мейнтейнером пакета)
**Ссылка:** `github.com/advisories/GHSA-h4mw-j7qp-8mwm`
**Raw:** отдельным файлом не сохранён — страница прочитана напрямую через WebFetch, без посредников-пересказов.

## Саммари

**CVE-2026-96620 / `GHSA-h4mw-j7qp-8mwm`** — критическая уязвимость (CVSS v4 9.2) в Python-пакете `claude-agent-sdk` (версии младше **0.2.121**). SDK передавал значение опции `resume` (а в некоторых путях — и `session_id`) в CLI Claude Code как токен командной строки без проверки. Значение, начинающееся с дефиса, CLI интерпретировал не как ID сессии, а как отдельный флаг. Атакующий, контролирующий это значение, мог впрыснуть флаг `--mcp-config`, определяющий stdio MCP-сервер, — тот запускался и выполнял произвольные команды уже при старте CLI, **минуя permission-контроль самого SDK** (`allowed_tools` и прочие ограничения просто не успевают сработать: впрыск происходит на уровне CLI-процесса, а не внутри agent loop, который эти ограничения проверяет).

Условие эксплуатации: приложение на SDK передаёт в `resume` (или `session_id`) значение, пришедшее снаружи — не сгенерированное самим приложением. Это ровно тот путь, которым многие приложения и реализуют «продолжить сессию по ссылке/ID из URL» — то есть уязвимость попадает в код, который выглядит обычным и безопасным на вид.

## Берём инструмент или логику

**Инструмент** — не ставим и не трогаем: `claude-agent-sdk` в этой вики не используется (саму вики ведёт Claude Code CLI, не SDK), страница существует только потому, что об SDK уже есть сущность [[claude-agent-sdk]].

**Логика — берём, применимо к любому приложению на agent SDK, не только к Claude:** непроверенное внешнее значение, уходящее в аргумент командной строки другого процесса, — классический argument injection (CWE-88), не специфичный для Claude. Конкретное правило для будущих проектов: **любой параметр, который приложение передаёт во внутренний CLI/subprocess как значение опции, обязан быть провалидирован по формату (whitelist символов, явный запрет префикса `-`), если он хотя бы теоретически может содержать внешний ввод** — ID сессии «выглядит как безопасные данные», но форма передачи (аргумент CLI, не поле JSON) делает его кодом. То же общее правило уже стояло на [[ai-security-by-design]] применительно к MCP-авторизации и плагинам; здесь — третья по счёту поверхность эксфильтрации/RCE через «данные, которые на самом деле аргументы».

## Что не взято / лиды

- **Есть ли похожая уязвимость в TypeScript-версии SDK (`@anthropic-ai/claude-agent-sdk`)** — advisory и найденные пересказы говорят только про pip-пакет; TS-пакет отдельно не проверялся, за пределами этого разбора.
- **EPSS 0.578% (46-й перцентиль)** — метрика вероятности эксплуатации за 30 дней, взята из вторичного агрегатора (не с самой страницы advisory, где она не показана в читаемом виде), presумпция «по пересказу», не «прочитано».
- **Связь версии фикса SDK (0.2.121) с версией бандлированного CLI (2.1.212)**, упомянутая одним агрегатором, — не проверена напрямую, не вносится как факт.
