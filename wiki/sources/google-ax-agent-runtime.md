## Саммари

AX — среда выполнения **агента как рода нагрузки**, а не как процесса. Исходная посылка README: агенты — *«ни stateless-микросервисы, ни batch-задачи, выполняемые до конца»*; они накапливают состояние, требуют строгой изоляции и способны съесть заметные ресурсы. Отсюда и устройство: декларативные YAML-манифесты, CLI в духе `kubectl` (`apply`, `get`, `describe`, `watch`, `delete`), работа поверх Kubernetes.

Сравнение «Kubernetes для агентов» из поста-наводки точное, и README его фактически подтверждает: *«если вы работали с Kubernetes, ax покажется знакомым»*.

**Сразу главное для применимости: нужен кластер Kubernetes.** Плюс сборщик контейнеров `ko`, доступный реестр образов и Control API нижележащей среды Agent Substrate. Это инструмент для тех, у кого уже есть кластер, — на одиночной рабочей машине он не живёт.

## Четыре примитива

| Примитив | Что задаёт |
|---|---|
| **Task** | запуск изолированного кода с ограничениями по процессору и памяти |
| **Workspace** | заранее подготовленное окружение: git-репозитории и серверы |
| **Gateway** | **контроль исходящего трафика по списку разрешённого** |
| **Model** | конфигурация языковой модели вместе с доступом к учётным данным кластера |

Плюс две операции, ради которых всё и затевалось: `ax suspend` / `ax resume` — контрольная точка состояния агента с последующим продолжением, и `ax ssh` — залезть внутрь и посмотреть, что происходит.

## Берём инструмент или логику

**Инструмент не берём** — для него нужен кластер Kubernetes, которого нет и заводить незачем: цена обслуживания несопоставима с задачами.

**Берём две идеи**, обе воспроизводимы в своём масштабе:

1. **Gateway: исходящий трафик по списку разрешённого.** Изоляция агента обычно обсуждается со стороны файлов и команд — «куда можно писать», «что можно запускать». AX ставит рядом третью ось: **куда агенту можно ходить по сети**. Это и есть канал утечки: агент, прочитавший чужую инструкцию из источника, вреден ровно настолько, насколько ему есть куда отправить прочитанное. В [[claude-code]] такой механизм уже существует (`allowed_domains` в правах, включая per-command), и AX — довод, что это не второстепенная настройка, а один из четырёх несущих примитивов.
2. **Suspend/resume как штатная операция, а не авария.** Долгая работа агента должна уметь остановиться и продолжиться с сохранённого состояния — без этого всякий обрыв означает потерю. У нас та же потребность закрыта иначе и слабее: инкрементальный коммит после каждой доведённой находки плюс отметка «начато» в журнале. AX показывает верхнюю планку — не «не потерять сделанное», а «продолжить прерванное с той же точки».

**Что сознательно не берём:** декларативные манифесты и оркестрацию как таковую. Для одной машины и одного агента это чистая накладная сложность.

## Что взято в вики

1. Новая сущность [[google-ax]].
2. **Сетевой allowlist как один из четырёх несущих примитивов изоляции агента** → дополнение к [[ai-security-by-design]].

## Допроверка 2026-09-26 (ежедневный процесс закрытия пробелов): Agent Substrate

Пункт бэклога «Agent Substrate: что это и обязателен ли он» (заведён 22.09) закрыт. README `google/ax` дал прямую ссылку на репозиторий `github.com/agent-substrate/substrate` — его README прочитан напрямую (`raw.githubusercontent.com`), плюс страница репозитория.

**Отдельный проект, не часть организации Google на GitHub.** Репозиторий живёт под организацией `agent-substrate`, а не `google`; лицензия Apache 2.0; 3,8k звёзд, 443 форка. README называет `google/ax` лишь одним из примеров экосистемы («Agent Executor: … built on Agent Substrate») — прямой принадлежности Google в самом README нет, ни подтвердить, ни опровергнуть её этим документом нельзя (`CONTRIBUTING.md`/`GOVERNANCE.md`/`MAINTAINERS.md` в репозитории есть, построчно не читались).

**Обязателен, не одна из опций.** README `google/ax` дословно: *«Substrate must be running in your cluster before you deploy AX»* — Control API (`api.ate-system.svc.cluster.local:443`) это предусловие развёртывания. Есть ли альтернативные совместимые бэкенды, README Agent Substrate не поднимает вообще — вопрос замены остаётся без ответа в доступных источниках.

**Что это.** Дословно: *«Agent Substrate is a secure-by-default agent execution runtime engineered to run millions of sandboxes with 10x higher density than standard container runtimes»* — маппинг «акторов» (приложений вроде агентов) на меньший набор готовых «воркеров». Зависимость от Kubernetes не убирает, а добавляет к ней свой слой: дословно *«leverages Kubernetes for the infrastructure provisioning and worker lifecycle management (Kubernetes Pods)»*.

**Зрелость** та же, что уже была известна у `ax`: pre-1.0, дословно *«not making any guarantees about backward compatibility at this stage»*.

**Вывод для цены входа.** Оценка «нужен кластер Kubernetes + Control API Agent Substrate» на [[google-ax]] по сути не меняется, но уточняется: Substrate — обязательный слой планирования поверх того же кластера, а не третья опциональная зависимость; вопрос замены его чем-то другим остаётся открытым за отсутствием ответа в первоисточнике.

## Оценка источника

**Пост-наводка неточен в главном слове.** «Google открыла исходный код AX» — репозиторий создан **30.03.2026** и публичен с тех пор; новостью является релиз **v0.3.0 от 20.09.2026**, совпавший с волной публикаций. На 22.09.2026 у проекта 6 645 звёзд и 316 форков — цифры живого, но не ажиотажного проекта.

Отдельно стоит предупреждения ради: **вторичные публикации об AX в поисковой выдаче противоречивы и похожи на сгенерированные**. Встречаются «150 000 разработчиков зарегистрировались за 48 часов» (против 6,6 тыс. звёзд по API), «анонс на I/O 18 сентября» и «эталонная реализация с Gemini 1.5 Pro» — модель прошлых поколений. Ни одно из этих утверждений в вики не внесено. Случай показателен: **вокруг свежего релиза крупной компании автоматически вырастает слой правдоподобного мусора**, и проверка по API репозитория занимает одну команду.

Сам README — первоисточник, честно называет незрелость: *«мы всё ещё активно уточняем базовые понятия, протоколы и спецификации; вероятны крупные ломающие изменения до стабильного релиза»*.
