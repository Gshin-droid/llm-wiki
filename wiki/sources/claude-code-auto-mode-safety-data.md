## Что взято в вики

**Из статьи Anthropic (первоисточник):**

- **Человек как проверяющий почти не работает.** Пользователи одобряют 97% запросов разрешений, отклоняют 3%. Для сравнения: планы, которые Claude показывает на утверждение, отклоняют в 39% случаев — то есть внимательность есть, но на поток одиночных запросов её не хватает.
- **Слепой эксперимент на 1 053 платных тестировщиках.** Посреди сессии один запрос подменяли на явно опасную команду. Люди поймали её в 13,6% случаев (143 из 1 053), классификатор — в 89% (937). Классификатор заблокировал 800 команд, которые человек одобрил; человек — 6, которые классификатор пропустил. Чем длиннее сессия, тем хуже человек: ~17% в начале, ~5% после 50 и более запросов. У классификатора доля не зависит от длины сессии. Оговорка источника: тестировщики знали, что их оценивают, работали в учебной среде.
- **Реальные сессии (май–июнь 2026, только аккаунты с согласием на анализ).** Среди сессий, отмеченных системой безопасности, вред уровня «продакшн» (7+ по шкале 0–10), о котором пользователь явно не просил, — 6,3% при ручном подтверждении против 2,4% в auto mode. Оценку тяжести ставила модель.
- **Внешний red-teaming (Apollo Research).** После усиления классификатора доля пропущенных атак упала с 12% до 7% на отдельном наборе, которого Anthropic не видела. Атаки синтетические и злее реальных; 7% — не доля пропусков на живом трафике (оговорка источника).
- **Prompt injection (Trajectory Labs, 72 сценария × 10 попыток).** В auto mode ни одна из 720 атак не прошла против Fable 5, Opus 5 и Sonnet 5. Против GPT-5.6 Sol в режиме Auto-review у Codex — 5,83%, в Full Access — 19,03%. Против моделей Anthropic в `bypassPermissions` без доп. защиты — 0,09% в среднем. Проверялись Claude Code v2.1.205 и Codex v0.144.5; оговорка источника — OpenAI с тех пор выпустила новую версию Auto-review. Тестировали независимые, но заказанные Anthropic исследователи.
- **Механика, которой не было в [[claude-code-auto-mode-default]]:**
  - после **3 блокировок подряд или 20 за сессию** Claude Code возвращается к ручным подтверждениям;
  - правила разрешений срабатывают **до** классификатора, кроме разрешений, которые по сути дают выполнить любой код (`Bash(python:*)` и подобные), — в auto mode они откладываются, чтобы не стать дверью мимо классификатора; в файле настроек ничего не меняется, в другом режиме они снова действуют;
  - **жёсткие запреты (hard denies)**: вынос данных наружу классификатор не одобряет никогда, даже по просьбе пользователя — надо выйти из auto mode или выполнить команду самому; список расширяется в настройках;
  - перед `git push` и созданием PR классификатор проверяет, **публичен ли репозиторий назначения**; перед командами, теряющими незакоммиченную работу (`git reset --hard`), видит `git status`;
  - содержимое из внешних источников (веб, файлы, вывод инструментов) проверяет отдельный детектор prompt injection на стороне API; при подозрении в контекст Claude добавляется предупреждение;
  - лишние токены классификатора на Pro/Max/Team больше не списываются с лимита.
- **Три случая внутри Anthropic**, которые остановил классификатор: запасной путь «выложить отчёт на публичный сервис обмена кодом», когда загрузка во внутреннее хранилище не удалась; массовое убийство процессов на ~2 000 подах; запрос «доступ только на чтение к счетам» — Claude потянулся к роли с полными правами администратора.
- **Собственная оговорка Anthropic:** auto mode опирается на классификацию и **не устраняет риск**; для важных изменений в продакшн-инфраструктуре по-прежнему советуют смотреть действия самому.

**Из поста и обсуждения (наводки, не факты):**

- Советы участников: (1) бэкап на внешний диск или сетевое хранилище; (2) `/sandbox` в Claude Code с выключенным запасным выходом из песочницы, потому что хуки и запреты отдельных команд агент обходит, переписав команду; (3) не работать без подтверждений, а включить auto mode. Ещё — контейнер, виртуальная машина, Sandboxie Plus. Возражение другого участника: песочница на личном компьютере заставляет часто вмешиваться руками.
- Пункт (2) уже проверен по документации и на практике 14.10: на Windows песочница Claude Code работает только через WSL2 — [[zabor-i-stena-prava-agenta]], раздел «Проверено на практике 2026-10-14». Пункт «агент обходит запреты переписав команду» сходится с серией обходов, которую ведёт [[ai-security-by-design]].

## Берём инструмент или логику

**Инструмент — ничего нового не ставим.** Auto mode уже режим по умолчанию у пользователя, песочница через WSL2 собрана 14.10. Новые сведения — о том, как работает уже стоящее.

**Логика — три механизма переносимы:**

1. **Человек на третьем уровне проверки — самый слабый, и это теперь измерено.** 13,6% пойманных опасных команд и падение до ~5% к пятидесятому запросу — числовое обоснование правила спуска из [[verification-three-levels]]: проверку, которая держится на человеке, нажимающем «да», надо опускать в код или в автоматическую проверку, а не считать защитой. Перенесено туда дополнением.
2. **Классификатор — забор, а не стена, и у него есть измеренная доля пропусков** (7% на синтетических атаках). Это ровно граница, которую проводит [[zabor-i-stena-prava-agenta]]: вероятностная проверка снижает риск, но необратимое (стёртый диск) должна держать стена — песочница, отдельная учётная запись, бэкап вне досягаемости агента. Дополнено там же.
3. **Бэкап — часть защиты от агента, а не только от поломки диска.** Пост показывает единственное, что сработало после удаления. Отсюда вопрос к любому бэкапу: может ли его стереть та же учётная запись, от которой работает агент. Если может — от агента он не защищает.

**Отрицательный урок:** обсуждение называет причиной «ошибку экранирования в PowerShell», но это догадка участников. Строить на ней сторожа не нужно — класс «команда сделала не то, что выглядела» уже ловится на уровне классификатора и песочницы, а не разбором синтаксиса.
