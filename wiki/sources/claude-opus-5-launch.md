## Саммари

Автономный прогон еженедельного разведчика. С предыдущего снапшота ([[claude-code-changelog-snapshot-2026-07-22]], покрывал до v2.1.217) вышло две версии Claude Code — **2.1.218** и **2.1.219** — и, параллельно, 24 июля 2026 Anthropic официально выпустила **Claude Opus 5**, новую флагманскую модель, которая в v2.1.219 сразу же стала дефолтной моделью Claude Code. Это самая значимая находка с момента запуска этой вики — не рутинный набор багфиксов, а смена модели, на которой по умолчанию работает сам инструмент, поддерживающий вики.

## Ключевой тезис: Claude Opus 5 — новый флагман, та же цена, thinking по умолчанию

Opus 5 — "step-change" улучшение над Opus 4.8 (не инкрементальное), при этом **цена не изменилась**: $5 / $25 за MTok, как у Opus 4.8. Контекстное окно 1M токенов — теперь единственный вариант (нет меньшего окна), 128k максимум на выход. Reliable knowledge cutoff — май 2026 (у Sonnet 5/Fable 5 — январь 2026, у Opus 5 самый свежий из всей линейки).

**Breaking change:** thinking включён по умолчанию (было выключено на Opus 4.8, если явно не запросить `thinking: {"type": "adaptive"}`). Отключить thinking (`type: "disabled"`) теперь можно только при effort `high` и ниже — на `xhigh`/`max` попытка отключить возвращает ошибку 400. При отключённом thinking модель иногда пишет вызов инструмента прямо в текст вместо `tool_use`-блока — источник явно предупреждает об этом как о крае поведения, а не баге.

**Официально отмеченные поведенческие отличия** (важно при переносе промптов со старых моделей): более длинные ответы по умолчанию, чаще проговаривает прогресс в агентских сессиях, охотнее делегирует субагентам — и **сама проверяет свою работу без явной просьбы**, из-за чего унаследованные с прошлых моделей инструкции "добавь шаг верификации в конце" вызывают избыточную повторную проверку. Прямое пересечение с практикой этой вики: [[dynamic-workflows|Dynamic Workflows]] и агентские инструкции этой вики регулярно просят субагентов "верифицировать находку" — стоит иметь в виду при следующей правке промптов workflow-скриптов под Opus 5.

Заявленные улучшения: код-ревью и поиск багов (высокая точность, мало false positives, держится на низких effort), мультиагентная координация (writer-verifier без взаимной перезаписи), long-horizon агентский кодинг без заглушек, long-context согласованность по всему 1M окну.

## Обновление Claude Code v2.1.218

- **`/code-review` теперь по умолчанию — фоновый субагент**, а не блокирующий текущий диалог. Не путать с уже зафиксированным изменением v2.1.215 ([[claude-code-changelog-snapshot-2026-07-20]]): то изменение — про то, что `/code-review` больше **не подключается автоматически** сам по себе; это изменение — про то, **как именно** он выполняется, когда его всё же явно вызвали. Два разных, не противоречащих друг другу изменения одного и того же скилла.
- **`/deep-research` изменён на manual-only invocation** — та же логика, что применена к `/verify`/`/code-review` в v2.1.215: раньше мог подключаться автоматически, когда Claude решал, что скилл релевантен, теперь только по явному вызову командой. Расширяет список исключений из общего механизма авто-подключения скиллов (см. [[claude-skills]]).
- **Auto mode: решение по опасным командам теперь через классификатор**, без диалоговых окон (формулировка changelog краткая, деталей о конкретных категориях команд нет).
- **Workspace trust теперь обязателен для хуков из frontmatter агентов в недоверенных папках** — защита от того, что склонированный чужой репозиторий с `.claude/agents/*.md` мог бы незаметно исполнить хук при первом же открытии.
- Плюс серия мелких фиксов (Windows-пути, screen reader, `/ultrareview`, Bedrock wizard и т.п.) — без изменения практической механики.

## Обновление Claude Code v2.1.219

- **Claude Opus 5 — новая модель по умолчанию** в Claude Code (см. выше).
- **`sandbox.network.strictAllowlist`** — новая настройка, блокирующая недоверенные хосты без запроса подтверждения (раньше сэндбокс мог в некоторых случаях спросить разрешение на новый хост вместо жёсткого отказа) — расширяет линейку точечных sandbox-настроек рядом с `sandbox.filesystem.disabled` ([[claude-code-changelog-snapshot-2026-07-22]]).
- **`workflowSizeGuideline`** — именованная настройка для дефолтного размера Dynamic Workflows; этим же релизом **дефолт сменился на medium (менее 15 агентов за прогон)** — ровно то значение, которое подтверждено в системном промпте сессий этой самой вики ("This session has the default workflow size guideline: medium — keep workflows under 15 agents"). Редкий случай, когда changelog можно сверить напрямую с наблюдаемым поведением собственной сессии, а не только с документацией.
- Статус-строка теперь показывает текущий размер workflow с подсказкой перехода в `/config`.
- **Изменение (заявлено, не подтверждено доками): "Increased subagent nesting depth to 3 levels by default"** — третья по счёту смена дефолта глубины вложенности субагентов подряд (5 уровней до v2.1.216 → 0 уровней с v2.1.217 → заявлено 3 уровня с v2.1.219). **Официальная документация `code.claude.com/docs/en/sub-agents` (перечитана целиком в этом прогоне) пока не подтверждает это значение** — по состоянию на 2026-07-25 страница всё ещё описывает дефолт как полностью выключенный (0 уровней) и историческую врезку про переход 5→0, без упоминания перехода к 3. Не переношу "3" на страницу [[claude-code]] как подтверждённый факт — оставлено как открытый пункт для допроверки следующим прогоном (см. `wiki/gaps-backlog.md`), по прецеденту 07-22/07-23, где документация досогласовалась с changelog за 1 день.
- Прочее: `DirectoryAdded`-хук, `mcp_server_errors` в stream-json, форвардинг вложенных субагентов в stream-json на глубине 2+, обновление встроенного справочного скилла `claude-api` под дефолт Opus 5 и путь миграции, удаление fast mode для Opus 4.7 (согласуется с официальными release notes — см. блок про Opus 5 выше).
