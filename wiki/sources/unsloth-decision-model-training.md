Содержание страницы поэтому читано по захваченной копии в raw-файле, а не напрямую; независимо подтверждено и дополнено прямым чтением трёх источников на `github.com`/`raw.githubusercontent.com` (которые открылись штатно): README репозитория `unslothai/notebooks`, сам ноутбук `Qwen3_5_(4B)-Decision.ipynb`, release notes `unslothai/unsloth` (v0.1.904-beta, v0.1.906-beta) и файл-источник `unsloth/models/decision_from_lm.py`.

Unsloth добавил `FastDecisionModel`/`DecisionTrainer` — API для превращения обычной LLM (Qwen, Llama, Gemma) в **модель решений** того же класса, что [[laya]], [[jev-typesafe]] и [[openjev-verdict-2]]: вход — состояние и вопросы, выход — выбор/да-нет/оценка с калиброванной вероятностью, без генерации текста. Это первый найденный в вики случай, когда рецепт «дообучи свою модель решений» **официально документирован и воспроизводим** (а не реконструирован из README чужой уже готовой модели), и единственный, применимый к **любому языку и домену**, включая русский — ровно то, чего не хватает открытому пункту `wiki/gaps-backlog.md` («Локальная модель решений на русском»).

## Что взято в вики

- **Архитектура.** «Clef-style» голова (по словам документации — «the same design as Cloudflare's Clef») дочитывает выход LLM по каждому вопросу и варианту и оценивает все вопросы разом за один проход; LLM не пишет текст и не тратит память на предсказание слов. Три типа вопроса: `choice` (метка + вероятности вариантов), `noul` (калиброванная вероятность 0.0–1.0, по сути то же, что `noul` у [[laya]]), `score` (уровень по шкале).
- **Два задокументированных рецепта обучения, не совпадающих друг с другом** — страница явно различает их, это не противоречие, а две конфигурации под разные цели:
  - **Быстрый старт** (воспроизведён и подтверждён прямым чтением ноутбука `Qwen3_5_(4B)-Decision.ipynb`): LoRA `r=16`, `lora_alpha=16`, `lora_dropout=0`, `learning_rate=2e-4`, `lr_scheduler_type="cosine"`, `warmup_steps=10`, `weight_decay=0.01`, `max_steps=60` (для полного прогона — `num_train_epochs=2`, без ограничения на шаги, в документации — «70 шагов»); батч 8 × 4 (эффективно 32). Qwen3.5-4B на этой конфигурации — 75–78% после 60 шагов, 10 минут на L4.
  - **Конфигурация официальной таблицы бенчмарков** (со страницы, не из ноутбука): LoRA `r=64`, **один эпох**, подъём точности с уровня почти случайного угадывания (30–37%) до 78–81% в зависимости от модели.
  - Обе конфигурации — варианты одного и того же API, расхождение в ранге LoRA и числе эпох честно объяснимо разной целью (быстрая проба против воспроизведения опубликованных цифр), а не ошибкой источника.
- **Датасет.** `LocalLLaMA/typed-decisions` (тот же набор, что уже используется в вики для оценки [[openjev-verdict-2]]) + 11 источников (`ag_news`, `arc`, `banking77`, `boolq`, `clinc150`, `commonsense_qa`, `mmlu`, `mnli`, `prompt_injections`, `snli`, `sst5`, `wanli`). Тестовый набор — 3000 строк (2000 typed-decisions + 500 BANKING77 + 500 CLINC150), decontaminated против обучающей выборки. Формат — своя схема: `state`, `questions`, `gold`, читается кодом ноутбука и подтверждён прямым чтением `.ipynb`.
- **Калибровка встроена в сам воркфлоу.** После обучения — `FastDecisionModel.calibrate` на отложенном сплите (`split_holdout`, `seed=3407`, 80 строк / 400 решений в ноутбуке), «so the model's probabilities match how often it's right» — то есть температурная подгонка по held-out выборке, ровно второй метод из раздела «Чем калибровку улучшают» в [[kalibrovka-uverennosti-resheniy]], только теперь не абстрактный пункт, а конкретный вызов API с воспроизводимым кодом. ECE после калибровки в документации — 0,02–0,06.
- **Бенчмарки по моделям** (со страницы, таблица с VRAM и временем обучения — не из ноутбука, т.к. ноутбук тестирует только Qwen3.5-4B): Qwen3.5-0.8B — 78%, 4 ГБ, 42 мин; Qwen3.5-2B — 81%, 8 ГБ, 40 мин; Llama 3.2 3B — 79%, 4,1 ГБ, 30 мин; Gemma 4 E4B — 77%, 14,4 ГБ, 49 мин; **Laya (fine-tuned) — 77%, 2,5 ГБ, 10 мин** — Unsloth умеет дообучать не только с нуля, но и продолжать обучение уже готовой [[laya]].
- **Сервинг.** Обученная модель регистрируется в «Decision API» Unsloth Desktop под именами `laya`, `default` или `jev-latest` — то есть собственная дообученная модель может подменить собой вызовы к [[laya]] или к облачному [[jev-typesafe]] без изменения кода, который её зовёт (чистая замена на уровне имени эндпоинта). Отдельно — экспорт моделей Laya/Clef-с-backbone-Qwen3.5 в GGUF и запуск через `llama.cpp` (release v0.1.904-beta, подтверждено прямым чтением release notes).
- **Лицензия расходится внутри одного проекта — проверено по заголовкам файлов, не по пересказу.** Основной пакет `unsloth` — Apache-2.0 (бейдж/README), `unsloth-zoo` — LGPL-3.0 (прямое чтение файла `LICENSE`), но конкретно файл с кодом decision-моделей, `unsloth/models/decision_from_lm.py`, несёт заголовок `SPDX-License-Identifier: AGPL-3.0-only` (прочитано напрямую, первые строки файла). Независимое подтверждение стороннего корейского форум-поста (`discuss.pytorch.kr`), который называл то же самое, но как несверенный пересказ. **Практический смысл:** AGPL — сетевой копилефт; если когда-нибудь встанет вопрос об оказании decision-model-инференса как сетевого сервиса на этом конкретном коде, а не просто о локальном обучении для себя, обязательства AGPL относятся именно к этому файлу, а не ко всему пакету Unsloth.

## Берём инструмент или логику

**Инструмент — не ставим сейчас, но путь расчищен.** Обучение требует GPU (бесплатно хватает Colab/Kaggle T4, бесплатный; локально — RTX PRO 6000/A100 в разы быстрее) и решения пользователя, какую модель и на каких данных дообучать — это не то, что автономная рутина может сделать сама. Установка через `curl https://unsloth.ai/install.sh | sh` — исполнение свежего неprочитанного скрипта, тот же класс риска, что уже отмечен у других установщиков в вики (например, `impeccable`, `claude-code-templates`): если ставить, то после чтения скрипта или через `pip install unsloth`/ноутбук без собственного инсталлятора.

**Логика — берём три вещи.** (1) Готовый, воспроизводимый рецепт («дообучи свою модель решений под любой домен и язык») закрывает методический разрыв открытого пункта бэклога «Локальная модель решений на русском»: раньше там не было ничего, кроме идеи «взять 40–60 своих примеров»; теперь есть конкретный API (`FastDecisionModel.from_pretrained` → `DecisionTrainer` → `FastDecisionModel.calibrate`) и формат данных, на которые эти примеры можно разложить. (2) Встроенный шаг калибровки на held-out выборке — рабочий образец того, что [[kalibrovka-uverennosti-resheniy]] раньше описывала только как общий принцип «температурная подгонка после обучения»: теперь это конкретный вызов, который стоит воспроизводить в любом самодельном пайплайне дообучения модели решений. (3) Регистрация своей модели под именем `jev-latest`/`laya` в локальном Decision API — рабочий пример того, как решение «не используем облачный Jev» ([[jev-typesafe]], решение 2026-09-22) может быть реализовано не отказом от удобного интерфейса, а подменой его локальной моделью на том же имени.

## Что не взято / лиды

- **Числа расходятся между релизами и описаниями, и это не сведено в одну цифру намеренно.** Страница документации называет диапазон 78–81% для разных базовых моделей на конфигурации `r=64`/1 эпоха; release notes v0.1.904-beta отдельно говорят «30% → 80%» без привязки к конкретной модели; сторонний пересказ (AlphaSignal) заголовком называет «78% accuracy» для 0.8B-модели. Цифры не противоречат друг другу впрямую (разные версии/конфигурации/модели), но и не образуют одну проверяемую линию — на странице это оставлено как есть, без придумывания единого числа.
- **Серверная сторона Decision API (как именно Unsloth Desktop поднимает инференс, что происходит при параллельных запросах во время обучения) не разбиралась** — документация упоминает, что обучение и инференс делят GPU и инференс ждёт, но код этого пути не читался. Не критично для нашей задачи (локальное обучение под свою модель), оставлено без отдельного пункта бэклога.
- **Ещё один раздел документации — «Decisions API + Serving Guide» и «Dataset Guide»** — упомянуты страницей, но не открывались отдельно (не было прямых ссылок в захваченном тексте, только название). Если понадобится реально обучать свою модель — читать их первыми.
