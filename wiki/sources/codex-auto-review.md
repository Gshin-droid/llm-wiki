## Саммари

Пересказ обсуждения практиков: в Codex стоит включить Auto-review вместо полного доступа (`--yolo`), потому что при полном доступе проверять нечего, а субагенты наследуют права основного агента. Приложенная документация OpenAI это подтверждает. Разобран вместе с пользователем; решение пользователя — Codex не используется, **берём только механизмы**. Главный из них оказался применим сразу: проверка своих правил разрешений Claude Code нашла три широких правила, мимо которых опасные команды проходили без классификатора.

## Как устроено (по документации)

- Агент Codex работает в песочнице (только чтение или запись в рабочую папку). Выход за неё — сеть, правка вне разрешённых папок, повышенные права, помеченные инструменты MCP — требует одобрения.
- При `approvals_reviewer = "auto_review"` одобрение решает не человек, а отдельный агент-проверяющий. Он видит сжатую переписку, вызовы инструментов и сам запрос, **но не скрытые рассуждения** основного агента; изредка делает проверки только на чтение.
- **Это замена проверяющего, а не выдача прав**: песочница, сеть и защищённые пути не меняются. При `approval_policy = "never"`, полном доступе или `--yolo` запросов не возникает — проверять нечего.
- Блокирует: отправку личных данных и секретов наружу, поиск ключей и токенов, широкое или постоянное ослабление защиты, разрушительные необратимые действия. Политика проверяющего открыта в репозитории Codex и заменяется своей целиком (не дополняется).

## Механизмы, которые переносимы

1. **Отказ — не ошибка.** После отказа основной агент получает обоснование и указание: не добиваться того же обходным путём, косвенным исполнением или обходом политики; продолжать только заметно более безопасным путём, иначе остановиться и спросить человека.
2. **Предохранитель отказов:** 3 отказа подряд или 10 из последних 50 проверок в одном ходе — ход прерывается, а не продолжает попытки. Любое одобрение сбрасывает счётчик подряд.
3. **Тайм-аут — не довод «опасно»**: о нём агенту сообщают отдельно от отказа.
4. **Узкая отмена отказа человеком** (`/approve`): одно конкретное отклонённое действие, один повтор, и повтор всё равно проходит проверку.
5. **Граница прежде проверяющего.** Если проверяющему идёт много рутины, чинить границу песочницы, а не приучать проверяющего одобрять шум. Правила по точному началу команды (`["pnpm", "run", "lint"]`) лучше широких (`["python"]`, `["curl"]`): **широкое правило стирает границу, которую проверяющий должен стеречь.**
6. **Субагенты наследуют права родителя**, включая режим, переключённый на ходу (`--yolo`), даже если файл субагента задаёт другое. Режим выбирается до того, как просишь делегировать.

## Берём инструмент или логику

- **Инструмент — нет.** Codex у пользователя не в работе; страница-инструкция по настройке не нужна (решение пользователя 19.10).
- **Логика — да, и одна уже применена.** У Claude Code тот же механизм — auto mode с классификатором вместо человека ([[claude-code-auto-mode-safety-data]]), и там же записано: правила «разрешено» срабатывают **до** классификатора, кроме правил, дающих выполнить любой код. Механизм 5 поэтому прямо применим к собственным настройкам: всё, что пропускает широкое правило, классификатор не видит.

## Проверка на практике: свои правила разрешений (2026-10-19)

Просмотрены правила `allow` в настройках Claude Code (общих и проекта вики). Найдено четыре широких правила, пропускающих опасное мимо классификатора:

| Правило | Что пропускало | Сторож ловит? | Решение |
|---|---|---|---|
| `gh repo *` | удаление репозитория, смену видимости закрытого на открытый | нет | заменено на `gh repo view *` |
| `docker system *` | `docker system prune -a` — удаление всех остановленных контейнеров и образов | нет | заменено на `docker system df` |
| `docker exec *` | любую команду внутри контейнера, в том числе в базе данных | нет | убрано — при надобности Claude Code спросит |
| `git push *` | принудительную отправку | да, сторож разрушительных команд | оставлено |

Правки — с согласия пользователя, обратимы (копия прежних настроек сохранена локально). Не проверено: как именно Claude Code сопоставляет правило с командой и действительно ли откладывает в auto mode правило `python -c ' *` из общих настроек.

## Что не взято / лиды

- Второй пост той же сводки (`2026-10-12-codex-лагает-на-больших-сессиях-перейти-на-cli`) — опыт участника без первоисточника («сессии весят сто гигабайт, в CLI не тормозит»). По правилу вики для сводок обсуждений не берётся до проверки самим пользователем; Codex не используется — проверять незачем.
- Страница о субагентах Codex (модели, свои агенты в TOML) — подробности конкретного продукта; переносимое (субагенты для шумной работы, чтобы не засорять основной контекст) в вики уже есть.
- `docker compose *` в тех же настройках тоже широкое (`docker compose down -v` удаляет тома с данными) — в эту правку не входило, вынесено пользователю.
