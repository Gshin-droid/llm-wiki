## Ключевые тезисы

**Собственная практика Anthropic:** за месяц до публикации отдельные разработчики внутри компании мигрировали 10 кодовых пакетов (десятки-сотни тысяч строк каждый) через Claude Fable 5 / Claude Opus 4.8 + Dynamic Workflows.

**Кейс Bun (Zig → Rust, Jarred Sumner):** ~750k–1M+ строк Rust, 99.8% старого тест-сьюта проходит без изменений поведения, 11 дней от первого коммита до мержа, пик 64 параллельных агента / ~50 workflow-прогонов, один инженер-оркестратор, ~$165k API-стоимости.

Архитектура — воспроизводимый паттерн для любой большой миграции:
1. Отдельный workflow вычисляет Rust lifetime для каждого поля каждой структуры во всей кодовой базе (до порта — только план типов)
2. Следующий workflow пишет каждый файл как behavior-identical порт — сотни агентов параллельно, **2+ ревьюера на файл** (adversarial review как обязательный этап, а не опция)
3. Fix-loop гоняет сборку+тесты до чистого прохода
4. Overnight-воркфлоу оптимизирует (убирает лишние копии данных), каждый фикс — отдельный PR на финальный человеческий ревью

Gate перед мержем — тест-сьют на 1.38M+ ассертов на всех 6 платформах в CI.

**Klarna** — Dynamic Workflows для security-аудита продакшена: отсутствующая аутентификация, хрупкая валидация, скопированные между микросервисами небезопасные паттерны.

**CyberAgent** — hardening-проходы по продакшен-сервисам, adversarial-агенты проверяют друг друга перед финальным результатом.

## Противоречие / критическая находка (не пропускать при беглом чтении)
Zig-creator **Andrew Kelley** публично назвал результат Bun "unreviewed slop": ~13 000 unsafe-блоков попали в продакшн без человеческого ревью; тест-сьют, по его аргументу, не доказывает отсутствие багов в непроверенном коде такого объёма. Это не техническая претензия к Rust, а прямое возражение против модели "adversarial review силами тех же агентов = достаточное ревью" — то есть ровно вопрос к принципу [[ai-security-by-design]] "разделение обязанностей" (автор кода ≠ ревьюер): в кейсе Bun ревьюер — тоже Claude, не человек. Hacker News раскололся: часть указывает, что компилятор Rust поймал тысячи багов по ходу порта; часть — на непроверенные unsafe-блоки как факт.

Вики фиксирует это не как "вывод", а как открытый вопрос практики: adversarial review субагентами — полезный quality-gate (описан в [[dynamic-workflows]]), но не эквивалент человеческого ревью для кода, идущего в прод без дополнительного шага. Решение "где нужен человек в петле" — не автономное, зависит от риск-профиля проекта.
