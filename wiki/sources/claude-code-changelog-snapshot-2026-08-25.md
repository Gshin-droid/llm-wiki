## Саммари

Прогон новостного разведчика через три дня после предыдущего снапшота (2026-08-22, покрывал до 2.1.240). Вышли **2.1.241–2.1.245**. Официальные **Claude Platform release notes** за то же окно проверены отдельно и нового материала не содержат — последняя запись там (Python SDK v1.0, 20.08) уже разобрана прошлым снапшотом, платформенная сторона в это окно молчала.

Единственная содержательная версия — **2.1.243**: без headline-анонса, но с прямым практическим весом для того, как эта же вики ведёт автономные прогоны — новые настройки TTL промпт-кэша и разбивка `/usage` по `/loop`-циклам напрямую касаются механик, которыми пользуется сама вики.

## Находка 1: `promptCacheTtl`/`subagentPromptCacheTtl` — управляемый TTL кэша, отдельно для главного диалога и субагентов (2.1.243)

Новые настройки для пользователей с API-ключом и облачных провайдеров: можно держать **часовой** TTL промпт-кэша на основном диалоге, при этом субагенты остаются на дефолтных **пяти минутах**. До этой версии TTL кэша управлялся неявно (автокэш) без раздельного контроля по уровню — основной диалог и субагенты делили один и тот же режим.

Прямое пересечение с [[claude-api-cost-optimization]]: официальный чеклист называет prompt caching вторым по отдаче шагом (после baseline) и требует byte-stable префикс для эффекта; TTL — соседний параметр той же техники (не префикс, а срок жизни кэша), раньше не выносившийся в настройку Claude Code отдельно от API. Час против пяти минут — это явно про длинные автономные прогоны (в духе [[claude-code-routines-docs|Cloud Routines]] и `/loop`), где ход растягивается дольше пяти минут между обращениями к модели; субагенты остаются короткоживущими, потому что типичный субагент укладывается в это окно.

Дополнено в [[claude-api-cost-optimization]] отдельной пометкой.

## Находка 2: разбивка `/usage` по `/loop`-циклам (2.1.243)

`/usage` получил раздел по каждому активному `/loop`: число прогонов, суммарные токены, токены на прогон, время последнего прогона. Цель, названная в самом changelog — находить «сбежавшие» или болтливые `/loop`-задачи по счётчику, а не по интуиции. Не меняет механику `/loop` (`ScheduleWakeup`, fallback-вейкап через ~20 минут, `loop.md` — всё как в [[claude-desktop-automation-modes]]), только видимость: раньше стоимость конкретного самопланируемого цикла не была отделена от остального usage сессии.

Практически применимо к этой самой вики — три автономные рутины держат несколько параллельных `/loop`-подобных циклов (хотя формально это Cloud Routines, не `/loop` напрямую); прямого 1:1 применения `/usage`-разбивки к Routines в источнике не описано, зафиксировано честно как нюанс, не факт.

## Что не взято

- **`modelPicker`, `modelPricing`, keyless sign-in через Anthropic Console, `Skipped sources` в `/status`, GitHub-connection статус в `/status`, модель+effort в `/tasks`** — организационные/UI-настройки без практического эффекта на механику, которой пользуется эта вики (нет managed-организации, нет мультиаккаунтового `/model`-пикера). Зафиксированы для полноты на [[claude-code]].
- **2.1.245** — единственный фикс: краш при старте на Linux-дистрибутивах с glibc 2.44 (Arch, CachyOS, Fedora Rawhide). Не применимо к окружению, в котором работает эта вики (автономные рутины — управляемая облачная инфраструктура, не глубинная Linux-специфика). Зафиксировано в [[claude-code]] одной строкой.
- **Компрессия бинарника (340 МБ → 75 МБ на Linux x64) и снижение памяти сессии** — операционное улучшение без изменения практической механики, не разбирается отдельно.
- **Десятки рутинных багфиксов** (VSCode Focus view, MCP-переподключение, история Ctrl+R, зомби-сокеты cross-session messaging и т.д.) — в raw-снапшоте целиком, на страницу вынесены только пункты с прямым весом.
- **Claude Platform release notes 08-22–08-25** — проверены отдельным фетчем, новых записей после 20.08 (Python SDK v1.0, уже разобран прошлым снапшотом) нет. Не заводится отдельная raw-страница — фиксируется этой строкой, чтобы следующий прогон не перепроверял то же окно с нуля.
