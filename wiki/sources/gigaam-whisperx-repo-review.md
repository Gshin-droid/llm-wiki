## Саммари

Пост инбокса — чистый пересказ обсуждения практиков без цитат и без первоисточника: «по словам участника» GigaAM лучше и быстрее Whisper на русском; WhisperX (Whisper + pyannote) разделяет по голосам; умеет ли GigaAM разделять собеседников — из текста неясно. По правилу CLAUDE.md для наводок `via: "сводка обсуждений"` такой пункт проверяется по первоисточнику, прежде чем попасть в вики как факт (`wiki/gaps-backlog.md`, закрываемый пункт).

Оба репозитория склонированы напрямую (`git clone`, без прокси — тот же приём, что уже сработал у [[impeccable]] и `openJev-verdict-2`) и прочитаны целиком: README (англ. и рус. у GigaAM), `evaluation.md` GigaAM, `pyproject.toml` обоих, `LICENSE` обоих. Код не выполнялся.

## Что взято в вики

- **GigaAM против Whisper на русском — цифра есть, и она официальная.** `evaluation.md` GigaAM приводит прямую таблицу WER на 10 валидационных наборах с колонкой `Whisper*` (large, с постобработкой). Средний WER: GigaAM-v3 CTC **9.1%**, v3 RNNT **8.3%**, против Whisper **21.0%** — на каждом отдельном наборе без исключения GigaAM ниже. Отдельно SBS-сравнение `e2e_ctc`/`e2e_rnnt` против Whisper через LLM-as-a-Judge — победа **70:30**. Наводка подтверждена первоисточником, не пересказом.
- **«Быстрее Whisper» — этой части наводки официальное подтверждение не нашлось.** README и `evaluation.md` дают только таблицы времени инференса варианта внимания (custom/SDPA/flash) внутри самого GigaAM и заметку про ONNX fp16 («faster and uses less VRAM»), но ни одного прямого замера скорости против Whisper. Молчание источника — не подтверждение и не опровержение; факт о скорости остаётся на уровне участника обсуждения, в вики как сравнение с Whisper не идёт.
- **Умеет ли GigaAM разделять собеседников — нет.** Прямой `grep -i "speaker\|diariz"` по README (рус./англ.) и по всему дереву репозитория (код, доки) — ноль совпадений. Единственное, что GigaAM подключает из `pyannote.audio` — модель `pyannote/segmentation-3.0` для **VAD** (voice activity detection, обнаружение речи/паузы) в режиме `transcribe_longform`, это не диаризация: она не присваивает сегментам метки говорящих, только режет аудио по паузам перед прогоном ASR. Наводка права: из README самого GigaAM разделение по голосам неясно — и прямая проверка кода подтверждает, что его там нет вовсе, не «неочевидно описано».
- **WhisperX действительно делит по голосам, и это не самодельная надстройка.** README прямо объявляет диаризацию заявленной функцией («speaker diarization») через класс `DiarizationPipeline`, подключающий модель `pyannote/speaker-diarization-community-1` — отдельную от VAD-модели GigaAM, лицензия модели CC-BY-4.0 (pyannoteAI), для использования нужен HF-токен и принятие лицензии на `huggingface.co`. ASR-движок WhisperX — сам Whisper (`large-v2`/`large-v3`) через `faster-whisper`, без собственной русской специфики: WhisperX не заменяет и не превосходит Whisper по WER, он добавляет batched-инференс, точные word-level таймстемпы через forced alignment (wav2vec2) и диаризацию поверх того же Whisper.
- **Официальная оговорка качества диаризации, которой в наводке не было.** Раздел «Limitations» README WhisperX прямо: «Diarization is far from perfect», и в TODO отдельным незакрытым пунктом — «Improve diarization (word level). Harder than first thought.» Разделение на уровне слова (кто сказал именно это слово, а не весь сегмент) — открытая, нерешённая задача по признанию самого автора, не мелкая деталь.
- **Лицензии.** GigaAM — MIT (файл `LICENSE`, автор GigaChat Team/Sber). WhisperX — BSD-2-Clause (файл `LICENSE`, Max Bain), но конкретно модель диаризации (`pyannote/speaker-diarization-community-1`) — отдельно CC-BY-4.0, требует атрибуции при использовании результата, не только установки пакета.
- **Требования.** GigaAM: Python ≥3.10, `ffmpeg`, `pip install -e .[torch]`; долгие записи (`transcribe_longform`) — отдельно HF-токен и принятие условий `pyannote/segmentation-3.0`. WhisperX: CUDA 12.8 для GPU-режима (CPU работает без неё), `pip install whisperx`; версия на момент проверки — `3.8.7rc1` (`pyproject.toml`), последний коммит 22.10.2026. GigaAM — версия пакета `0.2.0`, последний коммит 17.08.2026.

## Берём инструмент или логику

**Инструмент — GigaAM уже стоит у пользователя** (проект [[dictum-golosovaya-diktovka]], через `onnx-asr`, не через этот репозиторий напрямую) — наводка её не открывает заново, а подтверждает официальным числом выбор, который уже был сделан практикой. **WhisperX не ставим** этим прогоном: диаризация нужна для другой задачи (расшифровка Zoom-звонков с несколькими собеседниками), которой у пользователя сейчас нет открытой страницы-проекта, а сам автор честно пишет, что диаризация «far from perfect» — решение, брать ли её при реальной задаче, не автономное.

**Логика — две вещи.** (1) Если понадобится расшифровка с разделением по голосам на русском, комбинация из наводки архитектурно верна, но не в виде «поставить WhisperX»: WhisperX несёт собственный ASR (Whisper), который на русском хуже GigaAM по официальной таблице выше — выигрыш в диаризации достигается связкой **GigaAM для расшифровки + отдельно модель `pyannote/speaker-diarization-community-1` для разметки говорящих**, а не заменой движка на WhisperX целиком. (2) VAD (обнаружение речи) и диаризация (разметка говорящих) — разные задачи с разными моделями `pyannote`, их легко спутать по одной строке наводки («Whisper плюс pyannote») — на это стоит смотреть внимательно при следующей наводке с похожей формулировкой.

## Что не взято / лиды

- Скорость GigaAM против Whisper — официально не подтверждена и не опровергнута (см. выше), отдельного пункта бэклога не заводится: вопрос слишком мелкий для отдельной допроверки, пользователь уже выбрал GigaAM по собственному замеру качества в [[dictum-golosovaya-diktovka]].
- WhisperX на практике (реальный прогон на русской записи с несколькими голосами) не проверялся — это проверка инструмента в работе, не чтение репозитория; если понадобится для задачи расшифровки Zoom, делать отдельно.

## Оценка источника

Оба источника — официальные репозитории авторов, верх иерархии доверия из `source-evaluation.md`. README, `evaluation.md`, `pyproject.toml`, `LICENSE` прочитаны целиком напрямую через `git clone`; факт «GigaAM не умеет диаризацию» подтверждён не только отсутствием упоминания в README, но и явным `grep` по всему дереву кода — отрицательный результат, а не пропуск поиска.

## Проверка безопасности источника

Прочитаны README (оба языка у GigaAM), `evaluation.md`, `pyproject.toml`, заголовки `LICENSE` — целиком. Единственный нестандартный элемент — верхняя строка README WhisperX, рекламирующая сторонний коммерческий сервис (Recall.ai) как спонсорский блок: это маркетинговая вставка автора, не инструкция агенту, и не адресована модели. Кода не исполнялось. Инструкций, адресованных агенту («игнорируй», «сделай при следующей возможности» и т.п.), не найдено в обоих репозиториях.
