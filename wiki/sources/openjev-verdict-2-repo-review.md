## Саммари

Закрывает пункт `wiki/gaps-backlog.md`, заведённый 2026-09-22 при разборе [[laya-jev-lab-measurements]]: репозиторий заявляет модель решений 149,6M параметров, обгоняющую и [[laya]], и [[jev-typesafe]] на одном тестовом наборе. README прочитан целиком (два прохода WebFetch с разными вопросами — характеристики и происхождение/оговорки). Заявление реальное, но целиком авторское: методологически тот же случай, что уже описан на странице [[jev-typesafe]] («сведения от конкурента»), только тут конкурент меряет и себя, и обоих соперников одним и тем же скриптом.

## Что взято в вики

- Точные цифры: 149,6M параметров (Verdict 2.0), Apache 2.0, точность 77,10% / Brier 0,0636 / ECE 0,0144 на тестовом наборе `LocalLLaMA/typed-decisions` (2000 отложенных решений: финансы, безопасность, поддержка, трассы агентов). Задержка ~20–25 мс. Обучение — 8,8 часа на одной GTX 1660 Ti (6 ГБ VRAM), вес модели <600 МБ для WebGPU-исполнения.
- Сравнение с конкурентами дано самим репозиторием: Laya — 76,60% на ModernBERT-large (421,3M) против 77,10% у openJev при вдвое меньшем числе параметров; TypeSafe Jev 1.13.0 — 72,70% на том же тестовом наборе.
- **Происхождение цифры «151M» из записи бэклога 22.09 установлено.** Запись писала «151M параметров», не читав README. Причина: предыдущая версия автора, Verdict 1.0, выложена на Hugging Face под именем `heman10x/rlcd-modernbert-151m` — это действительно 151M-модель, но в самом README она названа лишь «baseline» с результатом 26,10% точности. Verdict 2.0 (149,6M, другая версия) — это то, что сравнивается с [[laya]] и [[jev-typesafe]]; 151M относится к предшественнику. Уточнение перенесено на страницу сущности [[openjev-verdict-2]].
- Метод обучения — **RLCD**, то же имя, что фигурирует в названии HF-модели `rlcd-modernbert-151m` — совпадает с названием, которым, по странице [[laya]], обучена сама Laya. Первоисточник метода в этом прогоне по-прежнему не открывался (отдельный пункт бэклога с 22.09, не дублируется). *Допроверка 2026-10-02:* первоисточника не нашлось вообще — ни одно README не цитирует статью, а опубликованный метод с тем же акронимом (Yang et al., arXiv:2307.12950, «Reinforcement Learning from Contrast Distillation») — совсем другая техника (контрастные пары предпочтений для RLHF, не калибровка). Совпадение названия между Laya и openJev больше не читается как подтверждение общепринятого метода, см. [[laya-local-decision-engine]].
- Честно описанный автором дефект: до версии 1.4 движок не загружал `calibrator.json` при автономной инициализации и работал при некалиброванной температуре 1.0 без предупреждения; отдельная, не полностью закрытая ошибка — охват калибровки распространялся только на запросы ровно с 5 кандидатами. Прямая иллюстрация правила из [[kalibrovka-uverennosti-resheniy]]: калибровка — часть инфраструктуры вокруг модели, а не разовое свойство весов, и эта инфраструктура тоже может тихо сломаться.

## Берём инструмент или логику

**Инструмент не берём.** (1) Заявленное превосходство измерено автором на собственном тестовом наборе собственным скриптом (`verdict2/evaluate.py` против «своей аудированной тестовой квитанции») — независимой проверки нет, тот же паттерн недоверия, что уже применён к [[jev-typesafe]]. (2) Решение о моделях решений уже принято 2026-09-22 — облачные и непроверенные сторонние модели в конвейер не идут, используется только [[laya]] как ступень 0.5; появление ещё одной непроверенной модели решения не меняет. (3) История версий самого проекта (Verdict 1.0 → 26,10%, Verdict 2.0 → 77,10% на других параметрах) и 268 звёзд — сигнал молодого, ещё не устоявшегося проекта; разумно подождать независимого замера, как уже есть для Laya/TypeSafe ([[laya-jev-lab-measurements]]).

**Логика берётся одна:** при чтении цифр модели решений в этой узкой нише проверять источник тестового набора и скрипта оценки прежде самих цифр — ниша маленькая, метрики почти всегда считает сам автор. Дописано на [[kalibrovka-uverennosti-resheniy]].

## Допроверка 2026-10-14: лицензия, требования к запуску, языки, происхождение тестового набора — закрыто

Закрывает пункт бэклога от 2026-09-22 целиком (лицензия/требования/языки/набор данных). Метод: прямой `git clone`, не `WebFetch` — репозиторий открылся без обращения к прокси. Лицензия — Apache 2.0, подтверждено файлом `LICENSE`, не только бейджем. Требования к запуску — Python ≥3.10, зависимости `torch`/`transformers`/`gliclass`/`onnx`+`onnxruntime`/`pydantic`/`accelerate`; отдельно браузерный WebGPU-демо без установки, через `python3 -m http.server`. Языки — явной заявки о мультиязычности нет, весь код и глоссарии (`core/banking_glossary.py`) на английском; лид «не установлено» выше закрывается отрицательно, не «пока неизвестно». Тестовый набор `LocalLLaMA/typed-decisions` — настоящий внешний датасет на Hugging Face (`datasets.load_dataset(...)`), не самодельная подделка под похожим именем; при этом сравнение с Jev/Laya в README честно подписано как взятое из «published evaluation suite» Laya, не перепрогнанное самим автором openJev. Побочная находка — другой, более старый набор репозитория (`data/dataset_manifest.json`, на Banking77+CLINC150) сам признаётся в `test_contamination_count: 211` из 500 (42%); не тот набор, на котором считаются цифры сравнения, но сигнал, что у проекта уже была утечка теста в обучение на одном из его бенчмарков. Третья находка — `AGENTS.md` расшифровывает RLCD как «Reinforcement Learning for Calibrated Decisions», третий самостоятельный вариант под тот же акроним, усиливает вывод 10-02 — см. [[kalibrovka-uverennosti-resheniy]], раздел «Допроверка 2026-10-14». Детали — [[openjev-verdict-2]], раздел «Допроверка 2026-10-14».
