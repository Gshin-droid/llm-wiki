## Саммари

Пост: Spotify сократил расход токенов Claude Code на ~90%, отдавая чтение больших файлов и типовой код дешёвой модели; правила в CLAUDE.md модель соблюдала не всегда, поэтому поставили хук. По README это верно, но «90%» — экономия **на чтении больших файлов в одном проекте**, а не на всей работе. Два независимых замера дали другие цифры, свой замер на журналах сессий пользователя — третью. Разобран вместе с пользователем; решение — не строить, вернуться, когда изменятся условия (ниже).

## Как устроено (README shunt)

Три слоя, от жёсткого к мягкому:

1. **Хуки — запрет.** `check-file-size`: чтение файла целиком длиннее 350 строк (`SHUNT_MIN_LINES`) блокируется, Claude получает подсказку отдать его дешёвой модели; чтение куска (`offset`/`limit`) пропускается. `check-bash-read` ловит обход через `cat`, `head`, `tail`, `less`, `more`.
2. **Скрипты с именованными параметрами** — «Claude никогда не собирает конвейер команд из прозы»: `bulk-read --question … --paths …` возвращает выжимку; `code-write --spec … --reference … --target …` пишет типовой код сразу на диск, образец обязателен.
3. **Скиллы** — когда звать скрипты.

Не отдаётся: отладка, правки, файлы короче порога, решения по архитектуре. Дешёвая модель вызывается через внутреннюю платформу Spotify Portal — без неё плагин не работает. У хуков свои проверки: 51 тест (маршрутизация хуков и обвязка), отдельно — замер экономии.

## Три замера — три цифры

| Кто | На чём | Итог |
|---|---|---|
| Spotify (README) | 4 сценария на Java-проекте в 162 тыс. строк, рабочая модель Gemini 2.5 Flash | 82–94% экономии на чтении больших файлов, в среднем 90% |
| Thaki Cloud | 1 099 своих сессий за 14 дней, 1 446 вызовов чтения | при пороге 350 отдать можно 14% прочитанного (при 100 — 85%); медиана файла 158 строк; чтение файлов — ~0,02% всего входящего трафика, счёт определяет контекст, повторно отправляемый с каждым запросом |
| XDA | Opus 5.5 + Qwen3-Coder-30B локально или Haiku, своё приложение | чтение: почти без разницы — Opus сам читает кусками через `grep`, хук не срабатывал; написание тестов: на 23–34% дороже и в 7–10 раз дольше — задание и проверка чужого черновика стоили больше самой работы |

## Свой замер (2026-10-19)

Журналы Claude Code рабочей машины за 16.07–19.10.2026: 149 сессий с субагентами, 23 729 ответов модели, 3 036 вызовов чтения файлов (целиком — 2 213, куском — 823). Скрипт по образцу Thaki: размер результата чтения, токены оценены как знаки / 3,5.

| Порог | Полных чтений длиннее | Доля во всём прочитанном |
|---|---|---|
| 100 строк | 936 | 64,7% |
| 200 | 344 | 38,9% |
| 350 | 182 | 26,5% |
| 1000 | 3 | 0,8% |

- Медиана полного чтения — 83 строки, 90% чтений — до 288 строк.
- Чтение файлов — ≈5,8 млн токенов, это **4,6% нового входящего** (без повторного чтения кеша) и 0,11% всего входящего.
- Из 182 больших полных чтений **157 сделали субагенты**, которые и так работают на моделях дешевле основной; основная сессия — 25 раз за три месяца.

**Вывод.** При пороге 350 отдать можно четверть прочитанного, то есть около 1,2% нового входящего, и почти всё это уже идёт через дешёвые субагенты. Строить свой shunt незачем. Не измерено: файл, прочитанный целиком, остаётся в контексте и перечитывается из кеша каждым следующим ходом — эта часть экономии делегирования в замер не вошла; чтение кеша в 10–20 раз дешевле нового входа, поэтому порядок вывода она вряд ли меняет, но это допущение.

## Берём инструмент или логику

- **Инструмент — нет:** без Spotify Portal не работает; свой замер показал, что и переносить незачем.
- **Логика — уже есть в своде, получила независимое подтверждение:**
  - хук вместо строки в CLAUDE.md — Spotify пришёл к этому тем же путём ([[verification-three-levels]], правило спуска);
  - скрипт с именованными параметрами вместо конвейера команд из прозы;
  - «проверка стоит как исполнение — не делегировать» — замер XDA показывает это в цифрах на написании кода ([[delegirovanie-deshevym-modelyam]]).
- **Новое:** порог делегирования брать из своего распределения, а не по умолчанию — у Thaki и у нас при одном пороге доли различаются вдвое (14% и 26,5%).

## Когда вернуться (решение пользователя 19.10)

Принцип отложен, не отвергнут. Пересмотреть, если: локальные модели станут достаточно сильными, чтобы им можно было доверить вычитку и выжимку без перепроверки основной сессией; изменится цена или лимиты подписки; основная сессия начнёт регулярно читать большие файлы целиком. Замер повторяется тем же скриптом (лежит локально, вне репозитория).
