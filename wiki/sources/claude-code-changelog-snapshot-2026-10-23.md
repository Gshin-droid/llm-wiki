## Находка 1: девятый узел серии bypass-фиксов (v2.1.309)

Три независимых обхода песочницы, исправленных одной версией:

1. «Bash commands in sandbox (macOS and Linux) executed shell startup files outside the sandbox before every command» — shell-команда в песочнице перед каждым вызовом исполняла стартовые файлы шелла (`.bashrc`/`.zshrc` и аналоги) **вне** песочницы.
2. «Sandbox on macOS: `denyWrite` glob did not apply to the real path if the folder was opened through a symlink» — правило запрета записи на macOS сверялось с путём симлинка, а не с реальным путём, на который он ведёт.
3. «Sandbox commands and auto-accepted edits could change the MCP config from `--mcp-config`» — команды внутри песочницы и автопринятые правки (auto mode) могли менять MCP-конфигурацию, заданную флагом запуска.

Плюс в той же версии — более мелкие precision-фиксы того же узла (без собственных CVE/нумерованных находок): Bash permission check доверял переменной, заданной командой с редиректом, который мог не открыться; не запрашивалось подтверждение для некоторых составных команд с `cd` перед git; правило `Edit(path)` с deny не блокировало редирект Bash на этот путь через subshell; worktree-изоляция пропускала команды с локалями/арифметикой zsh/awk, которые должна была отклонять; на Windows хуки PowerShell с кодом выхода 2 не блокировали вызов, а при отсутствии Git for Windows `PreToolUse`/`PermissionRequest` пропускали вызовы вовсе.

**Класс.** Все три главных пункта — тот же класс, что у восьми предыдущих узлов серии (см. [[ai-security-by-design]]): не прямой обход правила, а путь, который анализатор или песочница не распознаёт как рычаг. Пункты 1 и 2 — обход через то, что исполняется или резолвится раньше или вовне проверки (стартовые файлы шелла, реальный путь за симлинком); пункт 3 — тот же принцип, что у MCP-редиректов в восьмом узле (10-15): конфигурация, которая обязана быть неизменной внутри прогона, менялась самим прогоном.

## Находка 2: первое явное, документированное ослабление песочницы (v2.1.305, v2.1.310)

v2.1.305 добавляет настройку `sandbox.allowNestedUserNamespaces` — по пересказу WebFetch (без прямой цитаты, см. «Оценка источника»), сам changelog называет её прямо: она позволяет обходить защиту файлов песочницы. v2.1.310 даёт этой настройке контекст: на Linux команда `/sandbox` теперь прямо называет ограничение AppArmor в Ubuntu на вложенные user namespaces (именно из-за которого эта настройка может понадобиться) и способ его снять.

Разница с находкой 1 принципиальная: там — дефект, который чинят. Здесь — осознанный клапан, который Anthropic добавляет, потому что окружение пользователя (Ubuntu с активным AppArmor) само запрещает то, что песочнице нужно для нормальной работы. Решение сделано явным и документированным, не тихим дефолтом — но конечный эффект для того, кто включит настройку, формально тот же, что серия фиксов девять раз закрывала у других: дыра в изоляции файловой системы песочницы. Стоит отслеживать отдельно от самой серии — это не баг, а trade-off, предложенный вендором, и решение о включении остаётся за пользователем/организацией.

## Находка 3: событие `safety_event` — observability подхватывает случаи остановки инструмента (v2.1.307)

По пересказу WebFetch (без точной цитаты): добавлено событие OpenTelemetry `claude_code.safety_event` на каждый вызов инструмента, который был остановлен правилами разрешений, auto mode, проверкой безопасности, хуком или песочницей. Единое событие трассировки для любой причины отказа — прямое попадание в [[agent-observability]]: трассировка до этого покрывала нормальный ход выполнения, теперь покрывает и момент отказа. Это ровно то, чего не хватало, чтобы различить «агент не стал делать X» от «агенту не дали сделать X», не разбирая логи руками.

## Малое

- v2.1.304 (самый крупный релиз окна по числу пунктов): `rm -r` для смонтированных дисков и папок верхнего уровня теперь получает защитный запрос — сужение дефолта, тот же дух, что у находок выше, но изменение, а не исправление бага; на Linux sandbox падал на `denyRead`-glob в скобках; `PreToolUse`-хук с deny мог быть заменён ошибкой таймаута.
- v2.1.302: `claude -p` и Agent SDK без заданного режима разрешений стартуют в `default` на сторонних провайдерах.
- v2.1.306: два точечных фикса — `claude -p` в облачных сессиях, ошибочные сообщения при большом количестве подключённых MCP-инструментов.
- v2.1.303 и v2.1.308 — только общая строка «Bug fixes and reliability improvements», без детализации в самом changelog.
- Остальные пункты окна (модели/провайдеры Vertex/Bedrock/Foundry, Monitor tool, `/claude-api`, `/usage`, VS Code, Claude Tag, Code Review) — без веса для практики вики; полный текст в CHANGELOG.md репозитория.
