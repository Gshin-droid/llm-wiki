## Саммари

Наводка обещала «бесплатный способ сделать любую нейронку умнее»: дешёвый DeepSeek обходит Fable 5 в айти в 11 раз дешевле, потому что модель «учитывает, насколько уверена в каждой из оценок». Рутина 02.11 первоисточник не нашла и отказала; при пересмотре 05.11 он найден по описанию метода.

**Метод.** Обычный судья-модель выдаёт одну оценку («7 из 10»). LLM-as-a-Verifier берёт вероятности всех токенов-оценок, которые модель взвешивала в этой позиции, и считает **ожидаемую оценку** — среднее по распределению. Получается непрерывная шкала вместо дискретной, а в ней — уверенность судьи. Дальше — выбор лучшего из N вариантов: модель генерирует несколько решений, тот же проверяющий ранжирует их экономным алгоритмом попарных предпочтений, берётся лучшее. Три рычага масштабирования проверки: мельче шкала, повторная оценка, разбивка на отдельные критерии. Дообучение не требуется.

**Результаты статьи** (по аннотации): Terminal-Bench V2 — 86,5%, SWE-Bench Verified — 78,2%, RoboRewardBench — 87,4%, MedAgentBench — 73,3%; то есть код, роботы и медицина — отсюда «работает не только с кодом» в наводке.

## Где наводка приукрасила

- **«DeepSeek обошёл Fable 5, в 11 раз дешевле» — не из статьи**, а из [твита первого автора](https://x.com/jackyk02/status/2089421448784023553): DeepSeek V4 Flash с самопроверкой против Fable 5 на Terminal-Bench 2.1; пример — 5 вариантов, ранжирование той же моделью, точность с 79% до 88%. В аннотации статьи этого сравнения нет.
- **«Любую нейронку умнее» — неверно по сути.** Модель не меняется; она тратит больше прогонов на задачу и выбирает лучший ответ. Цена — N генераций плюс проверка.
- **Скрытое условие** наводка не называет: метод читает вероятности токенов (logprobs). Облачный API, который их не отдаёт, метод не поддержит.

## Что взято в вики

1. **Второй уровень проверки ([[verification-three-levels]]) можно сделать дешевле и тоньше.** Вместо двоичного «прошло/не прошло» судья-модель даёт оценку с уверенностью, и ею можно ранжировать варианты. Это не замена инварианту в коде — тот по-прежнему первый; это способ поднять качество там, где без смысла задачи не обойтись.
2. **Прямой кандидат для шлюза к дешёвым моделям ([[delegirovanie-deshevym-modelyam]]).** Каскад шлюза сейчас принимает ответ машинной проверкой «да/нет» и при провале поднимается на ступень выше. Альтернатива из статьи — остаться на дешёвой ступени, сгенерировать несколько вариантов и выбрать лучший. Для локальной модели повторные прогоны почти бесплатны — отсюда интерес для сервисов на локальных ИИ.
3. **Оговорка о проверяющем-авторе.** В примере из твита ранжирует **та же** модель, что генерировала. Это противоречит нашему правилу «приёмка — не автором» только на первый взгляд: метод выбирает лучший из своих вариантов, а не объявляет работу принятой. Внешняя приёмка после выбора остаётся.

## Берём инструмент или логику

**Логика — берём:** ожидаемая оценка по вероятностям токенов вместо одной цифры; выбор лучшего из N той же дешёвой моделью; три рычага масштабирования проверки.

**Инструмент — пока нет.** Код открыт, но не прочитан; лицензия кода не видна на странице статьи. Чужой код перед запуском читает проверяющий. Сама проба — дело в хабе: отдаёт ли Ollama вероятности токенов и что даёт выбор лучшего из N на задачах шлюза.
