## Саммари

Рутина новостей (ярус 2, [[claude-code-changelog-snapshot-2026-11-12]]) зафиксировала факт существования Code Mode в v2.1.323, но явно оставила страницу `code.claude.com/docs/en/code-mode` непрочитанной — «ниже порога этого разбора… порог полного разбора для неё отдельно, по мере появления задачи или следующей допроверки». Эта страница закрывает тот пробел: как включить, когда применять, какие ограничения, как проверяются права, как диагностировать отказ запуска.

**Что за режим.** Без Code Mode Claude просит по одному вызову инструмента (Bash/Read/Edit) и читает каждый результат, прежде чем решить следующий шаг. С Code Mode Claude пишет кусок JavaScript, который сам делает нужные вызовы инструментов, а Claude Code исполняет этот код в текущей сессии; в диалоге видны результаты вызовов (например, диф правки), а не сам код — код открывается по `Ctrl+O` в transcript viewer, свёрнутой строкой «Code».

Пример из документации — поднять лимит ретраев: Claude одним куском кода находит файл (`rg`), правит его (`edit`), прогоняет тесты (`npm test`) и возвращает путь + вывод тестов последней строкой — без промежуточных раундов «запрос инструмента → ответ модели».

**Когда применять** (формулировка источника): задачи с большим числом связанных вызовов — повторяющаяся правка по многим файлам; поиск, чей результат нужно отфильтровать до того, как Claude его читает; несколько независимых команд, которые можно пустить параллельно.

## Что взято в вики

1. **Как включить** — `CLAUDE_CODE_EXPERIMENTAL_CODE_MODE=1` (переменная среды в шелле — на один запуск; или блок `env` в `~/.claude/settings.json` — для всех новых сессий). Явно игнорируется в настройках **проекта** — чужой репозиторий не может включить Code Mode за пользователя. Требует подтверждения при первом запуске («Yes, turn on Code Mode»); выключается удалением переменной или значением `0`; `0` в любом из двух мест перекрывает `1` в другом. Организация блокирует режим целиком через managed settings (`env.CLAUDE_CODE_EXPERIMENTAL_CODE_MODE: "0"`) — но не может включить его централизованно.
2. **Требования** — v2.1.323+; только Claude Opus 5.5 / Sonnet 5.5 / Haiku 5.5 / Fable 5.2; только интерактивная терминальная сессия `claude`; **не работает** с `-p`, Agent SDK, панелью VS Code, Desktop-приложением и **cloud-сессиями**; не работает через гейтвей/Bedrock/Claude Platform on AWS/Google Cloud Agent Platform/Microsoft Foundry; недоступен при HIPAA-конфигурации или zero data retention; нужен native build; на Windows — установленный Git for Windows.
3. **Ограничения, которые стоит знать до включения** — резюмируется (`claude --resume`/`--continue` продолжает Code Mode-сессию только с тем же включённым режимом; классификатор auto mode проверяет **код целиком**, а не каждый вызов инструмента по отдельности — раздел ниже; код без фонового режима обрывается после 10 минут, с фоновым — до 2 часов, но нужен `auto`/`bypassPermissions`; недоступны Remote Control, Claude in Chrome, computer use; сессию нельзя перенести в Desktop, сделать background-сессией, `/fork` не может запустить фоновую копию).
4. **Проверка прав — новая единица контроля.** Каждый вызов инструмента из кода Claude всё равно проходит через `deny`/`ask`-правила и `PreToolUse`-хуки — без изменений. Но в auto mode классификатор теперь смотрит **весь кусок кода целиком до его запуска**, а не каждый отдельный вызов внутри — и явно **не видит значений, вычисленных во время выполнения** (например, путь файла, добытый из результата поиска внутри того же кода). Чтобы проверять именно код, а не вызовы, документация предлагает писать `PreToolUse`-хук, который матчит инструмент `REPL` (им выполняется написанный Claude код) и читает JavaScript из `tool_input.code`.
5. **Фоновый запуск длинного кода** — Claude либо ждёт (до 10 минут, включая время у permission prompt), либо, в `auto`/`bypassPermissions`, продолжает разговор, пока код выполняется в фоне (до 2 часов). Если код всё равно ждёт — проверить текущий режим (`Shift+Tab` до нужного) или перезапустить `claude --continue --permission-mode auto` без флага `--tools`.
6. **Таблица диагностики «Code Mode doesn't start»** — причины и исправления по точной фразе рядом со строкой статуса: устаревшая версия → `claude update`; маршрут через гейтвей/кастомный `ANTHROPIC_BASE_URL` → убрать; `apiKeyHelper`/кастомные auth-заголовки → убрать, войти через обычный вход или `ANTHROPIC_API_KEY`; не та модель → `--model opus` или другая из списка; `--remote-control`/фоновые задачи → запускать в foreground; выключен feature-flag fetching (`DISABLE_TELEMETRY`) → снять; включён OpenTelemetry-экспорт → снять `CLAUDE_CODE_ENABLE_TELEMETRY`/`ENABLE_BETA_TRACING_DETAILED`; активный мод, который сам проверяет вызовы → выключить; включены agent teams (`CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS`) → снять (режимы несовместимы); `--restricted`/`REPL` в `--disallowedTools`/`deny` → поправить флаги; `~/.claude.json` недоступен для записи → починить права; запрет организации → у администратора.
7. **Явное предупреждение источника про Bash-правила** — то же, что уже знает вики из `zabor-i-stena-prava-agenta`: правила `deny`/`ask` на Bash матчат текст команды, и обойти их можно и без Code Mode («with or without Code Mode»); Code Mode сам по себе не новая дыра этого класса, просто то же ограничение видно на новом месте.

## Берём инструмент или логику

**Инструмент (Code Mode как фича Claude Code).** Не включаем для автономных рутин этой вики — и не по выбору, а потому что это физически исключено источником: Code Mode не работает в cloud-сессиях, через которые идут все три рутины CLAUDE.md (новости/практики/хвосты), и несовместим с заголовком `--remote-control`/фоновыми задачами. Для **собственной интерактивной** работы пользователя в терминале — кандидат на пробу на задачах класса «правка по многим файлам» или «отфильтровать шумный вывод поиска до того, как Claude его читает», но это экспериментальная, по умолчанию выключенная функция с нетривиальной ценой (новая единица проверки прав, 10-минутный таймаут без фона, несовместимость с agent teams/модами/VS Code) — включать стоит осознанно, не «по умолчанию для всех сессий».

**Логика.** Два переносимых урока, оба — в [[zabor-i-stena-prava-agenta]] и [[dynamic-workflows]] дополнениями ниже: (1) когда агент пишет код, которым сам вызывает инструменты, забор на уровне отдельного вызова не исчезает, но единица, которую проверяет автоматический классификатор, укрупняется до всего фрагмента кода — и классификатор прямо признаёт слепую зону (значения, посчитанные во время выполнения); (2) если нужно детерминированно проверять именно код, а не результат его исполнения, — хук на специальный инструмент-исполнитель (`REPL`), читающий код из `tool_input.code`, тот же приём, что уже описан на `zabor-i-stena-prava-agenta` для скриптов-обёрток (раздел «Дополнение (2026-10-21)»), только для целого фрагмента кода, а не одной команды.

## Что не взято / лиды

- Внутренняя реализация песочницы, в которой исполняется написанный Claude JavaScript (что именно доступно коду помимо вызовов тулов, можно ли исполнить произвольный JS без обёртки `$`/`edit`) — страница это не раскрывает, за рамками документации для пользователя; не заводится лидом в бэклог, так как не всплывала как вопрос ни у одной страницы вики.
- 195-пунктный список Bug fixes релиза 2.1.323 и 21 пункт Improved — уже явно оставлены ниже порога записью рутины новостей (`claude-code-changelog-snapshot-2026-11-12`), повторно не открывались.

## Оценка источника

Официальная документация Anthropic по собственному продукту, страница, прочитанная целиком, а не по заголовкам. Для кого материал — для пользователя Claude Code, который сам работает в интерактивном терминале (ровно профиль применимости, описанный в разделе «Берём инструмент или логику»); не адресовано программным интеграциям (Agent SDK/cloud sessions прямо исключены как неподдерживаемые). Фактических ошибок при чтении не обнаружено — страница внутренне последовательна (таблица диагностики соответствует разделу требований).

## Проверка безопасности источника

Прочитано целиком через `WebFetch` официального домена `code.claude.com`. Инструкций, адресованных агенту («проверь», «сделай при следующей возможности» и т.п.), не обнаружено — текст описывает поведение продукта и инструкции для человека-пользователя CLI, а не задания для модели, читающей документацию. Единственный императив на странице («Select **Yes, turn on Code Mode**») — это описание шага UI для человека при первом запуске, не команда агенту-читателю.
