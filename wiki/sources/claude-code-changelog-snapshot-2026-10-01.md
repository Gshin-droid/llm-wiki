Главное событие окна — не в самом Claude Code, а в модели: Sonnet 5.5 (находка 1 сводки) стала дефолтной моделью Sonnet этим же релизом. ## Находка 1: Claude Sonnet 5.5 — дефолтная модель Sonnet (2.1.284)

*"Added Claude Sonnet 5.5 model as default Sonnet on Anthropic API"*. Модель вышла тем же днём официальным анонсом Anthropic (`anthropic.com/claude/sonnet`, первоисточник): цена не изменилась ($2/$10 за млн токенов, кэш-чтение $0.20/млн — та же, что у Sonnet 5), контекст 1M токенов, по замерам вендора на 30%+ быстрее и до 30% дешевле по токенам на типичных задачах, первая Sonnet-модель с cyber safeguards уровня топовых моделей (аналог механизма, уже описанного в [[claude-code]] для Opus 5.5 — «Смена модели при пометке сообщения») и классификаторами против экстракции рассуждений.

**Связь с уже описанным в этой вике.** Раздел «Модели и Effort» страницы [[claude-code]] фиксирует Opus 5.5 как модель по умолчанию для Opus (с v2.1.280) — Sonnet 5.5 занимает симметричную позицию в линейке Sonnet, не меняя саму структуру "Haiku → Sonnet → Opus → Fable". Открытый вопрос из допроверки 09-28 («какая модель подменяет Opus 5.5 при пометке сообщения») этим релизом не затронут — он про Opus-линейку, а здесь обновилась Sonnet.

## Находка 2: `allowedProviders` — ограничение API-провайдеров на уровне managed-настройки (2.1.285)

*"Added `allowedProviders` managed setting to limit API provider choices"*. Продолжает серию находок про managed-контроль организаций (см. «Обновление 2.1.283» на [[claude-code]]: `deniedModels`/`availableModelsMatch`) — но та пара ограничивала версии моделей, эта ограничивает сам провайдер API (прямой Anthropic API, Bedrock, Vertex, Foundry и т.п.) на уровне машины. Changelog не раскрывает, можно ли сочетать с `deniedModels` одновременно (ограничить и провайдера, и версию модели внутри него) — открытый вопрос, не критичный для практики этой вики (не организация, без managed-инфраструктуры).

## Находка 3: `CLAUDE_CODE_DISABLE_WEB_FETCH` — отключаемый WebFetch (2.1.285)

*"Added `CLAUDE_CODE_DISABLE_WEB_FETCH` environment variable"*. Полностью отключает инструмент WebFetch и автоматические веб-запросы во время работы других инструментов. Отличается от уже описанных в [[ai-security-by-design]] точечных сужений auto mode (allowlist доменов, Containment Escape rule) — та настройка не сужает WebFetch, а убирает его целиком, ближе по духу к `--restricted`/`CLAUDE_CODE_RESTRICTED=1` (2.1.248, см. «Обновление 2.1.246–2.1.250» на [[claude-code]]), но затрагивает только один конкретный инструмент, а не весь набор исполнения кода. Практическое значение: для задач, где сетевой доступ принципиально не нужен (чистый рефакторинг, работа с уже скачанными данными), можно явно убрать канал непредсказуемого внешнего контента — тот же принцип минимальных привилегий, что у `sandbox.filesystem.disabled`/`sandbox.network.strictAllowlist`.

## Малое

- **`claude --desktop`** (2.1.285) — открывает десктоп-приложение Claude на текущей директории либо на сессии, указанной через `--continue`/`--resume`; мостик между CLI и Desktop-приложением, ранее такой явной команды не было.
- **`claude plugin configure`** (2.1.285) — управление настройками уже установленного плагина, рядом с существующими `claude plugin eval` (2.1.269) и `claude plugin validate` (2.1.233), упомянутыми на [[claude-code]].
- **`/rate-limit-options`** (2.1.284) — команда для claude.ai-подписчиков, детали поведения changelog не раскрывает.
- **Permission-промпт показывает счётчик "2 из 5"** (2.1.286) при накоплении нескольких запросов разрешений подряд — эргономика, не меняет сами правила permissions.
- Остальные пункты трёх версий — рутинные UI/auth/MCP-фиксы без веса для практики, полный список в raw-снапшоте.

## Берём инструмент или логику
