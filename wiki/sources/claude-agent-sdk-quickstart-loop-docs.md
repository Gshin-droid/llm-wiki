## Саммари

Рутина практик искала материал, применимый к работе с Claude Agent SDK, появившийся с прошлого прогона (16.11 — Code Mode). Страница сущности [[claude-agent-sdk]] до сих пор знала SDK только на уровне обзора («что это», капабилити списком, два официальных cookbook-рецепта) — ни разу не читались сами страницы `quickstart` и `agent-loop`, которые официальная документация прямо называет следующим шагом после overview. Обе — не анонс и не пересказ, а дословный туториал с рабочим кодом (Quickstart) и инженерное объяснение механики цикла (turns, message types, permission modes, бюджет, контекстное окно, компакция), ровно то, что CLAUDE.md просит для рутины практик: «как этим пользоваться», не «что вышло».

Отдельная причина, почему это не рядовая находка: Agent SDK запускает **тот же execution loop, что исполняет Claude Code** — страница явно это утверждает («the same execution loop that powers Claude Code»). Три автономные рутины этой вики сами работают через этот движок (Cloud Routines/scheduled tasks), поэтому механика turns/budget/compaction описывает не абстрактный чужой SDK, а то, как фактически устроены собственные прогоны этой вики, включая риск, из-за которого в CLAUDE.md есть правило инкрементального коммита («прогон обрывается без предупреждения — 10.07.2026 весь ingest был сделан и потерян на лимите»).

## Что взято в вики

**1. Quickstart — рабочий код, не псевдокод.** Полный пример на Python и TypeScript: `query(prompt=..., options=ClaudeAgentOptions(allowed_tools=[...], permission_mode="acceptEdits"))`, `async for message in query(...)`. Три части объяснены по отдельности: `query` — асинхронный итератор, `prompt` — задача (Claude сам решает, какие инструменты нужны), `options` — конфигурация. Таблица наборов инструментов по уровню автономии:

| Набор | Что может агент |
|---|---|
| `Read`, `Glob`, `Grep` | только анализ |
| `Read`, `Edit`, `Glob` | анализ и правка |
| `Read`, `Edit`, `Bash`, `Glob`, `Grep` | полная автоматизация |

Важная тонкость, которой на странице [[claude-agent-sdk]] не было: `allowed_tools`/`allowedTools` **авто-одобряет** перечисленные инструменты, но не ограничивает агента только ими — остальные всё ещё доступны и идут через обычный permission flow. Ограничить набор целиком — отдельное поле `tools`.

**2. Turns и message types — то, что реально течёт по стриму.** Виток (turn) — один проход цикла: Claude отвечает, если есть вызов инструмента — SDK исполняет и возвращает результат автоматически, без возврата управления в код приложения; витки идут, пока Claude не ответит без вызовов инструментов. Пример на 4 витка («Fix the failing tests in auth.ts»: `Bash npm test` → `Read` двух файлов → `Edit` + повторный `Bash` → финальный текст) показывает, что `max_turns` считает **и финальный текстовый виток** — `max_turns=2` в этом примере остановил бы цикл до правки.

Пять типов сообщений в стриме: `SystemMessage` (subtype `init`/`compact_boundary`/`informational`/`worker_shutting_down`), `AssistantMessage` (один content-блок на сообщение — текст или вызов тула), `UserMessage` (результат тула или свой вход в стриминг-режиме), `StreamEvent` (только с `include_partial_messages`), `ResultMessage` (конец цикла: текст, токены, стоимость, `session_id`). `ResultMessage` может не быть последним в стриме — после него могут прийти служебные события (`prompt_suggestion`), поэтому дочитывать стрим до конца, а не выходить по первому результату.

**3. Таблица режимов разрешений — полная, не только названия.** `default` (нужен `canUseTool`-колбэк, без него — отказ), `acceptEdits` (авто-одобряет правки файлов и файловые команды типа `mkdir`/`mv` в рабочих директориях; остальной Bash — по обычным правилам), `plan` (даже разрешённые правки идут через `canUseTool`), `dontAsk` (никогда не спрашивает; всё, что требовало бы вопроса, — отказ, с оговоркой, что мод может переопределить часть отказов), `auto` (модель-классификатор разрешает/блокирует по одной команде/запросу отдельно — тот же классификатор, что уже разобран в [[ai-security-by-design]] на уровне Claude Code CLI, здесь он же как опция SDK), `bypassPermissions` (без вопросов вообще, включая не перечисленные в `allowedTools`; нельзя под root на Unix; только для изолированных сред). Страница прямо привязывает режим к сценарию — `acceptEdits` для доверенной правки на своей машине, `bypassPermissions` только для CI/контейнеров.

**4. Контроль цикла, которого на entity-странице не было вовсе:**
- **`max_turns`/`max_budget_usd`** — лимиты, после которых `ResultMessage` приходит с `error_max_turns`/`error_max_budget_usd`, без поля `result`. Бюджет **включает расход субагентов** — трата субагента на той же сессии считается в общий лимит; при достижении потолка новый субагент не запускается (`Budget limit reached»), а уже работающие фоновые субагенты останавливаются. Поведение требует Claude Code v2.1.217+.
- **Budget headroom — причина, по которой лимит не точный потолок.** Сверка со стоимостью идёт **после** ответа модели (цена известна только по токенам в уже пришедшем ответе), поэтому фактический расход может превысить `max_budget_usd` на стоимость этого последнего ответа плюс то, что успеют потратить уже запущенные субагенты, пока не остановятся. Практический вывод для любого бюджетного лимита на этой же вики или в проектах пользователя: закладывать запас, а не ставить потолок впритык к допустимому расходу.
- **Таблица уровней `effort`** (`low`/`medium`/`high`/`xhigh`/`max`) с рекомендацией по типу задачи (low — поиск файлов и листинг, max — многошаговые задачи с глубоким анализом); задаётся на уровне сессии или переопределяется на уровне субагента полем `effort` у `AgentDefinition`. Отдельная табличная форма того же рычага, который уже в вики на уровне CLI/API ([[claude-api-cost-optimization]]) — здесь это параметр кода, а не настройка интерфейса.
- **Параллельное исполнение тулов.** Вызовы, которые Claude запрашивает в одном витке, SDK может исполнить параллельно (read-only — `Read`/`Glob`/`Grep` и MCP-тулы с пометкой `readOnlyHint`) или последовательно (всё, что меняет состояние — `Edit`/`Write`/`Bash`, по умолчанию). Свой кастомный тул по умолчанию исполняется последовательно; чтобы разрешить параллельность — явно выставить `readOnlyHint` в аннотации.

**5. Контекстное окно — что именно его съедает и как его беречь.** Таблица источников расхода (системный промпт, `CLAUDE.md`, схемы тулов, история диалога, описания скиллов) с отдельной строкой: схемы встроенных тулов (Bash/Read/Edit) грузятся в каждый запрос целиком, а MCP-тулы по умолчанию откладываются (tool search) и подгружаются по требованию — несколько MCP-серверов с большим числом тулов без этого механизма съедают контекст до того, как агент сделал хоть один шаг.

**Автоматическая компакция — новая деталь, не покрытая [[kontekst-szhat-ili-nachat-zanovo]].** При приближении к лимиту окна SDK сам сжимает историю, сохраняя последние обмены и ключевые решения. Два управляемых рычага:
- **Раздел в `CLAUDE.md`, который читает компактор** — любой свободно озаглавленный раздел с инструкцией «при сжатии всегда сохраняй: цель задачи и критерии приёмки, пути прочитанных/изменённых файлов, результаты тестов и ошибки, принятые решения и почему» — компактор матчит по смыслу раздела, не по жёсткому имени заголовка.
- **`PreCompact`-хук** — выполняется до сжатия, например чтобы заархивировать полную расшифровку до того, как она превратится в саммари; получает `trigger` (`manual`/`auto`).

Плюс ручной путь — отправить `/compact` как обычный промпт в `query()`.

**6. Обработка результата — таблица subtype'ов и предупреждение про `None`.** `success`/`error_max_turns`/`error_max_budget_usd`/`error_during_execution`/`error_max_structured_output_retries` — только `success` несёт поле `result`. После краша сессии `total_cost_usd`/`usage` могут быть обнулены, а `stop_reason` — `null`; в Python эти поля типизированы как опциональные — обязательна проверка на `None` до чтения. Однократный `query()` **бросает исключение** после выдачи финального результата с ошибкой — в отличие от стриминговой сессии, которая остаётся живой и разрешает продолжать слать сообщения (кроме краша, после которого процесс также завершается).

## Берём инструмент или логику

**Инструмент.** Сам Agent SDK как библиотека не устанавливается для этой вики — три автономные рутины работают через Cloud Routines/Claude Code CLI, а не через прямой `import claude_agent_sdk`; страница подтверждает, что это тот же цикл, так что знание переносится без установки чего-либо нового.

**Логика — пять переносимых механизмов:**
1. **Бюджетный потолок пишется с запасом, а не впритык** — сверка идёт постфактум по уже пришедшему ответу, плюс работающие субагенты продолжают тратить до остановки. Прямо применимо, если пользователь когда-нибудь поставит `max_budget_usd` на свой собственный скрипт на SDK.
2. **`CLAUDE.md`-раздел для компактора** — конкретный, воспроизводимый приём защитить то, что должно переживать сжатие разговора, не только в SDK-агенте, но и в любой длинной интерактивной сессии Claude Code (тот же движок). Сам этот файл CLAUDE.md уже переинжектируется в каждый запрос (документация подтверждает это прямо), то есть правила вики компакции не боятся по определению — рычаг пригождается для деталей **сессии**, которых в CLAUDE.md нет и не должно быть (прогресс конкретного разбора, последний прочитанный файл).
3. **Параллельность по умолчанию — для read-only, не для write** — довод для любого самописного тула: если он не меняет состояние, явный `readOnlyHint` экономит время без риска гонки; если меняет — последовательность по умолчанию правильна, а не ограничение, которое надо снимать.
4. **`ResultMessage` может не быть последним в стриме** — практический урок для любой обёртки вокруг `query()`: дочитывать стрим до конца, не выходить по первому результату.
5. **`effort` как параметр кода, не только команда интерфейса** — довод в пользу того, чтобы субагенты с узкой, предсказуемой задачей (листинг, поиск файла) получали `effort="low"` явно, а не наследовали уровень родительской сессии.

## Что не взято / лиды

- **Session storage / dual-write architecture** (резюме: отдельный адаптер `session_store` для возобновления сессий между контейнерами) — упомянуто вскользь, страница отсылает к отдельному документу `session-storage.md`, не прочитанному в этом прогоне; не актуально сейчас (три рутины вики работают на одном `main`, не между контейнерами с раздельным диском).
- **`ToolSearch` как встроенный тул для динамической подгрузки тулов** — упомянут в таблице инструментов, не раскрыт здесь; пересекается с уже описанным MCP tool search, но для собственных кастомных тулов отдельно не читано.
- Полная таблица типов сообщений для каждого SDK (`python#message-types`, `typescript#message-types`) — не открывалась, вне порога этого разбора.

## Оценка источника

Официальная документация Anthropic, туториал плюс инженерное объяснение, прочитаны целиком через `WebFetch`, без блокировки. Для кого — для любого, кто пишет код на Agent SDK напрямую (profil применимости чуть шире, чем у Code Mode-страницы 16.11: там было прямое ограничение «не для cloud-сессий», здесь ограничений на среду исполнения нет). Фактических ошибок не найдено, страницы внутренне согласованы (таблица permission modes в agent-loop.md совпадает с упоминанием в quickstart.md).

## Проверка безопасности источника

Обе страницы прочитаны целиком через `WebFetch` домена `code.claude.com`. Инструкций, адресованных агенту-читателю документации («сделай X», «игнорируй предыдущие правила»), не обнаружено — весь императивный текст («Create a project folder», «Select Yes, turn on Code Mode» и подобные) адресован человеку, настраивающему свой собственный проект, а не модели, разбирающей документацию.
