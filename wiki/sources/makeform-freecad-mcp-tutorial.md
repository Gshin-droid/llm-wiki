## Саммари
Полный пошаговый туториал: подключение [[freecad|FreeCAD]] к Claude Desktop через сторонний MCP-сервер `neka-nat/freecad-mcp` и `UVX`, от установки до рабочего цикла «промпт → 3D-деталь». Материал лежал в очереди `raw/web-clipped/` с 08-11, разобран этим прогоном (еженедельный разведчик практики) как явный практический кейс — не анонс, не рерайт, воспроизводимая процедура с демонстрацией на реальных деталях.

Ценность для вики не в самом FreeCAD (домен CAD/3D-печати в проектах пользователя не встречался), а в двух вещах общего порядка: (1) конкретный, до мелочей описанный пример подключения MCP-сервера к нишевому desktop-приложению — тот же класс задачи, что каталог типовых MCP-подключений на [[mcp-model-context-protocol]]; (2) наглядная демонстрация agentic-цикла с **визуальной** обратной связью (скриншот вьюпорта вместо только текста) — конкретизирует абстрактное «шаг = запрос + инструменты» из [[ustroystvo-agentnoy-obolochki]] на кейсе, где у модели нет прямого доступа к результату иначе как через рендер.

## Что взято в вики
- **Механика цикла (0:25–0:51):** промпт → Claude рассуждает → вызов FreeCAD Python API через MCP → FreeCAD возвращает скриншот вьюпорта → Claude анализирует картинку и шлёт следующую команду. Цикл повторяется, деталь строится пошагово. Перенесено в [[mcp-model-context-protocol]] как пример MCP с визуальной обратной связью.
- **Компромисс screenshot vs text-only (9:04–9:55):** конфиг MCP-сервера поддерживает флаг «только текст» — без скриншота модель получает имена объектов/размеры/статус, заметно дешевле по токенам за операцию; автор рекомендует screenshot-режим для коротких сессий (1–2 детали) и text-only для длинных цепочек операций. Конкретный, измеримый в токенах пример того же компромисса «дороже и нагляднее модели» vs «дешевле и слепее», что уже разбирался абстрактно на [[claude-api-cost-optimization]] (там — про кэш и батч, не про модальность фидбека).
- **Обработка неоднозначного промпта (13:44–15:37):** «Fillet all edges» без указания радиуса → модель сама спрашивает радиус и предлагает диапазон (держать меньше 10 мм, иначе геометрические ошибки); «Make four holes on top» без координат → модель сама выбирает расположение (отступ от края) и **объясняет обоснование** (не задевает скругление). Конкретный пример того, что в вики раньше формулировалось только абстрактно («Claude reasons through placement») — здесь видно рассуждение целиком, с обоснованием инженерного, а не случайного выбора.
- **Честно названное ограничение (17:53–18:37):** промпт «close all documents» закрывает несохранённые документы **без запроса подтверждения**, предупреждение о потере данных приходит постфактум, одной строкой. Автор прямо советует привычку сохраняться вручную или явно просить Claude сохранить перед закрытием. Не общее свойство Claude, а следствие конкретной реализации MCP-сервера (нет explicit confirmation перед деструктивным вызовом инструмента) — стоит держать в уме как класс риска при оценке любого стороннего MCP-сервера, не только этого.

## Что не взято / лиды
- Сам процесс установки (Claude Desktop → FreeCAD → UVX → копирование папки аддона → правка `claude_desktop_config.json`) — механика типового локального MCP-подключения, уже покрыта абстрактно на [[mcp-model-context-protocol]] («последнее средство — попросить агента собрать подключение»); частности одного конкретного стороннего сервера в вики не переносятся, ссылка на видео/PDF-гайд автора достаточна тем, кому это понадобится предметно.
- Пример со шестернёй (spur gear «с нуля», 18:49–19:38) и деталью по эскизу от руки (15:49–16:44) — эффектные демо, но не новая техника относительно уже взятого (тот же цикл рассуждение+визуальный фидбак), поэтому не пересказаны отдельно.
- Заявление в описании видео «one of the most practical Claude Fable 5 use cases» — промо-формулировка автора, не проверялась и не вносилась как факт (страница не утверждает, что цикл специфичен для Fable 5 — тот же MCP-паттерн работает с любой моделью Claude, которую поддерживает Desktop-коннектор).
- Не проверено по первоисточнику: сам репозиторий `github.com/neka-nat/freecad-mcp` (звёзды, число открытых issues, статус поддержки) — в этот прогон не фетчился отдельно, автор видео не третья сторона по нему, а пользователь стороннего кода. Если пригодится предметно — отдельная допроверка репозитория, не сделанная этим прогоном.
