## Саммари

Лекция о новом классе агентов: работает на сервере, а не в терминале; будят его не только сообщения пользователя, но и Slack, почта, расписание; у него свой облачный компьютер, память, скиллы; он сам решает, когда беспокоить человека. Лектор рассказывает об устройстве Grok Bot, над которым работает. Разобрана вместе с пользователем по полной расшифровке. Для вики ценность двойная: независимое подтверждение уже принятых правил и один новый приём — сжатие разговора, пока кэш тёплый, — который привёл к собственному замеру.

## Главное по частям (с отметками времени расшифровки)

- **Лестница «от дешёвого к дорогому, человек — последним»** (21:31): сначала то, что агент знает из разговора; потом плагин или API; потом поиск в сети; потом браузер; потом весь компьютер; и только если всё это не помогло — спросить человека.
- **Три слоя памяти** (32:51): факты о пользователе — в каждом запросе; датированные журналы прошлой работы — по надобности; черновые заметки на ближайший час — исчезают сами. Остальное — в файлах, которые агент находит сам через `grep`.
- **Устойчивый процесс вместо очереди задач** (16:18): после сбоя на шаге 3 продолжать с шага 3, а не повторять всё; у них — открытый Temporal.
- **Приоритет сообщений** (17:21): сообщение владельца прерывает текущий ход; несколько сообщений подряд склеиваются в один ход.
- **Сортировщик «беспокоить или нет»** (11:43): событие проходит отсев дублей и решение, стоит ли его показывать человеку — как с коллегой, который не дёргает по каждому шагу.
- **Отдельная модель проверяет команды** (4:59, 26:29); недоверенный вход (письмо, вебхук) — не инструкция; необратимое (письмо, сообщение) — черновик на одобрение.
- **Субагенты держат основной разговор чистым** (23:30): тяжёлая работа — помощникам, назад — только итог; каждый помощник — свой устойчивый процесс.
- **Кэш** (27:47–31:30): неизменная часть запроса — сверху и в постоянном порядке; новый кусок промпта при пробе не должен ломать порядок для остальных; «промах кэша — это ошибка в системе»; не добавлять и не убирать инструменты посреди хода.
- **Сжатие, пока кэш тёплый** (31:32–32:40): длинный разговор, пользователь отошёл — сжать сразу, пока кэш жив; вернётся к короткой выжимке, а не к длинному разговору без кэша.
- **Если 90% времени уходит на одну команду оболочки — отдельный инструмент** (25:46); **сообщения об ошибках писать и для агентов** (26:21).
- **Цикл «ошибка → замер → исправление → проверка замером»** (36:06) — внутренний ежедневно, внешний с каждой новой моделью.
- **«Удаляй продукт»** (37:45): модели сейчас худшие из тех, что будут; строить как можно меньше, под следующее поколение.

## Что совпало с уже принятым

Лестница исполнителей из свода работы с ИИ; три слоя памяти — `CLAUDE.md` (факты), `log.md` и журналы (датированное), журнал состояния (черновик), всё в файлах; устойчивый процесс — правила инкрементального коммита и записи «начато, итог не записан» для рутин, у них то же сделано инфраструктурой; проверка команд моделью — замер [[claude-code-auto-mode-safety-data]]; правило спуска — [[verification-three-levels]] и [[claude-plugin-eval]]; кэш — своя доля попаданий 97,6% ([[prompt-cache-control-mod]]).

## Берём инструмент или логику

- **Инструмент — нет:** Grok Bot закрыт, подробности устройства — со слов лектора.
- **Логика — да:**
  - **сжатие, пока кэш тёплый** → проверено на своих журналах: перерывы дольше часа — около половины всей записи в кэш; в Claude Code такая функция уже есть, но только в терминале — разбор в [[prompt-cache-control-mod]];
  - **сортировщик «беспокоить или нет»** и **склейка подряд идущих сообщений** → делами в хабе для своего Telegram-ассистента — это и есть постоянно работающий агент.

## Что не взято / лиды

- «Галлюцинаций почти не осталось, задача по сути решена» (7:18) — мнение лектора, не замер.
- «В слепом тесте модель проверяет команды лучше человека» (5:20) — без ссылки на тест; совпадает по смыслу с данными Anthropic, но сам тест не назван.
- Устройство облачного компьютера (виртуальные машины Firecracker, снимки состояния) — для своих задач не нужно.

## Оценка источника

Практик, строящий такой продукт; лекция для студентов, без продажи, но и без цифр. Ценна как карта устройства и как сверка своих решений; утверждения о моделях — мнения.

## Проверка безопасности источника

Расшифровка лекции — без инструкций, обращённых к агенту.
