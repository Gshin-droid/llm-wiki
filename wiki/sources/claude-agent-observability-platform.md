## Саммари

Разведка практики (рутина 2), тот же прогон, что [[anthropic-redesigning-source-control]]. Официальное объявление публичной беты трассировки агентов на Claude Platform: модель-вызовы, tool use и обращения к MCP-серверам экспортируются как стандартные OpenTelemetry-трассы (GenAI semantic conventions), совместимые с любым OTLP-инструментом. Для Managed Agents/Messages API — добавить destination в Claude Console; для Claude SDKs — экспорт автоматический. Три названных применения: отладка в существующем стеке (Grafana Cloud, Honeycomb, Sentry, Splunk), улучшение агента по продакшн-трассам (Arize AI, Braintrust, Datadog, Langfuse, LangSmith, New Relic, PostHog), учёт по организации (Databricks Unity Gateway). Примеры клиентов с цифрами — Ramp (Reflect: −10–20% токенов, +30% скорость сессий), FloQast (аудит по одной временной шкале), Foxglove/Sterling Labs.

## Что взято в вики

- Паттерн «трасса → проверка надёжности → расширение доступа» — перенесён в новый концепт [[agent-observability]] как конкретная реализация «обнаружения», третьей ноги защиты из [[zabor-i-stena-prava-agenta]].
- Три категории инструментов и примеры клиентов с цифрами — целиком в новый концепт, как каталог готовых путей подключения (не инструкция по установке).
- Связь с [[verification-three-levels]]: продакшн-трассы как непрерывный канал данных для второго уровня проверки (замеры), в отличие от разового прогона эталонного набора.

## Берём инструмент или логику

**Инструмент — нет, не сейчас.** У персональной вики нет собственного продакшн-деплоя Managed Agents/Agent SDK с внешним трафиком, который стоило бы трейсить через Grafana/Langfuse/Datadog — автономные рутины этой вики и так пишут прозрачный след в `wiki/log.md` и git-историю, то есть собственный (markdown-based, не OTel) механизм наблюдения уже есть и покрывает текущую задачу. Если пользователь когда-нибудь перейдёт от Claude Code-рутин к собственному продукту на Agent SDK/Managed Agents с внешними пользователями, паттерн прямо пригодится.

**Логика — да.** Сама идея «наблюдение — отдельная, третья нога защиты, не забор и не стена» — то, чего не было явным механизмом на [[zabor-i-stena-prava-agenta]], хотя страница упоминала «обнаружение» в первом абзаце. Эта находка впервые даёт слову конкретную форму: не абстрактный мониторинг, а структурированная трасса каждого шага, которую можно просматривать до инцидента, а не только после.

## Что не взято / лиды

- Детали биллинга экспорта трасс (платно/бесплатно, есть ли лимиты) — источником не раскрыты, не выносится как факт.
- Конкретные дашборды/настройка каждого из названных инструментов (Grafana/Honeycomb/Langfuse и т.д.) — каталог имён, не разбор механики каждого.
- Цифры клиентских кейсов (Ramp, FloQast) — self-reported самими клиентами через пост Anthropic, не независимый аудит; помечено прямо на обеих страницах.

## Оценка источника

Официальный пост платформы Anthropic (`claude.com/blog`) со ссылкой на официальную документацию (`platform.claude.com/docs`) — верхняя ступень иерархии доверия.
