## Саммари

Разбор технологии RAG (Retrieval Augmented Generation) с нуля до продакшн-нюансов: зачем она нужна (модель не хранит факты, а генерирует текст по паттернам), как устроен базовый конвейер (чанки → эмбеддинги → векторная база → сборка контекста), пять продвинутых техник, из чего состоит объективная оценка качества (фреймворк Ragas) и что ломается в проде (кэш, мониторинг, безопасность данных).

Материал закрывает содержательный пробел: RAG упоминается на десятке страниц этой вики как контрастная модель для [[persistent-wiki-pattern]] (NotebookLM, классический чат-с-документами), но собственной концепт-страницы у него не было — только определение через противопоставление. Взято почти всё по существу: это первый источник, разбирающий сам механизм, а не то, чем он не является.

## Что взято в вики

- **Базовый конвейер RAG** (5:02–7:54) — chunking → embeddings → векторная база → similarity search → сборка контекста → генерация — → новая страница [[rag-retrieval-augmented-generation]].
- **Пять продвинутых техник** (9:21–12:48): гибридный поиск (BM25 + векторный, объединение результатов), parent document retrieval (искать по мелким чанкам, возвращать крупный документ), multi-query (модель сама переформулирует вопрос в несколько вариантов), реранкинг (LLM-оценка топ-кандидатов после первичного поиска), семантическое разбиение (границы чанка по смыслу, а не по числу символов) — → [[rag-retrieval-augmented-generation]], с явной оговоркой источника «нет универсального решения: для новостного сайта — быстрый BM25, для медицинской системы — точный реранкинг даже ценой скорости».
- **Ragas — фреймворк оценки качества RAG-систем** (13:19–15:19): синтетическая генерация тестовых вопросов по knowledge graph документов (простые / требующие синтеза нескольких источников / комбинирующие факты), четыре метрики (честность/faithfulness, полнота контекста, релевантность ответа, точность контекста) — → [[rag-retrieval-augmented-generation]], раздел «Оценка качества». Закрывает практический пробел: до этого в вики не было ответа на вопрос «как вообще измерить, что RAG-система работает», только качественные оценки.
- **Production-слой** (15:42–17:52): три уровня кэширования (embedding cache / exact-match cache / semantic cache через векторный поиск по вопросам, с явным риском протухания при обновлении документов), необходимость мониторинга задержек/стоимости/качества в реальном времени, приватность (эмбеддинг необратим в исходный текст, но нужен контроль доступа/audit log/data retention; приватные LLM для данных под NDA — публичные API "даже с enterprise-подпиской не гарантируют полной конфиденциальности" по словам автора, не проверено первоисточником вендора) — → [[rag-retrieval-augmented-generation]].
- **Довод «зачем RAG агентам, если у моделей уже есть веб-поиск»** (8:16–8:55): встроенный поиск (ChatGPT/Claude) работает только с публичными данными, каждый вызов стоит денег отдельно, нет контроля над источниками — RAG даёт доступ к приватным данным с кэшированием и настройкой под конкретную задачу — → дополнение к [[llm-memory-landscape]] (RAG как отдельный, третий способ дать модели знание, не пересекающийся с двумя описанными там задачами памяти).

## Что не взято / лиды

- **Иллюстрация через историю про шпаргалку на экзамене** (1:16–3:41) — авторская аналогия для интуиции, не техническое содержание, в концепт-страницу не перенесена.
- **Конкретные продукты для мониторинга RAG в проде** названы обобщённо («платформ довольно много»), без имён — не на что ссылаться, лид не заведён.
- **Утверждение про enterprise-конфиденциальность публичных LLM-провайдеров** — мнение автора без ссылки на договор/документацию конкретного вендора, перенесено с пометкой «по словам автора», как факт не утверждается.

## Оценка источника

Четвёртый разбор этого автора (после [[berezhnitsky-7-signs-old-jun]], [[berezhnitsky-attack-for-3-dollars]], [[berezhnitsky-agent-memory-lies]]); presunción сохраняется — прежние разборы фактических ошибок не вскрывали. Материал ровнее по уровню, чем «Пять вопросов»: это объяснение механики с нуля для незнакомых с темой, но с честной прогрессией до продакшн-деталей (кэш, мониторинг, приватность), которые в вводных материалах обычно опускают. Ссылок на источники цифр/фреймворков в видео нет (кроме упоминания Ragas по имени — сам факт существования фреймворка и его подход проверяемы, конкретные числовые пороги метрик не называются и не проверялись). Промо-нагрузки нет.
