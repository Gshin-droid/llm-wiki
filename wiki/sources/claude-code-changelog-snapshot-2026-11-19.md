## Саммари

Ярус 2 рутины 1 (новости), следом за сводкой [[novosti-2026-11-19]]. Три версии с прошлого снапшота [[claude-code-changelog-snapshot-2026-11-13]] (v2.1.325). Главное: **Manual перестаёт быть безусловным дефолтом режима разрешений** — серия изменений подряд переводит разные классы сессий без явно заданного режима на auto mode (классификатор решает за каждый вызов инструмента сам), а не на Manual, как было раньше. Это продолжение, а не новый узел: 2.1.325 (прошлый снапшот) уже сузила автодоверие внутри Bash-песочницы и git; здесь то же направление поднимается с уровня «что доверяется внутри сессии» на уровень «какой режим сессия получает при старте».

## Что взято в вики

1. **Auto mode становится дефолтом интерактивной сессии без заданного режима — по частям, тремя релизами.** 2.1.326 (16.11): организации с конфигурацией Claude Code + Cowork HIPAA получают auto mode по умолчанию в терминале и VS Code (`disableAutoMode` отключает), и отдельно — сессии без заданного режима стартуют в auto mode, а не в Manual, если политика организации ещё не загрузилась (временное окно до загрузки политики, не постоянное поведение). 2.1.328 (19.11): то же для Opus/Sonnet 4.6 на провайдерах третьей стороны (Bedrock, Google Cloud Agent Platform, Microsoft Foundry, шлюз приложений Claude) — ранее auto mode на этих путях не предлагался вовсе для этих моделей, теперь plan mode и запросы на Bash используют и предлагают auto mode, как у новых моделей. Прямая цитата 2.1.328: *«Interactive sessions with no permission mode set now start in auto mode.»* Это обобщение частных случаев 2.1.326 до общего правила.
2. **Серия сужений auto mode и песочницы тем же тройным релизом** (не фиксы конкретных обходов — changelog не нумерует узлом серии permission-bypass, в отличие от прошлых снапшотов): auto mode теперь отказывает в части команд, которые раньше пропускались по широким wildcard-правилам без указанной программы (`Bash(pnpm dlx *)` и аналоги — решает классификатор, не правило); команды, чьи переменные раскрываются в очень длинный текст, теперь отказываются; `permissions.blockReadsOutsideWorkingDirectories` в bypass/auto режимах спрашивает про больше команд и часть отказывает; сэндбокс на macOS/Linux/WSL перестал писать в некоторые чувствительные домашние папки по умолчанию (включается явно через `sandbox.filesystem.allowWrite`); файловые инструменты отказывают в записи в файлы входа Claude Code (`.credentials.json`).
3. **`/status` теперь показывает диагностику обвязки, а не только текущий режим** (2.1.327): сломанные файлы агентов/скиллов/команд, недоступный сэндбокс, игнорируемые настройки разрешений, hook-матчеры, которые никогда не срабатывают. Прямое следствие для этой вики: следующий прогон любой из трёх рутин может прогнать `/status` перед остальной работой и увидеть напрямую, активен ли сэндбокс, не проигнорированы ли правила `permissions.allow` — быстрее, чем спекулировать по описанию changelog.
4. **Проверка на собственной конфигурации — неожиданный результат.** Прошлый снапшот (2.1.325) предсказывал, что любая из трёх автономных рутин CLAUDE.md может упереться в вопрос разрешения при вызове `Skill(wiki-ingest)`/`Skill(wiki-lint)`, поскольку `.claude/settings.json` этой вики не содержит записи `Skill(имя)` в `permissions.allow`. Эта же автономная сессия (без пользователя, прогон рутины новостей) вызвала `Skill(wiki-ingest)` для этого самого разбора — **вопрос разрешения не возник, скилл запустился сразу**. Находка не закрывает пункт `wiki/gaps-backlog.md` (конфигурация не правилась, причина отсутствия вопроса не установлена — могла быть эта сессия в ином permission mode, чем сценарий из описания 2.1.325, или прогноз был верен только для части путей вызова), но ограничивает слишком быстрый вывод «риск подтверждён, просто ещё не сработал». Запись добавлена к открытому пункту бэклога, не поверх него.

## Берём инструмент или логику

Инструмент (сам Claude Code) уже стоит. Логика: смена дефолта — продолжение линии, разобранной на [[ai-security-by-design]] весь последний квартал (явный allow-список надёжнее автоматического доверия по категории) — только здесь категория шире: не «эта команда внутри песочницы», а «у этой сессии вообще не задан режим». Для [[urovni-avtonomnosti-agenta]] это не меняет шкалу R0–R5 этой вики (три рутины остаются фактически R3 по прежним основаниям — сторожи CI, не auto mode самого харнеса), но стоит знать: если у Cloud Routines когда-то режим не будет задан явно, дефолт теперь auto, а не Manual — повод явно фиксировать режим рутин, а не полагаться на дефолт.

## Что не взято / лиды

Основной объём версии 2.1.327 (ограничения `ExitWorktree`, правки стрелок в permission-промптах, проверки символических ссылок, субагенты на Bedrock/Vertex/Foundry) и 2.1.328 (несколько фиксов регрессий 2.1.327, PowerShell-правки) — ниже порога для этой вики, платформенно-специфичные детали. `/code-review` теперь по умолчанию репортит только баги и нарушения CLAUDE.md (раньше — плюс простота/эффективность, которые переехали в `/simplify`) — релевантно только тем, кто использует `/code-review` в своих проектах, здесь не практикуется предметно.
