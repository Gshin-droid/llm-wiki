# Auto mode становится дефолтным режимом Claude Code (14 августа 2026)

**Дата загрузки:** 2026-08-13
**Источник:** [raw/sources/claude-code-auto-mode-default-2026-08.md](../../raw/sources/claude-code-auto-mode-default-2026-08.md), официальная документация `code.claude.com/docs/en/permission-modes`, раздел "Eliminate prompts with auto mode"

## Саммари

С **14 августа 2026** (завтра относительно даты этого прогона) auto mode ([[claude-code]], раздел "Практическая механика") становится дефолтным режимом разрешений для **новых** сессий Claude Code на тарифах Pro, Max и Team — вместо нынешнего Manual (режим с запросом подтверждения на каждое действие). Затрагивает не эту вики напрямую (`.claude/settings.json` репозитория `defaultMode` не задаёт — переключение будет управляться уровнем пользователя/организации), но напрямую затрагивает интерактивные сессии пользователя.

## Ключевые детали

- **Кого не касается автоматически:** если пользователь уже сам выставил `defaultMode` (свой явный дефолт) — он остаётся в силе, если пользователь не примет одноразовый prompt-предложение переключиться. Дефолт, управляемый организацией (Team/Enterprise через managed settings), релизом тоже не переопределяется.
- **Требования к доступности auto mode** (не изменились этим релизом, но важны как контекст, кому переключение вообще коснётся): модель — Opus 4.6+/Sonnet 4.6+/Fable 5 на Anthropic API и Claude Platform on AWS; на Bedrock/Google Cloud Agent Platform/Microsoft Foundry/Claude apps gateway — только Sonnet 5, Opus 4.7+, Fable 5. Sonnet 4.5, Opus 4.5, Haiku и claude-3 не поддерживаются нигде.
- **Что делает classifier** (существующий механизм, не новый): отдельная модель-классификатор проверяет действия перед выполнением, блокирует то, что выходит за рамки запроса, целится в неизвестную инфраструктуру или выглядит навязанным враждебным содержимым из прочитанного. Также проверяет каждое сообщение через `SendMessage` (с v2.1.222) — это прямое продолжение находки [[claude-code-changelog-snapshot-2026-08-07]] ("Auto mode теперь проверяет SendMessage").
- **Явная оговорка источника:** *"Auto mode reduces permission prompts but does not guarantee safety. Use it for tasks where you trust the general direction, not as a replacement for review on sensitive operations."*
- **Механизм ручной настройки дефолта** не новый: `"permissions": {"defaultMode": "auto"}` в `~/.claude/settings.json` (не в `.claude/settings.json` проекта — с v2.1.142 репозиторий не может сам себе выдать auto mode, см. также [[ai-security-by-design]]).
- Блог-анонс (`claude.com/blog/auto-mode-default-in-claude-code`) не прочитан — домен `claude.com` был заблокирован сетевым прокси окружения при этом прогоне; факты выше только с doc-страницы `code.claude.com`.

## Почему это отмечено, а не отброшено как анонс без техники

Это не рерайт и не голый анонс — это единственный первоисточник (официальная страница документации, не блог/пересказ) с точной датой, точным списком незатронутых случаев (свой дефолт, org-дефолт) и точным списком требований доступности. Timing (за один день до этого прогона) и прямая применимость к тому, как сам пользователь работает с Claude Code интерактивно, дают материалу практическую ценность — не просто "что вышло", а "что изменится в поведении сессий пользователя завтра, если он ничего не настраивал".
