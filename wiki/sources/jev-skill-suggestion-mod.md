# Мод jev-skill-suggestion — перечень скиллов убирают из контекста

## Саммари

Мод к [[claude-code]], убирающий из контекста **перечень установленных скиллов**. Обычно этот перечень уходит модели каждую сессию целиком: имя и однострочное описание каждого скилла. Мод его прячет, а вместо него на каждый запрос подставляет **не более одного** скилла, выбранного классификатором, — сразу с содержимым его `SKILL.md`.

Это следующий шаг той же логики, что описана в [[skill-authoring-practical-rules]] как progressive disclosure. Там открывали по требованию **содержимое** скилла, оставляя в контексте перечень; здесь по требованию открывают **сам факт существования** скилла.

**Заявленная экономия: −5 496 входных токенов** (по биллингу API, не по оценке `/context`) на наборе из 40 скиллов. На наборе из 182 скиллов мод, по данным автора, заодно улучшил точность выбора: ошибочные загрузки скиллов упали с 16,8% до 7,3%, лишние — с 9,8% до 4,0%.

## Как устроено

- Скиллы не удаляются: им проставляется статус `user-invocable-only` в `~/.claude/settings.json`. Они остаются установленными, `/имя` по-прежнему работает — исчезает именно **листинг**, который Claude Code отправляет модели каждую сессию. `/context` перестаёт их считать.
- Выбранный скилл приезжает в промпт блоком `<skill_relevance>`: мод вставляет содержимое `SKILL.md` без фронтматтера, подставляя переменные окружения. То есть мод сам выступает загрузчиком, а не просто советчиком.
- Классификатор — **Jev** от TypeSafe ([[jev-typesafe]]), «System One decision model», доступный напрямую по API либо через Vercel AI Gateway. **Этот же класс модели, для которого [[laya]] заявлена открытой локальной альтернативой** — связь между двумя постами инбокса, ранее не установленная.
- Настройка — командой `/jev-skill-suggestion:setup`: показывает списки, спрашивает подтверждение, делает резервную копию настроек.

## Что уходит наружу — главный вопрос этого разбора

**С API-ключом** мод отправляет во внешний сервис: **текст запроса пользователя**, имена скиллов-кандидатов с однострочными описаниями (первый запрос) и первые 700 символов `SKILL.md` выбранных скиллов (второй запрос).

**Без ключа наружу не уходит ничего** — работает встроенный классификатор. Разница между конфигурациями, по карточке мода, в том, что TypeSafe дополнительно возвращает калиброванный коэффициент доверия (см. [[kalibrovka-uverennosti-resheniy]]).

Отсюда правило применения, а не запрет: **каждый промпт — это и есть содержимое работы**. Конфигурация с ключом означает, что формулировки задач уходят третьей стороне; для проектов с чувствительным содержимым это неприемлемо, для остальных — осознанный выбор. Вариант без ключа снимает вопрос целиком.

## Требования и обратимость

- Claude Code **не ниже 2.1.278** и экспериментальный флаг окружения `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`.
- Статус **Early Access**, API мода «может меняться между релизами».
- **Скиллы из плагинов спрятать нельзя** — `skillOverrides` их не затрагивает. Для набора, где большинство скиллов пришло плагинами, экономия окажется много меньше заявленной.
- После `/clear` содержимое надо подставлять заново.
- **Удалять мод только через `/jev-skill-suggestion:setup restore`.** Иначе скиллы останутся скрытыми от модели без способа их вернуть: мод, который их прятал, уже удалён, а статус `user-invocable-only` в настройках остался.

## Что взято в вики

1. Дополнение к [[claude-skills]] и [[skill-authoring-practical-rules]]: перечень скиллов сам по себе стоит токенов, и его цена растёт линейно с числом установленных скиллов; крупный набор — это постоянный налог на каждую сессию.
2. Цена в цифрах: −5 496 входных токенов на 40 скиллов, по биллингу API.
3. Связь [[jev-typesafe]] ↔ [[laya]]: классификатор этого мода — ровно тот сервис, альтернативой которому объявлена Laya.
4. Приём как таковой (спрятать листинг, подставлять по одному) — переносим без этого мода: статус `user-invocable-only` и `skillOverrides` штатные, подтверждены дословно официальной документацией (`code.claude.com/docs/en/skills`) при допроверке 2026-09-25.

## Что не взято / лиды

- Цифры −5 496 токенов и улучшение точности замерены автором мода на своих наборах; независимой проверки нет.

## Допроверка 2026-09-25 (ежедневный процесс закрытия пробелов) — исходник прочитан

Закрыт пункт бэклога «код мода не читался». Прочитаны напрямую: диф PR #944 (`github.com/davila7/claude-code-templates`, список файлов), исходники `hooks/jev-skill-suggestion.ts` и `hooks/policy.ts`, `README.md` мода — все через `raw.githubusercontent.com`. Отдельно сверено с официальной документацией Claude Code: `code.claude.com/docs/en/skills`, `.../hooks`, `.../env-vars`, плюс `CHANGELOG.md` репозитория `anthropics/claude-code`.

**Исходник подтвердил разбор по описанию, без расхождений.** С ключом действительно уходит полный текст запроса (`e.text`, не урезанный), имена и описания скиллов-кандидатов, и обрезка `SKILL.md` до `excerptChars` символов (700 — значение по умолчанию из README, не жёсткая константа кода, настраивается). Без ключа — единственный запрос к встроенному `$.model.classify`, наружу ничего не уходит. Скиллы из плагинов дословно не прячутся: `«Plugin skills cannot be hidden by skillOverrides; they stay listed unless the plugin is disabled»` — то же самое, слово в слово, что уже было записано со слов карточки мода.

**Уточнение, которого не было в разборе по описанию.** Сам мод в `settings.json` **не пишет** — только читает его и делает резервную копию (`jev-skill-suggestion.skill-overrides.backup.json`). Правку `user-invocable-only`/`skillOverrides` выполняет модель через собственные файловые инструменты по инструкции хука — дословно `«The model does the editing with its own tools»`. Разница практическая: правка проходит как обычная видимая правка файла моделью (со всеми штатными разрешениями на запись), а не тихая программная запись сторонним скриптом в обход интерфейса.

**Уточнение по порогу.** Отдельного порога уверенности для финального топ-1 скилла нет — есть только общий `gateThreshold` («gate mean under which nothing is suggested»), ниже которого не предлагается ничего. Это ближе к бинарному фильтру, чем к калиброванному порогу уверенности в духе [[kalibrovka-uverennosti-resheniy]].

**Главная находка: `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS` не подтверждается официальной документацией.** Флаг заявлен README мода как требование установки («Early access. Mods need `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`»), но: (1) на странице `code.claude.com/docs/en/hooks` (типы хуков: command/HTTP/MCP tool/prompt/agent) флаг не упомянут; (2) на `code.claude.com/docs/en/env-vars` флаг не упомянут; (3) в `CHANGELOG.md` `anthropics/claude-code` — ни разу, включая версию 2.1.278, которую README называет минимальной. Событие `prompt.attachment`, на которое опирается мод, тоже не встречается среди документированных типов хуков. Не установлено, идёт ли речь о непубличной/предрелизной функции Claude Code, о собственном слое проекта `claude-code-templates` поверх штатных хуков под нестандартным именем флага, или о недокументированном временном API. Официальные `skillOverrides` и `user-invocable-only`, которые мод только *использует*, документацией подтверждены дословно и без расхождений — под сомнением именно способ, которым мод получает право их менять, а не сама механика видимости скиллов.

**Решение не меняется.** Мод по-прежнему не устанавливается этим прогоном — решение об установке за пользователем. Находка про недокументированный флаг усиливает, а не снимает осторожность: Early Access плюс опора на функцию, которую независимо подтвердить не удалось.

## Оценка источника

Пост-наводка короткий и в главном верный: скиллы остаются вне контекста, выбирается подходящий, ставится одной командой. Три существенных умолчания: (1) не сказано, что **с ключом текст каждого запроса уходит во внешний сервис**; (2) не сказано про статус Early Access, требование версии 2.1.278 и экспериментальный флаг; (3) не сказано про `setup restore`, без которого удаление мода оставляет скиллы скрытыми. Приведённая в посте команда установки при этом короче реальной — в ней нет флага окружения.

Та же системная черта канала, что и в двух предыдущих разборах: фактическая часть верна, ограничения опущены.

**Команда установки из поста намеренно не выполнялась.** Это сторонний мод, который: ставится одной командой из каталога (то есть исполняет чужой код до того, как его прочитали), правит `~/.claude/settings.json`, читает каждый промпт пользователя и может отправлять его во внешний сервис. Все четыре признака — ровно те, из-за которых в правилах пользователя установка предпочитается инспектируемая, а не автоматическая, и проверяется отдельно доверие к автору и доверие к контенту, который расширение приносит в контекст.
