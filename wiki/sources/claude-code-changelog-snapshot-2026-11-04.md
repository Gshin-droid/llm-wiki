Четыре версии (2.1.314, 2.1.316–2.1.318) за неделю без одного headline-анонса и без критических security-фиксов — но с окончательным снятием одной из последних опор поколения Opus 4 и новой настройкой, которая впервые ограничивает запись файлов **вне зависимости от режима разрешений**, а не только в auto mode. Отдельно — первая явная защита от утечки email аккаунта через обычный вызов инструмента и первое ужесточение поведения хуков Agent SDK при сбое с «тихого пропуска» на «блокировать».

## Находка 1: `permissions.blockWritesOutsideWorkingDirectories` — граница записи, не зависящая от режима разрешений

*"Added `permissions.blockWritesOutsideWorkingDirectories`: Write, Edit and NotebookEdit refuse paths outside the working directories in every permission mode"* (2.1.314).

До этой настройки запрет писать за пределы рабочей директории был делом конкретного правила в `settings.json` (`deny` на путь/паттерн) или поведением auto mode-классификатора — то есть зависел от режима и мог быть обойдён переключением на `bypassPermissions` или отсутствием нужного правила deny. Формулировка «in every permission mode» означает, что при включении этой настройки граница держится даже в `bypassPermissions` — там, где раньше она не действовала вовсе. Это не включено по умолчанию (как и `sandbox.filesystem.disabled`/`sandbox.network.strictAllowlist` рядом, нужно явно включить в settings), но впервые даёт способ закодировать «агент не пишет вне рабочих директорий» как инвариант, а не как инструкцию или эвристику классификатора — ровно та разница, которую разбирает [[verification-three-levels]] («инвариант или эвристика»), и прямая иллюстрация принципа Хашимото уже записанного на [[mitchell-hashimoto]]: «ошибка должна стать структурно невозможной — кодом, а не промптом». Дополняет открытый на [[zabor-i-stena-prava-agenta]] вопрос о границах прав агента: там же разбирался случай локальной службы без авторизации как «инструмента вне списка `tools`» — здесь симметричный случай, когда сам список `tools` (Write/Edit/NotebookEdit) остаётся, но область их действия сужается конфигурацией, не описанием задачи.

Дополнено в [[claude-code]] (раздел Permissions) и [[zabor-i-stena-prava-agenta]].

## Находка 2: Fast mode для Opus 4.8 снимается 30.11.2026 — конец самой долгоживущей fast-mode опоры

*"Deprecated fast mode for Opus 4.8 as of October 30, 2026; it will be removed on November 30, 2026. After removal, fast mode requests on Opus 4.8 return an error and do not fall back to standard Opus 4.8."*

Вики уже фиксировала этот паттерн: fast mode снимается для предыдущей модели при выходе следующей (fast mode для Opus 4.7 убрана тем же релизом 2.1.219, что ввёл Opus 5, см. [[claude-opus-5-launch]] и строку «Обновление 2.1.219» на [[claude-code]]). Здесь интервал куда длиннее — Opus 4.8 давно не модель по умолчанию (её сменила Opus 5, затем Opus 5.5 с 2.1.280), но fast mode для неё жила ещё два поколения вперёд, видимо ради тех, кто явно закрепил `/model opus-4.8` в конфигурации. Снятие — не откат на обычный Opus 4.8 (как можно было бы ожидать по аналогии с другими деградациями), а прямая ошибка на запрос: кто не мигрирует до 30.11, тот не плавно теряет скорость, а получает отказ.

Дополнено в [[claude-code]] (раздел «Модели и Effort»).

## Находка 3: проверка перед отправкой email аккаунта в сеть — новый класс защиты от утечки через обычный вызов инструмента

*"Added a check that asks before a web or shell tool call sends your account email address to the network"* (2.1.317).

Раньше в вики фиксировались похожие по форме, но более узкие случаи: `forever-downloads-agents-md-attack` — угон `ANTHROPIC_BASE_URL` на чужой сервер через подмену настроек; память/токены, утекающие через `.env`. Этот чек — другого рода: не про подмену конфигурации атакующим, а про рутинный случай, когда сам легитимный вызов инструмента (например, API, которому для запроса нужен email пользователя, или сайт, просящий контакт в User-Agent — ровно тот случай, что явно упомянут в системном промпте этой же сессии про `userEmail`) рискует отправить персональные данные без явного решения пользователя. Прямое структурное применение правила «данные пользователя не идут наружу без спроса», уже практикуемого в этой вики (см. системную инструкцию про `userEmail` — «не отправлять без явного запроса»), но здесь оно впервые встроено в сам инструмент, а не держится на том, что агент помнит об этом каждый раз.

Дополнено в [[ai-security-by-design]].

## Находка 4: хуки Agent SDK при сбое теперь блокируют действие, а не пропускают его

*"Added `onFailure: "block"` for Agent SDK hook callbacks, so a callback that fails blocks the action instead of letting it run"* (2.1.317).

До этой опции сбой хука (сетевая ошибка, таймаут, необработанное исключение в коде самого хука) по умолчанию вёл себя как fail-open — действие, которое хук должен был проверить, всё равно выполнялось. `onFailure: "block"` делает проверяющий хук fail-closed: если проверка не отработала, действие не происходит вовсе. Тот же класс риска, что уже разбирался на [[invariant-vidno-znachit-zapisano]] и [[verification-three-levels]] под именем «тихий сбой без отчёта» (пример — фикс `/goal`, допроверка 09-13) — здесь ровно симметричный случай для хуков Agent SDK, и впервые с явной настройкой, а не только фиксом конкретного бага.

Дополнено в [[verification-three-levels]].

## Находка 5: Idle-компакция — автоматическое сжатие простаивающего диалога свыше 200K токенов

*"Added idle compaction to VS Code and Claude Desktop's Code tab: a 200K+ token conversation left idle is summarized; the summary is used on your next message if the prompt cache has expired"* (2.1.314).

Прямое продолжение темы, которую вики разбирала на этой же неделе на [[kontekst-szhat-ili-nachat-zanovo]] (контекст: сжать, начать заново или вынести в память — шесть наводок из инбокса, запись 2026-11-02) — там обсуждался запрос `/autocompact` при простое как «обходной путь модом» на версии 2.1.314, предрасчитанный на выход 2.1.314. Теперь это штатная функция официального релиза той же версии, а не мод: диалог длиннее 200K токенов, оставленный без дела в VS Code/Claude Desktop Code-вкладке, сжимается сам, и сжатая версия используется, если к моменту следующего сообщения кэш промпта уже истёк (то есть восстановление полного контекста всё равно было бы дорогим). Пока ограничено двумя поверхностями (VS Code, Desktop Code tab) — не упомянуты CLI и облачные сессии.

Дополнено в [[kontekst-szhat-ili-nachat-zanovo]] и [[claude-code]].

## Малое

- **Credential expiry warnings** — `claude auth status` (`loginExpiresAt`) и `claude -p` в JSON (`credential_expires_at`) показывают дату окончания claude.ai-входа; `claude -p` в текстовом режиме выводит предупреждение в stderr за 10 дней до истечения. Напрямую касается автономных рутин этой вики, работающих через `claude -p` из крона — связь с [[claude-subscription-automation-terms]], но не меняет сам разбор условий подписки, только добавляет технический способ заметить скорое истечение входа заранее.
- **Claude Code больше не ставит/не обновляет IDE-расширение**, если запущен из терминала внутри самой IDE — вместо этого `/ide` снаружи терминала.
- **Read-инструмент больше не возвращает заглушку «файл не менялся с прошлого Read»** — повторное чтение всегда отдаёт содержимое.
- Self-hosted runner: `CLAUDE_RUNNER_SPAWN_REASON` в окружении хука спауна (`runner_lost`, `resumed` и т.п.); лог-строки `ok session=…`/`nack session=…` получили `reason=…` — у кого скрипты парсят `retryable=true:`/`retryable=false:`, их нужно обновить.
- Убран фикс 2.1.288, сохранявший прежний thinking при возобновлении разговора, начатого на 2.1.286 и раньше — чисто историческая уборка, затрагивает только очень старые незавершённые сессии.
- `/schedule` предупреждает, если новая облачная задача получает коннекторы, которых не просили, и объясняет, как их убрать.
