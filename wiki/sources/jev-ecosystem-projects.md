## Саммари

Пост — голый список из двадцати проектов, сделанных на API [[jev-typesafe]]. Сам по себе он ничего не утверждает, и порога полного разбора не проходил бы. Ценность появляется от другого вопроса: **на что люди тратят модель, которая умеет только сказать «да/нет с вероятностью» и ничего не умеет написать.**

Ответ оказался неожиданно близким к делу: **четыре проекта из двадцати — обвязка для агентов-кодеров**, и три из них реализуют ровно те механизмы, которые записаны в этой вики как правила. Не «похожие по духу» — те же самые, вплоть до формулировок.

Разбор сделан по репозиториям (метаданные и README через API GitHub), а не по посту.

## Четыре проекта, которые касаются нашей работы

### fast-jev-compaction — сжатие контекста удалением, а не пересказом

`tamaratran/fast-jev-compaction`, 6 167★, TypeScript, MIT. Плагин к [[claude-code]], заменяющий штатную сводку при сжатии контекста.

Формулировка задачи из README сильнее самого решения: *«Обычное сжатие контекста просит модель пересказать старые ходы. Пересказ теряет: путь к файлу, точная ошибка, ограничение или команда могут исчезнуть, даже если понадобятся позже»*. Поэтому библиотека **ничего не переписывает** — она только **удаляет** пары «вызов инструмента + результат», которые Jev признал ненужными, а всё оставшееся хранит дословно и в прежнем порядке. Текст пользователя и ассистента не трогается вовсе.

Устройство: вызовы связываются с результатами по `tool_use_id`; первое сообщение и несколько свежих закреплены и не удаляются никогда; Jev получает **всю беседу целиком**, где результаты инструментов заменены пометкой вида `ok, 4213 chars (omitted)`, и решает по этой картине.

**Это третья независимая реализация того же инварианта**, что [[deepseek-harness]], [[apache-maka]] и [[sol-pi]]: сжимать можно, **терять доказательство нельзя**. Только здесь она доведена до предела — доказательство не архивируется, а просто не трогается.

### winnow — калиброванное сито перед контекстом

`GhalebDweikat/winnow`, 62★, Python, MIT. Судит каждый крупный результат `Read`, `Bash` или `Grep` **до того, как он попадёт в контекст**: текст режется на блоки примерно по 25 строк, по каждому задаётся один вопрос «нужен ли этот блок для текущей задачи», ответы приходят пачкой за сотни миллисекунд.

Блок, который судья уверенно признал ненужным, заменяется заглушкой из трёх строк: что скрыто, короткое изложение от дешёвой модели и **ключ, по которому полный текст возвращается по требованию**. Кеш полного текста пишется **до** подмены.

Два предохранителя, и README подчёркивает, что они не отключаются:

1. если судья считает, что в выводе **ошибка** — не скрывается ничего;
2. если вероятность **неуверенная** (между порогами `WINNOW_DROP` и `WINNOW_KEEP`) — блок сохраняется.

Пороги настраиваемые, сами правила — нет. Дефолт `WINNOW_DROP = 0.1` выбран не на глаз: это корзина, которая оказалась чистой на размеченном вручную повторном прогоне, и README прямо требует поднимать порог **только со своими данными**.

Отдельно honest note автора: Jev в раннем доступе, поэтому есть запасной путь через адаптер, который задаёт те же вопросы Haiku 4.5 — *«он не калиброван, но позволяет всему конвейеру работать уже сегодня»*.

### Canny — сторож, не дающий агенту объявить работу сделанной

`qkal/Canny`, 32★, TypeScript. Цепляется хуками к [[claude-code]] и Codex CLI, ведёт **дописываемый журнал** того, что агент действительно делал, и **не даёт закончить по заявлению**.

README открывается реальным случаем: агент написал файл через heredoc, ничего не запустил и отчитался *«Done. Skipped tests — one-liner, no branch to break»*. И вывод автора, который стоит того, чтобы его привести: *«Ничто в `CLAUDE.md` не могло бы этому помешать, потому что файл правил лишь просит модель помнить, и ничто не проверяет, что она помнила»*.

Главное правило проекта — дословно:

> **Facts go to code. Judgments go to Jev. Only facts can block.**
> Факты идут в код. Суждения идут в Jev. Блокировать может только факт.

Факт — то, что доказуемо по журналу: файл изменился, команда выполнялась, вернула 1, одна и та же команда трижды упала с тем же выводом, в тексте перед записью есть ключ AWS. Это решает код, офлайн, без всякого ключа к API. Суждение — то, чего код решить не может: заявляет ли сообщение о выполненной работе, нарушает ли изменение правило «никогда не зашивать идентификаторы моделей».

**Jev никогда не блокирует.** Заявление «готово» отклоняется не потому, что вероятность перешла порог, а потому что **в журнале нет ни одной пройденной проверки** после последней правки. Нарушение правила становится заметкой в контексте агента, а не стеной. Если Jev не уверен или ключа нет — остаётся детерминированное правило. Одна и та же сессия всегда даёт один и тот же вердикт, и `canny replay` доказывает это по журналу.

### jev-codex-router — выбор модели на каждый ход

`0xNatoshi/jev-codex-router`, 201★, JavaScript, MIT. Для каждого хода Codex выбирает модель, глубину размышления и режим скорости. Тот же класс задачи, что решает лестница исполнителей в [[delegirovanie-deshevym-modelyam]], только решение принимается **на каждом ходу** и дешёвым классификатором, а не заранее и человеком.

## Берём инструмент или логику

**Инструменты — ни один из четырёх не ставим сейчас**, и по разным причинам:

- `fast-jev-compaction` и `winnow` требуют раннего доступа к Jev (внешний платный API, куда уходит содержимое работы) либо запасного пути через Haiku, а `winnow` вдобавок — включённых function hooks, то есть экспериментального механизма. Это ровно тот класс расширения, для которого у нас действует правило «установку предпочитать инспектируемую автоматической», плюс цена обслуживания.
- `Canny` ближе всех к тому, что нам нужно, и **его детерминированная часть работает без ключа вообще**. Но он ставится «вставь промпт, агент склонирует и соберёт» — способ, который сам по себе требует прочитать исходник целиком до запуска.

**Логику берём, и она ложится на уже существующее:**

1. **Сжатие — это удаление, а не пересказ.** Формулировка `fast-jev-compaction` («пересказ теряет путь к файлу, точную ошибку, ограничение») — лучший короткий довод в пользу инварианта, который у нас уже записан. Применимо прямо к своей практике ведения вики: страница, которую переписывают «покрасивее», теряет якоря к источнику; страница, из которой **удаляют** устаревшее с пометкой, их сохраняет.
2. **Порог у сита должен быть замерен, а не выбран.** `winnow` ставит дефолт по размеченному вручную повторному прогону и требует своих данных для его изменения. Это ровно то, чем у нас закончились замеры делегирования: порог оценщика калибруется на нескольких образцах разного размера, а не на одном файле.
3. **Два предохранителя, которые не отключаются:** ошибка не скрывается никогда; неуверенность трактуется в пользу сохранения. Обобщённо — **сомнение всегда толкуется в сторону сохранения доказательства**, и это правило уровня кода, а не настройки.
4. **«Только факты могут блокировать»** — формулировка `Canny` короче и точнее нашей собственной. Она сводит вместе два действующих правила: проверка спускается в код только если замкнута на результате (эвристике место в замере), и отчёт без записи не считается. Практический вывод для нашей обвязки: там, где сторож зовёт модель, чтобы решить, блокировать ли, — это не сторож; модель может только дописать заметку.

**Отдельно стоит отметить наблюдение `Canny` про файлы правил:** правила просят помнить, но ничего не проверяет, что модель помнила. У нас этот вывод уже сделан и записан как «текст правил ничего не гарантирует — гарантирует перехватчик»; внешнее независимое подтверждение усиливает его.

## Допроверка 2026-09-24: исходник Canny прочитан

Ежедневный процесс закрытия пробелов. Прямое чтение `README.md` репозитория `qkal/Canny` (`raw.githubusercontent.com`) и структуры репозитория (`github.com/qkal/Canny`), а не пересказа README со стороны — то, чего требовал пункт бэклога: что попадает в журнал, куда он пишется, что уходит наружу при наличии ключа, прежде чем инструмент вообще рассматривать к установке.

**Пять хуков, не три.** README называет `PreToolUse` (паттерн-проверки: секреты, удаление тестов, обход pipe), `PostToolUse` (запись в журнал доказательств + вызов Jev с вопросом «не нарушает ли эта правка правило X») и `Stop` (финальный гейт — проходила ли проверка после последней правки кода) как основные три, но отдельно называет ещё два: `PostToolUseFailure` (специфичный хук Claude Code) и `SessionStart` (сообщает агенту о требованиях заранее, в начале сессии).

**Журнал.** Хранится под `~/.canny/sessions/`, один файл на сессию, append-only. Дословная цитата README о том, что именно пишется: *«The session ledger keeps the command line of every shell command the agent ran, its exit code, the last line of its output, and the paths of edited files. Never file contents.»* — то есть команда, код возврата, последняя строка вывода и путь изменённого файла, но никогда не содержимое самого файла.

**Что уходит наружу при наличии ключа `TYPESAFE_API_KEY` — дословно:** *«each edit's added and removed text (clipped to 4,000 characters), the extracted project rules, and the agent's final message go to TypeSafe»*. То есть у Jev (TypeSafe) оказываются вырезки диффа правки (добавленный/удалённый текст, обрезка 4000 символов), извлечённые правила проекта из `CLAUDE.md`/`AGENTS.md` и финальное сообщение агента. **Без ключа — дословно «Nothing leaves the machine»**: работает только детерминированная часть (паттерн-проверки и журнал), как и предполагалось при разборе каталога 22.09. Отдельная деталь, которой в разборе каталога не было: даже при наличии ключа каждый запрос и ответ **кешируется на диске** под `~/.canny/jev/` — «so that text also sits on disk», то есть однажды отправленный текст остаётся локально, а не только уходит наружу и забывается.

**Установка меняет настройки Claude Code, не только файлы проекта.** Быстрая установка — та же схема «вставь промпт, агент склонирует и соберёт»: клонирование в `~/.canny/src`, `node ~/.canny/src/dist/cli.js init`, симлинк в `~/.local/bin/canny`; `canny init` регистрирует сами хуки (иначе `PreToolUse`/`PostToolUse`/`Stop`/`SessionStart` не сработают) — то есть меняет хук-конфигурацию агента, не только добавляет файлы. Снятие — `canny remove` (заявлено, дословный эффект отдельно не проверялся). Конфигурация `.canny.json` может отключать отдельные проверки (`allow`) или переводить в `strict` (блокировать бесконечно до прохождения проверки) — изменение таких полей требует `canny trust`.

**Вывод.** Вопросы пункта бэклога закрыты источником: журнал не содержит содержимого файлов, без ключа не уходит ничего, с ключом уходит ограниченный и названный набор (дифф-вырезки, правила проекта, финальное сообщение), не весь код и не полная история. Дефекта не найдено, но **инструмент не устанавливается этим прогоном** — установка меняет хук-конфигурацию Claude Code самого пользователя, а не только добавляет страницу; решение об установке, как и для мода [[jev-skill-suggestion-mod]], — за пользователем, автономная рутина инспектирует источники, не меняет свою же обвязку.

## Допроверка 2026-10-15: исходник fast-jev-compaction прочитан

Ежедневный процесс закрытия пробелов, четверг (`date -d 2026-10-15` → Thursday — обычный порядок, не воскресный). Пункт 2 бэклога «Экосистема Jev» (`fast-jev-compaction`) был помечен допроверкой 09-24 неточно: пометка «README не читан» противоречит этой же странице — раздел выше про `fast-jev-compaction` написан именно по README, прочитанному при создании страницы 22.09. Открытым оставалось другое — то, что получил `Canny` и не получил `fast-jev-compaction`: разбор исходного кода, не только README, прежде чем закрывать пункт.

Прямой `git clone github.com/tamaratran/fast-jev-compaction` (сработал без прокси). Прочитаны `README.md`, `hooks/README.md`, `hooks/fast-jev.ts`, `.claude-plugin/plugin.json`, `src/compact.ts`, `src/state.ts`, `src/request.ts`, `src/client.ts`, `src/messages.ts`.

**README подтверждён кодом без расхождений** по всем утверждениям саммари выше: привязка вызова к результату по `tool_use_id` (`collectToolCalls`); первое сообщение и `preserveRecentMessages` (по умолчанию 6) последних закреплены навсегда (`isPinned`); текст пользователя/ассистента физически не трогается механизмом удаления (`applyDecisions` правит только `toolUses`/`toolResults`); пометка кода ровно `` `${isError ? 'error' : 'ok'}, ${resultChars} chars (omitted)` `` — буквально тот же пример `ok, 4213 chars (omitted)`, что в README и в саммари.

**Нюанс, которого в разборе каталога 22.09 не было, хотя он есть в самом README (раздел Limitations) и подтверждён кодом (`fitState`, `src/state.ts`).** «Jev получает всю беседу целиком» верно только пока состояние укладывается в `maxStateTokens` (25 000 по умолчанию). Сверх лимита состояние, которое видит Jev **перед тем, как решить**, деградирует по стадиям: входы инструментов обрезаются (1000→200→60 символов), длинные тексты сокращаются до головы+хвоста с пометкой `[… N chars omitted …]`, старые сообщения целиком сворачиваются в такую же пометку, старые вызовы инструментов сжимаются в одну строку, старые сообщения без вызовов выпадают из состояния совсем, соседние вызовы схлопываются в одну запись. То есть судящая модель на длинной сессии видит не «всю беседу», а её прогрессивно урезанную версию — риск того же класса, который принцип «сжатие это удаление, а не пересказ» призван исключать, только здесь он касается не финальной истории (она действительно не искажается никогда), а входа самого судьи. README честно называет это ограничением сам (дословно: «text messages are … only abridged in the state Jev sees») — формулировка каталога 22.09 этот абзац просто не перенесла.

**Побочная находка, усиливающая открытый вопрос [[jev-skill-suggestion-mod]].** Установка как плагина Claude Code требует того же экспериментального флага `CLAUDE_CODE_ENABLE_FUNCTION_HOOKS=1`, что и мод `jev-skill-suggestion` (допроверка 09-25 там же не нашла этот флаг ни в документации хуков, ни в `env-vars`, ни в `CHANGELOG.md`). Это уже второй независимый проект — другой автор, другой репозиторий, другое событие хука (`session.compact`/`turn.complete` здесь против `prompt.attachment` там) — опирающийся на один и тот же недокументированный флаг под тем же именем: совпадение не подтверждает флаг официально (документация так и не называет его), но делает версию «опечатка или самодельное имя одного автора» менее вероятной, чем версию «реальная, просто пока не опубликованная функция Claude Code». Статус флага не меняется — не подтверждён, подозрение, что он реален, усилено.

**Внешний вызов — один, без скрытого второго канала.** Единственный сетевой путь наружу — `POST https://api.typesafe.ai/v1/systemone` с `Authorization: Bearer <ключ>` и телом `{model, state, questions}` (`buildJevRequest`); в `src/`/`hooks/` другого сетевого кода и локального кеша на диске не найдено (в отличие от `Canny`, который кеширует отправленное под `~/.canny/jev/`). Отдельно от описания каталога 22.09, представлявшего мод пассивной заменой сводки: хук `turn.complete` сам инициирует `session.compact()`, когда контекст переходит `compactAtPercent` (60% по умолчанию) — плагин не только подменяет штатное сжатие по запросу, но и сам решает, когда его запускать.

**Вывод.** Дефекта безопасности не найдено; найдена одна содержательная неточность каталога (пропущенное ограничение про деградацию состояния под лимитом токенов) и один факт, отсутствовавший в разборе 22.09 (авто-триггер по порогу контекста). Инструмент не устанавливается этим прогоном — решение то же, что по `Canny`/`winnow`, за пользователем.

## Дополнение (2026-10-12): ещё два проекта и хайп-подборка

Из инбокса пришли пост Никиты Велса «JEV — что это и с чем едят» и подборка «551 способ применить Jev». Нового о самой модели в них нет (решение «не используем» от 2026-09-22 в силе — [[jev-typesafe]]); маркетинговые цифры подборки («в 190 раз быстрее, в 440 раз дешевле», 150 тыс. в листе ожидания) не сверялись. Новые проекты, метаданные сверены по GitHub:

- `BillionsBobby/JevRouter` (459★, создан 2026-09-18) — маршрутизатор: Jev выбирает модель, инструмент или субагента для Codex, Claude Code, Cursor. Цифра поста «9 из 12 задач ушли на модель попроще, токенов меньше почти на 70%» — не проверялась. Логика уже записана в [[delegirovanie-deshevym-modelyam]] (маршрут до ответа против каскада после); у нас роль модели решений отдана локальной [[laya]].
- `wy-coliney/jev-browser-use` (1 081★) — Jev делает механику браузера (клики, переходы, прокрутка), Codex — ввод текста и проверку глазами; заявлено ускорение в 5–10 раз. **Ставится командой `npx skills add … -g -a codex -y`** — глобально и с флагом «без подтверждения», то есть чужой код исполняется до того, как его прочитали. Отрицательный урок для установки любых навыков.

Полезная мысль поста Велса — проверка «можно ли заранее выписать все возможные ответы?»: да — задача для модели решений, нет — для генеративной модели. Совпадает с тем, как мы делим ступени 0.5 и 1 лестницы.

## Проверка безопасности источника

Пост прочитан целиком, инструкций агенту не обнаружено, промо-нагрузки нет; двадцать ссылок ведут на GitHub.

Ходил: API GitHub за метаданными двадцати репозиториев, README трёх из них. Ничего не устанавливалось и не запускалось. Отмечу отдельно, что два из разобранных проектов — **хуки, встраивающиеся в поток работы агента** (`Canny`, `winnow`), а третий подменяет механизм сжатия контекста: любой из них, будучи установленным, видит всё, что видит агент. Для таких расширений одного доверия к автору мало — нужен и разбор того, что расширение делает с содержимым; ни один из трёх не проверялся на этом уровне.
