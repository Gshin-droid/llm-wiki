## Саммари

Пост — голый список из двадцати проектов, сделанных на API [[jev-typesafe]]. Сам по себе он ничего не утверждает, и порога полного разбора не проходил бы. Ценность появляется от другого вопроса: **на что люди тратят модель, которая умеет только сказать «да/нет с вероятностью» и ничего не умеет написать.**

Ответ оказался неожиданно близким к делу: **четыре проекта из двадцати — обвязка для агентов-кодеров**, и три из них реализуют ровно те механизмы, которые записаны в этой вики как правила. Не «похожие по духу» — те же самые, вплоть до формулировок.

Разбор сделан по репозиториям (метаданные и README через API GitHub), а не по посту.

## Четыре проекта, которые касаются нашей работы

### fast-jev-compaction — сжатие контекста удалением, а не пересказом

`tamaratran/fast-jev-compaction`, 6 167★, TypeScript, MIT. Плагин к [[claude-code]], заменяющий штатную сводку при сжатии контекста.

Формулировка задачи из README сильнее самого решения: *«Обычное сжатие контекста просит модель пересказать старые ходы. Пересказ теряет: путь к файлу, точная ошибка, ограничение или команда могут исчезнуть, даже если понадобятся позже»*. Поэтому библиотека **ничего не переписывает** — она только **удаляет** пары «вызов инструмента + результат», которые Jev признал ненужными, а всё оставшееся хранит дословно и в прежнем порядке. Текст пользователя и ассистента не трогается вовсе.

Устройство: вызовы связываются с результатами по `tool_use_id`; первое сообщение и несколько свежих закреплены и не удаляются никогда; Jev получает **всю беседу целиком**, где результаты инструментов заменены пометкой вида `ok, 4213 chars (omitted)`, и решает по этой картине.

**Это третья независимая реализация того же инварианта**, что [[deepseek-harness]], [[apache-maka]] и [[sol-pi]]: сжимать можно, **терять доказательство нельзя**. Только здесь она доведена до предела — доказательство не архивируется, а просто не трогается.

### winnow — калиброванное сито перед контекстом

`GhalebDweikat/winnow`, 62★, Python, MIT. Судит каждый крупный результат `Read`, `Bash` или `Grep` **до того, как он попадёт в контекст**: текст режется на блоки примерно по 25 строк, по каждому задаётся один вопрос «нужен ли этот блок для текущей задачи», ответы приходят пачкой за сотни миллисекунд.

Блок, который судья уверенно признал ненужным, заменяется заглушкой из трёх строк: что скрыто, короткое изложение от дешёвой модели и **ключ, по которому полный текст возвращается по требованию**. Кеш полного текста пишется **до** подмены.

Два предохранителя, и README подчёркивает, что они не отключаются:

1. если судья считает, что в выводе **ошибка** — не скрывается ничего;
2. если вероятность **неуверенная** (между порогами `WINNOW_DROP` и `WINNOW_KEEP`) — блок сохраняется.

Пороги настраиваемые, сами правила — нет. Дефолт `WINNOW_DROP = 0.1` выбран не на глаз: это корзина, которая оказалась чистой на размеченном вручную повторном прогоне, и README прямо требует поднимать порог **только со своими данными**.

Отдельно honest note автора: Jev в раннем доступе, поэтому есть запасной путь через адаптер, который задаёт те же вопросы Haiku 4.5 — *«он не калиброван, но позволяет всему конвейеру работать уже сегодня»*.

### Canny — сторож, не дающий агенту объявить работу сделанной

`qkal/Canny`, 32★, TypeScript. Цепляется хуками к [[claude-code]] и Codex CLI, ведёт **дописываемый журнал** того, что агент действительно делал, и **не даёт закончить по заявлению**.

README открывается реальным случаем: агент написал файл через heredoc, ничего не запустил и отчитался *«Done. Skipped tests — one-liner, no branch to break»*. И вывод автора, который стоит того, чтобы его привести: *«Ничто в `CLAUDE.md` не могло бы этому помешать, потому что файл правил лишь просит модель помнить, и ничто не проверяет, что она помнила»*.

Главное правило проекта — дословно:

> **Facts go to code. Judgments go to Jev. Only facts can block.**
> Факты идут в код. Суждения идут в Jev. Блокировать может только факт.

Факт — то, что доказуемо по журналу: файл изменился, команда выполнялась, вернула 1, одна и та же команда трижды упала с тем же выводом, в тексте перед записью есть ключ AWS. Это решает код, офлайн, без всякого ключа к API. Суждение — то, чего код решить не может: заявляет ли сообщение о выполненной работе, нарушает ли изменение правило «никогда не зашивать идентификаторы моделей».

**Jev никогда не блокирует.** Заявление «готово» отклоняется не потому, что вероятность перешла порог, а потому что **в журнале нет ни одной пройденной проверки** после последней правки. Нарушение правила становится заметкой в контексте агента, а не стеной. Если Jev не уверен или ключа нет — остаётся детерминированное правило. Одна и та же сессия всегда даёт один и тот же вердикт, и `canny replay` доказывает это по журналу.

### jev-codex-router — выбор модели на каждый ход

`0xNatoshi/jev-codex-router`, 201★, JavaScript, MIT. Для каждого хода Codex выбирает модель, глубину размышления и режим скорости. Тот же класс задачи, что решает лестница исполнителей в [[delegirovanie-deshevym-modelyam]], только решение принимается **на каждом ходу** и дешёвым классификатором, а не заранее и человеком.

Остальное — применения за пределами разработки: `semdecide` (типизированные решения для конвейеров Unix и CI), `jev-curate` (просеивание датасетов, 24 строки в секунду), `neo4jev` (обход графа Neo4j классификатором по соседним связям), `jev-drone` (дрон в симуляторе с моделью решений в контуре на 2,5 Гц), `typesafe-mario`, `OneVOneJev`, `blink` (поиск по коду), `prism-liquidity-agent`, `killmyidea`, `Canny` уже выше.

## Берём инструмент или логику

**Инструменты — ни один из четырёх не ставим сейчас**, и по разным причинам:

- `fast-jev-compaction` и `winnow` требуют раннего доступа к Jev (внешний платный API, куда уходит содержимое работы) либо запасного пути через Haiku, а `winnow` вдобавок — включённых function hooks, то есть экспериментального механизма. Это ровно тот класс расширения, для которого у нас действует правило «установку предпочитать инспектируемую автоматической», плюс цена обслуживания.
- `Canny` ближе всех к тому, что нам нужно, и **его детерминированная часть работает без ключа вообще**. Но он ставится «вставь промпт, агент склонирует и соберёт» — способ, который сам по себе требует прочитать исходник целиком до запуска.

**Логику берём, и она ложится на уже существующее:**

1. **Сжатие — это удаление, а не пересказ.** Формулировка `fast-jev-compaction` («пересказ теряет путь к файлу, точную ошибку, ограничение») — лучший короткий довод в пользу инварианта, который у нас уже записан. Применимо прямо к своей практике ведения вики: страница, которую переписывают «покрасивее», теряет якоря к источнику; страница, из которой **удаляют** устаревшее с пометкой, их сохраняет.
2. **Порог у сита должен быть замерен, а не выбран.** `winnow` ставит дефолт по размеченному вручную повторному прогону и требует своих данных для его изменения. Это ровно то, чем у нас закончились замеры делегирования: порог оценщика калибруется на нескольких образцах разного размера, а не на одном файле.
3. **Два предохранителя, которые не отключаются:** ошибка не скрывается никогда; неуверенность трактуется в пользу сохранения. Обобщённо — **сомнение всегда толкуется в сторону сохранения доказательства**, и это правило уровня кода, а не настройки.
4. **«Только факты могут блокировать»** — формулировка `Canny` короче и точнее нашей собственной. Она сводит вместе два действующих правила: проверка спускается в код только если замкнута на результате (эвристике место в замере), и отчёт без записи не считается. Практический вывод для нашей обвязки: там, где сторож зовёт модель, чтобы решить, блокировать ли, — это не сторож; модель может только дописать заметку.

**Отдельно стоит отметить наблюдение `Canny` про файлы правил:** правила просят помнить, но ничего не проверяет, что модель помнила. У нас этот вывод уже сделан и записан как «текст правил ничего не гарантирует — гарантирует перехватчик»; внешнее независимое подтверждение усиливает его.
