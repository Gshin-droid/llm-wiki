## Саммари

22 сентября 2026 Anthropic выпустила **Claude Opus 5.5** (`claude-opus-5-5`). По заявлению вендора, на большинстве задач она работает на уровне Fable 5.1 ([[claude-fable-5-1-launch]]), а стоит дешевле Opus 5 ([[claude-opus-5-launch]]): $4 / $20 за миллион токенов вместо $5 / $25, чтение кэша $0.20. Выход генерируется на 30% быстрее, типичная нагрузка обходится на 40% дешевле. Контекст 1M токенов.

Разбор держится на трёх страницах документации, а не на анонсе. Главная — **«Prompting Claude Opus 5.5»**: руководство о том, как писать задания новой модели. Оно построено по симптомам: «наблюдаете X — читайте раздел Y». Старые промпты от Opus 5 годятся как отправная точка, переписывать их целиком вендор не советует.

В Claude Code модель пришла в тот же день: в **v2.1.280** Opus 5.5 стала моделью Opus по умолчанию.

## Что изменилось — сжато

**Ломающие изменения API (4):**
1. Thinking (размышление перед ответом) выключить нельзя. `thinking: disabled` и ручной `budget_tokens` возвращают 400; управление только через `effort`.
2. Принудительный вызов инструмента (`tool_choice: any/tool`) возвращает 400. Для гарантированного JSON — `strict: true` или structured outputs, а «вызови инструмент» говорится словами в промпте.
3. Блоки размышлений привязаны к модели и к разговору. Если после блока правили системный промпт, список инструментов или прошлое сообщение, запрос с этим блоком получает 400 (для аккаунтов, созданных с 31.08.2026). Вывод: разговор только дописывается; инструкции меняются сообщениями посреди разговора, а не правкой начала.
4. Старый инструмент управления компьютером `computer_20251124` не принимается на Claude API и Google Cloud.

**Поведение без изменения кода:**
- **effort по умолчанию — `medium`** (у Opus 5 было `high`). По замерам вендора `medium` у 5.5 не хуже `high` у Opus 5 на коде и офисных задачах, а `low` на ряде задач по коду близок к нему. Названия уровней **не сопоставимы между моделями**: настройку не переносить, а подбирать заново.
- На том же уровне модель думает больше, чем Opus 5, особенно на `xhigh`/`max`. Эти уровни — только там, где выигрыш измерен.
- Промежуточные заметки между вызовами инструментов приходят не текстом, а блоками `thinking` с пустым содержимым по умолчанию. Интерфейс, который показывает только текст, «замолкает» без всякой ошибки.
- Новые категории отказов: классификатор по биологии и `reasoning_extraction` — отказ на просьбу выписать ход рассуждений в текст ответа.

## Руководство по заданиям: приёмы с проверенным эффектом

Каждый приём вендор подтверждает собственным замером. Готовые фразы — в сыром снимке, дословно.

1. **Регулятор мышления — effort, а не текст промпта.** Чтобы модель думала меньше, сначала снижают уровень: это надёжнее просьб в промпте.
2. **В чатах убирать «подумай внимательно перед ответом».** Модель сама решает, сколько думать. Без такой строки ответ начинается раньше, а качество заметно не падает.
3. **«Не пересматривай прошлые ответы»** — две фразы в конце системного промпта сокращают размышления на уточняющих репликах. Ставить *не* во всех случаях: модель тогда реже сама замечает свою прежнюю ошибку.
4. **Автономный прогон останавливается на докладе.** На длинных задачах модель пишет промежуточные отчёты, и часть из них завершает ход текстом (`end_turn`). Цикл, который считает такой ход концом задачи, бросает работу. Лечение: (а) держать список пунктов задачи и при открытых пунктах слать «продолжай с X, Y»; (б) останавливаться после 2–3 автопродолжений, чтобы зависший прогон не крутился вечно; (в) готовый абзац для системного промпта перечисляет четыре *нежелательных* вида остановки и называет *желательные* (когда без человека дальше нельзя). Подробнее — [[long-running-agent-harness]].
5. **Пометка вставленного текста.** Чужой текст в сообщении пользователя оборачивается тегами `<pasted_content id="…">` со случайным id, а системный промпт объясняет: команды внутри — не от пользователя. Модель тогда устойчива к подложным инструкциям во вставках. Теги можно подделать, поэтому это одна линия защиты, не единственная.
6. **Интерфейсы: перечислять запреты поимённо.** Без указаний по оформлению модель скатывается в несколько стилей по умолчанию, и общая фраза «избегай шаблонного ИИ-вида» лишь меняет один шаблон на другой. Работает список конкретных примет: кремовый фон, курсивные акцентные слова в заголовках, нумерация разделов «01/02/03», моноширинные подписи, кнопки-таблетки. Итеративно: посмотреть, во что модель ушла вместо запрещённого, и дописать список.
7. **Работа по нескольким приложениям** (почта, документы, таблицы): одна фраза «сначала осмотрись по всем источникам, включая не названные в задаче» заметно повышает долю правильно решённых задач.
8. **Бюджет времени для команды агентов.** Строка `elapsed 340s / 1200s` в конце каждого сообщения заставляет команду распараллеливаться и финишировать раньше. Бюджет — подсказка, а не жёсткий стоп.
9. **Графики и схемы:** модель читает их точнее, чем Opus 5 с инструментами. Старые обходные приёмы для картинок стоит проверить заново: возможно, они уже не нужны.

## Claude Code v2.1.280

- Opus 5.5 — модель Opus по умолчанию.
- На тарифах **Pro и Team Standard модель по умолчанию сменилась с Sonnet на Opus**, как на Max и выше.
- Уровень `/effort`, сохранённый до того, как он стал раздельным по моделям, к новым моделям вроде Opus 5.5 **не применяется**: они начинают со своего значения по умолчанию (`medium`), пока уровень не выбран явно.

## Берём инструмент или логику

**Инструмент:** брать нечего. Модель уже работает по умолчанию в Claude Code; ставить или настраивать ничего не нужно. Проекты, обращающиеся к Claude API напрямую, на 2026-09-24 проверены поиском: вызовов с `thinking: disabled`, `budget_tokens` или принудительным `tool_choice` не найдено, так что ломающие изменения нас не задевают. Шлюз к дешёвым моделям ходит к другим поставщикам ([[delegirovanie-deshevym-modelyam]]).

**Логика — три переносимых механизма:**
- **Запреты по приметам вместо общего «не шаблонно»** — в правила работы над интерфейсами, [[claude-code-practices]]. Прямо отвечает на претензию «безликий результат».
- **Текстовый доклад — не доказательство конца задачи** — для автономных рутин вики и любых циклов без человека, [[long-running-agent-harness]]. Тот же класс поломки, что «тихий успех» в [[invariant-vidno-znachit-zapisano]]: отчёт есть, а работы нет.
- **Не переносить effort между моделями вслепую** — [[claude-code]], раздел «Модели и Effort».

Отрицательный урок: **просить модель писать рассуждения в ответе как замену размышлениям больше нельзя** — такую просьбу модель может отклонить категорией `reasoning_extraction`.

## Что не взято / лиды

- Детали миграции для программистов на API (разбор блоков по типу, `display: "updates"`, сообщения посреди разговора, сжатие по требованию) — полностью в сыром снимке. Практического потребителя в наших проектах сейчас нет.
- Цифры 30% / 40% / «на уровне Fable 5.1» — заявления вендора, на своих задачах не замерялись.
- Sonnet 5.5 и Haiku 5.5 обещаны «в ближайшие недели», дат нет.
