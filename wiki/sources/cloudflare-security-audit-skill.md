## Саммари

Скилл, которым Cloudflare внутри компании ищет уязвимости силами агентов. Разобран вместе с пользователем: репозиторий прочитал агент-проверяющий только на чтение (инструкции внутри — данные, а не команды), два утверждения проверены запуском. Главная ценность — не сам скилл, а **механизмы**, которых обычно нет у самодельной схемы «агент ищет — другой агент перепроверяет».

## Как устроен (шесть фаз)

1. **Разведка** — четыре агента только на чтение: продукт и стек, права и границы доверия, все точки входа, что можно запускать офлайн. Итог — описание архитектуры и **журнал покрытия**.
2. **Журнал покрытия** — запись на каждое сочетание «точка входа × граница доверия × подсистема × класс атаки», у каждой записи состояние: запланировано / покрыто / кандидат / заблокировано / отложено / вне охвата. «Покрыто» без списка прочитанных путей и записи о проверке недопустимо; «отложено» и «заблокировано» — только с причиной.
3. **Охота волнами** — охотникам раздаются записи журнала; после каждой волны свежий **критик покрытия** ищет не уязвимости, а то, что никто не проверил. Волны повторяются до чистого прохода критика.
4. **Подтверждение** — каждого кандидата берёт новый агент с задачей «попробуй опровергнуть»: заново читает цитируемые строки, ищет защитный слой, при наличии песочницы воспроизводит минимальный результат.
5. **Перепроверка записанного** — ещё один новый агент проверяет уже оформленную запись, а не рассказ охотника.
6. **Отчёт** с тремя вердиктами: подтверждено / нужна проверка (с названным препятствием и безопасным планом) / отвергнуто (с причиной — следующий прогон не поднимает то же заново).

Порог находки: нужно назвать, **кто атакует, через какую границу, какой чужой ресурс страдает и что наблюдаемо происходит**. Отсутствие «лучшей практики», вред самому себе, сбой без границы доверия — не находки.

## Проверено запуском (2026-10-19)

- **Валидаторы на Windows не работают напрямую:** берут `fs.constants.O_NOFOLLOW` и `O_NONBLOCK`; в Node v24 под Windows обе константы `undefined`, и валидатор отказывается читать любой файл. Только в WSL/Linux.
- **«Один прогон находит примерно половину того, что находят повторные»** — действительно стоит в их README (раздел Design principles). Это замер самих авторов, независимо не проверен.

## Берём инструмент или логику

**Инструмент целиком — не ставим.** Дорог: в полном аудите текст справочников копируется в промпт каждого охотника и проверяющего, даже профиль `quick` дороже самодельной связки из двух агентов. Рассчитан на песочницу без сети и с лимитами, которой Windows сама не даёт; без неё скилл запрещает запуск и превращается в чтение. Валидаторы проверяют форму отчёта, а не правду (это сказано и у самих авторов): `observed_result` в подтверждённой находке может записать агент, который ничего не запускал.

**Логика — берём механизмы:**
1. **Порог находки** «нет пострадавшего ресурса — не находка, а заметка по укреплению» — режет шум до дорогой перепроверки.
2. **Форма «что проверял → что прочёл → результат»** для чистых участков и поле «заметил, но не проверил» — делает видимым непросмотренное. Это тот же принцип, что [[invariant-vidno-znachit-zapisano]]: заявить «покрыто» без записи о проверке нельзя.
3. **«Попробуй опровергнуть»** вместо «проверь» и третий вердикт «нужна проверка» с обязательным названием недостающего факта.
4. **Отпечаток причины находки** (файл :: функция :: класс атаки, без номеров строк) — сверка с прошлым аудитом поиском, а не на глаз; **хранилище отвергнутого** с причинами.
5. **Критик покрытия** — на пробу: один дешёвый агент ищет пропуски «точка входа × класс атаки».
6. Три справочника (классы атак, веб и авторизация, изоляция данных между пользователями) — как готовый список вопросов искателю.

**Что у самодельной связки сильнее:** приёмка основной сессией с запуском (у Cloudflare запускает только проверяющий и только в песочнице) и реальные сканеры рядом с агентами (у Cloudflare сканеров нет).

## Раздел про атаки на ИИ (AI-AND-LLM.md), главное

- Сама по себе prompt injection — не находка; находка — сбой в коде: чужой текст попал в контекст другого принципала, получил права, которых нет у запросившего, раскрыл недоступное.
- Ответ модели, память, описания инструментов и ответы MCP — **недоверенный ввод**.
- Ограничение в промпте — не граница безопасности; считаются только детерминированные проверки в коде, авторизация на ресурсе, изоляция, ключи с урезанными правами. Тот же вывод, что [[zabor-i-stena-prava-agenta]].
- «Растерянный заместитель» (confused deputy): агент под общим служебным ключом, обработчик инструмента не проверяет права конкретного пользователя на ресурс.
- Подтверждение должно быть привязано к полному объекту действия: одобрили одно — выполняется другое.

## Что не взято / лиды

- Цена полного прогона в токенах — авторы не называют, оценка по структуре.
- Блог Cloudflare об устройстве их внутренней системы («Build your own vulnerability harness», ссылка в README) не открывался — возможно, глубже скилла. Лид.
- Справочники для нативного кода, облака, протоколов — к вебу на Python не относятся, не разбирались.

## Оценка источника

Первоисточник производителя, открытый код, собственные оговорки авторов (валидатор проверяет форму, не правду; один прогон — половина находок). Замеры эффективности — только авторские.

## Проверка безопасности источника

Прочитан агентом-проверяющим без оболочки и сети. Опасных инструкций агенту нет — только ограничения (не трогать живые серверы, не ставить пакеты, запускать только в песочнице). Валидаторы: только `fs`, `path`, `util`; запуск процессов — лишь в тестах. Единственная установочная команда — `npx skills add …` в README; не выполнялась. Ничего не устанавливалось.
