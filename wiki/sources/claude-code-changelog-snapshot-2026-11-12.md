## Что взято в вики

1. **Code Mode (экспериментальный, по организации включается/выключается отдельно).** Вместо обычного протокола tool calls Claude в этом режиме пишет JavaScript, который сам вызывает нужные инструменты — то есть оркестрация инструментов делегируется написанному агентом коду внутри одного хода, а не повторяющимся раундам «модель просит вызов → харнес выполняет → результат обратно модели». Включается/отключается для организации через настройку, документация — отдельная страница `code.claude.com/docs/en/code-mode`, не читана целиком (ниже порога этого разбора — здесь зафиксирован только факт существования режима и его идея). Связь, которую стоит проговорить явно, чтобы не путать с другим механизмом: [[dynamic-workflows]] — это сценарий, который пишет **пользователь/Claude заранее** и который оркестрирует **множество субагентов**; Code Mode — это код, который **модель пишет сама в моменте**, чтобы вызвать **свои же инструменты** внутри одного хода. Разные уровни, разные риски (Dynamic Workflows размножает агентов, Code Mode — способ одного агента звать тулы). Дополнение сделано на [[claude-code]]; отдельного дополнения на [[dynamic-workflows]] не сделано — пересечение есть, но страница посвящена другому примитиву, и привязывать туда экспериментальную фичу без собственного разбора означало бы приписать странице то, чего в источнике нет.
2. **Лимит сообщений между сессиями (resume/continue) поднят с «около 20» до 100 000.** Это не 5-часовой/недельный лимит использования (цена токенов не меняется) — это отдельный внутренний потолок на число сообщений, которые харнес хранит/учитывает при продолжении сессии. Снятие практического потолка — у кого рабочая сессия жила подолгу через `resume`, прежний лимит иногда обрывал её историю на 20-м сообщении независимо от токенов. Дополнение на [[claude-code]].
3. **Дефолтное окно контекста для нераспознанных моделей — 1M токенов вместо 200K**, откат переменной `CLAUDE_CODE_DISABLE_1M_CONTEXT=1`. Это относится к моделям, для которых харнес не находит точного ID в своей внутренней таблице (нестандартные эндпоинты, самостоятельно подключённые шлюзы) — раньше харнес консервативно предполагал 200K, теперь оптимистично предполагает 1M. **Риск, который changelog не проговаривает явно, но который стоит записать как предупреждение:** если модель за нераспознанным ID на деле меньше 1M, харнес будет резать историю позже, чем нужно, то есть завершающие сообщения контекста могут не влезть в реальное окно модели и обрезаться незаметно для пользователя — обратное тому, что бывает с консервативным дефолтом (там недогружали контекст, но без риска тихого переполнения). Дополнение на [[claude-code]].
4. **Bash-песочница перестала доверять symlink-grant'ам, ведущим в другое место или на несуществующий путь.** *«The Bash sandbox ignores symlinked write grants that lead elsewhere or to missing paths. Grant the real path instead»* — в разделе Changed, не Bug fixes, то есть сам changelog не называет это фиксом обхода, а подаёт как уточнение поведения. По механике (разрешение на путь, данное через символическую ссылку, раньше действовало и на то, куда она фактически ведёт) это тот же класс, что серия permission-bypass, которую вики ведёт с 10-04 (ср. узел 10, 11-07: там тоже путаница «куда на самом деле идёт запись»), но formal-подтверждения номера узла в этом релизе нет — не нумеруется, фиксируется как отдельная находка на [[ai-security-by-design]] с явной оговоркой об этом отличии.
5. **`/security-review` теперь спрашивает подтверждение перед запуском**, а инлайн-команды git у скиллов не выполняются в bare-репозитории worktree без разрешения вне auto/bypass режимов. Оба — сужение автоматических действий без явного согласия, в русле общего направления вики (разбор серии bypass-фиксов). Дополнение на [[claude-code]].
6. Малое — перенесено в [[claude-code]] одной строкой без отдельного разбора: правило «don't ask again», похожее на секрет или ведущее в git-отслеживаемый `settings.local.json`, теперь живёт только в пределах сессии (не сохраняется навсегда) — прямая связь с находкой 11-09 про секреты в `settings.local.json` ([[claude-code-practices]], раздел 6в); проверка прав, упавшая после `PreToolUse`-хука с ответом «allow», теперь решается как если бы хук вообще не ответил (не доверяет частично отработавшему хуку); установка плагина/маркетплейса падает, если git-сабмодуль не на зафиксированном коммите (ещё один узел supply-chain гигиены, рядом с [[plugin4shell-vulnerability]]); удалена настройка `subagentStatusLine`, плагинная настройка `agent` deprecated.

## Берём инструмент или логику

Инструмент (сам Claude Code) в этой вики уже стоит и обновляется автоматически — вопрос «ставить или нет» не возникает. Логика, которая прямо касается того, как ведётся эта вики: лимит сообщений 100 000 снимает практическое беспокойство про обрыв долгих автономных прогонов рутин на пределе числа сообщений сессии (отдельно от бюджета подписки, который и так уже учтён правилом инкрементального коммита в `CLAUDE.md`) — ничего не меняется в `.claude/settings.json`, это не настройка, а внутренний дефолт харнеса. Про 1M-дефолт для неизвестных моделей — здесь не действует напрямую (рутины работают на управляемой инфраструктуре Anthropic, не через сторонний шлюз с нераспознанным ID), но урок переносится в формулировку на [[claude-code]]: смена консервативного дефолта на оптимистичный меняет направление риска с «недогрузили» на «тихо переполнили» — стоит иметь в виду при подключении любой модели через нестандартный эндпоинт в будущем.
