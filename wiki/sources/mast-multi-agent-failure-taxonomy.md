## Саммари

Закрывает часть пробела «Первоисточники исследований из [[berezhnitsky-agent-memory-lies]]»: источник называл это исследование на слух, без ссылки — «обзор Berkeley о причинах падения мультиагентных систем (~1500 прогонов, семь фреймворков, ~¾ падений — дизайн и рассинхрон)». Полный текст статьи (`arxiv.org`) и датасет (`huggingface.co`) заблокированы сетевым прокси этого окружения — см. «Оценка источника». Но официальный репозиторий авторов (не форк, не пересказ) содержит саму таксономию отказов текстом, а не только диаграммой из статьи.

## Что подтверждено официальным репозиторием напрямую

**Проект.** README репозитория называет работу «the first comprehensive study of MAS challenges: MAST (Multi-Agent Systems Failure Taxonomy)» с датасетом «over 1K annotated MAS traces» (LLM-annotated и human-labeled версии, доступны через HuggingFace). Библиографическая запись — arXiv:2503.13657, Cemri и соавторы, 2025.

**Полная таксономия из 14 отказов в 3 категориях** — дословно из `taxonomy_definitions_examples/definitions.txt`:

- **Category 1: Task/Role Execution Failures** — Disobey Task Specification (агент не следует ограничениям из-за нечётких инструкций или неспособности их интерпретировать); Disobey Role Specification (агент игнорирует назначенные ему обязанности); Step Repetition (лишнее повторение уже пройденных шагов из-за плохого отслеживания состояния); Loss of Conversation History (обрезка контекста откатывает агента к более раннему состоянию); Unaware of Termination Conditions (агент не распознаёт момент, когда пора остановиться, и тратит ресурсы впустую).
- **Category 2: Communication & Coordination Breakdowns** — Conversation Reset (необоснованный перезапуск диалога с потерей прогресса); Fail to Ask for Clarification (неспособность запросить нужную информацию); Task Derailment (отклонение от исходной цели); Information Withholding (критичные данные не переданы зависимому агенту, отсюда каскад отказов); Ignored Other Agent's Input (игнорирование рекомендаций другого агента); Action-Reasoning Mismatch (расхождение между заявленной логикой рассуждения и фактическим действием).
- **Category 3: Verification Deficiencies** — Premature Termination (завершение работы до фактического достижения цели); Weak Verification (неполная проверка результата); No or Incorrect Verification (проверка отсутствует или ошибочна, из-за чего ошибка проходит дальше по цепочке — пример из источника: код объявлен рабочим при том, что фактически не компилируется).

Документ отдельно подчёркивает, что именно отказы верификации особенно опасны — они пропускают ошибку дальше необнаруженной.

## Что не подтверждено первоисточником

- **Название и состав трёх категорий в самой статье могут отличаться от названий в `definitions.txt`.** По вторичным пересказам (WebSearch, не первоисточник) в статье категории называются «system design issues / inter-agent misalignment / task verification failures» — близко, но не дословно совпадает с «Task/Role Execution Failures / Communication & Coordination Breakdowns / Verification Deficiencies» из репозитория. Файл `definitions.txt`, возможно, использует более развёрнутые рабочие названия той же структуры — не установлено, требует чтения полного текста статьи.
- **Точные цифры: 1642 трассы, 7 фреймворков, kappa = 0.88, 79% отказов на «inter-agent misalignment».** Все — только из вторичных пересказов (LinkedIn, dev.to, ADS/Harvard abstract-агрегатор), ни разу не встречены дословно в доступных файлах официального репозитория — README называет только «over 1K annotated traces» без разбивки по фреймворкам и без kappa. На страницы вики как факт не переносятся.
- **Вывод «улучшение базовой модели не решает проблему».** Формулировка встречается только во вторичных пересказах, в README её нет.
- **Полный текст статьи** (`arxiv.org`), карточка датасета (`huggingface.co`), официальная страница проекта (`sites.google.com/berkeley.edu/mast/`) — все вернули `EGRESS_BLOCKED` при прямом фетче в этот заход.

## Оценка источника

Официальный репозиторий авторов (организация `multi-agent-systems-failure-taxonomy` на GitHub, та же цитата и тот же arXiv ID, что и во вторичных пересказах) — не сторонний форк. Таксономия из 14 названных отказов получена текстом файла, которым сами авторы документируют категории, а не реконструкцией по диаграмме или пересказу. Количественные результаты исследования (число трасс/фреймворков, kappa, процент отказов по категориям) подтвердить не удалось — все домены, где они могли бы быть (arXiv, HuggingFace, сайт проекта на Google Sites), заблокированы сетевым прокси этого окружения на уровне домена (`EGRESS_BLOCKED`), не 403 конкретной страницы — проблема окружения, не источника.

## Проверка безопасности источника

Прочитаны README и текстовый файл таксономии официального репозитория напрямую. Обычный исследовательский материал, инструкций, адресованных ИИ-агенту, не обнаружено.
