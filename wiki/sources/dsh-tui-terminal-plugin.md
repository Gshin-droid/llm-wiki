## Саммари

Наводка из инбокса ассистента — пост канала «Вайб-кодинг» про плагин терминального интерфейса для [[deepseek-harness]], якобы лично рекомендованный руководителем проекта. Разобран не по посту, а прямым чтением README, `package.json` и `docs/architecture.md` репозитория — пост почти ничего не искажает в цифрах, но, как обычно для этого канала, опускает ограничения (см. [[vibe-coding-channel]], четвёртый случай).

Ценность для вики не в самом плагине (DeepSeek Harness не установлен и не планируется — решение от 19.08.2026), а в двух фактах, уточняющих уже имеющуюся страницу [[deepseek-harness]]: (1) community-плагин может работать как **предкомпилированный** Cordis-плагин, устанавливаемый через обычный `npm install -g`, без пересборки `dsh` из исходников — старое утверждение страницы было точнее для исходного способа разработки плагинов, но не универсально; (2) у плагина есть экспериментальный backend на **Claude Agent SDK** — конкурирующий харнес опционально умеет говорить с моделями Anthropic через официальную библиотеку, а не только через API-ключ напрямую.

## Что взято в вики

1. **Предкомпилированный плагин не требует пересборки `dsh`.** `package.json` даёт готовый бинарник (`bin/dsh-tui.js`), а собственный `docs/architecture.md` репозитория dsh-TUI говорит прямо: *«dsh-tui 作为已编译的 Cordis 插件运行，使用宿主提供的模型路由和凭据»* — работает как уже скомпилированный Cordis-плагин, используя предоставленные хостом (главным процессом `dsh`) маршрутизацию моделей и credentials; явно сказано — **«无需重新编译源码»** («пересборка исходников не требуется»). Это не противоречит впрямую `docs/architecture.md` самого `deepseek-harness` (там плагин описан как не-исполняемый, не отдельный бинарник — *«not another executable or inline application tree»*), но показывает, что ограничение «плагины пишутся только при сборке из исходников» относится к *авторской разработке* плагина, а не к его *установке и запуску* готовым пользователем — разница, которую страница вики раньше не разделяла.
2. **Делегирование учётных данных хосту.** Dословно: *«DeepSeek 账号登录委派给宿主服务»* (вход в аккаунт DeepSeek делегирован хост-сервису) и *«DEEPSEEK_API_KEY 只应来自环境变量或受控的运行时注入»* (ключ — только из переменной окружения или контролируемой инъекции) — TUI не хранит и не запрашивает credentials самостоятельно. Разумная практика для аддона, расширяющая список примеров из [[ai-security-by-design]].
3. **Опциональный backend на Claude Agent SDK.** `package.json`: `@anthropic-ai/claude-agent-sdk` как `peerDependency` (версия 0.3.287), реализация — отдельная папка `src/backends/claude/`. Экспериментальный, не основной (основной — DSH 0.2.0-rc.2), но факт существования показывает, что чужой агентный харнес опционально подключает модели Anthropic не через голый Messages API, а через официальную встраиваемую библиотеку — косвенное подтверждение того, что Agent SDK воспринимается экосистемой как стандартный способ встраивания, а не только Anthropic-инструмент. Добавлено как заметка на [[claude-agent-sdk]].
4. **Небезопасный профиль по умолчанию — предупреждение, не найденное в посте.** README прямо называет это ограничением (не прячет): дефолтный профиль Windows-сборки использует `danger-full-access` с approval-настройкой `never` — инструменты получают неограниченный доступ к файловой системе без единого запроса подтверждения. Это прямое нарушение принципа fail-closed, которым хвалится сама документация `deepseek-harness` (см. [[habr-deepseek-harness-plugins]], раздел про песочницу) — плагин сообщества ставит менее безопасный профиль, чем рекомендует платформа, и ни разработчик, ни пост канала это не выделяют как тревожный факт, а как опцию.

## Берём инструмент или логику

**Инструмент не берём.** `deepseek-harness` сам не установлен (решение 19.08.2026 — подписка Claude Pro уже оплачена, задача не определена), ставить к нему community-плагин терминального интерфейса бессмысленно без основы.

**Логику берём частично:**
- Различие «автор пишет плагин → нужна сборка из исходников» vs «пользователь ставит готовый плагин → достаточно `npm install`» — уточнение на будущее при оценке любых плагинных экосистем агентных харнесов, не только dsh.
- Отрицательный урок: заявленный по умолчанию профиль `danger-full-access` + `never`-approval у «официально рекомендованного» плагина — напоминание, что рекомендация лидера проекта не означает проверку безопасности конфигурации по умолчанию. Применимо и к тому, как читать любые маркетинговые формулировки «рекомендовано X» в вики дальше.

## Что не взято / лиды

- **Заявление «первый среди плагинов, рекомендованных лидером DeepSeek Harness»** — цитата взята из собственного README плагина (*«Among the community plugins recommended by the official lead of DeepSeek Harness, dsh-TUI is the first»*), не из независимого источника на стороне `deepseek-ai`. Официального списка рекомендованных плагинов от `deepseek-ai` не найдено за один заход — не проверено, не заносится как факт отдельно от самоаттестации автора. Лид не заводится отдельным пунктом бэклога ввиду низкого приоритета (инструмент не используется).
- Полный список функций (пиксельный кит-талисман, timeline rail, side panel и т.п.) не переносится — маркетинговые детали продукта, который вики не ставит.
- Точная дата первого релиза и история версий — `CHANGELOG.md` в репозитории не нашёлся за один заход, не перепроверялось.
