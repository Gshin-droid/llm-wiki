## Саммари

Агент — не промпт с инструментами, а **набор артефактов в репозитории**: цель и уровень автономности, конституция, спецификация агента и его скиллов, эталонные примеры, ограничители в настройках, метрики. Каждый проходит ревью и меняется как код. Сквозной пример — агент-ревьюер PR на соответствие `spec.md` фичи, на уровне R1 (только отчёт, решает человек). Всё показано в формате Claude Code с работающим кодом: описание субагента, скрипт сборки пакета для ревью, скилл единственного действия, `settings.json`, файл эталонного случая.

Ядро совпадает с тем, что в вики уже есть на большей глубине: стена из списка инструментов ([[zabor-i-stena-prava-agenta]]), три уровня проверки ([[verification-three-levels]]), спецификация первична ([[agentic-sdlc-frameworks]]). Новое — **шкала автономности «для среды»**, **формат спецификации Spec Kit на живом примере**, **метрики качества агента** и **паттерн «действие = один разрешённый скрипт»**. Его вики раньше формулировала только как принцип.

## Что взято в вики

- **Шкала R0–R5 и шкала агентов-защитников T1–T5** (из whitepaper Сбера «AI-Disrupt PDLC» v2.0, разделы 4.3 и 4.5) → новая страница [[urovni-avtonomnosti-agenta]].
- **Метрики агента и порядок повышения автономности** (сначала снять исходный замер, доля результатов без переделок, ложные «реализовано», доля эскалаций, пороги — до запуска) → [[urovni-avtonomnosti-agenta]], [[verification-three-levels]].
- **Эталонный набор агента**: 10–20 размеченных человеком случаев плюс ловушки, сравнивает скрипт, главная цифра — ложные «реализовано»; прогон при каждом изменении конституции, скиллов или модели; инциденты возвращаются в спеку и в набор → [[verification-three-levels]].
- **Формат `spec.md` Spec Kit** на примере `pamburus/hl` (журнал уточнений → пронумерованные FR, сценарии «дано/когда/тогда» с числами, крайние случаи, измеримые критерии успеха) и **критерии приёмки в форме EARS** («КОГДА… / ЕСЛИ… ТО система ОБЯЗАНА…») → [[agentic-sdlc-frameworks]].
- **Три слоя промпта по частоте изменений** (конституция / контекст / инструкция) → [[agentic-sdlc-frameworks]].
- **Действие с последствиями — через один скрипт, который сам проверяет входы**; в скилле `allowed-tools: Bash(${CLAUDE_SKILL_DIR}/scripts/... *)` разрешает ровно его → [[zabor-i-stena-prava-agenta]], [[claude-code]].
- **MCP против своего API-скрипта против CLI** и пять правил работы через CLI (разрешать префиксы команд, отдельный токен с минимальными правами, `--json` и ограничение вывода, вывод — данные, действия — в скрипт) → [[ai-security-by-design]].
- **Инцидент Replit** (июль 2025, AI Incident Database № 1152): агент удалил продовую базу во время объявленной «заморозки кода» и неверно сообщил, что отката нет. Запрет был только текстом, проверял агента он сам → [[ai-security-by-design]].
- **superpowers v6.4.1**: пять раундов «исправление + повторное ревью», 1–3 — прежний исполнитель, 4–5 — новый на модели сильнее; журнал решений (`Ruling`). Сверено через `gh` с коммитом `5bf4e78` (выпуск v6.4.1, 19.09.2026) → [[superpowers]].
- **Признаки отбора чужого скилла** (активность, лицензия, узость цели, права, наличие собственных evals, способ установки) и каталог `addyosmani/agent-skills` → [[claude-skills]].

## Берём инструмент или логику

**Инструмент.** Spec Kit не ставим: его работу у нас уже делают [[superpowers]] (brainstorming → spec → plan) и [[mattpocock-skills]]. Второй процессный набор — лишний процесс без новой способности. Берём **формат** его `spec.md` как образец для спецификаций. Код статьи (ревьюер, `review-package.sh`, скилл публикации) — образцы, не ставятся. Отдельно: **superpowers обновить до 6.4.1**. У нас стоит 6.1.1, и в ней нет правила пяти раундов. Решение пользователя 21.10 — обновить.

**Логика — что и куда:**
- Агента собирать как набор файлов: цель одним предложением, уровень R, `tools` белым списком, `maxTurns` и `effort` в описании, эталонный набор, метрика «ложное готово». Это легло в основу метода создания агентов для своих проектов (FinApp и далее).
- Наши агенты-проверяющие получили `maxTurns` и `effort` (21.10, решение пользователя). Журнал исполнителей — графу «ложное "готово"».
- Состязательная установка проверяющего — **мягкая форма**: «перечисли, что проверил и не нашёл», а не квота «найди не меньше пяти расхождений» (EPAM). Квота толкает выдумывать находки, а лишнее у нас отсеивает слепой перепроверяющий и проверка запуском. Решение пользователя 21.10.
- Для внедрения ИИ в организации — шкала R0–R5 и метрики как язык разговора «сколько свободы даём и чем докажем пользу».

## Что не взято / лиды

- **«После 20+ подтверждений за сессию точность падает с 85% до 55%»** (статья ссылается на Anthropic через whitepaper Сбера). Первоисточник не найден. **Противоречит по цифрам** первичным данным Anthropic, уже разобранным в [[claude-code-auto-mode-safety-data]]: там человек ловит опасный запрос в ~17% случаев в начале сессии и ~5% после 50 запросов. Направление то же — внимание падает с длиной сессии; числа другие. Пункт в бэклог.
- **Whitepaper «AI-Disrupt PDLC»** (Сбер, 175 стр.) — первоисточник обеих шкал, evals эскалаций, Evidence Bundle. Отдельный разбор, под задачу внедрения ИИ в организации → бэклог.
- **Статья EPAM** про рой агентов с одной ответственностью и состязательных ревьюеров (апрель 2026) → бэклог.
- `--max-budget-usd` и командные метрики (время до ревью, стоимость на PR) — для запусков по API-ключу в CI и для команды. У нас подписка и один человек. Применимо при внедрении в организации с доступом по API.

## Оценка источника

Практичный и проверяемый. Код рабочий и с лицензиями. Фрагменты чужих репозиториев процитированы с коммитом. Утверждение про superpowers, которое при первом чтении показалось ошибкой, подтвердилось на указанном коммите — расхождение было в нашей устаревшей версии. Слабое место — шкалы и цифры даны со слов whitepaper Сбера, без собственной проверки; числовых порогов перехода между уровнями нет. Клип содержит шум Хабра: «Объяснить с» в конце каждого блока кода; схема архитектуры — только картинкой.

## Проверка безопасности источника

Инструкций, обращённых к агенту-читателю, нет. Код примеров — bash и конфигурация, ничего не запускалось. `curl | bash` упомянут только как плохой признак при отборе скиллов.
