## Саммари

Ярус 2 рутины 1 (новости), следом за сводкой [[novosti-2026-11-22]]. Две версии с прошлого снапшота [[claude-code-changelog-snapshot-2026-11-19]], который разобрал 2.1.326–2.1.328 — 328 вышла 19.11, и 329 вышла тем же днём, но следом и за кромкой того разбора. Главное здесь не очередной узел серии permission-bypass, а изменение, касающееся напрямую инфраструктуры, на которой держатся все три автономные рутины этой вики: горизонт жизни scheduled tasks и `/loop` выращен с 7 до 30 дней. Рядом — разнонаправленная пара по безопасности тем же релизом: Code Mode **ослабляет** контроль за упавшим хуком, `rm`-защита в ту же версию, наоборот, **ужесточается**.

## Что взято в вики

1. **Scheduled tasks и `/loop` теперь живут до 30 дней вместо 7 (2.1.330, 20.11) — прямая релевантность рутинам этой вики.** Цитата: *«Recurring scheduled tasks and `/loop` now run up to 30 days instead of 7 while their session keeps running.»* Три автономные рутины CLAUDE.md (`jarvis-wiki-news`, `jarvis-wiki-practical-scout`, `jarvis-wiki-gaps-backlog`) — это и есть scheduled tasks/Cloud Routines, то есть изменение касается именно того механизма, на котором стоит вся автоматизация вики. **Важная оговорка той же строки**: *«Tasks created before this release still end at 7 days»* — старые задачи не получают новый горизонт автоматически, нужно пересоздание расписания. Непонятно без проверки, когда (и получат ли) три рутины этой вики новый горизонт — это не факт о самих рутинах, а факт о платформе; добавлено наблюдением к открытому пункту `wiki/gaps-backlog.md` (см. «Связи»), не как закрытие вопроса.
2. **Сохранённые scheduled tasks из старых версий обычно требуют пересоздания расписания в новых залогиненных сессиях (2.1.329, 19.11).** Цитата: *«Saved scheduled tasks from earlier versions mostly need scheduling again in new signed-in sessions. `--resume` of their own session still runs them.»* То есть расписание переживает `--resume` собственной сессии, но не гарантированно переживает новый вход. Для рутин этой вики прямых последствий без проверки на практике не выводится — записано как факт платформы, не как диагноз.
3. **Code Mode больше не блокирует вызов тула скрипта при упавшем PreToolUse-хуке — ослабление, не фикс (2.1.329).** Цитата: *«Code Mode no longer refuses a script's tool call when a PreToolUse hook errors. Set `"onFailure": "block"` on hooks that must block.»* Раньше ошибка хука перед вызовом инструмента останавливала выполнение по умолчанию (fail-closed); теперь по умолчанию она пропускается (fail-open), и чтобы вернуть прежнее поведение, на хук нужно явно поставить `onFailure: "block"`. Это смена дефолта в сторону меньшей защиты — тема [[ai-security-by-design]], дополнение ниже.
4. **Встречное ужесточение той же версией (2.1.330): больше `rm`-команд, направленных на корень, домашнюю папку, верхнеуровневые папки или саму рабочую папку, теперь спрашивают подтверждение — а где спросить некого, отказывают.** Цитата: *«More `rm` commands aimed at the root, home, top-level folders or the working folder now ask for approval. Where nobody can answer, they are refused.»* Продолжение линии, разобранной на [[claude-code-critical-path-rm-docs]] и в узлах серии permission-bypass — но здесь сам changelog не нумерует это узлом, как и в нескольких прошлых снапшотах подряд.
5. **Прочее, взятое кратко.** 2.1.330: вход в организации Enterprise Admin Console (`claude auth login` подхватывает настройки организации и её cloud-провайдера/гейтвей); встроенный мод **Easel** — автоматически рисует графики по результатам MCP-метрик (Pro/Max/где доступно Team/Enterprise, macOS/Linux), отключается в `/config`; `claude --teleport` может печатать git-команды переключения веток вместо их выполнения. 2.1.329: Computer use на macOS использует более новые правила безопасности (часть действий отказывается, часть приложений получает меньший доступ); auto mode для Opus/Sonnet 4.6 у сторонних провайдеров подтверждён не отдельными случаями, а общим правилом (ранее заявленным частями в 2.1.326/328, разобрано в [[claude-code-changelog-snapshot-2026-11-19]]) — здесь это уже устоявшееся поведение, не новая находка.

## Берём инструмент или логику

**Инструмент** уже стоит — Claude Code — движок этой вики, решение по установке принято задолго до этого разбора.

**Логика.** Два механизма переносимы прямо на практику ведения вики: (1) горизонт автоматизации — платформа отныне формально разделяет «жизнь сессии» (до 30 дней) от «жизнь расписания», и это стоит знать при диагностике, если одна из трёх рутин вдруг не отработает в срок — первый вопрос не «сломалась рутина», а «не истекло ли расписание на стороне платформы»; (2) пример fail-open/fail-closed смены дефолта без переименования в «фикс» (Code Mode, пункт 3) — тот же урок, что уже сформулирован на [[ai-security-by-design]] про предыдущие сужения: каждая новая версия харнеса может незаметно сдвинуть дефолт в любую сторону, не только в сторону ужесточения, и единственная защита — читать changelog предметно, а не полагаться на общее направление «вендор обычно укрепляет безопасность».

## Что не взято / лиды

Основной объём 2.1.329 (14 улучшений + 91 фикс: `~/.claude.json` сбрасывался, повторные выходы из macOS Keychain, `/rewind` восстанавливал старые версии файлов) и 2.1.330 (14 улучшений + 98 фиксов: зависания после сжатия долгих разговоров, подвисания `WebFetch`, удаление worktree при параллельных сессиях, несколько проблем ввода в VS Code) — платформенные детали ниже порога для этой вики. Новые self-hosted runner метрики (`claude_code_self_hosted_runner_order_to_registered_seconds` и аналоги) и флаг `--start-dir` — не используются (self-hosted runner у этой вики не настроен). VS Code-специфика (`/fork`, `/workflows`, `claudeCode.pinPrompt` и другие настройки) — релевантна пользователям VS Code-режима, здесь не практикуется предметно.
