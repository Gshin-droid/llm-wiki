## Саммари

Разбор одного вопроса: как превратить скилл-однофайловик в многофайловую структуру. Четыре «апгрейда» поверх базового скилла, показанные на сквозном примере (сборщик новостей → дайджест в Notion → пост в Telegram):

1. **Ресурсы в отдельный файл** — список источников выносится из инструкции; ключевая фраза в промпте «перед сбором сначала прочитай файл с источниками» (автор называет это progressive disclosure).
2. **Логику в скрипт** — обход сайтов уходит в Python-файл: предсказуемо, одинаково, дешевле по токенам.
3. **Правила в отдельные файлы** — фильтры и шаблоны в свою папку; главный файл — «карта, а не энциклопедия». Отдельно подчёркнуто: в промпте надо явно запретить дублировать вынесенные правила обратно в SKILL.md, иначе Claude скопирует их «на всякий случай» и архитектура развалится.
4. **Связь с внешним миром** — запись в Notion через коннектор и вызов другого, уже существующего скилла (пост в Telegram).

Сквозная техника — **метапромтинг**: попросить Claude составить промпт для того, в чём не разбираешься, потом отдать результат в новый чат.

## Проверка валидности (2026-07-29, по официальной документации)

Проверялось против [Creating custom skills](https://claude.com/docs/skills/how-to), [Extend Claude with skills](https://code.claude.com/docs/en/skills), [Help Center: how to create custom skills](https://support.claude.com/en/articles/12512198-how-to-create-custom-skills) и [agentskills.io](https://agentskills.io/skill-creation/evaluating-skills).

**Подтверждено:** структура `SKILL.md` + `references/` + `scripts/` + `assets/`; правило «SKILL.md < 500 строк»; progressive disclosure как принцип; скрипты как детерминированная замена ручной работы модели (официально поддерживаются Python/JS/Bash); композиционность («Claude can use multiple skills together automatically»); внешние сервисы через MCP-коннекторы. Всё это уже описано в [[skill-authoring-practical-rules]] — метод видео является корректным, но урезанным подмножеством официальной методологии.

**Устарело.** Центральная жалоба видео (11:20, «час за кадром») — «с уровня чата нельзя дописать файл в существующий скилл, надо удалить и пересобрать весь скилл целиком» — на момент проверки неверна. Официальная справка описывает правку на месте: выделить текст → **Edit with Claude** → сформулировать правку; для многофайловых скиллов правки по разным файлам отправляются вместе и применяются за один проход; новые файлы просто добавляются в директорию скилла. Точную дату изменения установить не удалось (справка не датирована) — зафиксирован факт на 2026-07-29, не момент перехода.

**Не подтверждено.** Формат `.skill` и кнопка «Save Skill в один клик». Официально документирована только упаковка в ZIP, причём архив должен содержать **папку** скилла (`my-skill.zip → my-skill/SKILL.md`), а не файлы в корне. Занесено в `wiki/gaps-backlog.md`.

**Неточность.** «По умолчанию Claude делает JSON — это его стандарт»: никакого стандарта нет, формат ресурсного файла выбирает автор скилла.

**Контекст времени.** В видео «сегодня вышел Opus 4.8»; актуальная дефолтная модель — Opus 5 с 24.07.2026 (см. [[claude-opus-5-launch]]). На архитектуру скиллов не влияет.

## Чего в методе нет (пробелы против официальной методологии)

- **Description как единственный триггер** — не упомянут вообще, хотя именно от него зависит, подхватится ли скилл. Плюс не названо ограничение claude.ai в 200 символов (спецификация допускает 1024) — перенесено в [[skill-authoring-practical-rules]].
- **Eval-цикл** — проверка «работает же» одним прогоном вместо прогонов со скиллом и без (baseline), ассершенов и дельты по pass rate/токенам. Самый крупный пробел.
- **`skill-creator`** — официальный плагин, автоматизирующий ровно тот цикл, который в видео заменён метапромтингом и интуицией.
- **`dependencies` во frontmatter** — если скрипт тянет pandas/matplotlib, зависимости объявляются там; без этого скрипт упадёт у любого, кому скилл передан.
- **Gotchas и накопление по сессиям** — скилл как живой документ, а не разовая генерация.

## Оценка источника

Формат — для не-разработчиков, кода почти нет. Архитектурная часть верная и хорошо объяснённая, инженерной (тестирование, эволюция скилла) нет вовсе. Ценность для этой вики — не новые факты, а два уточнения, найденных при проверке утверждений видео (лимит 200 символов и правка на месте вместо пересборки), и наглядная иллюстрация уже описанных принципов.

Отдельно полезен приём, которого в вики не было явно: **при выносе чего-либо в отдельный файл нужно явно запрещать модели дублировать вынесенное обратно в главный файл**.

## Проверка безопасности источника

Транскрипт прочитан целиком. Инструкций, адресованных агенту, не обнаружено. Материал плотно упакован промо (Ko-fi, PayPal, партнёрские ссылки на технику) — на техническую часть не влияет. Обещанный «готовый шаблон промпта» раздаётся через закрытый Telegram-канал: проверить его содержимое до использования нельзя, в вики не берётся.
