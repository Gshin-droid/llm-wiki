## Саммари

Оркестратор агентов кодинга. Задача проходит граф шагов: агент-автор пишет код, затем отдельные агенты-проверяющие (приёмка по задаче и ревью кода, параллельно) выносят вердикт; провал возвращает работу автору с причиной. Девиз проекта — «агент, написавший код, не должен сам говорить, что он работает». Это наше правило «приёмка не автором» ([[verification-three-levels]]), собранное в программу. Агентами служат уже установленные Claude Code, Codex, Copilot CLI или Pi со своим входом; на каждый шаг можно поставить свою модель. Бесплатно для одного прогона за раз; облако — платное, нам не нужно.

Главное на странице — **своя проба, четыре прогона**, а не описание с сайта.

## Проверка кода до установки

Репозиторий прочитал проверяющий без сети и оболочки, главное перепроверено по исходникам:

- Телеметрии нет; в облако ничего не уходит без явного `--target cloud`; скачанный бинарник сверяется по SHA256 (сумма лежит в том же релизе — защита от порчи, не от взлома автора).
- **Главный подвох:** если zeroshot не находит у Claude Code настроек прав, он запускает его с `--dangerously-skip-permissions` (`zeroshot/src/native_v2_claude/permissions.rs`). Режим `auto` в настройках считается «заданной политикой» — флаг не ставится; по журналам сессий проб все агенты шли в `auto`.
- Изоляции по умолчанию нет: агенты правят папку на месте. Без `--push`, `--pr`, `--ship` в git ничего не уходит.
- Установщик кладёт свой скилл в `~/.claude/skills/zeroshot` и `~/.agents/skills/zeroshot`; `npm uninstall` их не удаляет.
- Не проверено: соответствие собранного бинарника исходнику, зависимости, веб-интерфейс.

## Проба: четыре прогона в песочнице WSL

Поставлен в среду WSL с песочницей Claude (запись только в папку запуска, диск C: только чтение) от пользователя без прав администратора — `npm install -g --prefix ~/.local`. Шаблон `software-change`: автор → приёмка + ревью кода.

| № | Задача | Автор | Проверяющие | Итог | Возвратов |
|---|---|---|---|---|---|
| 1 | учебная: разбор «1h30m», 8 ловушек ввода | Sonnet 5.5 medium | Sonnet 5.5 medium | моих 25 ловушек — 0 провалов | 0 |
| 2 | учебная, сложнее: миллисекунды («ms» ≠ «m»+«s»), обратная функция | Haiku 5.5 low | Sonnet 5.5 medium | 48 ловушек + 20 000 проверок «туда-обратно» — 0 провалов | 0 |
| 3 | настоящая доработка в копии своего Telegram-ассистента: первый JSON из ответа модели, отказ при времени в прошлом, часовой пояс; общая функция у двух модулей | Haiku 5.5 low | Sonnet 5.5 medium | 43 теста, мои 17 ловушек — 0 провалов, вызовы обновлены | 0 |
| 4 | то же + два легко упускаемых требования (журнал каждого отказа, раздел README) | Haiku 5.5 low | Sonnet 5.5 medium | оба выполнены, с тестом на запись в журнал | 0 |

Расход за прогон — от ~200 до ~640 тыс. токенов (в основном чтение кэша), вывод 2–12 тыс.

**Что увидели:** установка, распределение моделей по шагам, режим прав, параллельные проверяющие, отсутствие отправки в git — работают. Проверяющие неглубоки: в каждом прогоне один ограничивался диффом и тестами автора, свои пограничные случаи писал не каждый раз; один раз проверяющий сверил всех вызывающих изменённую функцию. Поведенческое следствие правки (бот теперь отказывает на «напомни сегодня» днём, т.к. модель ставит 09:00) не заметил ни один — заметила основная сессия, читая обработчик.

**Чего не увидели — возврата на доработку.** За четыре прогона автор ни разу не ошибся, даже самая дешёвая модель на низком уровне рассуждений. Поэтому ради чего инструмент существует — ловит ли проверяющий ошибку автора — на наших задачах проверить не удалось.

## Берём инструмент или логику

- **Инструмент — не берём в постоянную работу.** На задачах нашего размера (небольшая доработка с тестами) автор не ошибается, и вторая пара глаз за ~2–3× расхода ничего не поймала. Остаётся установленным в песочнице WSL для пробы на крупной задаче; удаление — `npm uninstall -g` от пользователя песочницы и две папки скилла.
- **Логика — берём:**
  1. «Приёмка не автором» как граф с обязательным возвратом — та же мысль, что в нашей связке «искатель + перепроверяющий», но автоматическая. Переносить имеет смысл туда, где автор реально ошибается: крупные многомодульные задачи, а не функция с тестами.
  2. Проверяющий без отдельного задания проверяет мелко (дифф + тесты автора). Если ставить проверяющего — давать ему в наряд **свои** проверки (вызовы, пограничные случаи, поведение для пользователя), а не «посмотри».
  3. Для карты исполнителей ([[delegirovanie-deshevym-modelyam]]): Haiku 5.5 на низком уровне рассуждений трижды подряд без ошибок сделал небольшую чётко описанную доработку с тестами.
  4. Чужой оркестратор агентов проверять на флаг обхода разрешений: тихо включённый `--dangerously-skip-permissions` — обычная форма удобства.

## Что не взято / лиды

- Проба на крупной задаче (несколько модулей, где автор ошибётся) — открыта; без неё вывод о механизме возврата неполон.
- Свои графы (шаг оценки риска, ревью безопасности для платежей и миграций) — не пробовали.
