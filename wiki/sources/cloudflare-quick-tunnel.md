## Саммари

Одна команда выдаёт локальному серверу публичный HTTPS-адрес:

```
cloudflared tunnel --url http://localhost:8000
```

Cloudflare поднимает случайный поддомен на `trycloudflare.com` и проксирует на него трафик. **Аккаунт не нужен, оплата не нужна, порты на роутере открывать не нужно** — соединение исходящее, инициирует его сама машина.

Пост-наводка состоит из одной команды, и она верна. Разбор сделан ради того, чего в посте нет: **официальных границ применимости**, без которых инструмент попадёт не туда, где он уместен.

## Границы, названные Cloudflare дословно

- *«Quick Tunnels are intended for testing and development only»* — только для тестирования и разработки.
- *«We don't guarantee any SLA or uptime of TryCloudflare — we plan to test new features on these free tunnels»*: гарантий доступности нет, и на этих бесплатных туннелях Cloudflare сама обкатывает новые функции.
- Жёсткий лимит: **200 одновременных запросов**, сверх них — код `429`.
- **Server-Sent Events не поддерживаются.** Для потоковой отдачи (а это обычный способ стримить ответы модели) быстрый туннель не годится.
- Адрес **случайный и новый при каждом запуске**: туннель перезапустили — прежняя ссылка мертва.

Для постоянного адреса и гарантий существуют **именованные туннели** (named tunnels) — они требуют аккаунта Cloudflare и своего домена. Быстрый туннель их не заменяет, а служит пробником.

## Где это применимо на практике

Четыре задачи, где быстрый туннель закрывает реальную дыру:

1. **Показать работу заказчику или коллеге**, не выкладывая на хостинг. Живёт столько, сколько открыт терминал.
2. **Вебхуки.** Сервис, которому нужно постучаться в наш код (платёжный шлюз, Telegram, GitHub), не может обратиться на `localhost`. Быстрый туннель даёт адрес для вебхука на время отладки.
3. **Проверка с телефона** — настоящий мобильный браузер вместо режима эмуляции в десктопном.
4. **Доступ ИИ-агента к локальному приложению** — назван в посте-наводке; частный случай вебхука.

**Особый случай, который стоит назвать отдельно: Telegram-бот на опросе.** Бот, работающий опросом (`getUpdates`), не требует публичного адреса — и потому его вебхучный режим обычно не проверяется вовсе до самой выкладки. Быстрый туннель позволяет один раз прогнать боевой путь «Telegram → вебхук → наш обработчик» заранее, на своей машине. При этом **адрес меняется при каждом перезапуске туннеля**, поэтому вебхук придётся переустанавливать всякий раз — для разовой проверки нормально, для постоянной работы нужен именованный туннель или хостинг.

## Безопасность: что именно открывается

Туннель публикует наружу приложение целиком, без какой-либо аутентификации со стороны Cloudflare. Ссылку случайную, но угадываемой её считать нельзя — она уходит в логи, в мессенджер, в историю браузера.

Отсюда три правила, вытекающие из уже принятых в вики:

- **Открывать только то, что переживёт чужой запрос.** Отладочная панель, доступ к базе без пароля, включённый режим отладки фреймворка — всё это станет публичным на время туннеля.
- **Не оставлять туннель открытым дольше задачи.** Закрыт терминал — закрыт доступ; это хорошее свойство, и им стоит пользоваться намеренно.
- **Секреты остаются секретами.** Приложение с отключённой в целях удобства проверкой прав выставляется наружу ровно в таком виде — см. [[ai-security-by-design]] и [[vibecoding-app-security]].

## Что взято в вики

1. Новая сущность [[cloudflare-tunnel]] — команда, границы, отличие быстрого туннеля от именованного.
2. Четыре применимых задачи и случай «проверить вебхук бота, работающего опросом» → туда же.
3. Ограничения как факты, а не мелким шрифтом: 200 одновременных запросов, отсутствие SSE, нестабильный адрес, отсутствие SLA, «только для разработки».

## Что не взято / лиды

- **Установка `cloudflared` не разбиралась** — ни способ установки на Windows, ни версия, ни требования. Лид в [[gaps-backlog]].
- Именованные туннели (постоянный адрес, свой домен, политики доступа Cloudflare Access) в вики не разобраны — только упомянуты как то, чем быстрый туннель не является.

## Оценка источника

Официальная документация — высшая ступень доверия, прочитана напрямую.

Пост-наводка на одну команду: команда верна, применения названы точно (вебхуки, демонстрация клиенту, превью, доступ агента). Не названо ничего из ограничений — ни «только для разработки», ни лимит 200 запросов, ни отсутствие SSE, ни смена адреса при перезапуске. Для поста из трёх строк это ожидаемо; в вики они и есть главная ценность разбора.
