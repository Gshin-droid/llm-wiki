## Саммари

Пост — личный отзыв («я протестировал много скиллов, и последний из них...») о скилле `planning-with-files` для Claude Code: три файла (`task_plan.md`, `findings.md`, `progress.md`), которые агент держит перед глазами весь план и выполнение, вместо стандартного plan mode, — и за счёт этого «дрейф почти пропадает». Установка — одна команда `npx skills add`. Ценой названо больше токенов.

Пост взят рутиной практик (не новостей): вопрос «как этим пользоваться», а не «что вышло» — критерий разделения тем из `CLAUDE.md`. Это тот же класс материала, что [[geekneural-sepia-de-ai-skill]] две недели назад — голая наводка без ссылки, инструмент настоящий и заслуживает разбора по первоисточнику, а не по пересказу.

**Официальный репозиторий прочитан напрямую** (`github.com/OthmanAdi/planning-with-files` — главная страница, `README.md`, канонический `skills/planning-with-files/SKILL.md`, `CHANGELOG.md`, все через `raw.githubusercontent.com/.../HEAD/...` и обзор структуры репозитория). Пост подтвердился и оказался **преуменьшением**: заявленный механизм — лишь верхний слой, у инструмента ещё есть hash attestation против порчи плана, gated/autonomous режимы v3, оптимизация задержки хука под prompt cache и заявленные (не независимо проверенные) бенчмарки восстановления после обрыва сессии.

## Что не взято / лиды

- **Независимая проверка заявленных цифр (96,7%, 3/3, 5,0 против 13,3 хода)** не проводилась — методология замера, состав тестового набора и дата (замер на Claude Sonnet 4.6, март 2026 — уже не последняя модель семейства на дату этого разбора) не позволяют перепроверить самостоятельно без установки инструмента и повторения прогона. Записано как открытый лид, не как факт.
- **Установка на машину пользователя не делалась.** Разбор — чтение репозитория, не эксплуатация; вопрос «работает ли это так же хорошо в Claude Code конкретно этого пользователя» остаётся открытым.
- **Число звёзд/форков (26,7 тыс./2,2 тыс.)** взято с текста главной страницы репозитория при её просмотре, не через прямой запрос к GitHub API (репозиторий стороннего автора вне разрешённого для этой сессии списка `add_repo`, доступны только публичные страницы и `raw.githubusercontent.com`) — оставлено с этой оговоркой на странице сущности.
- **Сравнение с GSD/Superpowers** (свои файловые/spec-driven агентские фреймворки, уже разобраны на [[agentic-sdlc-frameworks]]) не проводилось содержательно — только упомянуто в связях `planning-with-files` как родственный класс инструментов, требует отдельного разбора при следующей возможности.

## Оценка источника

Пост — личный отзыв без ссылки и без единой проверяемой детали механизма (в отличие от обещаний в посте про Sepia, здесь нет искажённых цифр — просто нет цифр вовсе, только впечатление «работает в 99% случаев», не подтверждаемое и не опровергаемое). Инструмент за наводкой оказался настоящим: MIT, активно поддерживается (релиз в день разбора), с описанной механикой, которая заметно шире одного абзаца поста. Презумпция для будущих постов этого же анонимного отправителя ассистента: наводка на реальный, стоящий проверки инструмент, но без единой технической детали, которой можно доверять без первоисточника — то же, что уже установлено для [[geekneural]].

## Проверка безопасности источника

Пост прочитан целиком. Инструкций, адресованных агенту, не обнаружено — обычный личный отзыв, реклама отсутствует (не канал, а пересланное личное сообщение).

Отдельно: при разборе читался **чужой скилл** — файл, целиком состоящий из инструкций агенту (`SKILL.md` и его варианты под разные хосты). Читался как данные через `raw.githubusercontent.com`/поиск по коду GitHub, не исполнялся и не подключался к этой сессии, на машину не ставился. Содержимое не подозрительно — наоборот, frontmatter `description` необычно детально описывает собственные границы безопасности инструмента (нет пути загрузки в сеть, чтение сессий ограничено тем же проектом и агрегатами, gated mode не исполняет команды из markdown) — зафиксировано на странице [[planning-with-files]] как заметная деталь, а не как гарантия: сам факт декларации в описании не проверялся независимым аудитом кода хуков.

Хождение по ссылкам: только `github.com/OthmanAdi/planning-with-files` и файлы репозитория через `raw.githubusercontent.com` и поиск по коду GitHub. Внешние ссылки из самого поста и из README не открывались за отсутствием необходимости.
