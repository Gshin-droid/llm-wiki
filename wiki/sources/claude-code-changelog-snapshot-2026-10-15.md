## Находка 1: восьмой узел серии bypass-фиксов — песочница плагинов и MCP-редиректы

1. *(2.1.299)* «Fixed a sandboxed shell command being able to write into a `--plugin-dir` folder, whose code Claude Code reloads and runs outside the sandbox» — сандбоксированная shell-команда могла дописать файл в папку, заданную флагом `--plugin-dir`; код из этой папки харнес перезагружает и исполняет уже **вне** песочницы. Класс ровно тот же, что у находок шестого узла (10-07): не прямой обход правила, а путь, который анализатор не распознал как рычаг повышения привилегий — здесь рычаг не файловая система вообще, а конкретно папка плагинов, чьё содержимое получает привилегию запуска без песочницы по самому назначению механизма.
2. *(2.1.300)* «Changed requests to claude.ai's connector proxy and to Anthropic-hosted MCP servers to no longer follow HTTP redirects» и отдельно «Changed MCP requests in cloud and self-hosted runner sessions to no longer follow HTTP redirects from the session's MCP proxy» — до фикса ответ стороннего сервера с кодом редиректа мог увести запрос (вместе с тем, что в нём передано) на другой адрес; защита — не валидация адреса редиректа, а полный отказ следовать редиректам от этого класса прокси. Переносимый принцип для любой обвязки, проксирующей вызовы к внешним сервисам от имени агента: редирект — канал, которым управляет чужая сторона, а не твой код.
3. *(2.1.300)* «Changed MCP allow rules to reach only the server they name: `mcp__a` no longer allows a server named `a__b` or `a_`» — правило разрешения `mcp__<server>` раньше матчило по префиксу строки, а не по имени сервера целиком; сервер с похожим, но другим именем попадал под то же разрешение. Precision-фикс: сузили совпадение с «начинается с» до «равно».

**Что это значит практически.** Находка 1 — прямое продолжение риска Claude Mods/плагинов, который эта серия ведёт с 08-31 (путь плагина обходил проверки контейнмента) и с 10-04 (сам механизм Mods назван с предупреждением вендора «ставить только из доверенных источников»): здесь предупреждение получило ещё один конкретный механизм, почему оно не формальность. Находки 2 и 3 — новый для серии технический контекст (MCP-прокси, не файловый анализатор), но тот же принцип: защита по умолчанию должна быть у́же, чем кажется разумным, а не шире.

## Находка 2: тихий пропуск шага у Dynamic Workflows-агентов — не bypass, а дыра в отчётности

*(2.1.301)* «Fixed workflow agents sometimes skipping their step, and the run still reporting success, after reading the harness note that their task text carries no user authority» — агент внутри прогона Dynamic Workflows иногда пропускал свой шаг целиком, прочитав харнес-пометку о том, что текст задачи не несёт авторитета пользователя (ровно тот защитный механизм, которым оформлены промпты автономных scheduled tasks — его формулировку эта вики видит в системных инструкциях собственных прогонов). Пропуск — не баг разбора задачи сам по себе; баг в том, что **прогон после этого всё равно отчитывался успехом**, то есть скрывал, что часть работы не выполнена.

Это не находка permission-bypass (там дыра — агент получает доступ, которого не должен иметь); здесь дыра — агент **не делает** работу, но говорит, что сделал. Прямое попадание в инвариант [[verification-three-levels]], раздел «Дыра в состоянии: тихий успех хуже краша»: «если агент сообщил о выполненном действии, запись об этом действии уже обязана существовать». Отличается от уже разобранного туда же соседнего случая 2.1.269/`/goal` ([[claude-code-changelog-snapshot-2026-09-13]]): там агент **молчал** после сбоя (отсутствие отчёта), здесь агент **докладывал успех** при фактическом пропуске (ложный отчёт) — тот же корень («врёт в проверке» из [[agent-harness]]), но другой из двух подвидов тихого сбоя, который страница уже разделяет.

**Применимо напрямую к этой вики.** Автономные рутины (новости, практики, хвосты) получают прогонный промпт как scheduled task — тот самый текст, который харнес помечает «не несёт авторитета пользователя» в описанном выше смысле; сама вика не использует Dynamic Workflows для рутин (`CLAUDE.md` описывает их как линейный прогон одной сессии, не fan-out субагентов), поэтому конкретный баг эту вику не задевает технически. Но принцип переносится прямо: граница между «агент прочитал защитную пометку и корректно отказался от шага» и «агент прочитал защитную пометку, пропустил шаг и всё равно отчитался успехом» — это ровно тот зазор, который нужно закрывать в любой собственной обвязке с автономными агентами, не только у Anthropic.

## Малое

- *(2.1.299)* Idle-компакция в терминале: диалог на 200K+ токенов, простоявший без действий ~54 минуты, сжимается заранее, пока не истёк час промпт-кэша — настройка `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS`/`"idleCompaction": false`.
- *(2.1.300)* `/advisor` стал доступен на Claude Platform on AWS.
- *(2.1.300)* Изменение, ослабляющее защиту по умолчанию, а не усиливающее: «Changed Claude in Chrome in Cowork cloud sessions outside auto mode: an approved-site action the safety classifier flags now asks you instead of being refused, unless managed settings apply» — действие на разрешённом сайте, которое классификатор безопасности помечает подозрительным, раньше отклонялось автоматически, теперь спрашивает подтверждение у пользователя (если managed settings организации не предписывают иное). Стоит отметить отдельно от bypass-находок: это не дыра, а осознанное смягчение — но оно двигает умолчание в сторону больше спросить, чем отказать, обратное направление по сравнению со всей серией выше.
- *(2.1.301)* Изменение резолва при выходе: команда для возобновления сессии теперь печатает её по ID, а не по имени — «so that nothing in a session name can run when the line is pasted» — защита от инъекции через произвольное имя сессии, которое пользователь мог вставить во вставленную команду не читая.
- Остальные пункты трёх версий (UI/VSCode/Claude Tag/Code Review фиксы, мод-API) — без веса для практики вики; полный текст — в CHANGELOG.md репозитория.
