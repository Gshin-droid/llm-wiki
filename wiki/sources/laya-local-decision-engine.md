## Саммари

Laya — открытая (Apache 2.0) модель на 322–421M параметров, которая делает **не текст, а решение**: «да/нет с вероятностью», «выбор из вариантов», «оценка по шкале». Один проход сети, 33 мс на GPU, меньше гигабайта памяти, запускается на ноутбуке. Прямая альтернатива платному облачному API [[jev-typesafe]] — в 7,8 раза быстрее при лучшей калибровке.

Для вики материал ценен двумя вещами, которых в посте-наводке нет.

**Первое — это отдельный класс инструмента, а не «маленькая LLM».** Модель не авторегрессионная: она не генерирует ответ по токену, а выдаёт распределение вероятностей за один проход. Отсюда и скорость, и жёсткое ограничение: контекст 512–1024 токена, никакого рассуждения, никакого текста на выходе. Это классификатор промышленного качества с человеческим интерфейсом задания вопроса.

**Второе — раздел ограничений README, который стоит дороже самой модели.** Авторы публикуют случаи, где их модель проигрывает, включая один показательный: на кхмерском языке англоязычная версия даёт **0,000 точности при 95,2% уверенности**. Разбор — в [[kalibrovka-uverennosti-resheniy]].

## Что модель делает

Три примитива решения:

- **noul** — калиброванная вероятность истинности от 0.0 до 1.0 (бинарное решение);
- **choice** — метка-победитель, вероятность каждого варианта, уверенность;
- **score** — ожидаемый уровень по порядковой шкале (рубрике).

Три контрольные точки: `laya` (энкодер ModernBERT-large, 421M, контекст 512, английский), `laya-multilingual` (mmBERT-base, 322M, контекст 1024, 100+ языков, вдвое быстрее), `laya-typed-decisions` (421M, контекст 1024). Обучение — RLCD: обучение с подкреплением по **строго правильным правилам скоринга** (proper scoring rules), градиент политики в стиле GRPO. Проще: модель награждали не за угаданный ответ, а за честно названную вероятность — за самоуверенность штрафовали.

Установка `pip install laya`, Python 3.10+. Рекомендуемый путь — через `Router`, который сам выбирает контрольную точку.

## Замеры из README

| Что | Laya | [[jev-typesafe]] |
|---|---|---|
| Типизированные решения (routed) | **0,766** | 0,727 |
| DAIR Emotion | **0,595** | 0,480 |
| Калибровка ECE (меньше — лучше) | **0,081** | 0,144 |
| Задержка на вопрос | **32,8 мс** | 236–276 мс |
| Banking77 (77 вариантов) | 0,425 | **0,870** |

Скорость на Tesla T4: один вопрос 39,5 мс (`laya`) и 32,8 мс (multilingual); десять вопросов — 158,6 мс и 72,3 мс, то есть 7,2 мс на вопрос при пакетной обработке. На процессоре без видеокарты — 193–464 мс.

## Ограничения, названные авторами

- **Больше 50 вариантов выбора — не её задача.** На Banking77 (77 классов) 0,425 против 0,870 у облачного конкурента. Вдвое хуже, и это не мелочь.
- **Порядковые шкалы даются плохо**: SST-5 — 0,372.
- **Английская версия разваливается вне английского**; многоязычная слабее на английском (0,657 против 0,783). Выбор версии — компромисс, а не апгрейд.
- Базовые энкодеры без дообучения работают **на уровне случайного угадывания** (0,362 и 0,352 при случайном 0,318): вся ценность в дообучении, а не в архитектуре самой по себе.
- Под конкретный домен требуется дообучение.
- Контекст 512–1024 токена — задача, не влезающая в этот объём, просто не ставится.

## Что взято в вики

1. Новая сущность [[laya]] и справочная [[jev-typesafe]] (платный облачный аналог, из-за которого материал вообще появился).
2. Новый концепт [[kalibrovka-uverennosti-resheniy]] — уверенность как **измеримая** величина (ECE), а не интуиция; кхмерский случай как предельный пример.
3. Дополнение к [[delegirovanie-deshevym-modelyam]]: между ступенью 0 (детерминированный скрипт) и ступенью 1 (локальная языковая модель) есть пропущенная ступень — **обученный классификатор**, если задача сводится к выбору из фиксированного набора.

## Что не взято / лиды

- **Демонстрация со змейкой из поста** (Laya 46 очков против 1 у облачного Jev, 86,5 решений в секунду) в README отсутствует — это отдельный ролик. Как замер она малоценна: сравнивается не качество решений, а задержка, и результат предрешён условиями (30 секунд реального времени против сетевого запроса в 300 мс). В вики не переносится.
- Страница модели на Hugging Face не открывалась — размер весов, формат и число скачиваний не проверены. Лид в [[gaps-backlog]].
- Что такое RLCD в деталях и почему proper scoring rules дают лучшую калибровку — тема глубже разбора; лид туда же.

## Оценка источника

README — первоисточник, прочитан напрямую, и это **необычно честный** README: раздел ограничений подробнее раздела достижений, приведены случаи проигрыша конкуренту. Презумпция для цифр отсюда — высокая, но все они замерены авторами на своём наборе задач, независимой проверки нет.

Пост-наводка верно назвал класс задачи, размер модели, требование к памяти и оба ограничения, объявленных авторами (контекст 512–1024, слабое обобщение без дообучения). Но основан на ролике со змейкой, а не на README: главные слабости модели — провал на большом числе вариантов и на порядковых шкалах — в посте отсутствуют, зато присутствует эффектная цифра «20-кратной разницы», которая измеряет задержку сети, а не качество.
