## Саммари

Мод (Claude Mod — TypeScript-плагин, подключающийся к событиям [[claude-code]], см. [[claude-code-changelog-snapshot-2026-10-04]]) рисует над полем ввода полоску: какая доля промпта последнего запроса пришла из кэша, сколько записано заново, сколько ушло без кэша, и **обратный отсчёт до истечения кэша**. При приближении конца — всплывающие уведомления «отправь сообщение, чтобы кэш не остыл»; после истечения на большом контексте — совет сделать `/compact` или `/clear`. Команда `/cache` открывает таблицу по ходам.

Пост подаёт мод как «один из самых экономящих токены» и говорит о **5-минутном** кэше. Для работы по подписке это неверно, и это главный вывод разбора — см. ниже.

## Что взято в вики

**1. Срок жизни кэша зависит от способа оплаты, а не только от настройки.** По официальной документации ([prompt caching → Which TTL each request gets](https://code.claude.com/docs/en/prompt-caching#which-ttl-each-request-gets)):

| Запросы | Подписка Claude, в пределах лимита плана | Кредиты сверх плана, API-ключ, облачный провайдер |
|---|---|---|
| Основной диалог | **1 час** | 5 минут |
| Всё остальное (субагенты, workflow, сжатие, заголовки) | 5 минут | 5 минут |

Когда подписка выходит за лимит и начинает тратить кредиты, Claude Code сам **опускает основной диалог до 5 минут** — запись в 5-минутный кэш дешевле. Переопределения — `promptCacheTtl` / `CLAUDE_CODE_PROMPT_CACHE_TTL` для основного диалога, `subagentPromptCacheTtl` / `CLAUDE_CODE_SUBAGENT_PROMPT_CACHE_TTL` для остального; полный порядок старшинства — в документации. Дописано в [[claude-api-cost-optimization]].

**2. Что сбрасывает кэш — список из документации, совпадающий с логикой мода:** смена модели, смена уровня усилий (кроме моделей 5.5 и Fable 5.1 на API-ключе или подписке — там кэш сохраняется), включение fast mode, подключение MCP-сервера без отложенной загрузки инструментов, запрет инструмента целиком, `/compact`, обновление Claude Code. **Правка CLAUDE.md посреди сессии кэш не сбрасывает, но и не применяется** до `/clear`, `/compact` или перезапуска.

**3. Проверка своими руками без мода** — встроенная: `/usage` с версии 2.1.251 показывает строку `Prompt cache (main)` (доля попаданий, число промахов, тёплый ли кэш сейчас), с 2.1.260 — ещё и вероятную причину последнего промаха. Строка состояния читает те же цифры из объекта `prompt_cache`. Какой срок реально записан — `claude -p "hello" --output-format json`, поле `usage.cache_creation` (`ephemeral_1h_input_tokens` / `ephemeral_5m_input_tokens`).

## Берём инструмент или логику

**Инструмент — не ставим.**
- Дублирует встроенное: `/usage` уже показывает попадания, промахи, тёплость кэша и причину промаха.
- Главная польза мода — отсчёт пятиминутного окна. На подписке в пределах плана окно основного диалога — час, и отсчёт почти не нужен. Субагенты, где окно действительно пять минут, мод сознательно не учитывает (`if (e.agentId) return`).
- Совет «отправь сообщение, пока кэш не остыл» на подписке — трата лимита плана ради сохранения кэша; оправдан только перед тяжёлым продолжением на большом контексте.
- Отображается ли полоса мода в плагине VS Code — **не проверено**: README говорит о терминале и панели Desktop.
- Установка через `npx claude-code-templates@latest --mod …` — исполнение скрипта до чтения; если когда-нибудь понадобится, ставить вручную копированием папки (сам мод — два файла без сетевых вызовов).

**Логика — берём одно:** решение «продолжать / `/compact` / `/clear`» зависит от двух чисел — размера контекста и того, тёплый ли кэш. Холодный кэш на большом контексте — самый дорогой момент сессии: следующий ход перезаписывает весь префикс. Отсюда правило применения: после долгого перерыва в большой сессии сначала `/compact` (или новая сессия), а не сразу следующий вопрос. Документация говорит то же: на Pro и Max Claude Code сам предлагает «продолжить из выжимки» при возврате в большую сессию после паузы.

**Отрицательный урок — о посте, а не о моде:** пересказ перенёс в рекомендацию цифру «5 минут», которая верна для API-ключа и неверна для подписки. Сам README мода это различие описывает подробно — до него пересказ не дочитал.

## Что не взято / лиды

- Порог `compactAtTokens = 100 000` — по словам самого автора, «суждение, а не цифра из документации». Не берём как правило.
- Вывод срока жизни кэша по промежуткам между запросами (`observeTtl`) — нужен моду только потому, что API модов не передаёт срок записи; нам не нужен, есть `usage.cache_creation`.

## Проверка безопасности источника

Код мода: читает переменные окружения кэша и три файла настроек (`.claude/settings.local.json`, `.claude/settings.json`, `~/.claude/settings.json`) — только поле `promptCacheTtl`. **Сетевых вызовов нет**, данные никуда не уходят. Инструкций, обращённых к агенту, в README и коде нет. Риск — только способ установки через `npx … @latest` (исполняется свежая, непрочитанная версия установщика).

## Дополнение (2026-10-19): своя доля попаданий в кэш — 97,6%

Замер по журналам Claude Code рабочей машины за 16.07–19.10.2026 (149 сессий с субагентами, 23 729 ответов модели): всего на входе ≈5,2 млрд токенов, из них 97,6% — чтение из кэша, новых и записи в кэш — 126,5 млн. Это без какой-либо перестройки документации: Claude Code сам кладёт неизменную часть (системный текст, правила, `CLAUDE.md`) в начало запроса. Цифра — ориентир: заметное падение значит, что что-то начало менять начало запросов. Доля посчитана по токенам, не по деньгам: чтение кеша дешевле в 10–20 раз, и в счёте доля нового входа заметно больше.

Повод — наводка из обсуждения практиков («шапка документации неизменна → 97–99% попаданий, кэш остывает за 5 минут»): опыт участника на своих данных уже выполнен без переделки; «5 минут» для основного диалога на подписке неверно (выше, раздел 1).

## Дополнение (2026-10-20): цена перерывов и сжатие при простое ([[stanford-always-on-agents]])

Повод — приём из лекции о постоянно работающих агентах: сжимать разговор, пока кэш ещё тёплый, чтобы после перерыва не отправлять длинный разговор заново по полной цене.

**Замер на своих журналах** (149 основных сессий, 16.07–19.10.2026; скрипт по паузам между ответами модели): пауз дольше часа — 209, после 201 из них следующий ответ заново записал контекст в кэш; типичная перезапись — 234 тыс. токенов (медиана), максимум 543 тыс. Эти перезаписи — 49% всей записи в кэш. Грубо в ценах API (запись на час — 2× входа, чтение — 0,1×) это около 14% всей входной стороны расхода. Перерывы — заметная статья, а не мелочь.

**Готовое уже есть, но не там, где работает пользователь.** В Claude Code с версии 2.1.299 есть сжатие при простое (`idleCompaction`, включено по умолчанию; порог `CLAUDE_CODE_IDLE_COMPACT_MIN_TOKENS`, по умолчанию 200 тыс., не ниже 100 тыс.): разговор длиннее порога, простоявший около 54 минут, сжимается, пока часовой кэш тёплый. Журнал изменений и оглавление справки настроек называют это простоем **терминальной** сессии ([[claude-code-changelog-snapshot-2026-10-15]]). Свои журналы подтверждают: в плагине VS Code ни одного сжатия по простою, в том числе за ночь 19–20.10 на версии 2.1.301 при простое ~16 часов; все 32 сжатия в журналах — «manual». Полную статью справки о `idleCompaction` прочитать не удалось (страница обрезается), поэтому «только терминал» — по оглавлению, журналу изменений и своим журналам, а не по прямой фразе.

В трекере Claude Code: запрос #44789 «автосжатие после простоя» закрыт 20.05.2026 как неактивный; открыт #103400 — запускать при простое свой промпт (например, «запиши передаточную записку в файл») вместо встроенного сжатия. Запроса про VS Code не нашлось (два поиска, 20.10).
