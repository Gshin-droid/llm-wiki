## Находка 1: `claude plugin eval` — официальный тест-раннер для плагинов (2.1.269)

*"Added `claude plugin eval`: run a plugin's eval suite against Claude Code and get scored, reproducible results (JSON + HTML report)"*.

Первый штатный способ прогнать eval-сьют плагина и получить воспроизводимую оценку (JSON + HTML), а не полагаться на ручное тестирование "работает / не работает". Прямое продолжение темы `/skill-doctor` из прошлого снапшота (2.1.261, 09-10) — там появился инструмент, считающий стоимость и использование уже установленного скилла; здесь — инструмент, проверяющий плагин **до** установки/публикации, по формальному сьюту тестов, а не по факту использования. Разный момент в жизненном цикле (автор плагина vs. пользователь плагина), общая тема — официальная диагностика расширений перестаёт быть исключительно ручной. Changelog не раскрывает формат eval-сьюта (что именно можно проверять — поведение скилла, MCP-конфиг, permission-hooks) и не даёт числовых примеров прогона.

Дополнено в [[claude-skills]].

## Находка 2: `/goal` больше не замирает молча (2.1.269)

*"Fixed `/goal` runs silently stalling after API errors, network drops, or token limits: the goal now retries with backoff, or pauses and says why, including until a usage limit resets"*.

`/goal` — встроенная команда для многосессионных задач с критерием завершения (см. [[claude-code]], раздел «Долгоживущие агенты: `/goal` и harness-паттерны»). До этого фикса прогон мог остановиться без объяснения — не упасть с ошибкой, а просто перестать что-либо делать, что для автономной рутины неотличимо от «ещё работает». Это не тот же класс, что «тихий успех» из [[verification-three-levels]] (там агент **соврал**, что выполнил действие) — здесь агент вообще ничего не сообщил, ни успеха, ни отказа. Соседний, но отдельный вид тихого сбоя: не ложный отчёт, а отсутствие отчёта. Вендор чинит его тем же средством, что уже описано для инвариантов этой вики: не молчать, а явно сказать причину остановки. Дополнено в [[verification-three-levels]].

## Находка 3: продолжение серии — утечки секретов и права доступа плагинов (2.1.268–2.1.269)

Тот же узел, что уже три раза подряд фигурировал в предыдущих снапшотах (path traversal → backslash → macOS/Linux-вариант, все — контейнмент директории плагина/маркетплейса), в этом окне дал смежный, но отдельный класс находок — не выход за границу директории, а **утечка секрета в текст ошибки или в результат распаковки**:

- **2.1.268**: *"Fixed plugin and marketplace errors showing a token or password from a git source URL"* — токен/пароль из URL git-источника плагина светился в тексте ошибки.
- **2.1.268**: *"Fixed `/mcp` and `/plugin` server details, `claude mcp list`/`get`, and MCP login errors showing secrets resolved from `${VAR}` placeholders in MCP configs"* — секрет, подставленный вместо плейсхолдера `${VAR}` в MCP-конфиге, попадал в вывод команд диагностики того же конфига.
- **2.1.269**: *"Fixed plugin archives extracted for a session being readable by other local users, extracted files keeping world-writable bits from the archive, and stale files surviving re-extraction"* — три независимых находки сразу на одной операции (распаковка архива плагина): читаемость другими локальными пользователями, унаследованные world-writable биты из самого архива, и файлы прошлой распаковки, переживающие новую.

Отдельно, тем же окном (2.1.268) — не секьюрити-фикс, а регрессия предыдущей волны: *"Fixed every turn failing with HTTP 400 on third-party Anthropic-compatible endpoints since 2.1.265: a regex in the Artifact tool's input schema that those endpoints reject"*. Схема инструмента Artifact, ужесточённая в 2.1.265 (та же версия, что закрыла backslash-обход контейнмента плагинов — см. предыдущий снапшот), ломала **все** ходы на сторонних Anthropic-совместимых эндпоинтах на три версии подряд. Прямая иллюстрация вывода прошлого снапшота: у security-фикса есть цена, и не только в виде обхода, который он закрывает, но и в виде легитимного трафика, который он может заодно сломать, если правило написано слишком широко.

Дополнено в [[ai-security-by-design]].

## Малое

- **Атрибуция коммитов и PR под управлением CLAUDE.md** (2.1.269) — *"Fixed the attribution reminder overriding a CLAUDE.md or memory rule against commit and pull request attribution; lines set by managed settings still apply"*. Раньше системное напоминание об атрибуции могло перебить явный запрет пользователя в `CLAUDE.md`/memory на подпись коммитов; теперь правило пользователя имеет приоритет, кроме случая, когда атрибуцию требует managed settings организации. Прямо касается механики, которой подчиняется сама эта вики (`CLAUDE.md` этой вики атрибуцию не запрещает, так что для наших коммитов изменение нейтрально) — не разобрано отдельной находкой, помечено как малое из-за отсутствия дальнейших деталей в changelog.
- **`/output-style [name]`** (2.1.269) — список и переключение output styles, включая Remote Control и headless-сессии.
- **`bashEditDiffEnabled`** (2.1.269) — диф изменённых файлов прямо в результате Bash-инструмента, когда команда сама правит файлы.
- **`OTEL_METRICS_INCLUDE_REPOSITORY`** (2.1.269) — репозиторные атрибуты (`vcs.*`) в OpenTelemetry-метриках.
- **`CLAUDE_CODE_WORKFLOW_MAX_CONCURRENT_AGENTS`** (2.1.269) — верхний предел одновременных агентов в одном прогоне [[dynamic-workflows|Workflow]] теперь настраивается (1–256), раньше был фиксирован.
- **`claude self-hosted-runner --remove-session-state`** (2.1.268) — опциональная (по умолчанию выключена) очистка per-session директорий раннера при завершении сессии; дополняет [[claude-code-self-hosted-environments-docs]].
- **Задачи-трекеры (TaskCreate/Get/Update/List, TodoWrite) ограничены списком моделей** (2.1.268) — доступны только на Claude 3.x, Opus 4.0–4.7, Sonnet 4.0–4.6, Haiku 4.5; на прочих моделях требуют явного `CLAUDE_CODE_ENABLE_TODO_TOOLS=1`. Точная причина ограничения в changelog не раскрыта.
- **2.1.270** — единственная строка, регрессия предыдущей версии: read-only git-команды в Bash иногда снова стали спрашивать разрешение после долгой сессии.
