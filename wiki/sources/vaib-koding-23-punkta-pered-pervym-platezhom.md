## Саммари

Список того, что проверить, прежде чем приложение, собранное с агентом, начнёт брать деньги: интерфейс (дизайн-система, экраны загрузки, пустоты и ошибки), безопасность (ключи только на сервере, проверка прав на каждом эндпоинте), платежи (подпись вебхуков, один учёт повторного уведомления, возвраты и отмены в тестовом режиме, отзыв доступа после подписки, смена ключей при переходе в боевой режим, деньги целыми числами, двойное нажатие, налоги), данные (бэкап с проверкой восстановления, откат миграций, обрезанные списки, время с часовым поясом, мягкое удаление, экспорт, странные имена, индексы), жизнь после запуска (лимиты расходов на платные API, мониторинг ошибок, документы, совпадающие с поведением).

К списку — промпт: раздать проверку пяти субагентам по направлениям, **ничего не менять**, на каждый пункт — «пройдено / нет» и файл; что видно только в панели сервиса — статус «Требуется моё подтверждение» с пошаговой инструкцией; бэкапы и платежи — только на тестовой базе и в тестовом режиме; сначала таблица, исправления — после подтверждения.

**Как попал в вики.** Ассистент принёс пост пересказом в сводке обсуждений, без самого списка; полный текст приложил пользователь. Авторские посты канала с этого случая рассматриваются отдельно от сводок чата.

## Что взято в вики

Сверка с тем, что у нас уже стоит (скиллы `security-checklist`, `project-kickoff`, страница [[pre-project-architecture-checklist]]): закрыты только пункты 3–4 (ключи, права) и частично 15 (миграции). Остальные двадцать — новые. Переложение на стек «своё API + Postgres без Supabase»:

| Пункт | Переносится | Как проверять у нас |
|---|---|---|
| 4. RLS в базе | смыслом | права проверяет API, фильтр по владельцу в каждом запросе и тест изоляции между пользователями; RLS — вторая линия, если база общая |
| 6. Подпись вебхука, один учёт | как есть | подпись по секрету провайдера; уникальный ключ события в базе — повтор не создаёт второй записи |
| 9. Ключи боевого режима | как есть | отдельный секрет вебхука для боевого режима; проверка при старте, как fail-fast конфиг |
| 10. Деньги целыми | как есть | суммы в минимальных единицах валюты целым числом; не `float` ни в базе, ни в коде |
| 11. Двойное нажатие | как есть | ключ идемпотентности у запроса создания + блокировка кнопки |
| 12. Налоги | смыслом | по своей юрисдикции и провайдеру; Stripe в посте — пример, не требование |
| 14. Бэкап | смыслом | ежедневный дамп вне сервера и одно восстановление в чистую базу; см. [[bazovaya-zashchita-servera]] |
| 16. Обрезка на 1000 строк | смыслом | пагинация не обрезает молча: тест на списке больше страницы |
| 17. `timestamptz` + пояс | как есть | время в `timestamptz`, пояс пользователя отдельным полем |
| 18. Мягкое удаление | как есть | скрыто во всех выборках; удаление аккаунта — окончательно |
| 1–2, 20–21 | как есть | интерфейс: дизайн-система, три состояния экрана, апострофы/эмодзи/RTL, WebP/AVIF и ленивая загрузка |
| 5, 13, 19, 22–23 | как есть | лимиты расходов, документы, экспорт, индексы, мониторинг ошибок |

Из промпта взят статус **«Требуется моё подтверждение»** — для проверок, которые агент не может сделать сам (панель платёжного провайдера, тариф хостинга): не «пройдено» и не «не пройдено», а отдельная строка с инструкцией человеку. В нашей связке проверяющих такого статуса не было, и такие пункты молча выпадали или помечались «не проверяемо».

## Берём инструмент или логику

- **Инструмент:** готового инструмента нет, список и промпт — текст. Берём его основой **своего скилла-чек-листа «перед первым платежом / перед выпуском»**, переложенного на наш стек (таблица выше) — решение пользователя 2026-10-30: пригодится в двух своих веб-проектах.
- **Логика:** (1) проверка до выпуска — только чтение и таблица, решение за человеком; это уже наша связка «искатель + перепроверяющий», совпадение независимое; (2) статус «требуется подтверждение человека» как третий исход проверки; (3) опасные проверки — только в тестовом режиме, записано в самом промпте, а не оставлено агенту.

## Что не взято / лиды

- Пять субагентов одной модели — не пять независимых взглядов; у нас проверяющих разных уровней и слепая перепроверка.
- Пункты под Supabase (бесплатный тариф без бэкапов, лимит 1000 строк) дословно не переносятся — переложены смыслом.
