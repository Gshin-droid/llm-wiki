## Саммари

Ярус 2 рутины 1 (новости), следом за сводкой [[novosti-2026-10-04]]. Две новые версии с прошлого снапшота (10-01, версия 2.1.286) — окно 01-02.10.2026. Два события прямого практического веса: новый, не изолированный механизм расширения поведения агента (Claude Mods) и критический фикс дыры в защите от деструктивного `rm`, прямо относящийся к серии bypass-находок [[ai-security-by-design]].

## Находка 1: критический фикс обхода защиты «всегда спрашивать» перед `rm` (bypassPermissions / bash -c)

Текст изменения (дан дословно, цитата по прямому запросу к `CHANGELOG.md`): *"Fixed a dangerous `rm` (such as one on `/` or the home directory) inside a `bash -c` or `sh -c` script running without a prompt in bypassPermissions mode or under a shell allow rule"* (anthropics/claude-code#96300).

**Что это значит практически.** Claude Code защищает «критические пути» (корень файловой системы, прямые дети вроде `/usr`/`/etc`, домашняя директория, рабочая директория и её родители) отдельным правилом: `rm`/`rmdir`, нацеленный на такой путь, всегда переспрашивает подтверждение — даже в режимах, которые иначе пропускают все вопросы (`bypassPermissions`, разрешающие shell-правила). Фикс закрывает конкретный обход: если та же опасная команда была обёрнута в `bash -c '...'`/`sh -c '...'` (например, `bash -c 'rm -rf "$(echo /)"'`), анализатор не распознавал её как критическую и пропускал без единого вопроса. До фикса агент в `bypassPermissions`-режиме мог молча снести файловую систему, если опасная команда приходила через любую shell-обёртку, а не напрямую.

**Расхождение источников по номеру версии.** Официальная страница `code.claude.com/docs/en/changelog` дважды (два отдельных запроса этого прогона) приписала именно этот фикс версии **2.1.287** (01.10.2026, issue #96300), а более узкий, отдельный фикс (потеря safeguard при редиректе вывода в `~`/wildcard-путь) — версии 2.1.288. Прямой третий запрос к самому `raw.githubusercontent.com/.../CHANGELOG.md` дал противоположную расстановку, и три независимых технических разбора — mixed-news.com («Claude Code 2.1.288 fixes an rm guard a bash -c wrapper walked past, but stable is on 2.1.285», со временем публикации на npm — 02.10, 18:30 UTC), dev.classmethod.jp («Fixed Missing Dangerous rm Confirmation Detection Inside bash -c» — в заголовке про версию 2.1.288) и windowsforum.com («Claude Code 2.1.288 Fixes Dangerous rm Bypass») — независимо друг от друга относят критический фикс к **2.1.288** (02.10.2026). Для вики взята версия с бóльшим числом независимых совпадений (2.1.288) — но расхождение явно названо, а не скрыто: WebFetch по одному и тому же URL `code.claude.com/docs/en/changelog` дважды дал одинаковый (ошибочный, по всей видимости) ответ, а третий заход к другому URL и внешние разборы совпали между собой на противоположном. Открытый вопрос для `wiki/gaps-backlog.md`: допроверить номер версии напрямую через `npm view @anthropic-ai/claude-code versions` или аналог, когда появится доступ.

**Важный практический нюанс независимо от номера версии** — по данным mixed-news.com, на момент публикации (02.10, вскоре после выхода фикса) npm-тег `stable` всё ещё указывал на **2.1.285**, то есть пользователи, закреплённые на стабильном канале (а не на `latest`), фикса на момент написания разбора не имели. Для автономных рутин этой вики, работающих предположительно на одном из более свежих каналов (облачная инфраструктура Anthropic для Cloud Routines), это не блокер, но стоит иметь в виду при любой локальной установке через `stable`.

**Связь с серией bypass-фиксов.** Прямое продолжение темы [[ai-security-by-design]] — очередной, после долгой череды находок с 07-19 по 09-22, фикс класса «защитное правило существует, но shell-обёртка/маскировка команды даёт его обойти» (ср. находки прошлых снапшотов: backslash-bypass пути плагина 09-10, скрытие части Bash-команды через Unicode 08-07, zsh `[[ ]]`-условия 08-16). Отличие этого случая от большинства прошлых — задета не периферийная функция (плагины, MCP, креды), а самый прямой и разрушительный класс действий (`rm` на критическом пути), и обход требовал минимума усилий (простая `bash -c`-обёртка, без экзотики вроде Unicode-символов или гонки по времени).

## Находка 2: Claude Mods — новый, не изолированный механизм расширения

*"Added Claude Mods: plugins may now modify deeper behavior"* (2.1.287). Моды — TypeScript-функции внутри плагинов, подключающиеся к внутренним событиям Claude Code: могут переписать промпт до того, как он дойдёт до модели, заблокировать/отретраить/одобрить вызов инструмента, отредактировать (в т.ч. вычистить секреты из) вывод инструмента, заменить встроенную функциональность или добавить свою — вплоть до собственной панели интерфейса рядом с чатом. Ставятся через `/plugin`, работают и в CLI, и в desktop-приложении; можно написать мод руками или попросить Claude Code написать его.

**Встроенный первый мод — «You should know».** Отдельный фоновый агент следит за выводом основной сессии и присылает уведомление «Heads up», когда замечает важное, что пользователь или сам Claude мог упустить. Концептуально близко к уже описанной в [[claude-code]] карте агентов (наблюдение 09-28) и к практике проверки отчёта субагента по транскрипту — но здесь наблюдатель уже встроен в продукт, а не требует ручного захода в карту агентов.

**Security-предупреждение самого вендора.** Моды исполняются с правами пользователя, **без песочницы** — officialный анонс прямо предупреждает ставить их только из доверенных источников, тем же языком, каким в [[claude-code]] уже описана осторожность с обычными Skills («риск промпт-инъекций в чужих скилах»). Отличие от Skills по степени риска: мод может не просто дать агенту вредную инструкцию, а перехватить и переписать само поведение харнеса — заблокировать показ предупреждения, тихо одобрить permission-запрос, подменить вывод инструмента так, что пользователь увидит не то, что реально произошло. Это первый механизм расширения такого уровня глубины, официально поставляемый без изоляции.

## Оценка источника

Официальный `CHANGELOG.md` репозитория `anthropics/claude-code`, получен через `WebFetch` доменом `raw.githubusercontent.com` — высшая презумпция доверия по `references/source-evaluation.md`; даты релизов (01-02.10.2026) отдельно подтверждены официальной страницей `code.claude.com/docs/en/changelog`. ## Проверка безопасности источника

Официальный `CHANGELOG.md` и официальная страница документации — только описание изменений продукта. Исполняемых инструкций или текста, замаскированного под команды агенту, не обнаружено. Отдельно отмечено (не инструкция, а предупреждение вендора, уже отражённое в разборе выше): Claude Mods исполняются без песочницы, вендор прямо предупреждает об осторожности при установке чужих модов.
