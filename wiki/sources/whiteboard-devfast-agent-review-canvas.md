## Саммари

Настольное приложение с открытым кодом (MIT), в котором агент — Claude Code, Codex и другие — получает SDK, чтобы **рисовать объяснение своей работы на холсте**: диаграммы последовательности, схемы связей данных, цитаты из собственной трассы. Главный сценарий из README — «сделай ревью текущей ветки против свежего `main` и открой его в Whiteboard».

Три механизма, ради которых проект существует (раздел README «Why does this exist?»):

1. **Схема связана с кодом.** Клик по элементу диаграммы или цитате из трассы агента ведёт в соответствующее место кода. Для этого авторы взяли целиком Code OSS (открытое ядро VS Code) — приложение по сути редактор, заточенный под чтение, а не под правку.
2. **Смысловой дифф.** Сравнение изменений по синтаксическому дереву (AST), написанное на Rust: большие новые функции сворачиваются в псевдокод, тесты и документация прячутся. Настраивается плагинами на WASM.
3. **Журнал решений.** Агент связывает свою трассу с холстом, и видно три вещи рядом: какие требования ставил человек, как они реализованы и **какие решения агент принял сам, без спроса**.

Отправная мысль авторов — эссе Джеффри Литта «Understanding is the new bottleneck» («узким местом стало понимание»): код пишется быстрее, чем человек успевает его понять.

## Берём инструмент или логику

**Инструмент — не ставим.** Причины:
- Он рассчитан на того, кто **читает код**: главный ход — клик по схеме ведёт в строку кода. Пользователь код не читает, и ровно эта половина пропадает зря.
- Тяжёлый: целиком свой форк VS Code, v0.1.x, релизы по несколько в неделю. Ограничения из README: файлы в нём не правятся, ревью через несколько репозиториев сразу поддерживается плохо.
- Что уходит наружу (`docs/privacy.md`): анонимная телеметрия **включена по умолчанию** (выключается в настройках или `DO_NOT_TRACK=1`). Вход через GitHub запрашивает право **`repo`** — полный доступ ко всем репозиториям, включая приватные. Облачное хранилище трасс выключено по умолчанию, но если его включить, полные расшифровки сессий (промпты, код, пути, почты) уходят на сервер dev.fast, и ключи шифрования у них: *«/dev/fast can decrypt stored traces»*. Для нашей рамки «личное не публикуется» это исключает облачную часть целиком.

**Логика — берём две вещи, обе без установки:**
1. **Отчёт о куске работы — со схемой, а не только текстом.** Мы уже умеем рисовать схемы в артефактах (скилл `artifact-diagramming`) и Mermaid. Не хватало привычки: закрывая фазу с кодом, показывать схему «что с чем теперь связано». Это прямо ложится на правило пользователя «показывай код и рядом словами, что делает каждый кусок» — схема и есть такое «рядом».
2. **Раздел «решил сам, без спроса» в отчёте.** Самое ценное в Whiteboard — не рисование, а журнал решений: отделить то, о чём договорились, от того, что агент выбрал сам. Для пользователя, который не может проверить код, это единственный способ увидеть, где агент мог уйти в сторону. Дешёвая форма у нас — отдельный пункт в отчёте о завершении работы; в форме наряда субагенту (`rules/rabota-s-ii.md`, п. 6) его сейчас нет. Предложение пользователю, в правила не внесено.
