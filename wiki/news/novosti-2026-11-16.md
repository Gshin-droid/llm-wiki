# Новости ИИ — 2026-11-16

Прогон рутины 1 «новости» (раз в 3 дня, 21:00 Алматы — фактический запуск 16.11 в 16:07 UTC). Прошлая сводка — [[novosti-2026-11-13]], закрыла окно 10.11–13.11.2026. Окно этого прогона — **13.11–16.11.2026**.

## Что изменилось

1. **Claude Code 2.1.325 (13.11.2026) — скиллы с `allowed-tools`/хуками теперь спрашивают разрешение в автоматизации, включая эту вики.** Прямым WebFetch официального `code.claude.com/docs/en/changelog` подтверждён релиз: **«Scheduled tasks and `/loop` ask before running a skill that declares `allowed-tools` or hooks. Add `Skill(name)` to `permissions.allow` to run it unattended»**. До этого релиза скилл с объявленным `allowed-tools` в шапке запускался в автоматическом прогоне без вопроса; теперь харнес спрашивает разрешение перед запуском такого скилла внутри Cloud/scheduled-прогона или `/loop` — и если ответить некому (ровно наша ситуация: рутина идёт без пользователя), шаг зависает или прерывается, если явно не добавить `Skill(имя-скилла)` в `permissions.allow`.

   **Прямая проверка на своей конфигурации, не только по описанию.** `wiki-ingest` и `wiki-lint` — оба скилла этой вики — объявляют `allowed-tools` в шапке `SKILL.md` (у `wiki-lint` в списке есть ещё и `RemoteTrigger`). `.claude/settings.json` этого репозитория на дату прогона содержит в `permissions.allow` только отдельные Bash/Read/WebFetch-правила и явные вызовы `ingest.py`/`lint_wiki.py` напрямую через Bash — записи `Skill(wiki-ingest)` и `Skill(wiki-lint)` там нет. Из трёх автономных рутин CLAUDE.md все три в какой-то момент вызывают эти скиллы инструментом Skill (а не только напрямую скриптом через Bash) — то есть после раскатки этой версии харнеса на окружение, где выполняются Cloud Routines, у любой из трёх рутин есть шанс столкнуться с запросом разрешения, на который нет кому ответить. Деталь и пункт действия — ниже, раздел «Проверено и не взято», и в `wiki/gaps-backlog.md` (это конфигурационное исправление, не вики-факт — чинить его не роль рутины новостей).
2. **Тот же релиз — Bash-песочница и git по умолчанию строже, не только для скиллов.** «Sandboxed Bash commands follow the normal permission flow by default» (отменяет прежнее автоодобрение) и «Read-only git commands ask first in repositories that aren't the project's or one you trusted» — оба в русле общего направления вики последних месяцев (разбор серии permission-bypass), но здесь это не фикс уязвимости, а осознанное сужение дефолта. Полный разбор обоих версий (2.1.323, уже известной прошлой сводке, и новой 2.1.325) — ярусом 2 этого прогона.

Больше новых подтверждённых фактов в критерий сводки за 13.11–16.11 не попало — см. «Проверено и не взято» ниже.
