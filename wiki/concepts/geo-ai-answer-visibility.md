# GEO: видимость в ответах ИИ-поисковиков

**Актуально на:** 2026-08-01

## Определение

Generative Engine Optimization (GEO) — практика делать контент видимым и цитируемым в ответах ИИ-систем с доступом к вебу (ChatGPT search, Perplexity, Gemini с Grounding, Google AI Overviews), в отличие от классического SEO, целящегося в позицию в списке ссылок. Вопрос поднят в [[mogilko-ai-system-five-levels]] через упражнение «спроси ChatGPT/Perplexity/Gemini порекомендовать кого-то в твоей сфере» и наблюдение «YouTube-подкаст видит Gemini, не видят ChatGPT/Perplexity» — механика закрыта по официальной документации в [[geo-ai-search-official-docs]].

## Общий механизм (по официальным источникам, не по SEO-блогам)

Несмотря на разных провайдеров, схема одна и та же:

1. **Отдельный краулер строит фоновый индекс** — `OAI-SearchBot` у OpenAI, `PerplexityBot` у Perplexity; Google Search использует уже существующий поисковый индекс (нет отдельного «ИИ-индекса»); Gemini через Grounding берёт результаты из того же индекса Google Search.
2. **`robots.txt` — реальный переключатель видимости**, не декоративный. У OpenAI и Perplexity можно разрешить поисковому краулеру индексацию, одновременно запретив тренировочному (`GPTBot` у OpenAI) — это два разных вопроса разрешения, не один.
3. **Закрытая страница не исчезает полностью** — оба (OpenAI, Perplexity) могут показать домен/заголовок/краткое резюме, собранное из сторонних сигналов, даже если сама страница закрыта. Полное исключение — `noindex`.
4. **Контент должен быть текстом, доступным без рендера тяжёлого JS и без логина** — типичная причина «невидимости» не заговор, а техническая: краулеру нечего распарсить.
5. **Никто из провайдеров формально не поддерживает `llms.txt`** как отдельный канал — Google явно написал (15.06.2026), что файл не нужен для Search. Разговоры о нём в GEO-контенте — по факту community-конвенция, выдаваемая частью блогов за официальный стандарт.

## Асимметрия видео: почему подкаст виден Gemini и не виден ChatGPT/Perplexity

Текстовые краулеры (`OAI-SearchBot`, `PerplexityBot`) не заявлены как способные разбирать видео/аудио как таковое — им для цитирования нужен текст: транскрипт, статья с описанием. Без текстовой страницы для конкретного видео обоим нечего проиндексировать.

Gemini — часть экосистемы Google, той же, что и YouTube, и умеет анализировать транскрипт/метаданные видео напрямую по запросу, без обязательной отдельной текстовой страницы-транскрипта на стороннем сайте.

**Практическое следствие:** чтобы видео/подкаст попадал в ответы ChatGPT и Perplexity — нужна текстовая страница-транскрипт, доступная для краулинга (не за логином, не заблокирована `robots.txt`, не только клиентский рендер). Для Gemini это не обязательно, но не мешает.

## Применимость к этой вики и к пользователю

- **[[ai-content-farming-workflow]] (Дзен-конвейер)**: если цель — не только показы на самой платформе, а и видимость в ИИ-ответах, статья должна существовать как индексируемый текст (что Дзен и так требует) — дополнительных действий для GEO не нужно сверх обычной публикации текстом, `robots.txt` Дзена вне контроля пользователя.
- **Сама эта вики**: публикуется как сайт через GitHub Pages (см. `CLAUDE.md` → «Личное не публикуется»). Если понадобится проверить, видна ли она ИИ-поисковикам — это тот же тест: `robots.txt` GitHub Pages не блокирует по умолчанию, значит текстовые краулеры технически могут её достичь; фактическая цитируемость — отдельный вопрос ранжирования, не рассмотренный здесь.

## Не проверено / открыто

- Конкретные веса ранжирования (какие сигналы важнее) ни один провайдер не публикует — не факт для этой вики, только упомянутые в источнике официальные общие принципы (E-E-A-T у Google, доступность для краулинга у OpenAI/Perplexity).
- Числовая проверка «выдаётся ли пользователь в ответах ИИ-поисковиков» (упражнение из [[mogilko-ai-system-five-levels]]) не проводилась — вопрос эмпирический, не документационный, и касается личной видимости, не темы вики.
