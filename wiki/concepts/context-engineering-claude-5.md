# Контекст-инжиниринг для моделей поколения Claude 5

## Определение

Свод правил Anthropic о том, чем наполнять контекст агента, когда модель стала сильнее самой инструкции ([[anthropic-context-engineering-claude-5]], 2026-07-24). Опорный факт: **из системного промпта Claude Code убрали более 80% текста для Opus 5 и Fable 5 без измеримой потери на внутренних coding-evals**.

Механизм, который за этим стоит: большая часть накопленных инструкций писалась как страховка под модели, которые хуже соображали. Для пятёрки эти же инструкции — источник конфликтующих сигналов; бюджет рассуждения уходит на их разруливание, а не на задачу. Устаревшая инструкция не нейтральна, она вредна.

## Шесть сдвигов

| Область | Раньше | Теперь |
|---|---|---|
| Правила | Задать модели правила: *«по умолчанию не пиши комментарии, никогда не пиши многоабзацные docstring'и»* | Дать сформулировать суждение: *«пиши код в стиле окружающего — с той же плотностью комментариев»* |
| Примеры | Прикладывать примеры использования инструментов | Проектировать интерфейс: выразительные параметры и внятное описание инструмента вместо пачки примеров |
| Структура | Выложить всё заранее в системный промпт | Progressive disclosure: детали в скиллах, грузятся выборочно; инструменты — с отложенной загрузкой |
| Повторение | Дублировать инструкцию и в промпте, и в описании инструмента | Инструкция живёт в одном месте — в описании инструмента |
| Память | Ручная дописка `CLAUDE.md` (хоткей `#`) | Auto-memory: Claude сам сохраняет релевантное по ходу работы |
| Спецификации | Markdown-план на несколько экранов | Rich references: HTML-макет, ссылки на код, тестовый набор, рубрика оценки |

Про примеры важна причина, а не только рекомендация: примеры теперь **сужают** поиск решения — модель цепляется за показанный способ и перестаёт искать за его пределами.

## Где что должно жить

- **Системный промпт** — продуктовый контекст: в каком продукте модель работает. Пользователю Claude Code менять почти нечего; для собственного агента на [[claude-agent-sdk|SDK]] это, наоборот, слой максимального внимания.
- **`CLAUDE.md`** — лёгкий. Основное содержание — **gotchas конкретного репозитория** (пример статьи: «типы у нас лежат в одном монолитном файле и больше нигде»). Очевидное из структуры файлов — выбросить: это Claude выведет сам.
- **Skills** — «лёгкие путеводители», чтобы модель нашла нужное, когда понадобится. Кодируют мнения и практики команды/продукта. Не переограничивать — жёсткие рамки оставить критичным областям. Длинный скилл разбивать на файлы (см. [[skill-authoring-practical-rules]]).
- **References (`@`-упоминания)** — глубина по текущей задаче: спецификации, макеты, целые куски кодовой базы. Предпочтительно кодом — это инструкция высокой точности на языке, который модель знает лучше прозы: HTML-макет дизайна работает лучше, чем описание или скриншот.

Инструмент рихтовки — `/doctor` в Claude Code: находит перегруженный контекст и предлагает обрезать в `CLAUDE.md` то, что выводится из кода. Уже описан в [[claude-code]] (раздел про 2.1.206–2.1.210) — статья подтверждает назначение, а не добавляет новое.

## Границы применимости

Статья не отменяет правила вообще, и читать её так — ошибка:

- **Ограничения остаются в критичных областях.** Жёсткие правила исторически писались, чтобы исключить худший сценарий (удаление файлов); лучшее суждение модели — не гарантия.
- **Правило адресовано поколению 5.** Для старых моделей прежний стиль остаётся уместным.
- **Конфликт инструкций — по-прежнему проблема,** и она не только в промпте: «оставь документацию, где уместно» из системного слоя против «НЕ добавляй комментарии» из просьбы пользователя ломается одинаково.
- **Единственный замер — свой.** «Убрали 80%, потерь нет» измерено Anthropic на своих coding-evals, методика не раскрыта. Для чужого `CLAUDE.md` это направление, а не доказательство.

## Что это меняет в накопленном

Три места в этой вики, где правила писались в устаревающей форме:

- **[[llm-coding-guidelines]]** — набор Карпати сформулирован как «никогда/всегда» и при этом, по наблюдению самой страницы, дублирует поведение Claude Code по умолчанию. Двойной кандидат на сокращение.
- **[[claude-code-practices]]** — личный свод пользователя и синхронизированный с ним `~/.claude/CLAUDE.md`: список запретов, часть которых — страховка под старые модели.
- **Инструкции «добавь шаг верификации»** — уже отмечены как избыточные для Opus 5 в [[claude-code]] по данным [[claude-opus-5-launch]]. Статья обобщает частный случай в правило.

Отдельный сюжет — **auto-memory**: ровно этот механизм виден в сессиях этой вики (директория памяти с файлами-фактами и индексом, которые агент ведёт сам). Он не заменяет `CLAUDE.md` и тем более wiki-слой: память копит факты о пользователе и работе, вики — курируемое знание с проверкой на входе (см. [[persistent-wiki-pattern]], [[claude-memory-tool]]). Механику (формат, область видимости, конфликт с `CLAUDE.md`), которую эта статья не раскрывает, закрывает официальная документация Claude Code — см. [[claude-code-memory-docs]].
