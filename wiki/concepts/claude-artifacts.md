# Claude Artifacts

**Актуально на:** 2026-10-24

## Что это
Артефакт — живая интерактивная веб-страница, которую Claude Code (или другая поверхность Claude) публикует из сессии на приватный URL на claude.ai. Открывается в браузере и обновляется на месте по мере продолжения сессии — в отличие от статичного вывода в терминал. Используется, когда текст в терминале — не тот носитель для результата: разбор PR с аннотациями, дашборд по данным сессии, набор вариантов для сравнения бок о бок, таймлайн расследования, который заполняется по ходу долгой задачи.

Артефакт — это "снимок работы, а не приложение": одна самодостаточная страница без бэкенда, не может хранить ввод из формы и не может обслуживать несколько маршрутов. Единственный способ получить внешние данные при просмотре — вызов MCP-коннекторов (см. ниже).

## Создание, обновление, шаринг
- Claude пишет `.html` или `.md` файл в проекте и публикует его; перед первой публикацией спрашивает разрешение. Повторная публикация уже одобрённого артефакта не спрашивает снова.
- Обновление — та же публикация на тот же URL: каждая публикация становится версией, зритель может выбрать, какую версию видеть, через контрол **Share**.
- Обновить артефакт из другой сессии можно, дав Claude его URL — без URL новая сессия всегда создаёт новый артефакт.
- Новый артефакт виден только автору. Поделиться — контрол **Share** в шапке страницы:
  - **Внутри организации** (Team/Enterprise) — доступ конкретным людям или всем в организации.
  - **Публично** — ссылка без входа на claude.ai. На Pro/Max это единственный способ поделиться. На Team/Enterprise публичный шаринг по умолчанию выключен, включает Owner.
  - **Роль редактора** (Team/Enterprise) — зритель по умолчанию не может менять страницу; редактор публикует новые версии тем же способом, что обновление из другой сессии (даёт Claude URL артефакта).

## Вызов MCP-коннекторов зрителя (ключевая функция обновления 2.1.209+)
Артефакт может вызывать [[mcp-model-context-protocol|MCP-коннекторы]] при каждом открытии страницы — тогда страница показывает актуальные данные, а не снапшот момента сборки. Требует Claude Code v2.1.209+, доступно на Pro/Max/Team/Enterprise.

Механика для зрителя:
- **У каждого зрителя — свои коннекторы**: вызов идёт через подключения того аккаунта, который сейчас смотрит страницу, а не автора публикации — два человека, открывшие один дашборд, могут увидеть разные данные. Страница не видит ничьих credentials, вызовы делает сам claude.ai от её имени.
- **Зритель одобряет доступ** перед первым вызовом коннектора; отказ действует до конца этой загрузки страницы, при перезагрузке спрашивает заново.
- **Действия тоже идут от аккаунта зрителя** — если страница даёт контрол, вызывающий инструмент с побочным эффектом (написать сообщение, обновить issue), это выполняется от аккаунта того, кто нажал.
- Ответы кешируются в браузере зрителя — повторное открытие рендерится из кеша, затем обновляется свежими данными.
- Локальные MCP-серверы, настроенные в Claude Code (`.mcp.json`), могут снабжать данными на этапе сборки страницы, но опубликованная страница их вызывать не может — только коннекторы из аккаунта claude.ai зрителя, явно задекларированные при публикации.

**Важный нюанс, не попавший в исходный ingest-снапшот 2026-07-19** ([[claude-code-changelog-snapshot-2026-07-19]]): **артефакт, вызывающий коннекторы, нельзя опубликовать по публичной ссылке ни на одном тарифе** — это отдельное ограничение, не связанное с общим включением/выключением публичного шаринга. На Team/Enterprise такой артефакт можно расшарить только внутри организации или оставить приватным; на Pro/Max (где публичная ссылка — единственный способ шаринга) артефакт с коннекторами вообще остаётся приватным автору.

## Технические ограничения страницы
- Строгий CSP: блокирует запросы к любому другому хосту (скрипты, стили, шрифты, картинки, `fetch`/XHR/WebSocket) — Claude инлайнит CSS/JS и встраивает картинки как data URI. Исключение — вызовы коннекторов: их делает сам claude.ai, а не страница напрямую.
- Без бэкенда, без хранения form-ввода, без своего API.
- Одна страница — относительные ссылки на другие файлы не резолвятся, для многосекционного контента используются якоря на странице.
- Допустимые типы исходного файла: `.html`, `.htm`, `.md` (markdown рендерится как стилизованный HTML).
- Итоговый размер страницы ≤ 16 MiB.
- С v2.1.182+ Claude применяет встроенный design-skill (палитра/типографика/лейаут по умолчанию), но сначала ищет уже заданную дизайн-систему проекта (например, в `CLAUDE.md` или theme-файле) и считает её приоритетнее собственного выбора.

## Доступность
Нужны одновременно: план Pro/Max/Team/Enterprise; сессия авторизована через `/login` (не API-ключ/gateway-токен/облачные credentials); модель-провайдер — Anthropic API напрямую (недоступно на Bedrock/Vertex/Foundry); у организации не включены CMEK/HIPAA/Zero Data Retention; поверхность — Claude Code CLI v2.1.183+ или Claude Desktop v1.13576.0+ (в Agent SDK, GitHub Action и MCP-server контекстах выключено по умолчанию).

## Управление на уровне организации
Owner на Team/Enterprise включает/выключает артефакты в целом и отдельно — вызовы коннекторов из артефактов (переключатель **Enable artifact connectors**, действует и на артефакты из обычных разговоров claude.ai, не только Claude Code). Отдельные переключатели: публичный шаринг (**External sharing**, по умолчанию выключен), retention policy — **раздельно для приватных и расшаренных артефактов**, Compliance API для листинга/чтения/удаления артефактов организации, аудит-лог событий `claude_artifact_*`.

**Compliance API — точные эндпоинты** (`docs.claude.com/en/api/compliance`): `GET /v1/compliance/code/artifacts` (список), `GET /v1/compliance/code/artifacts/{artifact_id}/versions/{version_id}` (содержимое конкретной версии), `DELETE /v1/compliance/code/artifacts/{artifact_id}` (удаление).

**Allowlist для организаций с ограничением исходящего трафика:** зритель загружает артефакт с изолированного домена `*.claudeusercontent.com` — его нужно разрешить отдельно от `claude.ai`. Внешние скрипты — только с `cdnjs.cloudflare.com`, `cdn.jsdelivr.net`, `cdn.tailwindcss.com`, `code.jquery.com`, `unpkg.com` (пятый хост добавлен допроверкой 10-24, без фолбэка при блокировке — часть страницы просто не работает); шрифты — только Google Fonts (`fonts.googleapis.com`/`fonts.gstatic.com`, опционально, при блокировке — фолбэк на системный шрифт). Рекомендация документации — блокировать быстрым отказом, а не молчаливым дропом, чтобы запрос не подвисал до таймаута.

## Найдено при допроверке 2026-09-05 — не было в исходном ingest-снапшоте

Официальная `code.claude.com/docs/en/artifacts` прочитана заново целиком напрямую (без блокировки). Страница выросла заметно с 07-19 — три раздела ниже отсутствовали на странице вики полностью, не формальная сверка даты:

**Комментарии на артефакте (новое, не только политика — сама функция).** Зритель, которому артефакт расшарен **внутри организации** (не публично — на публичной ссылке комментарии недоступны вовсе, страница явно об этом пишет), может оставлять комментарии; Claude может их прочитать и ответить. Два пути активации нити (thread): либо автор сам просит Claude прочитать по URL, либо тот, у кого есть право редактировать артефакт, отправляет комментарий кнопкой **Send to Claude** или упоминанием `@claude` — только после этого Claude может отвечать/резолвить именно эту нить, остальные остаются открытыми до ручного разрешения человеком. Требует Claude Code v2.1.221+ для чтения по запросу и v2.1.228+ для автономных ответов без вопроса пользователю (правило зависит от режима разрешений сессии — auto отвечает сам, manual спрашивает, plan mode ждёт выхода из режима). Ограничение автономных ответов — не больше 60 обработанных нитей/активаций на один артефакт за час. Это ровно тот механизм, которым эта сессия сама пользуется (`Artifact` action `reply`/`resolve`/`comments`) — впервые страница вики привязывает наблюдаемое поведение инструмента к официальному первоисточнику, а не только к системному промпту сессии.

**`/design` — канвас-режим (не было на странице вообще).** Отдельная команда для мокапов UI/скринфлоу/лендингов/постеров вместо публикации одной готовой страницы: Claude раскладывает драфт артбордами на одном pan/zoom-канвасе и публикует сам канвас как артефакт, который запускает research-preview редактора Claude Design. Там, где для аккаунта включено сохранение — клик по элементу, правка на месте, сохранение публикует новую версию; иначе — просмотр и экспорт в PNG/PDF. Требует Claude Code v2.1.234+ и вообще доступных артефактов (те же требования Availability).

**Отключение артефактов на своей стороне (не было на странице).** Четыре независимых способа, помимо уровня организации: `/config` → строка **Artifacts** (пишет `"enableArtifact": false` в user settings), тот же ключ в settings-файле (устаревший синоним — `"disableArtifact": true`), переменная окружения `CLAUDE_CODE_DISABLE_ARTIFACT=1`, правило `Artifact` в `permissions.deny`. Важный нюанс приоритета: выключение через `--settings`-файл, переменную окружения или managed settings администратора необратимо снизу — ни один менее приоритетный settings-файл не может включить обратно (до v2.1.242 более приоритетный файл мог перебить нижний `false` — это было исправлено).

**Мелкие уточнения, дополняющие уже известное:** `/artifacts` листинг требует Claude Code v2.1.208+, а поведение клавиши Enter поменялось в v2.1.216 (раньше открывала в браузере, теперь — прикрепляет к текущей сессии, открытие — клавиша `o`); `Ctrl+]` в любой момент переоткрывает последний опубликованный артефакт; `CLAUDE_CODE_ARTIFACT_AUTO_OPEN=0` отключает автооткрытие браузера при публикации. В Auto mode публикацию нового артефакта не спрашивает пользователя явно — классификатор одобряет её сам вместо промпта (тот же механизм auto mode, что уже задокументирован на [[ai-security-by-design]] для других разрешений). Claude Tag-сессии тоже могут публиковать артефакты, если фича включена и для Claude Tag, и для артефактов организации отдельно.

**Расхождений с уже записанным не найдено** — все шесть проверенных цифр/условий (v2.1.209+ для коннекторов, CLI v2.1.183+/Desktop v1.13576.0+, design-skill с v2.1.182+, ≤16 MiB, недоступность на Bedrock/Vertex(«Google Cloud's Agent Platform»)/Microsoft Foundry, требование отсутствия CMEK/HIPAA/ZDR) подтверждены дословно без изменений.

## Противоречия

Повторное чтение `code.claude.com/docs/en/artifacts` 2026-10-24 нашло два места, где первоисточник сейчас говорит иначе, чем записано выше — не формальная сверка даты, обе проверены дословной цитатой.

**Публикация артефакта с коннекторами по публичной ссылке — возможна, вопреки записи 09-05.** Раздел «Найдено при допроверке 2026-09-05» выше утверждает: «артефакт, вызывающий коннекторы, нельзя опубликовать по публичной ссылке ни на одном тарифе». Текущая документация прямо противоречит: «You can share a connector-backed page within your organization or publicly, as your plan and organization settings allow. Connector calls don't run for a viewer who opens the public link without signing in to claude.ai, or from outside your organization. That viewer sees the page without its live sections.» — публикация по публичной ссылке разрешена, просто вызовы коннекторов не срабатывают для анонимного зрителя или зрителя не из той же организации (страница рендерится без «живых» секций). Не установлено, когда это изменилось — такая возможность появилась после 09-05 или запись 09-05 ошиблась изначально; raw-файл для записи 09-05 не был сохранён отдельно (допроверка 09-05 сама читала живую документацию, как и сейчас), построчно сверить со снимком того дня нельзя. Старый текст выше не удалён, это и есть расхождение, которое чинит исправление, а не переписывание.

**Эндпойнты Compliance API сменили путь — добавился сегмент `apps/`.** Раздел «Compliance API — точные эндпоинты» выше называет `GET /v1/compliance/code/artifacts`, `GET /v1/compliance/code/artifacts/{artifact_id}/versions/{version_id}`, `DELETE /v1/compliance/code/artifacts/{artifact_id}` со ссылкой на `docs.claude.com/en/api/compliance`. Текущая официальная страница даёт другие пути — `GET /v1/compliance/apps/code/artifacts`, `GET /v1/compliance/apps/code/artifacts/{artifact_id}/versions/{version_id}`, `DELETE /v1/compliance/apps/code/artifacts/{artifact_id}` — и ссылается на `platform.claude.com/docs/en/api/compliance/apps/code/artifacts`, не на прежний адрес. Похоже на реструктуризацию Compliance API под несколько приложений (`apps/code/...` вместо плоского `code/...`), не на опечатку источника — но старые пути этим прогоном не перепроверены на практике (вызовов API не делалось). Старые пути выше оставлены как есть, с этой пометкой рядом.

## Допроверка 2026-10-24

Официальная `code.claude.com/docs/en/artifacts` перечитана целиком напрямую (без блокировки). Кроме двух противоречий выше, нашлось содержательно новое — не было на странице вовсе:

**Remote Control может публиковать артефакты (новое с версии после 09-05).** «Sessions served by `claude remote-control` can publish artifacts when you started the session yourself. Requires Claude Code v2.1.281 or later.» — ограничение «сам запустил сессию» специально оговорено: с чужого запуска remote-control-сессия не публикует. Версия 2.1.281 вышла после даты прошлой допроверки (её разбирала новостная сводка [[novosti-2026-09-25]]), то есть это реальное расширение поверхности, а не пропуск старого ingest.

**Скачивание файла со страницы — отдельная runtime capability, которой на странице не было вовсе.** Артефакт может предложить зрителю скачать сгенерированный файл (CSV таблицы, PNG графика) через контрол на странице — обычная ссылка/скрипт на `data:`/`blob:` зрителю скачать не даст, вьювер claude.ai их блокирует; нужна явная декларация capability при публикации, тем же механизмом, что и декларация коннекторов.

**Шаблоны Slides/Design/Docs (бета) — весь раздел новый.** Вместо страницы с нуля Claude может начать артефакт из шаблона на аккаунте claude.ai: **Claude Slides** (`/slides` с брифом — готовая презентация, экспорт в PowerPoint/PDF), **Claude Design** (тот же канвас-режим, что уже знала страница как «`/design`», только теперь явно в составе шаблонов) и **Claude Docs** (не артефакт, а коннектор claude.ai — `/mcp` показывает его как «claude.ai Claude Docs»; запрос документа для чужого чтения идёт туда, а не в артефакт). На Pro/Max/Team включены по умолчанию, на Enterprise — переключатель Owner'а на каждый шаблон отдельно. **Версия у `/design` разошлась:** запись 09-05 называла «Claude Code v2.1.234+», текущая страница в разделе шаблонов — «Both commands [`/slides`, `/design`] require Claude Code v2.1.265 or later» для этой, видимо переработанной под шаблонную систему версии команды. Не установлено, был ли `/design` v2.1.234 отдельной более ранней фичей, позже поднявшей порог версии при переезде в шаблоны, или 09-05 перепутала номер — обе цифры оставлены на странице рядом, не выбрана одна.

**Механика остановки автоответа на комментарии — страница знала только лимит 60/час.** Три независимых способа остановить автоответ Claude на нити комментариев: `Ctrl+C` на пустом промпте (ставит на паузу для всех наблюдаемых артефактов сессии, автоответ возвращается после следующего сообщения), остановка в `/tasks` (точечно для одного артефакта, не возобновляется публикацией заново), хорд `Ctrl+X Ctrl+K` дважды за 3 секунды (тот же хорд, что останавливает все фоновые субагенты — гасит автоответы на все артефакты до конца сессии). `/tasks` показывает собственные наблюдения Claude Code под «System tasks», наблюдения по явной просьбе пользователя — под «Monitors».

**Список CDN-хостов — пятый хост, которого страница не называла.** Раздел «Allowlist для организаций» выше называет четыре хоста (`cdnjs.cloudflare.com`, `cdn.jsdelivr.net`, `cdn.tailwindcss.com`, `code.jquery.com`). Текущая документация называет пять — добавлен **`unpkg.com`**. Не расхождение (старые четыре не отрицаются), пропуск при ingest; добавлено в описание выше без удаления прежнего текста.

## Связь с этой вики
Ровно та функция (вызов MCP-коннекторов зрителя при открытии страницы), которая стоит за параметром `capabilities: {mcp: ...}` инструмента `Artifact`, доступного в сессиях этой вики, и за скиллом `artifact-capabilities` (обязателен к прочтению перед объявлением capability или написанием `window.claude.mcp`-кода в артефакте). До этой страницы концепт был описан только фрагментарно, в разделе changelog-снапшота [[claude-code]] — эта страница закрывает пробел, найденный при lint-прогоне 2026-07-19 (см. `wiki/gaps-backlog.md`).
