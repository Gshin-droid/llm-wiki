# Claude "смотрит" видео (Watch skill)

## Определение
Техника из [[romaray-claude-watch-video]]: вместо того чтобы давать Claude только транскрипт видео, настраивается связка из трёх бесплатных пакетов, которая позволяет агенту буквально анализировать кадры видео, привязанные к тайм-кодам транскрипта — то есть видеть, что происходило на экране, а не только слышать, что говорилось.

## Стек (3 пакета)
1. **Whisper** (OpenAI, локальный, бесплатный) — транскрибирует видео/аудио, если публичных субтитров нет
2. **yt-dlp** — скачивает видео, публичные субтитры, метаданные (заголовок, описание, канал) с YouTube и не только
3. **FFmpeg** — нарезает видео на кадры (скриншоты) по сменам сцен, привязанные к тайм-кодам

Итог: в Claude/Claude Code добавляется команда `Watch` — вставляешь ссылку, агент скачивает видео, режет на кадры, читает транскрипт (из субтитров или Whisper) и связывает кадры с текстом по тайм-кодам.

## Сценарии применения
- Разбор скринкастов с созвонов/клиентских демо → агент сам готовит план исправления багов
- Обучающие YouTube-видео по конкретной фиче → агент видит именно то, что делалось на экране, не гадает и не галлюцинирует
- Личный кейс автора: анализ видео с себя (сёрфинг) → персональный разбор техники с конкретными таймкодами, точнее шаблонного совета тренера

## Наблюдение
Технически это частный случай того же паттерна, что и вся эта вики — Claude обрабатывает сырой источник (видео) и по желанию сохраняет разбор в личную базу знаний в Obsidian (агент сам спрашивает, сохранить ли обзор — прямая параллель с [[ingest-query-lint|операцией Ingest]]).

## Почему нужен обходной путь (допроверка 2026-08-07, официальный первоисточник)
Углубление старой concept-страницы (создана 2026-07-07, без содержательных правок с тех пор) — ежедневный процесс закрытия пробелов, бэклог пуст, шаг 2 fallback ([[claude-managed-agents]], единственная страница вне кулдауна) не дал новых фактов (release notes 08-01…08-07 не содержат ничего про Managed Agents сверх уже известного), переход к шагу 3.

Официальная документация Claude API по vision (`platform.claude.com/docs/en/build-with-claude/vision`, прочитана напрямую целиком) подтверждает: Claude принимает **только статичные изображения** — JPEG/PNG/GIF/WebP, из GIF используется только первый кадр («Animations are unsupported, and only the first frame is used»), про видео-формат ничего нет вообще. Три источника картинки (base64, URL, `file_id` через Files API) — все для одиночных кадров.

Это не новость и не расхождение с уже описанным в источнике методом — но раньше страница объясняла технику (Whisper + yt-dlp + FFmpeg) только со слов автора видео, без опоры на официальное подтверждение, зачем обходной путь вообще нужен. Теперь ясно: связка трёх пакетов — не устаревший трюк, а прямое следствие реального ограничения API на дату проверки — у Claude нет нативного понимания видео как модальности, только кадры-изображения. Отсюда и обязательность двух шагов техники: FFmpeg нарезает видео на кадры именно потому, что иначе Claude их не увидит, а транскрипт (Whisper/субтитры) нужен отдельно, потому что аудиодорожку из видео Claude тоже не воспринимает напрямую — только текст и изображения.
