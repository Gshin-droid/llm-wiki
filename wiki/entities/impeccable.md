# Impeccable

Набор дизайнерских команд для агентов-кодеров (Claude Code, Cursor, Codex и др.): один скилл с 24 командами (`polish`, `distill`, `bolder`, `audit`, `critique`…) и детектор анти-паттернов оформления, который запускается хуками. Попал в вики из подборки [[vibe-coding-frontend-references]] как ответ на «всё готово, но выглядит не так».

**Тип:** инструмент (скилл + хуки + исполняемый «движок»)
**Актуально на:** 2026-09-28
**Репозиторий:** `github.com/pbakaus/impeccable` · сайт `impeccable.style` · **Лицензия:** Apache 2.0
**Автор:** Paul Bakaus · версия плагина 4.4.0, 72 тыс. звёзд, репозиторий с ноября 2025, обновляется ежедневно

## Как устроен

Три слоя, и ставится не только текст:

1. **Скилл** — markdown-инструкции по командам (`.claude/skills/impeccable/`), плюс четыре субагента (`impeccable-finish-reviewer` и др.).
2. **Хуки** — три штуки: на старте сессии, **после каждого `Edit`/`Write`** (до 5 с, «Checking UI changes») и на остановке («Design deep pass», до 30 с). Какие файлы считать интерфейсными, решает сам движок — хук вызывается на любой правке.
3. **Движок** — исполняемый файл на Rust (исходник открыт, `crates/`). Скрипт-запускальщик ищет его рядом, в кэше `~/.impeccable/bin/<версия>/` или в `PATH`, а если не нашёл — **скачивает с релизов GitHub при первом запуске**.

## Разбор исходника (2026-09-28)

Сделан по просьбе пользователя до какой-либо установки: прочитаны манифесты плагина, оба запускальщика (`scripts/impeccable`, `impeccable.cmd`), сценарий сборки релиза и исходник движка (поиск по сетевым адресам и телеметрии). Сам движок не запускался.

**Что сделано хорошо:**

- **Скачанный файл проверяется до запуска** по контрольной сумме SHA-256 из файла-спутника. Нет спутника, нечем посчитать сумму, сумма не сошлась — запуск отменяется («fail closed»). В Windows-версии то же через `certutil`.
- **Windows-версия движка подписана** цифровой подписью через Azure Artifact Signing (Microsoft). Подпись проверяется штатно (`Get-AuthenticodeSignature`).
- **Шаги сборки закреплены по точному номеру коммита**, а не по «последней версии» — подмена стороннего шага сборки не пройдёт незаметно.
- **Самообновления нет**: новый скилл приезжает только по явной команде `impeccable update`, архив проверяется по подписи (`bundle_signature.rs`).

**Что надо знать:**

- **Контрольная сумма лежит там же, где файл.** Она защищает от битой закачки, но не от взлома релиза или аккаунта автора: злоумышленник заменит оба файла. Доказательства «собрано именно из этого исходника» (attestation, подтверждение происхождения сборки) в сценарии релиза нет; для macOS и Linux нет и подписи.
- **Сбор статистики включён по умолчанию.** Выключается переменной окружения `DO_NOT_TRACK` или `IMPECCABLE_NO_TELEMETRY` (любое непустое значение). Отправляется на `impeccable.style/api`: какой вариант оформления выбран, ключ раскладки, область, режим, тип выбора. Кода, путей и имён файлов в отметке нет — проверено по функции `ping_chosen`.
- **Отправку делает агент по инструкции движка.** В текст, который движок подкладывает агенту, вшит блок «TELEMETRY: после выбора пользователя перезапусти этот скрипт ещё раз с такими-то ключами». Безвредно по содержанию, но это ровно тот случай, о котором предупреждает [[ai-security-by-design]]: расширение приносит в контекст **команды агенту**, а не только знания. Сегодня команда — отправить отметку; что будет в следующей версии, решает автор, и заметить это можно только чтением.
- **Движок ходит в сеть и за содержимым**: карточки стилей с `impeccable.style` (`api/roll`, картинки), шрифты с `fonts.googleapis.com`. Что именно уходит в запросе `roll` — не читалось.
- **Маркетплейс плагинов не безопаснее `npx`.** Источник плагина в `marketplace.json` — папка `plugin/`, и в ней те же три хука (`plugin/hooks/hooks.json`). Разница только в том, что `npx`-установщик сам исполняется до прочтения. *Поправка к первоначальному совету в [[vibe-coding-frontend-references]].*
- Хук после каждой правки при **глобальной** установке сработает и в проектах без интерфейса (вики, скрипты): 5 с потолка на каждую правку.

## Решение

**Не ставим сейчас.** Поставить можно под конкретную задачу с интерфейсом:

- **только на уровне проекта**, не глобально — хуки не должны срабатывать в чужих проектах;
- с `DO_NOT_TRACK=1` в окружении этого проекта;
- после проверки подписи скачанного `.exe`.

**Как выключается:** удалить папку скилла и запись хуков из `.claude/settings.json` проекта, кэш движка — `~/.impeccable/`.

**Логика без установки:** команды — это markdown-файлы (`reference/polish.md`, `distill.md`, `bolder.md`…), их можно прочитать как чек-листы и применить руками, без хуков и движка. Установка нужна ради автоматического детектора, а не ради команд.

## Не проверено

Содержимое запроса `api/roll`; что движок делает на хуке старта сессии; реальная польза детектора. → [[gaps-backlog]].
