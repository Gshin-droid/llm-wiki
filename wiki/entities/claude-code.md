# Claude Code

**Тип:** инструмент (CLI-агент от Anthropic)
**Актуально на:** 2026-08-25

## Что это
CLI-инструмент для работы с LLM-агентом (Anthropic Claude) прямо в терминале/IDE. В [[persistent-wiki-pattern|паттерне персональной вики]] выступает "программистом", который читает источники, пишет и поддерживает wiki-слой markdown-файлов по правилам из [[CLAUDE.md]].

## Роль в этой вики
Именно Claude Code используется как движок для ведения этой вики (`C:\jarvis`) — см. [[jarvis-personal-wiki]].

## Гайдлайны поведения
Помимо роли движка вики, для Claude Code существует популярный готовый набор поведенческих правил — [[llm-coding-guidelines]] (репозиторий [[karpathy-skills-claude-md]], 188.8k звёзд), который можно подключить как `CLAUDE.md` поверх project-specific инструкций. Эти же правила во многом уже встроены в поведение Claude Code по умолчанию.

## Место в линейке продуктов Claude
Claude Code — инструмент для терминала/IDE (уровни 4-5 в [[five-levels-of-claude-mastery]]), в отличие от [[claude-projects]] (память под роль в браузере), [[claude-skills]] (переносимые умения) и [[claude-cowork]] (агент с доступом к файлам компьютера, без терминала). Ещё один сосед — **[[claude-agent-sdk]]**: та же связка agent loop + инструменты + context management, но как библиотека Python/TypeScript для встраивания в собственные CI/CD и продакшн-приложения, а не CLI для интерактивной разработки. Многие команды используют оба: CLI повседневно, SDK — в продакшне; конфигурация (`.claude/skills`, `CLAUDE.md`, plugins) читается одинаково в обоих.

## Практическая механика (из [[nikita-vels-claude-code-30-concepts]])

### Контекстное окно и сессии
Один диалог = одна задача. Индикатор контекста >50% — сигнал начинать новый диалог (`/new`) или сжимать (`/compact`, можно с уточнением "сохрани важное про X"). `/clear` — очистить и начать с нуля. `/resume` — вернуться к прошлой сессии со всем контекстом (сессии сохраняются автоматически).

### CLAUDE.md и Memory — разные вещи
`CLAUDE.md` — ручная, явно прописанная память (архитектура проекта, режимы запуска, пошаговые планы); читается в начале каждого диалога. Команда `/init` генерирует первую версию по имеющимся у агента знаниям о проекте. Memory — отдельно, автоматически запоминает паттерны/предпочтения между сессиями (можно попросить показать/скорректировать).

**Смена акцента для поколения 5 (2026-07-24, [[anthropic-context-engineering-claude-5]]).** Anthropic называет ручную дописку `CLAUDE.md` через хоткей `#` прошлым подходом, а рабочим — **auto-memory**: Claude сам сохраняет то, что относится к работе и к пользователю. Сам `CLAUDE.md` при этом не отменяется, но его роль сужается до **gotchas конкретного репозитория** — того, что из структуры кода не выводится; длинные процедуры уезжают в скиллы. Это же изменение объясняет, зачем `/doctor` предлагает обрезать `CLAUDE.md` (см. «Обновление 2.1.206–2.1.210» ниже) — не косметика, а следствие того, что лишние инструкции для пятёрки не нейтральны, а конфликтуют между собой. Полный разбор — [[context-engineering-claude-5]].

**Механика auto-memory (закрыто 2026-07-31, официальная документация [[claude-code-memory-docs]]).** Хранится в `~/.claude/projects/<project>/memory/` — индекс `MEMORY.md` (грузится в каждую сессию, лимит 200 строк/25KB) + тематические файлы (по требованию). Область видимости — один репозиторий на одной машине (не user/org уровни, как у `CLAUDE.md`); между машинами не синхронизируется; у субагентов своя отдельная auto-memory. Конфликт с `CLAUDE.md` формально не разрешается — оба источника необязательны к исполнению («context, not enforced configuration»), при противоречии Claude может выбрать любой; гарантированно исполнить правило можно только hook'ом. Отдельный вывод: auto-memory и [[claude-memory-tool|memory tool из Claude API]] — независимые механизмы, официальная страница о первом второй не упоминает вообще, несмотря на архитектурное сходство (индекс + файлы, just-in-time подгрузка). Полный разбор — [[claude-memory-tool]].

### Модели и Effort
Haiku — простые задачи; Sonnet — "золотая середина", ~80% работы (личная эвристика пользователя, не официальный показатель — см. [[moi-pravila]]); Opus — планирование, сложный ресёрч, самостоятельная разработка решения; Fable — самые тяжёлые/длинные автономные задачи. Effort (`low/medium/high/xhigh/max`, плюс `ultracode`) — бюджет на размышление перед действием; high/max — для архитектуры и глубокого ресёрча.

**Claude Opus 5 (2026-07-24, [[claude-opus-5-launch]]) — новая модель по умолчанию в Claude Code (v2.1.219).** Та же цена, что у Opus 4.8 ($5/$25 за MTok), но thinking включён по умолчанию (breaking change — на Opus 4.8 был выключен без явного запроса). **Отключить thinking можно только при effort `high` и ниже** — на `xhigh`/`max` попытка отключить возвращает ошибку. Anthropic прямо отмечает: Opus 5 сам добавляет верификацию своей работы без просьбы — унаследованные из промптов старых моделей инструкции вида "добавь шаг верификации" вызывают избыточную повторную проверку, стоит их убирать при следующей правке промптов (актуально для workflow-скриптов, см. [[dynamic-workflows]]).

**`opusplan` (официальное task-based автопереключение)** — единственный по-настоящему автоматический режим выбора модели по типу задачи, не эвристика: `/model opusplan` включает режим, где Opus используется в Plan Mode (сложное рассуждение, архитектура), а при переходе к выполнению сессия сама переключается на Sonnet (генерация кода). Экономия: Opus тарифицируется только на фазе планирования. Источник: [[claude-code-model-config-docs]].

**Другие автоматические переключения (не task-based, другая природа):**
- **Fallback-цепочки** (`fallbackModel` в settings / `--fallback-model`) — при перегрузке/недоступности модели сессия сама пробует следующую в списке; действует только на текущий ход.
- **Content-based fallback Fable 5** — если классификатор безопасности (кибербезопасность/биология) помечает запрос, сессия автоматически переключается на Opus 4.8 и остаётся на нём до ручного `/model fable`.
- **Max-плана усечение лимита** — по данным Help Center, при исчерпании лимита Opus сессия может автоматически откатиться на Sonnet; точный порог не публикуется.

### Permissions и .claudeignore
По умолчанию Claude Code спрашивает разрешение перед каждым действием — можно заранее разрешить безопасное (чтение файлов, тесты, git-операции, dev-серверы) и оставить под контролем опасное (установка пакетов, удаление файлов, внешние API-вызовы) через `settings.json`. `Bypass Permissions` — режим без вопросов вообще, использовать осторожно. `.env` и другие секретные файлы стоит явно закрывать от чтения через настройки — прямое применение [[ai-security-by-design|минимальных привилегий]]. Дополнительно есть `sandbox.credentials` — настройка, блокирующая доступ к файлам credentials в sandboxed-режиме, отдельно от `settings.json` allow/deny. **`mode: "mask"` (2.1.221, 2026-08-04, [[claude-code-changelog-snapshot-2026-08-04]])** — более гибкий режим рядом с блокировкой: на Linux/WSL сэндбоксированная команда видит файл-сентинел (весь файл или только фрагменты, пойманные regex-параметром `extract`), а реальное значение подставляется прокси сэндбокса на выходе (egress); на macOS маскирование недоступно, откатывается на `deny`. Инструменту не нужно видеть секрет целиком, чтобы им пользоваться — точечное применение минимальных привилегий из [[ai-security-by-design]].

**`sandbox.filesystem.disabled` (2.1.216, 2026-07-22, [[claude-code-changelog-snapshot-2026-07-22]]):** сэндбокс состоит из двух независимых слоёв — файловой и сетевой изоляции; эта настройка отключает только файловый слой, оставляя сетевой в силе. Полезно для тулчейнов (`kubectl`/`terraform`), которым нужен широкий доступ к диску, но не нужен произвольный сетевой доступ. Официальный компромисс: с отключённой файловой изоляцией сэндбоксированная команда может расширить себе доступ на будущее, переписав shell rc-файлы или файлы в `$PATH` — включать только для доверенных нагрузок; из настроек проекта включить нельзя, только user/managed.

**Расширение маскирования кредов (2.1.224, 2026-08-10, [[claude-code-changelog-snapshot-2026-08-10]]):** к `mode: "mask"` добавились `extract`/`onExtractNoMatch` (точечное маскирование по regex внутри структурированного env-значения, не всего секрета целиком), `decode: "jwt"` с `maskClaims` (маскирование конкретных claims внутри JWT) и `awsPairs`/`sigv4` (сэндбокс сам переподписывает AWS SigV4-запросы). Требует `network.tlsTerminate`, та же граница, что у `sandbox.filesystem.disabled` — доступно только из user/managed/`--settings`, не из проектного `.claude/settings.json`.

**`sandbox.network.strictAllowlist` (2.1.219, 2026-07-25, [[claude-opus-5-launch]]):** сетевой аналог — блокирует недоверенные хосты жёстко, без диалогового запроса подтверждения (раньше в части случаев сэндбокс мог спросить разрешение на новый хост вместо отказа). Дополняет `sandbox.filesystem.disabled` — теперь оба слоя сэндбокса имеют отдельную точечную настройку.

**Обновление терминологии (2026-07-09, [[claude-code-changelog-snapshot-2026-07]]):** режим "по умолчанию спрашивать разрешение" переименован в UI из "default" в **"Manual"** (значок ⏸ в статус-строке при включённом Manual mode) — сути не меняет, только название. Auto mode (автономный режим без ручных подтверждений) параллельно ужесточён: блокирует деструктивные git/инфраструктурные команды и правку файлов транскрипта сессии, спрашивает перед `rm -rf` на неразрешённых переменных.

**Применено в этой вики** (2026-07-08): `.claude/settings.json` содержит `deny` на чтение/правку `.env`/секретов (`*.pem`, `*.key`, `id_rsa` и т.п.), `allow` на чтение файлов/git-статус-diff-log/запуск тестов, `ask` на установку-удаление пакетов, `rm`, `curl`/`wget`.

**✅ Подтверждено практикой на 2026-07-08 (после перезапуска сессии).** Повторный тест всех трёх категорий правил дал ожидаемый результат: `deny` заблокировал чтение `.env` без запроса, `allow` пропустил `git status` без запроса, `ask` вывел запрос на подтверждение перед `rm -rf`. Гипотеза из предыдущего теста подтвердилась — конфиг `settings.json` подхватывается только при старте новой сессии, "живое" редактирование в открытой сессии не действует. Подробности теста и вывод — [[jarvis-personal-wiki]].

**Лимит субагентов на сессию убран (2.1.224, 2026-08-10, [[claude-code-changelog-snapshot-2026-08-10]]).** *Устарело:* ниже и в [[ai-security-by-design]] до этой правки числился лимит 200 суммарно за сессию (`CLAUDE_CODE_MAX_SUBAGENTS_PER_SESSION`, действовал с 2.1.212) — changelog 2.1.224 убрал его целиком: *"long-running sessions no longer refuse new agents (concurrency and depth limits still apply)"*. В силе остаются только лимит на одновременно бегущих (20 по умолчанию) и лимит вложенности (3 уровня по умолчанию) — оба описаны ниже, не изменились.

### MCP, Skills, Subagents, Agent Teams, Workflows — когда что использовать
- **[[mcp-model-context-protocol|MCP]]-серверы** — мост к внешним сервисам (Notion, Google Таблицы, календари, CRM) прямо из диалога, тот же механизм использует и [[claude-agent-sdk]]. `claude mcp login/logout` — аутентификация MCP-серверов из CLI без интерактивного меню.
- **[[claude-skills|Skills]]** — готовые плейбуки под конкретную задачу (копирайтинг, презентации); ставить только из проверенных источников (Anthropic, GitHub verified) — риск промпт-инъекций в чужих скилах, см. [[ai-security-by-design]]
- **Субагенты** — для проекта из многих независимых задач: каждый работает в изолированном контексте, отчитывается только главному агенту. С 2026-07-09 ([[claude-code-changelog-snapshot-2026-07]]) субагенты по умолчанию работают в фоне (не блокируют основной диалог до завершения). **Устарело (исправлено 2026-07-23):** до v2.1.216 включительно субагенты по умолчанию могли вкладываться до 5 уровней без возможности настройки; с **v2.1.217 поведение по умолчанию сменилось на противоположное** — субагент по умолчанию вообще не может породить своих субагентов (`Agent`-инструмент у него возвращает ошибку вместо спавна), вложенность включается явно через `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH` — см. раздел "Обновление 2.1.216–2.1.217" ниже. **Подтверждено 2026-07-27** (официальная страница `code.claude.com/docs/en/sub-agents`, полностью перечитана — закрывает нюанс от 2026-07-25/26, см. `wiki/gaps-backlog.md`): changelog v2.1.219 был прав — дефолт глубины вложенности вырос до **3** уровней. Страница также впервые дала точную историческую таблицу дефолтов по версиям: v2.1.172–2.1.216 — 5 (не настраивается); v2.1.217–2.1.218 — **1** (не 0, как записано в вики ранее — поведение то же самое, "вложенность выключена", но точное числовое значение переменной отличается); с v2.1.219 — 3. См. раздел "Обновление 2.1.218–2.1.219" ниже.
- **[[agent-teams|Agent Teams]]** (новее) — агенты общаются друг с другом напрямую, не только через главного; для сложных проектов, где нужна координация между задачами. С той же даты команды создаются неявно — явных команд `TeamCreate`/`TeamDelete` больше нет. **2026-07-09: тема развёрнута в полноценный концепт [[agent-teams]]** по официальной документации ([[claude-code-agent-teams-docs]]) — когда team вместо субагентов, размеры команд, failure modes, security-модель.
- **[[dynamic-workflows|Workflows]]** (2026-07-15, до этого пробел вики) — когда оркестрацию стоит закодировать как JavaScript-скрипт, а не оставлять её Claude "по ходу диалога": десятки-сотни агентов за прогон, resumable, повторяемые quality-паттерны (adversarial verify, judge panel, loop-until-dry). Отличие от трёх предыдущих механизмов — план держит скрипт, а не Claude или lead-агент; промежуточные результаты живут в переменных скрипта, не в контекстном окне.
- Простое правило источника: одна задача → один агент; несколько независимых задач → субагенты; сложный проект с координацией → Agent Teams; задача больше одной сессии или нужен воспроизводимый скрипт с quality-паттерном → Workflows (детальные критерии — в [[agent-teams]] и [[dynamic-workflows]])

### Safety net
**Checkpoints** создаются автоматически перед каждым изменением файла; `/rewind` откатывает к конкретной точке — особенно важно при автономной работе или Bypass Permissions.

### Автономный режим и параллельная работа
Флаг `-p` (`claude -p "задача"`) — выполнение без открытия приложения, для фоновых больших задач. **RALPH-loop** — большая задача выполняется итеративно самостоятельно (можно запустить на ночь). **Worktrees** (`claude --worktree`) — параллельные изолированные копии для независимых веток/фич, чтобы два диалога не портили файлы друг друга.

**Изменение поведения (2026-07-09, [[claude-code-changelog-snapshot-2026-07]]):** фоновые агенты (`claude agents`), закончив работу с кодом в worktree, теперь сами коммитят, пушат и открывают draft PR — вместо того чтобы останавливаться и спрашивать подтверждение. Это существенно повышает автономность по умолчанию; стоит явно проговаривать с пользователем перед запуском таких агентов на важных репозиториях, а не полагаться, что оно "просто спросит" как раньше.

**Уточнение (2.1.221, 2026-08-04, [[claude-code-changelog-snapshot-2026-08-04]]):** формулировка выше могла читаться так, будто draft PR открывается всегда — официальный changelog уточняет точнее: *"commit and push to preserve work, open a draft PR only when the task calls for one, follow your CLAUDE.md git instructions, and always end by reporting where the work lives"*. PR — решение по существу задачи, а не автоматический побочный эффект; фоновая сессия обязана следовать git-инструкциям конкретного `CLAUDE.md` (именно так уже работает раздел «Автономные рутины: инкрементальный коммит и пуш» в `CLAUDE.md` этой вики — коммит и пуш каждой законченной находки отдельно, без итогового PR).

### Автоматизации: Cowork Scheduler, Routines, `/loop` (2026-07-10, допроверено 2026-08-03 по официальной документации)
Помимо CLI-механик выше, есть отдельный слой автоматизации без открытой сессии: **Cowork Scheduler**/**Local Routines** (Desktop, пока включён компьютер), **Cloud Routines** (Anthropic-managed инфраструктура, работают при выключенном компьютере, без доступа к локальным файлам, без permission-промптов; триггеры Scheduled/API/GitHub — комбинируемые, а не взаимоисключающие), и `/loop` внутри текущей сессии CLI (self-paced режим через `ScheduleWakeup`, `loop.md` как персистентный дефолт-промпт, скедулед-файр с v2.1.196 не может вызывать скиллы с `disable-model-invocation`). Официальная документация также впервые называет и датирует (v2.1.214) security-механизм: сработавший триггер рутины — не живое подтверждение пользователя, только удостоверение, что промпт сохранён заранее авторизованной сессией; произвольный текст конкретного прогона (API `text`, Run Now) отдельно оборачивается в `<routine-fire-payload>` как недоверенные данные. Полная механика, таблица сравнения трёх способов и разбор security-части — [[claude-desktop-automation-modes]].

### Auto mode становится дефолтом с 14.08.2026 (2026-08-13, [[claude-code-auto-mode-default]])
Официальная документация (`code.claude.com/docs/en/permission-modes`): начиная с **14 августа 2026** auto mode — дефолтный режим разрешений для **новых** сессий на Pro/Max/Team вместо Manual. Не затрагивает сессии, где пользователь уже сам задал `defaultMode`, и org-управляемый дефолт (Team/Enterprise managed settings) — оба остаются в силе. `.claude/settings.json` этой вики `defaultMode` не задаёт, так что автономные прогоны этой вики зависят от дефолта уровня пользователя. Требования к доступности auto mode (модель Opus 4.6+/Sonnet 4.6+/Fable 5 на Anthropic API, доп. ограничения на Bedrock/Agent Platform/Foundry) не изменились этим релизом — см. подробности в источнике.
