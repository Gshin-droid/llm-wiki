# Letta (бывший MemGPT)

**Тип:** инструмент (см. "Допроверка 2026-08-10" — на момент ingest 07-07 описан как memory-as-OS framework, актуальный флагманский продукт сместился в сторону coding-агента с памятью)
**Актуально на:** 2026-11-21

## Что это (по состоянию на ingest 2026-07-07)
Память по метафоре операционной системы: main context = RAM (жёсткий лимит, обычно 16-32K токенов), recall storage = swap (полный лог сообщений), archival storage = disk (агент сам решает, что туда выгружать через свои function calls). Ключевое отличие от Mem0/Zep: управление памятью — не отдельный сервис, а операция, которой владеет сам агент. ([[shubin-llm-memory-landscape]])

**Не переподтверждено первоисточником 2026-08-10** — см. ниже, текущие официальные README (ни легаси-репозиторий, ни флагманский) эту метафору дословно не повторяют.

## Ограничения (по состоянию на 07-07)
Крутая кривая обучения (недели тюнинга системного промпта), лишние LLM-вызовы на каждое решение "что архивировать", мало production-историй по сравнению с конкурентами. ([[shubin-llm-memory-landscape]])

## Когда уместен (по состоянию на 07-07)
Нужен полный контроль над policy памяти (например: "помни жалобы 2 года, забывай транзакции через 30 дней"), регулируемые домены с требованием аудита. ([[shubin-llm-memory-landscape]])

## Допроверка 2026-08-10: активная разработка переехала в Letta Code

Ежедневный процесс закрытия пробелов, продолжение пункта «25 entity-страниц с просроченной пометкой "Актуально на"» (первыми — продукты). Прочитаны напрямую официальные репозитории `github.com/letta-ai/letta` (тот же, что цитировал источник 07-07) и `github.com/letta-ai/letta-code`.

Старый репозиторий `letta-ai/letta` сам себя описывает как **legacy Letta server** и прямо указывает, что активная разработка переехала в отдельный репозиторий агента (Letta Agent / `letta-code`). Флагманский продукт сегодня — **Letta Code**: "stateful agents that are like people, with memory, identity, and the ability to learn and adapt" — CLI/десктоп-инструмент (macOS/Windows/Linux, также облако и веб), распространяется через npm/desktop apps/Letta Cloud, по форме ближе к coding-агенту (наподобие Claude Code) с памятью как встроенной чертой, чем к библиотеке памяти для чужого агента. Архитектурно README называет: memory blocks с программной перезаписью контекста самим агентом ("agents programmatically rewrite their context to improve and adapt over time"), **MemFS** — git-отслеживаемый контекст, скиллы на уровне агента/проекта/глобально, встроенные субагенты (general-purpose, forked, recall, history-analyzer), запускаемые sync/async.

Легаси-репозиторий `letta-ai/letta` (тот, что старая память вики цитировала как первоисточник метафоры RAM/swap/disk) сегодня документирует не архитектуру памяти, а быстрый старт SDK: V1 SDK `@letta-ai/letta-client` (TypeScript) и `letta-client` (Python), требование Node.js 22.19+, поддерживаемые модели — Anthropic/OpenAI/zAI.

**Не подтверждено первоисточником:** ни один из двух текущих README дословно не повторяет метафору "main context = RAM, recall storage = swap, archival storage = disk" — она не опровергнута прямо (могла остаться внутренним устройством, просто не вынесенным в README верхнего уровня), но и не переподтверждена. Старое описание оставлено с пометкой "по состоянию на 07-07", не переписано и не удалено. Токен-лимиты, детали function-calls управления архивом и прямое сравнение с Mem0/Zep в текущих README не встречены — `docs.letta.com` заблокирован сетевым прокси окружения (`EGRESS_BLOCKED`), допроверить эти детали не удалось.

## Допроверка 2026-09-29: репозиторий перестроен — legacy V1 ушёл на отдельную ветку `archive`

Ежедневный процесс закрытия пробелов, обычный порядок (не воскресенье). Очередная сверка списка просроченных «Актуально на» (48 дн. на 09-27, без движения с 08-10) — тот же приоритет, что уже приводил к сверкам `mem0`/`zep-graphiti`. Прочитаны напрямую (`raw.githubusercontent.com`, дважды с требованием дословного текста) README `github.com/letta-ai/letta` и `github.com/letta-ai/letta-code`.

**Не расхождение, а перестройка репозитория с 08-10.** Тогда главная ветка `letta-ai/letta` сама описывала себя как *legacy Letta server* и документировала быстрый старт V1 SDK (`@letta-ai/letta-client`, Node.js 22.19+, модели Anthropic/OpenAI/zAI) прямо в README. Сейчас главная ветка — не quickstart, а редирект: дословно «Letta (f.k.a. MemGPT) is actively developed. The current source code lives in `letta-ai/letta-code`». Старый V1 API-сервер переехал на отдельную именованную ветку **`archive`** («retired Letta V1 API server», теги и релизы сохранены «for reproducibility»). Детали V1 SDK-квикстарта, которые допроверка 08-10 читала с главной ветки, в текущем README главной ветки уже не найти — они либо ушли в `archive`, либо в документацию; сама ветка `archive` этим прогоном не открывалась, отдельным пунктом не заводится, малозначимо (V1 официально сдан в архив).

**Новое, чего страница не знала.** Флагман `letta-ai/letta-code` описывает себя дословно как «a stateful agent harness for creating agents that are more like people than tools» — формулировка почти совпадает с записанной 08-10 («stateful agents that are like people, with memory, identity, and the ability to learn and adapt»), не расхождение. Сверх известного: поиск по истории сообщений («message search»), субагенты для координации нескольких агентов (то же слово «subagents», что уже упоминала запись 08-10, но здесь явно названо «multi-agent coordination»), планирование через «heartbeats and crons», **экспорт/импорт AgentFile объявлен deprecated**, выбор между Letta Cloud (по умолчанию) и локальным запуском при первом старте, поддержка ключей произвольных LLM-провайдеров (не только Anthropic/OpenAI), community-пакеты для Arch Linux (AUR) и Nix.

**По-прежнему не подтверждено.** Метафора «main context = RAM, recall storage = swap, archival storage = disk» — не встречена ни в одном из двух README и сейчас, как и 08-10. Токен-лимиты main context и спецификация function calls для архивации — тоже нет ни в одном README. `docs.letta.com` — один заход, снова `EGRESS_BLOCKED`, повторно не пробовать.

## Допроверка 2026-11-21: AgentFile полностью снят, появилась внешняя биржа навыков и удалённые компьютеры

Ежедневный процесс закрытия пробелов (субботний обычный порядок — проверено по дате, 2026-11-21 — Saturday). `python ingest.py pending` — инбокс пуст. Пункт `wiki/gaps-backlog.md` со статусом «не начато», закрываемый автономно без локальной машины/GPU/решения пользователя/уже многократно заблокированного домена — не нашёлся (все открытые позиции либо помечены «локально», либо упираются в домены, многократно вернувшие `EGRESS_BLOCKED`/`ENOTFOUND` в прошлых прогонах). Шаг 2 — допроверка страницы с открытым статусом: `letta` — самая давняя просроченная «Актуально на» среди продуктовых страниц (2026-09-29, 53 дня), кулдаун 3 дня соблюдён (страница не трогалась с 09-29). Прочитаны напрямую README `github.com/letta-ai/letta` и `github.com/letta-ai/letta-code` (`raw.githubusercontent.com`, без блокировки).

**AgentFile — прогресс от «deprecated» (допроверка 09-29) до полностью снятого.** README `letta-code` сейчас дословно: экспорт и импорт `.af` удалены, `/export`, `/download`, `--import` и `--from-af` (включая импорт из реестра агентов) не работают. Экспорт/импорт памяти и выгрузка транскриптов разговоров не затронуты — снят только формат агента целиком, не память как таковая.

**Новое, чего страница не знала:**
- **Внешняя биржа навыков** — `letta skills install` ставит навыки из GitHub, ClawHub и **Hermes Skills Hub** (просмотр/удаление — `letta skills list`/`letta skills delete`); Hermes уже упоминался в вики как одна из разобранных оболочек агентов ([[obolochki-agentov-chto-berem]]) — связь между двумя инструментами раньше не отмечалась.
- **Удалённые компьютеры** — `letta server --computer-name`, просмотр `letta computers list`, маршрутизация headless-сообщений через `--computer`, официальные гайды для Railway/DigitalOcean/Fly.io; старые названия `environments`/`envs` поддерживаются для совместимости.
- **Облако по умолчанию, локальный запуск — выбором**: `letta setup`/`letta backend cloud|local`/разовый флаг `--backend`; при облачном backend системные промпты при возобновлении становятся управляемыми облаком (пользовательские остаются явными), отключается через `LETTA_CODE_PRESERVE_CLOUD_SYSTEM_PROMPT=1`.
- **Переименование «sleep-time compute» → «dreaming»** — команды `/sleeptime`, `/dream`, `/reflect`, `/doctor`, `/palace`; на нативном Windows автоматическое клиентское «сновидение» по умолчанию выключено (включается `LETTA_ENABLE_WINDOWS_AUTO_REFLECTION=1`), на macOS/Linux/WSL и на серверном сновидении это не влияет.
- **Требования к платформе уточнены**: Python 3.9+ (сверх Node.js, который идёт в npm-пакете), поддерживаются glibc Linux 2.28+ (x86-64/ARM64), macOS 14+, Windows x64; явно не поддерживаются Alpine/musl, 32-битные системы, Windows ARM64.
- Легаси-репозиторий `letta-ai/letta` не изменился по существу с 09-29: главная ветка остаётся редиректом («actively developed… lives in letta-ai/letta-code»), V1 API-сервер — на ветке `archive`.

**По-прежнему не подтверждено, третий заход подряд (08-10, 09-29, 11-21):** метафора «main context = RAM, recall storage = swap, archival storage = disk» не встречается ни в одном README; токен-лимиты main context нигде не названы. `docs.letta.com` не пробовался — домен уже два подтверждённых подряд `EGRESS_BLOCKED` (08-10, 09-29), повторный заход не делался.

Звёзды `letta-code` — 3,9k (не отслеживались на прошлых сверках, точка отсчёта заведена этим прогоном).

Безопасность: прочитанные файлы — официальные README репозиториев GitHub, инструкций агенту не найдено. Ничего не устанавливалось.
