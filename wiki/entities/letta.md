# Letta (бывший MemGPT)

**Тип:** инструмент (см. "Допроверка 2026-08-10" — на момент ingest 07-07 описан как memory-as-OS framework, актуальный флагманский продукт сместился в сторону coding-агента с памятью)
**Актуально на:** 2026-08-10

## Что это (по состоянию на ingest 2026-07-07)
Память по метафоре операционной системы: main context = RAM (жёсткий лимит, обычно 16-32K токенов), recall storage = swap (полный лог сообщений), archival storage = disk (агент сам решает, что туда выгружать через свои function calls). Ключевое отличие от Mem0/Zep: управление памятью — не отдельный сервис, а операция, которой владеет сам агент. ([[shubin-llm-memory-landscape]])

**Не переподтверждено первоисточником 2026-08-10** — см. ниже, текущие официальные README (ни легаси-репозиторий, ни флагманский) эту метафору дословно не повторяют.

## Ограничения (по состоянию на 07-07)
Крутая кривая обучения (недели тюнинга системного промпта), лишние LLM-вызовы на каждое решение "что архивировать", мало production-историй по сравнению с конкурентами. ([[shubin-llm-memory-landscape]])

## Когда уместен (по состоянию на 07-07)
Нужен полный контроль над policy памяти (например: "помни жалобы 2 года, забывай транзакции через 30 дней"), регулируемые домены с требованием аудита. ([[shubin-llm-memory-landscape]])

## Допроверка 2026-08-10: активная разработка переехала в Letta Code

Ежедневный процесс закрытия пробелов, продолжение пункта «25 entity-страниц с просроченной пометкой "Актуально на"» (первыми — продукты). Прочитаны напрямую официальные репозитории `github.com/letta-ai/letta` (тот же, что цитировал источник 07-07) и `github.com/letta-ai/letta-code`.

Старый репозиторий `letta-ai/letta` сам себя описывает как **legacy Letta server** и прямо указывает, что активная разработка переехала в отдельный репозиторий агента (Letta Agent / `letta-code`). Флагманский продукт сегодня — **Letta Code**: "stateful agents that are like people, with memory, identity, and the ability to learn and adapt" — CLI/десктоп-инструмент (macOS/Windows/Linux, также облако и веб), распространяется через npm/desktop apps/Letta Cloud, по форме ближе к coding-агенту (наподобие Claude Code) с памятью как встроенной чертой, чем к библиотеке памяти для чужого агента. Архитектурно README называет: memory blocks с программной перезаписью контекста самим агентом ("agents programmatically rewrite their context to improve and adapt over time"), **MemFS** — git-отслеживаемый контекст, скиллы на уровне агента/проекта/глобально, встроенные субагенты (general-purpose, forked, recall, history-analyzer), запускаемые sync/async.

Легаси-репозиторий `letta-ai/letta` (тот, что старая память вики цитировала как первоисточник метафоры RAM/swap/disk) сегодня документирует не архитектуру памяти, а быстрый старт SDK: V1 SDK `@letta-ai/letta-client` (TypeScript) и `letta-client` (Python), требование Node.js 22.19+, поддерживаемые модели — Anthropic/OpenAI/zAI.

**Не подтверждено первоисточником:** ни один из двух текущих README дословно не повторяет метафору "main context = RAM, recall storage = swap, archival storage = disk" — она не опровергнута прямо (могла остаться внутренним устройством, просто не вынесенным в README верхнего уровня), но и не переподтверждена. Старое описание оставлено с пометкой "по состоянию на 07-07", не переписано и не удалено. Токен-лимиты, детали function-calls управления архивом и прямое сравнение с Mem0/Zep в текущих README не встречены — `docs.letta.com` заблокирован сетевым прокси окружения (`EGRESS_BLOCKED`), допроверить эти детали не удалось.
