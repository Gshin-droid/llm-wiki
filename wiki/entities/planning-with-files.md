# Planning with Files

Открытый (MIT) Agent Skill: персистентное файловое планирование для многошаговой работы агента. Держит три markdown-файла на диске (`task_plan.md`, `findings.md`, `progress.md`) вместо того, чтобы полагаться на память модели внутри контекстного окна — «Context Window = RAM (волатильно, ограничено) / Filesystem = Disk (персистентно, неограничено)», дословная формулировка автора.

**Тип:** инструмент (скилл по стандарту [Agent Skills](https://agentskills.io))
**Автор:** OthmanAdi
**Лицензия:** MIT
**Репозиторий:** https://github.com/OthmanAdi/planning-with-files
**Актуально на:** 2026-09-07

## Три файла

- **`task_plan.md`** — фазы и статус (`in_progress` → `complete`), с чекбоксами.
- **`findings.md`** — находки исследования по ходу задачи.
- **`progress.md`** — журнал сессии и результаты тестов.

Прямая параллель с `PROGRESS.md` из [[long-running-agent-harness]] (примитив Agent-Maintained Handoff) — независимая реализация той же идеи с разбивкой на три файла вместо одного и без привязки к git-коммитам как чекпоинтам.

## Механика

- **«Правило двух действий».** После каждых двух операций просмотра/браузера/поиска — немедленно сохранить ключевые находки в файл, чтобы не терять мультимодальную информацию между шагами.
- **Протокол трёх попыток при ошибке.** Первая — диагностировать и исправить; вторая — другой метод; третья неудача — эскалация человеку. Повторять один и тот же неудавшийся шаг запрещено правилом самого скилла.
- **Lifecycle hooks** переинжектят выбранный контекст плана на каждый ход (или раз в ход в autonomous-режиме, см. ниже), не давая плану выпасть из окна модели по мере роста диалога.

## Режимы v3 (опциональные)

- **Autonomous mode** — снижает частоту повторной инъекции плана до одного раза за ход вместо каждого хода.
- **Gated mode** (с v3.0.0) — гейт завершения: не даёт агенту остановиться, пока не все фазы плана отмечены `complete` одновременно; отдельная защита от stall (зависания на месте) — не даёт гейту превратиться в бесконечный цикл.

## Hash attestation (с v2.37.0)

Файл плана запечатывается SHA-256; расхождение хэша при инъекции даёт отказ с флагом `[PLAN TAMPERED]` вместо тихой инъекции испорченного тела — защита от порчи плана в многоагентных сценариях (несколько агентов/сессий пишут в один и тот же файл).

## Производительность инъекции

Хук оптимизирован с 2,0–2,4 с до **289 мс** на ход (с v3.6.0, консолидация в один Python-процесс) — держит план в стабильном месте промпта ради prompt cache (см. [[claude-api-cost-optimization]]: нестабильный префикс убивает кэш-хиты).

## Заявленные замеры (самоотчёт автора, не независимая проверка)

- **96,7% (29/30)** прохождения структурных ассертов на паттерн файлов, замер на Claude Sonnet 4.6, март 2026 — устаревшая по модели точка на дату этого разбора (09-2026), пока Sonnet 4.6 давно не последняя версия семейства.
- **3 из 3** побед в слепом A/B против агента-бейзлайна.
- **Восстановление после обрыва сессии** — в среднем 5,0 ходов до возврата к работе против 13,3 у агента без плана (≈62% сокращения на переориентацию).

Выборки маленькие (29/30, 3/3), методология и независимое воспроизведение не описаны в прочитанных файлах — цифры взяты как позиция автора, не как подтверждённый факт. Не проверялось отдельно.

## Охват платформ

60+ агентов через стандарт Agent Skills; нативные плагины для Claude Code, Codex CLI, Pi, Hermes Agent, OpenCode; отдельные гайды под Cursor, GitHub Copilot и другие IDE. Локализация — пять языков (арабский, немецкий, испанский, упрощённый/традиционный китайский); **русского нет**.

## Безопасность: необычно защитная формулировка description

Frontmatter `SKILL.md` (across всех host-вариантов репозитория) содержит явные security-заявления прямо в поле `description`, которое видит агент при авто-подключении: «no network upload path», `session-catchup.py --metadata` читает только локальные записи сессий **того же проекта** и отдаёт агрегированные счётчики, `--replay` — «bounded nonce-framed excerpts», gated mode «never runs commands declared in Markdown». Формулировка выглядит как прямой ответ на класс претензий, которым посвящена [[claude-skills]] → «Безопасность: цепочка поставок скиллов» (ToxicSkills, эксфильтрация через скилл, инструкции, замаскированные под markdown) — не подтверждено напрямую (нет issue/раздела «зачем эти формулировки» в прочитанном), но сама защитная риторика внутри поля, которое обычно просто описывает функцию, не техника защиты — редкость среди разобранных вики скиллов.
