# FreeCAD

Открытый (LGPL) параметрический CAD-редактор, используется как площадка для практического кейса «Claude как CAD-инженер» через MCP.

**Тип:** инструмент (открытое ПО)
**Актуально на:** 2026-08-24

## Что это
`freecad.org` — desktop-приложение для параметрического 3D-моделирования (детали, чертежи, инженерные расчёты), популярно у мейкеров и в 3D-печати.

## FreeCAD MCP (`neka-nat/freecad-mcp`)
Сторонний (не от Anthropic и не от разработчиков FreeCAD) MCP-сервер на GitHub, устанавливается как add-on внутрь FreeCAD и связывает его с [[claude-code|Claude Desktop]] через `UVX`. Разобран практически по [[makeform-freecad-mcp-tutorial]] — полный пошаговый сетап и работающий цикл «промпт → код Python API FreeCAD → скриншот вьюпорта обратно модели» подтверждены, не только заявлены автором.

## Зачем это нам — направление взято в работу 2026-08-24

Разбирая материал в тот же день, рутина отметила, что домен CAD и 3D-печати «в проектах пользователя не встречался», и брала кейс как пример MCP вне кодинга. **Это уточнено в тот же вечер: направление взято в работу целенаправленно** — интерес именно к моделированию с прицелом на 3D-печать, то есть на деталь, которую печатают и которая должна подойти по размеру.

Отсюда меняется и критерий оценки инструмента. Для «примера MCP» достаточно, что цикл работает; для печати нужна цепочка целиком: **промпт → геометрия → экспорт STL/3MF → слайсер → печать**, с размерами, которые не поплыли. Ни один из этих шагов, кроме первого, по [[makeform-freecad-mcp-tutorial]] не проверялся — туториал заканчивается на детали в окне FreeCAD.

**Три пути к одной задаче**, и FreeCAD+MCP только один из них:

| Путь | Как работает | Чем хорош / чем плох |
|---|---|---|
| **FreeCAD + MCP** (этот) | модель зовёт Python API редактора, видит скриншот вьюпорта | наглядно, живой редактор под рукой; зависит от стороннего сервера, дорого по токенам в screenshot-режиме |
| **Код вместо геометрии** — OpenSCAD или CadQuery | модель пишет скрипт, скрипт компилируется в модель и STL | параметрично и воспроизводимо: правка размера — это правка строки, а не перерисовка; исторически основной путь для 3D-печати |
| **Генераторы меша** (text-to-3D) | модель сразу выдаёт сетку | быстро и красиво для декоративного; **для функциональной детали не годится** — у меша нет размерных ограничений, а деталь должна попадать в допуск |

Общий вывод современных обзоров: надёжнее всего работает не «нейросеть рисует геометрию», а **нейросеть пишет код, который строит геометрию**. Что из этого лучше на наших задачах — вопрос замера, а не чтения; заведено пунктом в `gaps-backlog.md`.

**Что известно про риск.** Сервер `neka-nat/freecad-mcp` сам по себе не допроверялся ни рутиной, ни нами: звёзды, живость, открытые issues, кто автор — не смотрели. По туториалу известен один конкретный дефект: команда «закрыть все документы» закрывает несохранённое **без запроса подтверждения**, предупреждение приходит постфактум. Это ровно тот класс, о котором предупреждает [[ai-security-by-design]]: сторонний MCP-сервер исполняет действия в приложении, а подтверждение — не изоляция.
