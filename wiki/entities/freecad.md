# FreeCAD

Открытый (LGPL) параметрический CAD-редактор, используется как площадка для практического кейса «Claude как CAD-инженер» через MCP.

**Тип:** инструмент (открытое ПО)
**Актуально на:** 2026-10-08

## Что это
`freecad.org` — desktop-приложение для параметрического 3D-моделирования (детали, чертежи, инженерные расчёты), популярно у мейкеров и в 3D-печати.

## FreeCAD MCP (`neka-nat/freecad-mcp`)
Сторонний (не от Anthropic и не от разработчиков FreeCAD) MCP-сервер на GitHub, устанавливается как add-on внутрь FreeCAD и связывает его с [[claude-code|Claude Desktop]] через `UVX`. Разобран практически по [[makeform-freecad-mcp-tutorial]] — полный пошаговый сетап и работающий цикл «промпт → код Python API FreeCAD → скриншот вьюпорта обратно модели» подтверждены, не только заявлены автором.

## Зачем это нам — направление взято в работу 2026-08-24

Разбирая материал в тот же день, рутина отметила, что домен CAD и 3D-печати «в проектах пользователя не встречался», и брала кейс как пример MCP вне кодинга. **Это уточнено в тот же вечер: направление взято в работу целенаправленно** — интерес именно к моделированию с прицелом на 3D-печать, то есть на деталь, которую печатают и которая должна подойти по размеру.

Отсюда меняется и критерий оценки инструмента. Для «примера MCP» достаточно, что цикл работает; для печати нужна цепочка целиком: **промпт → геометрия → экспорт STL/3MF → слайсер → печать**, с размерами, которые не поплыли. Ни один из этих шагов, кроме первого, по [[makeform-freecad-mcp-tutorial]] не проверялся — туториал заканчивается на детали в окне FreeCAD.

**Три пути к одной задаче**, и FreeCAD+MCP только один из них:

| Путь | Как работает | Чем хорош / чем плох |
|---|---|---|
| **FreeCAD + MCP** (этот) | модель зовёт Python API редактора, видит скриншот вьюпорта | наглядно, живой редактор под рукой; зависит от стороннего сервера, дорого по токенам в screenshot-режиме |
| **Код вместо геометрии** — OpenSCAD или CadQuery | модель пишет скрипт, скрипт компилируется в модель и STL | параметрично и воспроизводимо: правка размера — это правка строки, а не перерисовка; исторически основной путь для 3D-печати |
| **Генераторы меша** (text-to-3D) | модель сразу выдаёт сетку | быстро и красиво для декоративного; **для функциональной детали не годится** — у меша нет размерных ограничений, а деталь должна попадать в допуск |

Общий вывод современных обзоров: надёжнее всего работает не «нейросеть рисует геометрию», а **нейросеть пишет код, который строит геометрию**. Что из этого лучше на наших задачах — вопрос замера, а не чтения; заведено пунктом в `gaps-backlog.md`.

**Допроверка сервера 2026-08-25** (шаг 1 из плана бэклога, прямая проверка репозитория `github.com/neka-nat/freecad-mcp`, ветка `master`, README + список открытых issues).

Живость подтверждена: 1.9k★, MIT, 147 коммитов на `main`, последний открытый issue — 12.08.2026 (13 дней назад на момент проверки), 6 открытых issues, ни один не про подтверждение деструктивных действий или потерю данных.

**Официальный список из 12 тулов README не содержит отдельного тула «закрыть документ»** (`create_document`, `create_object`, `edit_object`, `delete_object`, `execute_code`, `insert_part_from_library`, `get_view`, `get_objects`, `get_object`, `get_parts_list`, `get_rpc_status`, `run_fem_analysis`). Значит команда «close all documents» из туториала не была вызовом специального тула — она прошла через **`execute_code`**, который выполняет произвольный Python-код FreeCAD API. Это меняет масштаб риска: дело не в одной недодуманной команде закрытия, а в том, что `execute_code` даёт модели безусловный доступ к любому деструктивному вызову API редактора — удалению, перезаписи, закрытию без сохранения — **без единого механизма подтверждения где бы то ни было в сервере**. README документирует защиту только на уровне сети (remote-доступ выключен по умолчанию, IP whitelist) и на уровне зависаний GUI-диспетчера (таймаут → `GUI_DISPATCH_STUCK`) — ни то, ни другое не про подтверждение операций. Прежняя формулировка страницы («один конкретный дефект — закрытие документов») сужала находку туториала; исправлено на общий класс риска.

Это ровно то, о чём предупреждает [[ai-security-by-design]]: сторонний MCP-сервер исполняет действия в приложении, а подтверждение — не изоляция. Здесь изоляции и подтверждения нет вовсе там, где сервер даёт `execute_code`.

## Допроверка сервера 2026-10-08 (ежедневный процесс закрытия пробелов)

Повторное истечение порога (08-25 → сейчас, 44 дн.). README больше не один файл — распался на `docs/`; `docs/tools.md`, `docs/execution.md`, страница репозитория и список issues прочитаны напрямую (`raw.githubusercontent.com` + `WebFetch`).

**Рост, не расхождение:** звёзды **1.9k → 2.7k**, коммитов **147 → 222**, открытых issues **6 → 21**. Проверены заголовки всех 21 — ни один не про подтверждение деструктивных действий, потерю данных или безопасность `execute_code`.

**Находка, усиливающая прежний вывод, а не противоречащая ему.** Список тулов вырос **12 → 17** — добавились `list_documents`, `reload_document` и, главное, **два новых пути исполнения произвольного кода** сверх исходного `execute_code`: `execute_code_async` (фон, GUI-поток) и `execute_code_headless` (отдельный процесс `freecadcmd`). `docs/execution.md` дословно подтверждает отсутствие изменений в сути риска — «code execution still has FreeCAD's full privileges» — ни для одного из трёх путей подтверждения или sandboxing не описано. Найденные защиты — не про деструктивные действия: изоляция процесса от GUI-краша, таймауты (600 сек по умолчанию для headless), очистка временных файлов. Вывод страницы («execute_code даёт безусловный доступ без единого механизма подтверждения») не просто подтверждён — риск шире: теперь три пути, а не один.
