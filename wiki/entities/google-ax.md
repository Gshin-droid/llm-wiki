# Google AX

Открытая (Apache 2.0) среда выполнения агентов поверх Kubernetes: декларативные манифесты, CLI в духе `kubectl`, контрольные точки состояния. Попала в вики не как кандидат на установку, а как чужая формулировка вопроса «что такое агент с точки зрения инфраструктуры» — и как довод, что сетевой allowlist относится к несущим механизмам изоляции.

**Тип:** инструмент (среда выполнения / оркестратор агентов)
**Актуально на:** 2026-09-26 (допроверка Agent Substrate)
**Репозиторий:** `github.com/google/ax` · Go · **Лицензия:** Apache-2.0
**Состояние:** репозиторий создан 30.03.2026, релиз v0.3.0 — 20.09.2026; 6 645 звёзд, 316 форков (по API 22.09.2026)

## Исходная посылка

Агенты — *«ни stateless-микросервисы, ни batch-задачи, выполняемые до конца»*: они накапливают состояние, требуют строгой изоляции и способны съесть заметные ресурсы. AX рассматривает агента как **отдельный род нагрузки** и даёт под него четыре примитива:

- **Task** — изолированный запуск кода с лимитами процессора и памяти;
- **Workspace** — заранее подготовленное окружение (git-репозитории, серверы);
- **Gateway** — **контроль исходящего трафика по списку разрешённого**;
- **Model** — конфигурация языковой модели с доступом к учётным данным кластера.

Плюс `ax suspend` / `ax resume` — остановка с сохранением состояния и продолжение с той же точки, и `ax ssh` для отладки.

## Цена входа

Нужен кластер **Kubernetes**, сборщик контейнеров `ko`, доступный реестр образов и Control API нижележащей среды **Agent Substrate**. На одиночной рабочей машине не применимо.

Зрелость названа авторами прямо: базовые понятия и протоколы ещё уточняются, *«вероятны крупные ломающие изменения до стабильного релиза»*.

## Agent Substrate

Отдельный открытый (Apache 2.0) проект `github.com/agent-substrate/substrate` (3,8k★, 443 форка), не в организации Google на GitHub — принадлежность Google README не заявляет и не опровергает. Обязателен, не опционален: README `ax` дословно — *«Substrate must be running in your cluster before you deploy AX»*. Сам себя называет «secure-by-default agent execution runtime … 10x higher density than standard container runtimes», маппинг «акторов» на «воркеров»; зависимость от Kubernetes не убирает, а добавляет свой слой поверх неё (Kubernetes Pods управляют жизненным циклом воркеров). Тоже pre-1.0, без гарантий обратной совместимости. Есть ли альтернативные бэкенды для `ax` — не установлено, README Substrate вопрос не поднимает. Допроверка — [[google-ax-agent-runtime]].

## Осторожно со вторичными источниками

Вокруг релиза v0.3.0 выросла волна публикаций с непроверяемыми и противоречащими API цифрами (например «150 000 разработчиков за 48 часов» при 6,6 тыс. звёзд). Проверять по репозиторию — разбор в [[google-ax-agent-runtime]].
