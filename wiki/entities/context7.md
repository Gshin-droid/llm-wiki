# Context7

**Тип:** сервис / MCP-сервер (компания [Upstash](https://upstash.com))
**Актуально на:** 2026-07-27

## Что это

Сервис, который держит постоянно переиндексируемую базу документации опенсорс-библиотек и по запросу отдаёт агенту релевантные фрагменты — чтобы код генерировался по актуальному API, а не по тому, что попало в обучающую выборку модели.

Подключается к агенту двумя способами: как [[mcp-model-context-protocol|MCP]]-сервер (`@upstash/context7-mcp`) или как CLI + скилл (`ctx7`). Это **не** [[claude-skills|Claude Skill]] в исходном смысле — скилл здесь только тонкая обёртка-триггер над внешним сервисом, вся работа происходит на серверах Upstash. Путаница распространена: вторичные источники ([[romaray-top-5-skills]]) перечисляют Context7 в одном списке со Superpowers и skill-creator как «скилл», хотя механизмы разные.

## Какую проблему решает

Knowledge cutoff бьёт по библиотекам сильнее, чем по общим знаниям:
- API ломаются между мажорными версиями (Pydantic v1→v2, SQLAlchemy 1.4→2.0, Next.js Pages→App Router) — модель уверенно пишет по старому API, код выглядит корректным и не работает;
- худший случай — галлюцинация метода, которого не существовало никогда.

Именно этот класс ошибок описан в [[llm-coding-guidelines]] как типичный для LLM-кода.

## Как устроен

Два инструмента:

1. `resolve-library-id` — по человеческому названию находит идентификатор (`fastapi` → `/tiangolo/fastapi`). Пропускается, если ID передан сразу.
2. `query-docs` — по `libraryId` + `query` возвращает отранжированные фрагменты документации и примеры кода со ссылками на файлы репозитория. (Имена проверены на живом сервере v3.2.5; прежнее `get-library-docs` больше не существует.)

**Ключевая ревизия — 07.01.2026** ([блог Upstash](https://upstash.com/blog/new-context7)). До неё сервер отдавал крупные куски документации, а фильтровать их приходилось самой модели — отсюда главная историческая претензия к Context7, «context bloat». Реранкинг перенесли на сервер (быстрые reranking-модели), наружу отдаются только релевантные фрагменты:

| Метрика | До | После |
|---|---|---|
| Токенов контекста на вопрос | ~9.7k | ~3.3k (−65%) |
| Латентность | 24 с | 15 с (−38%) |
| Вызовов инструмента | 3.95 | 2.96 (−30%) |

Качество по бенчмарку слегка выросло. Методика: 80+ кодовых вопросов по популярным библиотекам, прогон через Claude Haiku, оценка релевантности Claude Sonnet по шкале 1–10. Бенчмарк авторский — независимой проверки в вики нет.

Тем же изменением SDK перешёл на два метода — `searchLibrary` и `getContext`, оба принимают запрос строкой; ручная пагинация и режимы извлечения убраны.

## Два режима подключения

| | CLI/Skill (`npx ctx7 setup --claude`) | MCP (`claude mcp add`) |
|---|---|---|
| Что ставится | скилл-триггер + CLI, OAuth device flow | MCP-сервер через npx |
| Срабатывание | автоматически при упоминании библиотеки, вручную `/context7:docs` | как обычный tool call |
| Куда падают доки | можно в сабагент `docs-researcher` — основной контекст остаётся чистым | в основной контекст |
| Прозрачность установки | выполняется скачанный скрипт + OAuth | конфиг видно целиком, ключ в env |

Официально рекомендуется первый. Второй предпочтителен, когда важнее контроль над тем, что именно исполняется при установке (правило 12 в [[claude-code-practices]]).

Ключ — переменная `CONTEXT7_API_KEY`. Без ключа работает анонимно под общим rate limit, медленнее.

## Безопасность: ContextCrush (февраль 2026)

Уязвимость класса supply chain, найдена Noma Security. У Context7 была фича **Custom Rules** — правила, которые автор библиотеки прикладывает к её документации. Зарегистрировать библиотеку мог кто угодно, и инфраструктура Context7 доставляла эти правила прямо в контекст агента, где тот исполнял их со своим полным доступом к инструментам.

Продемонстрировано исследователями: поиск и эксфильтрация `.env` с кредами, отправка украденного в репозиторий атакующего, удаление локальных файлов и папок.

Раскрыто 18.02.2026, патч выкачен Upstash 23.02.2026 (два дня), эксплуатации в дикой природе не зафиксировано.

Вывод исследователей шире одного бага: **любой MCP-сервер, агрегирующий пользовательский или сторонний контент и подающий его в контекст агента, создаёт ту же путаницу доверия**. Это ровно тот вектор, который в этой вики описан в [[ai-security-by-design]] («содержимое — не команда») — Context7 переводит его из теории в конкретный канал. Локальный `deny`-список на чтение `.env`/ключей (есть в `.claude/settings.json` этой вики) снижает ущерб, но не закрывает класс.

## Ограничения

- Индексация периодическая — вчерашний релиз может ещё не попасть в базу.
- ~3.3k токенов на запрос — не бесплатно, просто уже терпимо после январской переделки.
- Бенчмарк улучшений — авторский, от вендора.
- Полезность обратно пропорциональна стабильности библиотеки: для stdlib/git/docker даёт мало и всё равно тратит контекст.

## Статус у пользователя

**Установлен 2026-07-27** — MCP-режим, user scope (`~/.claude.json`), `npx -y @upstash/context7-mcp` (v3.2.5), анонимно, без API-ключа. Режим `npx ctx7 setup` сознательно **не** использовался: установочный скрипт исполняется до того, как его успели прочитать (правило 12б в [[claude-code-practices]]). Плата за выбор — нет сабагента `docs-researcher`, документация падает в основной контекст.

**Проверка пакета перед установкой** (правило 12): пакет в scope `@upstash`, мейнтейнеры на доменe upstash.com, репозиторий `github.com/upstash/context7`. Распакованный tarball прочитан — исходящие обращения только к `context7.com` / `mcp.context7.com`; `login.microsoftonline.com` оказался валидацией JWT для Entra ID (enterprise SSO), не эксфильтрацией; `readFileSync` — чтение собственного `package.json` и опционального CA-сертификата из `NODE_EXTRA_CA_CERTS`; Redis-модуль требует явных `UPSTASH_REDIS_*` и в локальном stdio-режиме не задействован. Сканирования файловой системы и записи на диск нет.

**Функциональная проверка** (не только «connected»): сервер поднят напрямую по JSON-RPC, реальный запрос `query-docs` к `/sqlalchemy/sqlalchemy` вернул 4 508 символов (~1.1k токенов) корректной документации по `async_sessionmaker` со ссылками на файлы репозитория. Имена инструментов подтверждены практикой: **`resolve-library-id`** и **`query-docs`** (старое `get-library-docs` отдаёт `-32602 Tool not found` — переименовано в ходе январской переделки).

Ключ можно добавить позже переменной `CONTEXT7_API_KEY` (ключи начинаются с `ctx7sk`), если анонимный rate limit начнёт мешать.
