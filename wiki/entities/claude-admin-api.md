# Claude Admin API

Программный доступ к администрированию организации Claude Console: пользователи, воркспейсы, API-ключи, сервис-аккаунты, лимиты — без похода в веб-консоль руками.

**Тип:** функция платформы (Claude Console / Claude Developer Platform, часть Claude API)
**Актуально на:** 2026-10-28

## Что это

`client.organization.*` в официальном Python SDK — эндпоинты уровня организации, отдельные от обычных вызовов Messages API (см. «Допроверка 2026-10-28» — раньше был `client.beta.organization.*`, namespace вышел из беты). Доступны только организациям Claude Console, Claude Enterprise (claude.ai) и Claude Platform on AWS — для индивидуальных аккаунтов недоступны вовсе. Аутентификация — OAuth-профиль со scope `org:admin` (`ant auth login --profile admin --scope org:admin`, рекомендован для сервис-аккаунтов), отдельный Admin API key, либо (см. допроверку) персональный/сервис-аккаунтный ключ без привязки к воркспейсу.

## Возможности

- **Пользователи** — приглашения по email (`invites.create`, срок жизни 21 день, не настраивается), список (`users.list`), смена роли — developer/user/billing (`users.update`), офбординг (`users.remove`).
- **Воркспейсы** — создание с метаданными-тегами (`workspaces.create`), правка названия/цвета/тегов (`workspaces.update`), явные участники (`workspaces.members.add`/`.list`).
- **Аудит API-ключей** — `api_keys.list` (возраст, срок действия, воркспейс, признаки использования), `api_keys.update` — деактивация (обратима, запросы падают немедленно) или архивация (**необратима**).
- **Сервис-аккаунты** — `service_accounts.create` + `service_accounts.workspaces.add`; принимают только OAuth-креды, Admin API key здесь отклоняется. У новых объектов возможна задержка согласованности (кратковременный 404 сразу после создания) — официальный notebook оборачивает такие вызовы в retry.
- **Лимиты** — `rate_limits.list` отдельно на уровне организации и на уровне воркспейса.
- **Federation issuers/rules** (найдено при допроверке 10-28) — регистрация OIDC-провайдеров и правил, по которым их токены подтверждают workload identity организации; только `org:admin` OAuth-токен, та же оговорка, что у сервис-аккаунтов.

## Ограничения, названные первоисточником

- Роль admin выдаётся только через веб-консоль — через API не назначается, и участников с ролью admin через API не удалить.
- Сами API-ключи тоже создаются только через консоль, не программно — Admin API умеет только читать, переименовывать и менять статус существующих.
- Архивация воркспейса необратима и разом отзывает все ключи в нём.
- При удалении участника организации: персональные ключи сразу перестают работать; ключи сервис-аккаунта продолжают работать, даже если создавшего их участника удалили, и останавливаются только при архивации самого сервис-аккаунта; ключи воркспейса продолжают работать; ключи в Claude Code workspace привязаны к создавшему их участнику и останавливаются вместе с ним.

## Допроверка 2026-10-28

Первая содержательная сверка с ingest (09-21 → сейчас, 37 дней), `platform.claude.com/docs/en/manage-claude/admin-api` прочитана целиком напрямую через `WebFetch`, без блокировки.

**Исправление, не просто рост.** SDK-намespace сменился с `client.beta.organization.*` на **`client.organization.*`** — Admin API вышел из бета-неймспейса; старое название эндпоинтов ingest'а (09-21) устарело, а не было неточным на момент записи.

**Чего страница не знала вовсе:**
- **Три способа аутентификации, не два.** Кроме Admin API key и OAuth `org:admin`-токена, Admin API принимает **персональный ключ или ключ сервис-аккаунта без привязки к конкретному воркспейсу** — он несёт те же права, что у привязанного аккаунта, передаётся в том же заголовке `x-api-key`.
- **Federation issuers/rules** — два новых класса сущностей (`fdis_...`, `fdrl_...`) для Workload Identity Federation: issuer регистрирует OIDC-провайдера, rule — правило, по какому токену какой сервис-аккаунт и с каким scope выдаётся. Оба требуют `org:admin` OAuth, как и сервис-аккаунты.
- **Доступность шире одной Console-организации.** Claude Enterprise (claude.ai) организации тоже зовут Admin API — но только members/invites, плюс эксклюзивные для Enterprise эндпоинты (чтение групп и custom-ролей, spend limits, Plugins API и Claude Tag API — обе в бете). На **Claude Platform on AWS** доступен совсем другой, узкий набор — только workspace CRUD, CMEK external-key эндпоинты и telemetry destinations; участники организации/воркспейса, инвайты, API-ключи и отчёты usage/cost/rate-limit там не работают вовсе.
- **Таблица организационных ролей — пять, не три.** `user` (playground), `claude_code_user` (playground + Claude Code), `developer` (+ управление API-ключами), `billing` (+ биллинг), `admin` (всё плюс управление пользователями); owner/primary owner имеют все права admin плюс управление самими admin-ами. Страница знала только три роли смены (`users.update`).
- **Поведение API-ключей при офбординге** (раздел выше) — страница знала только то, что архивация воркспейса отзывает ключи разом; четыре отдельных сценария при удалении пользователя не были описаны вовсе.
- **Соседние API названы явным списком, не только упомянуты вскользь:** Usage and Cost API, Claude Code Analytics API, Rate Limits API, **Compliance API** (Admin API key читает только Activity Feed, полный доступ требует отдельной настройки) и **Organization webhooks** (события принудительных действий над профилями пользователей организации) — последний вообще не был известен странице.

Деталь про OAuth/Admin-key/сервис-аккаунты для `service_accounts`/federation подтверждена без расхождений («accept only an `org:admin` OAuth token»).

Безопасность: прочитана только официальная документация `platform.claude.com`; текста, похожего на инструкцию для агента, не найдено.

## Почему это не топ-находка этой вики

Весь механизм рассчитан на организацию с несколькими участниками — приглашения, роли, воркспейсы под команду. У пользователя этой вики Claude Console используется соло, без второго участника или отдельных воркспейсов. Материал зафиксирован как часть ландшафта платформы: закрывает пробел (факт «Admin API user-management вышла из беты» лежал на [[claude-code-changelog-snapshot-2026-08-22]] с 08-19 без единого практического примера), но без применения к текущим проектам пользователя — поэтому без ⭐.
