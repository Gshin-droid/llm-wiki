# Mem0

**Тип:** инструмент (memory framework / библиотека)
**Актуально на:** 2026-08-09

## Что это
Библиотека памяти для собственных ИИ-агентов на API (не для пользователей готовых продуктов вроде Claude.ai). Извлекает факты из сообщений через LLM, хранит в векторной базе, применяет ADD/UPDATE/DELETE/NOOP при новых фактах. В свежих версиях упрощена до однопроходного ADD-only + entity linking, поддержка графовых хранилищ убрана (подтверждено официальным `github.com/mem0ai/mem0`, `git clone` 2026-08-09: в README и коде репозитория ни одной директории/упоминания graph store не осталось).

## Ограничения

**Устарело (актуально до апреля 2026, снято официальным обновлением — см. ниже):** ~~Нет временной модели (может перепутать старый и новый факт при противоречии)~~.

Embedding-поиск не всегда склеивает семантические дубликаты на больших объёмах — актуально, официальный README на это ограничение прямо не отвечает.

## Допроверка 2026-08-09 (ежедневный процесс закрытия пробелов): "New Memory Algorithm" (апрель 2026)

Прочитан официальный README репозитория напрямую (`git clone github.com/mem0ai/mem0`, не сторонний форк). С апреля 2026 объявлен новый алгоритм памяти, который прямо снимает записанное выше ограничение «нет временной модели» — добавлена **Temporal Reasoning**: time-aware retrieval, которая при запросе ранжирует нужную по времени версию факта (текущее состояние / прошлое событие / будущий план), а не путает старую и новую версию, как раньше.

Дословно из README, раздел "New Memory Algorithm (April 2026)", остальные заявленные изменения: **Single-pass ADD-only extraction** (без изменений — та же логика, что уже знала вики) + новое: **Agent-generated facts as first-class** (факты, подтверждённые самим агентом, теперь хранятся с равным весом), **Multi-signal retrieval** (semantic + BM25 keyword + entity matching, слитые параллельно).

Бенчмарки, приведённые README (managed-платформа Mem0, не open-source SDK "as is" — оговорка самого README: open-source ожидает "похожий по направлению, но не идентичный" прирост):

## Дополнение (2026-08-07, [[berezhnitsky-agent-memory-lies]]): почему ADD-only — это не упрощение, а вывод

Переход на «только добавление», записанный выше как факт версии, получил объяснение. В Mem0 пытались решить противоречия при записи: новый факт спорит со старым — пусть модель перезапишет старое. Поставили симуляцию, где предпочтения пользователя меняются по ходу, и смотрели, разделит ли модель старое и новое или свалит в кучу. На паре фактов работает; на сотнях, где часть уже сменилась, надёжно разруливать не выходило — противоречия оставались висеть. Отсюда отказ от перезаписи: новые записи добавляются, ничего не переписывается и не удаляется, история остаётся на месте.

Это же и есть общий ответ на «накопление противоречий» в [[agent-memory-five-questions]] (вопрос 2): append-only даёт ноль конфликтов при слиянии в любом порядке, а осмысление выносится в отдельный периодический проход поверх лога. Ограничение «нет временной модели» выше при этом никуда не девается — добавление сохраняет обе версии факта, но не отвечает, какая из них верна сейчас; это закрывает [[zep-graphiti]] закрытием записи датой.

Название исследования и его детали даны в источнике на слух, без ссылки — механизм взят, цифр в нём нет.

## Когда уместен
Свой агент на API, нужна персонализация под пользователя, десятки тысяч фактов без экзотики. Не нужен, если хватает встроенной памяти Claude/ChatGPT как продукта.
