# Laya

Открытая (Apache 2.0) модель на 322–421M параметров, выдающая не текст, а **типизированное решение**: вероятность истинности, выбор из вариантов или оценку по шкале. Попала в вики как пример пропущенной ступени делегирования — обученный классификатор там, где по привычке зовут языковую модель.

**Тип:** модель (движок типизированных решений)
**Актуально на:** 2026-09-22
**Разработчик:** Convai Innovations · **Репозиторий:** `github.com/NandhaKishorM/laya` · веса на Hugging Face (`convaiinnovations/laya`)

## Чем отличается от языковой модели

Не авторегрессионная: ответ не генерируется по токену, а получается **одним проходом сети** — отсюда 33 мс на GPU и меньше гигабайта памяти. Платой идут жёсткие рамки: контекст 512–1024 токена, никакого рассуждения, текста на выходе нет вообще. Три примитива — `noul` (калиброванная вероятность 0.0–1.0), `choice` (метка + вероятности вариантов), `score` (уровень по порядковой шкале).

Обучена методом RLCD — обучение с подкреплением по **строго правильным правилам скоринга**: награда не за угаданный ответ, а за честно названную вероятность. Следствие — хорошая калибровка (ECE 0,081 против 0,144 у [[jev-typesafe]]), см. [[kalibrovka-uverennosti-resheniy]].

Установка `pip install laya`, Python 3.10+; рекомендуемый вход — через `Router`, который сам выбирает контрольную точку.

## Где выигрывает и где проигрывает

Выигрывает у платного облачного [[jev-typesafe]] в скорости (32,8 мс против 236–276 мс, в 7,8 раза), в калибровке и на части задач (типизированные решения 0,766 против 0,727; DAIR Emotion 0,595 против 0,480).

Проигрывает там, где авторы это прямо называют: **больше 50 вариантов выбора** (Banking77 — 0,425 против 0,870), порядковые шкалы (SST-5 — 0,372), любой язык кроме английского у английской версии. Многоязычная версия слабее на английском. Базовые энкодеры без дообучения работают на уровне случайного угадывания — ценность создаёт дообучение, а не архитектура.
