# shunt (Spotify)

Плагин Claude Code от Spotify: хук запрещает читать целиком файлы длиннее порога (по умолчанию 350 строк) и отправляет их дешёвой модели за выжимкой; типовой код пишет дешёвая модель сразу на диск. Работает только через внутреннюю платформу Spotify Portal. Не ставим.

**Тип:** инструмент (плагин Claude Code, Apache-2.0)
**Автор:** Spotify
**Актуально на:** 2026-11-27 (допроверка по первоисточнику)
**Ссылка:** https://github.com/spotify/portal-ai-plugins

## Допроверка 2026-11-27

Последняя из пяти никогда не допроверявшихся по первоисточнику страниц воскресного механического прохода 11-22 (вместе с `claude-agent-sdk`/`gstack`/`inspo`/`ponytail`, все четыре уже закрыты 11-23…11-26). README `plugins/shunt/README.md` прочитан напрямую через прямой `git clone github.com/spotify/portal-ai-plugins` (сработал без блокировки сети); страница репозитория — через `WebFetch`.

**Без расхождений.** Порог делегирования (350 строк, `SHUNT_MIN_LINES`), три слоя (хуки → скрипты с именованными параметрами → скиллы), запрет конвейеров из прозы, платформа Spotify Portal как обязательная зависимость, 51 тест маршрутизации/обвязки (17+17+17 — read-hook/bash-hook/transport) плюс отдельно 3 end-to-end и 4 бенчмарк-сценария, цифры замера (82%/94%/94%, в среднем 90% на 162-тысячестрочном Java-монорепо) — всё подтвердилось дословно первоисточником.

**Код плагина не менялся с момента ingest'а.** `git log` по `plugins/shunt/` показывает всего два коммита, оба от **2026-08-14** (добавление + правка таблицы замера в README) — почти на два месяца раньше ingest'а страницы (10-19) и единственный коммит всего репозитория с 10-12 (23.10, #24) правит другой плагин (`fleetshift-run-shift`), не `shunt`. Рост звёзд/форков/issues — это рост внимания к репозиторию, не изменение самого инструмента.

**Рост:** звёзды ~2 500 → **3,3k**, форки — **260** (не были известны), открытых issues — **13** (не были известны). Тегов/релизов и `CHANGELOG.md` в репозитории по-прежнему нет.

**Новые детали, которых страница не называла.** (1) Механизм делегирования официально называется **«AiKA modes»** (Portal CLI, один вызов `aika:invoke-chat` на делегирование; режимы ищутся по имени регистронезависимо: сначала свои, потом групповые, потом публичные) — термин уже был в самом первом коммите 08-14, не новая терминология, страница просто не называла его явно. (2) Вызов — **одноразовый**: `aika:invoke-chat` ничего не хранит на сервере, повтор контекста плагин намеренно не делает (каждый вызов самостоятелен). (3) **Ограничение, которого страница не знала:** хук блокирует только `bulk-reader` (`check-file-size`/`check-bash-read`); `code-writer` вообще не защищён хуком и работает только через узнавание по описанию скилла — Claude может пропустить делегирование генерации кода, и ничто это не поймает. (4) Полная таблица конфигурации (`SHUNT_PORTAL_INSTANCE`, `PORTAL_CLI_BIN`, `SHUNT_MAX_PAYLOAD_BYTES` — 400000/120000 на Linux, `SHUNT_TIMEOUT_SECONDS=180`, `SHUNT_BULK_READER_MODE_ID`/`SHUNT_CODE_WRITER_MODE_ID`) — страница знала только порог строк. (5) Предпосылки — `jq` и плагин `portal` того же маркетплейса, установка через `/portal:setup`.

Деталь не проверена, решение не меняется — плагин всё ещё не ставим (без Spotify Portal не работает, свой замер 10-19 уже показал, что переносить незачем).
