# OpenJev-Verdict-2.0

Открытая (Apache 2.0) модель типизированных решений на 149,6M параметров — третий известный вики инструмент этого класса рядом с [[laya]] и [[jev-typesafe]]. Заявляет превосходство над обеими на собственном тестовом наборе.

**Тип:** модель (движок типизированных решений)
**Актуально на:** 2026-10-14
**Разработчик:** Heman10x-NGU · **Репозиторий:** `github.com/Heman10x-NGU/openJev-verdict-2.0` · 268 звёзд · веса частично на Hugging Face (`heman10x/rlcd-modernbert-151m` — предыдущая версия, Verdict 1.0), частично в Git LFS репозитория (`artifacts/verdict2-base/model.pt`)
**Лицензия:** Apache 2.0 (файл `LICENSE` — стандартный полный текст, подтверждено прямым чтением)

## Заявленные цифры (авторские, не независимые)

Точность 77,10% / Brier 0,0636 / ECE 0,0144 на тестовом наборе `LocalLLaMA/typed-decisions` (2000 отложенных решений — финансы, безопасность, поддержка, трассы агентов), задержка ~20–25 мс. Для сравнения на этом же наборе: [[laya]] (ModernBERT-large, 421,3M) — 76,60%; [[jev-typesafe]] (TypeSafe Jev 1.13.0) — 72,70%. Обучение — 8,8 часа на одной GTX 1660 Ti (6 ГБ VRAM); модель для WebGPU-исполнения весит <600 МБ.

**Оговорка важнее цифр:** тестовый набор и подсчёт готовит и запускает сам автор репозитория (`verdict2/evaluate.py`), независимой проверки нет — то же ограничение, что у [[jev-typesafe]] («сведения от конкурента»), только в квадрате: конкурент здесь оценивает и себя, и обоих соперников одним и тем же скриптом.

## Метод обучения

RLCD — то же название, что и у [[laya]] (обучение по строго правильным правилам скоринга: награда за честно названную вероятность, а не за угаданный ответ). Название найдено в имени модели-предшественника на Hugging Face — `rlcd-modernbert-151m`. *Допроверка 2026-10-02:* первоисточника у этого имени нет — ни одно из двух README не ссылается на статью, а реально опубликованный метод с тем же акронимом (Yang et al., «RLCD: Reinforcement Learning from Contrast Distillation», arXiv:2307.12950) занят генерацией контрастных пар предпочтений для RLHF и к proper scoring rules не имеет отношения. Совпадение названия у Laya и openJev теперь не читается как подтверждение общепринятого метода — скорее переиспользование одного и того же непроцитированного лейбла внутри ниши, см. [[laya-local-decision-engine]].

## Известный дефект калибровки

До версии 1.4 движок не загружал `calibrator.json` при автономной инициализации — работал при некалиброванной температуре 1.0 без предупреждения. Отдельная, не полностью закрытая ошибка: охват калибровки распространялся только на запросы ровно с 5 кандидатами, для другой мощности вариантов требуется доработка. Автор описывает это сам. См. [[kalibrovka-uverennosti-resheniy]] — калибровка не разовое свойство модели, а часть инфраструктуры вокруг неё, которая тоже может тихо сломаться.

## Допроверка 2026-10-14: лицензия, требования к запуску, третий вариант RLCD

Закрывает пункт бэклога, заведённый 2026-09-22 (лицензия/требования/языки/набор данных не проверялись). Метод: прямой `git clone github.com/Heman10x-NGU/openJev-verdict-2.0` (сработал без прокси, тот же приём, что у [[pi-coding-agent]]/[[impeccable]]), чтение `LICENSE`, `README.md`, `AGENTS.md`, `pyproject.toml`, `rlcd/__init__.py`, `data/dataset_manifest.json`, `data/real_benchmark_manifest.json`, `verdict2/data.py`, `verdict2/evaluate.py`.

**Лицензия** — Apache 2.0, подтверждено файлом (не только бейджем в README).

**Требования к запуску:** Python ≥3.10, пакет называется `rlcd` (не `openjev`); зависимости — `torch`, `transformers`, `gliclass`, `safetensors`, `onnx`+`onnxruntime`, `pydantic`, `accelerate`. Отдельно браузерный WebGPU-плеер (`webgpu-demo/`) — без установки чего-либо, нужен только локальный статический сервер (`python3 -m http.server`) и Chrome/Edge.

**Языки** — явной заявки о мультиязычности нет; `core/banking_glossary.py`/`core/formatting.py` строят *natural-language* описания категорий для backbone GLiClass/ModernBERT-base на английском, русский или любой другой язык не упоминается ни разу во всём репозитории.

**Набор данных, на котором получены цифры.** `LocalLLaMA/typed-decisions` — не самодельный, а подгружается штатно через `datasets.load_dataset("LocalLLaMA/typed-decisions", "all", split=...)` в нескольких скриптах (`verdict2/data.py`, `scripts/evaluate_verdict_baseline.py`, `scripts/analysis/reference_floors.py`) — то же публичное имя датасета на Hugging Face, что уже известно вики по [[laya]]/[[jev-typesafe]], не отдельная подделка под похожим именем. При этом сноска к таблице сравнения в README прямо признаёт: цифры Jev/Laya — «vendor baseline cataloged in Laya's published evaluation suite», то есть взяты из чужого опубликованного замера, а не прогнаны автором openJev самостоятельно; только цифры самой openJev-verdict-2.0 — собственный прогон `verdict2/evaluate.py` с «аудированной» квитанцией (`reports/verdict2_base_test.json`).

**Побочная находка — другой набор с отметкой о загрязнении теста.** В `data/` лежит отдельный, более старый набор (`real_banking_*.jsonl`, `dataset_manifest.json`) не на базе `LocalLLaMA/typed-decisions`, а на Banking77 (`PolyAI-LDN/task-specific-datasets`) и CLINC150 (`clinc/oos-eval`) — его собственный манифест дословно называет `"test_contamination_count": 211` при 500 тестовых примерах (42%). Второй, более новый манифест (`real_benchmark_manifest.json`) помечен версией `"2.0.0-honest-splits"` — похоже на попытку исправить именно эту утечку отдельным, более аккуратным сплитом. Этот набор не тот, на котором считались цифры сравнения из раздела «Benchmark breakthrough» (там `LocalLLaMA/typed-decisions`), поэтому находка не меняет заявленные цифры, но показывает, что у самого проекта уже случалась утечка теста в обучение на другом из его же бенчмарков — повод не доверять будущим цифрам без проверки `*_manifest.json` каждого набора.

**RLCD — третий самостоятельный вариант расшифровки, не второй.** `AGENTS.md` этого репозитория прямо расшифровывает акроним как «**Reinforcement Learning for Calibrated Decisions**» — третья формулировка под одним и тем же акронимом, не совпадающая ни с фразой [[laya]] («обучение по строго правильным правилам скоринга»/«against strictly proper scoring rules»), ни с реально опубликованным методом Yang et al. (Reinforcement Learning from **Contrast Distillation**, arXiv:2307.12950). Ни одна из трёх не цитирует источник. Вывод допроверки 10-02 («совпадение названия — не подтверждение общепринятого метода, а переиспользование непроцитированного лейбла внутри нишевого кластера») усиливается: третий независимый проект того же кластера приписывает тому же акрониму третий смысл, а не повторяет чужой.

## История версий

Verdict 1.0 (151M, HF `rlcd-modernbert-151m`) заявлен как «baseline» с результатом 26,10% точности. Verdict 2.0 (149,6M, другая версия) — 77,10%. Резкий скачок между версиями на разном числе параметров — сигнал быстро меняющегося, ещё не устоявшегося проекта (268 звёзд).

## Решение: не используем (2026-09-23)

Как и облачный [[jev-typesafe]], в конвейер не идёт — решение о моделях решений принято 2026-09-22: используется только [[laya]] как локальная ступень 0.5, эскалация ведёт сразу к языковой модели. Появление openJev-verdict-2.0 это не меняет: заявленное превосходство не подтверждено независимо, а сам продукт моложе и менее устоявшийся, чем уже отклонённый [[jev-typesafe]].
