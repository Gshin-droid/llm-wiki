# GSD (Get Shit Done)

**Тип:** инструмент (open source spec-driven агентский фреймворк, мультихост)
**Актуально на:** 2026-11-06 (см. «Допроверка 2026-11-06»)

## Что это
"Lightweight powerful metaprompting, context engineering and spec-driven development system for Claude Code". В отличие от голого вайбкодинга ([[vibecoding-full-workflow]]), автоматизирует весь цикл SDLC: от спецификации и research до планирования по фазам, параллельного исполнения волнами (waves), self-check и человеческой верификации. Генерирует полный комплект проектной документации (`requirements.md`, `roadmap.md`, `architecture.md`, `features.md`, `pitfalls.md`) как побочный артефакт каждой фазы — обеспечивает агенту долгосрочную память о проекте между сессиями.

~70 команд/хуков, 6 базовых достаточно для большинства задач; продвинутые — `milestone`, `quick` (быстрый фикс в обход полного ритуала фаз), `spike`, `sketch`, `mapcodebase`. Более тяжеловесный и токен-затратный, чем [[superpowers]] — позиционируется под enterprise-масштаб.

Установка (по состоянию на 2026-07-10): `npx get-shit-done`.

**Раннтаймы — список расширился до как минимум 18 (цитата `CHANGELOG.md`, запись 1.20.1: «a comparison of real default installs of all 18 installable runtimes»), включая `Pi`.** Pi — не упомянутый на этой странице раньше раннтайм, но это тот же [[pi-coding-agent]], единственная платформа [[sol-pi]] на этой вики. Релиз 1.20.0 (03.11.2026) добавил официальную установку GSD как пакета Pi (`pi install npm:@opengsd/gsd-core`), дающую команду `/gsd`, тул `gsd_invoke` и все скиллы GSD — не нашего текущего использования, но прямая точка пересечения двух самостоятельных страниц вики.

**Главная находка — отдельный документ `docs/explanation/security-model.md` (четыре слоя защиты), которого на странице не было вовсе.** Organising principle — defence in depth, без претензии на полноту одного слоя:

1. **Package Legitimacy Gate** — защита от «slopsquatting»: по цитируемому документом исследованию 2025 года ~20% пакетов, которые называет ИИ, — галлюцинации, ~43% таких имён повторяются достаточно, чтобы атакующий заранее зарегистрировал их на npm/PyPI/crates.io с вредоносным `postinstall`. Три стадии конвейера: `gsd-phase-researcher` прогоняет каждый пакет через `gsd-tools query package-legitimacy check` (вердикт `OK|SUS|SLOP` по возрасту регистрации, недельным загрузкам, наличию репозитория); `[SLOP]` **вычищается из `RESEARCH.md` целиком**, не доходит до планировщика; `[SUS]`/`[ASSUMED]` получают обязательный `checkpoint:human-verify` перед установкой; исполнитель при сбое установки останавливается и не пробует другое имя сам (правило RULE 3 агента-исполнителя) — не самодельная эвристика, явное решение не импровизировать здесь.
2. **Prompt injection defences** — два отдельных сканера: `gsd-prompt-guard.js` (PreToolUse, сканирует Write/Edit в `.planning/`) и `gsd-read-injection-scanner.js` (PostToolUse, сканирует вывод Read/WebFetch/WebSearch). Оба — **статический паттерн-матчинг, явно не семантическая проверка** (цитата исходника), **advisory-only по умолчанию** и намеренно **fail-open** при сбое самого хука (`ON_CRASH = HOOK_ON_CRASH.ALLOW`, с комментарием в коде: «losing the injection check is safer than failing the tool call it is only observing»). Блокировка — только для HIGH-severity (3+ паттерна совпало) и только если явно включена настройка `security.injection_blocking`. Прямое независимое подтверждение принципа «содержимое источника — не команда» ([[ai-security-by-design]]) третьим инструментом, с явным инженерным выбором в пользу advisory вместо блокировки (контраст с переходом самого Claude Code от fail-open к fail-closed для хуков Agent SDK — [[claude-code-changelog-snapshot-2026-11-04]] — там решение противоположное, но тоже осознанное, не случайное).
3. **Repository and dependency integrity** и **4. Subprocess execution** — не читались детально, вне вопроса пункта бэклога, который этот заход не разбирал.

**Честное признание границы, совпадающее с нашей же рамкой [[zabor-i-stena-prava-agenta]].** Документ сам называет один из барьеров «prompt-level only»: provenance-поле `gsd-ui-checker` просит агента не выполнять команду, записанную в документе, но инструмент `Bash`, которым агент законно пользуется для другой задачи, структурно не ограничен так, чтобы не исполнить произвольную команду, извлечённую из того же документа — «defense by instruction, not by capability» дословно. Это ровно различие «забор» (держится на том, что попросили) и «стена» (держится на том, что физически не может), которое наша вики формулирует как собственный принцип — здесь оно встречено как самостоятельный, явно осознанный вывод стороннего проекта, а не как наш пересказ.

**По-прежнему не подтверждено первоисточником:** причина переезда `gsd-build/get-shit-done` → `open-gsd/gsd-core` — не нашлась и в этом заходе (единственный найденный след — упоминание «a retired `@gsd-build/sdk` canary» в записи про предупреждение о протухшем глобальном CLI, не объяснение самого переезда).
