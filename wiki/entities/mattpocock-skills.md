## Пайплайн из четырёх шагов

Основная ценность — не отдельные скиллы, а порядок:

1. **`grilling` / `grill-me`** — агент допрашивает пользователя по каждой ветке дерева решений, пока не достигнуто взаимопонимание. Явная оговорка внутри скилла: если факт можно установить, изучив окружение, — искать самому, а не спрашивать. Закрывает главный источник брака — модель не поняла, что от неё хотят.
2. **`to-spec`** — превращает транскрипт опроса в спецификацию. Ничего не спрашивает, только оформляет уже известное.
3. **`to-tickets`** — нарезает спецификацию на тикеты методом **tracer bullet**: каждый тикет — узкий, но полный вертикальный срез через все слои (схема, API, UI, тесты), демонстрируемый сам по себе и размером ровно в одно контекстное окно. Каждый тикет объявляет свои blocking edges — какие тикеты должны завершиться раньше.
4. **`implement`** — запускает разработку по тикету, внутри ссылается на `tdd` и `code-review`.

**`wayfinder`** (свежее дополнение) — для работы, которая не помещается в одну сессию: пишет не все тикеты сразу, а карту решений; тикет здесь разрешает *решение*, а не исполняет срез сборки.

## Что есть в исходнике, но не попало во вторичный пересказ

**Исключение для широких рефакторов.** `to-tickets/SKILL.md` прямо оговаривает: механическая правка с большим blast radius (переименовать колонку, сменить тип общего символа) в вертикальный срез не лезет — ни один срез не встанет «зелёным». Для таких случаев предписана схема **expand–contract**: добавить новую форму рядом со старой → мигрировать вызовы пачками (каждая пачка — свой тикет, блокируемый expand) → удалить старую форму тикетом, блокируемым всеми пачками. Если даже пачки не держат зелёный поодиночке — общая интеграционная ветка и финальный тикет integrate-and-verify.

Это существенно, потому что именно на широких рефакторах правило «каждый тикет — готовая фича» ломается, и автор это предусмотрел. В пересказе [[nickvels-mattpocock-pipeline]] оговорки нет.

**Ручной запуск — заявленный дизайн, а не недоработка.** У `to-tickets` и `wayfinder` во frontmatter стоит `disable-model-invocation: true` — скиллы принципиально не подключаются автоматически. «Слабое место», о котором говорит вторичный источник, — осознанная позиция автора: пак сделан инженером для инженеров, каждый тикет предполагается прочитать глазами.

## Содержательный тезис: убирать рамки, а не ставить

Скиллы намеренно короткие. Логика (из пересказа, подтверждается объёмом файлов): огромные промпты и толстые фреймворки писались под слабые модели, которые надо было загонять в рамки. Современным моделям рамки, наоборот, мешают — работает порядок операций, а не объём инструкций. Прямое противопоставление тяжёлым фреймворкам полного SDLC — см. [[agentic-sdlc-frameworks]].

## Установка (как сделано у пользователя)

**Установлен 2026-07-27**, user scope, через **нативный плагин-механизм Claude Code**, а не через `npx skills add mattpocock/skills`:

```
claude plugin marketplace add mattpocock/skills
claude plugin install mattpocock-skills@mattpocock
```

Причина выбора (правило 12б в [[claude-code-practices]]): npm-пакет `skills` принадлежит **не Пококу**, а `vercel-labs` (мейнтейнер `rauchg` — Guillermo Rauch, CEO Vercel). Источник сам по себе приличный, но это лишнее звено в цепочке поставок, о котором вторичный источник не упоминает. Плагин-путь короче на одну сторону и показывает манифест целиком.

**Проверка после установки:** `claude plugin details` — 22 скилла, **0 агентов, 0 хуков, 0 MCP-серверов**, то есть исполняемой поверхности нет вообще. Стоимость: ~1 419 токенов always-on на каждую сессию, on-invoke от ~20 токенов (`grill-me`) до ~3.9k (`wayfinder`).

Манифест плагина курирован: 22 скилла из репозитория, категории `in-progress` и `deprecated` в него не входят.
