# Superpowers

**Тип:** инструмент (open source набор скиллов для агентской разработки, TDD-ориентированный)
**Актуально на:** 2026-09-18

## Что это
Набор скиллов на разные этапы разработки (идея → спека → план → сборка (TDD) → проверка → финиш), устанавливаемый как plugin в Claude Code, Codex CLI, Gemini, OpenCode, Cursor. Легче и менее токен-затратный, чем [[gsd-get-shit-done]] — под небольшие/некорпоративные проекты.

Ключевой скилл — **`using superpowers`**: диспетчер, сам определяющий, какой скилл из набора нужен на текущем этапе (brainstorming для спеки, writing plans для декомпозиции, TDD для сборки, verification-before-complete, finish-development-branch). При исполнении плана может выбрать **subagent-driven execution** — самостоятельно создаёт именованных субагентов с явной ролью под конкретные подзадачи, работающих параллельно волнами; также автоматически подключает сторонние обнаруженные скиллы (пример: `frontend-design`, `deploy-to-vercel`), то есть работает как рамочная система с автообнаружением инструментов, а не жёсткий фреймворк.

## Версия 6.4.1: предохранитель пяти раундов (2026-10-21, [[habr-agent-po-specifikacii]])

Статья ссылается на коммит `5bf4e78`. Сверено через `gh`: это выпуск **v6.4.1 от 19.09.2026**. В subagent-driven-development появился предел — не больше пяти раундов «исправление + повторное ревью» на задачу. Раунды 1–3 ведёт прежний исполнитель, 4–5 — новый на модели сильнее. Конфликт находки с планом решается записью `Ruling` в журнале выполнения. Скрипт `review-package` собирает пакет для ревью одним файлом и не даёт собрать его с чужой ветки или пустым. Промпт ревьюера требует считать отчёт исполнителя непроверенным, включая его обоснования («оставил по YAGNI»). Ошибки делятся на Missing / Extra / Misunderstood (не сделано / лишнее / сделано не так). У пользователя на 21.10 стояла 6.1.1 — без предела раундов.

Чего в superpowers нет, по разбору статьи: запрет «ревьюер не трогает ветку» держится только текстом промпта, а не настройкой; метрик качества ревьюера нет.
