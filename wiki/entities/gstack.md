# gstack

Набор Гарри Тана (Y Combinator) для Claude Code и других агентов: около 50 скиллов-ролей «команды стартапа» — директор, дизайнер, инженерный менеджер, тестировщик, специалист по безопасности, выпуск и выкладка, технический писатель, отдельный блок для iOS. Не ставим — разобран как каталог механизмов.

**Тип:** инструмент (набор скиллов, MIT)
**Автор:** Garry Tan
**Актуально на:** 2026-11-25 (допроверка по README/docs — ниже; состав ролей подтверждён, звёзды не пересчитаны этим заходом)
**Ссылка:** https://github.com/garrytan/gstack

## Цена установки и обслуживания (по README)

- Нужны Bun 1.4.2+, на Windows ещё Node.js; браузер Chromium через Playwright. На Windows — только через Git Bash или WSL, часть функций недоступна.
- Пишет в `~/.claude/skills/`, `~/.gstack`; в глобальный `settings.json` — хуки при завершении сессии (включён по умолчанию), при старте и вокруг вопросов пользователю; каждый `./setup` правит `settings.json`.
- Установщик предлагает агенту дописать раздел в `CLAUDE.md` и запретить другие браузерные инструменты; режим `--team` коммитит `.claude/` и `CLAUDE.md` в репозиторий.
- Удаление — скрипт или семь ручных шагов; разделы в `CLAUDE.md` убираются руками.

## Сеть и телеметрия (по README)

- Статистика использования выключена по умолчанию.
- Проверка обновлений включена по умолчанию.
- **Внешние проверки включены по умолчанию**: планы, правки и код уходят второй модели (Codex под Claude Code) под логином пользователя; выключаются `gstack-config set codex_reviews disabled`.
- Каждая исходящая отправка пишется строкой в `~/.gstack/security/egress.jsonl`.

## Почему не ставим

Дублирует уже стоящие [[superpowers]] и [[mattpocock-skills]] (планирование, проверка кода, тестирование), дорог в обслуживании, отправляет код наружу без отдельного решения пользователя, ставится по схеме «вставь в агента, он сделает остальное» — то есть исполняется до того, как установку успели прочитать.

## Что берём логикой

- **Журнал исходящих отправок** — строка на каждую отправку наружу: кому, что, когда. Кандидат для шлюза дешёвых моделей вместе с маскировкой личных данных.
- Не разобраны, но стоят внимания: `/careful`, `/freeze`, `/guard` — режимы «осторожно» и «заморозить файлы».

## Допроверка 2026-11-25

Первая допроверка по первоисточнику с момента разбора (12.10 → сейчас, 44 дня) — страница держалась только на README того дня. `README.md` и `docs/privacy.md` репозитория `garrytan/gstack` прочитаны напрямую через `raw.githubusercontent.com`, без блокировки.

**Подтверждено без расхождений:** телеметрия выключена по умолчанию; проверка обновлений включена по умолчанию; внешние проверки включены по умолчанию, выключаются `gstack-config set codex_reviews disabled`; установщик дописывает раздел в `CLAUDE.md` про `/browse` и запрет `mcp__claude-in-chrome__*`; `--team` коммитит `.claude/` и `CLAUDE.md`; путь журнала `~/.gstack/security/egress.jsonl` — дословно подтверждён в `docs/privacy.md` (в самом README этого пути нет, он только в отдельном доке — не расхождение, уточнение, где искать); ручное удаление — семь шагов (пронумерованы 1–7 в `docs/uninstall.md`, нулевой шаг — вспомогательная функция, не удаление).

**Уточнение состава:** README называет семь именованных ролей (CEO, eng manager, designer, reviewer, QA lead, security officer, release engineer) и не даёт итоговую цифру скиллов текстом — отдельный подсчёт по таблицам даёт ~55, близко к «~50» страницы; «технический писатель» среди явно названных ролей не встречен отдельно (мог быть частью другой роли), iOS-блок подтверждён (`v1.43.0.0+`).

**Уточнение (не расхождение, но страница была неполной):** «внешние проверки… уходят второй модели (Codex под Claude Code)» — однонаправленно и неполно. На деле два отдельных провайдера-ревьюера в обе стороны: `/codex` (Codex под логином Claude Code) и `/claude-code` (Claude Code под логином Codex) — `docs/privacy.md` дословно: «Codex under Claude Code, Claude Code under Codex». Неподтверждённый конфиг (не читается) по умолчанию считается отключённым, а не включённым — fail-closed, не fail-open.

**Новое, чего страница не знала вовсе:**
- Журнал отправок — хеш-цепочка с защитой от подмены («hash-chained, tamper-evident»), не просто построчный лог; команды `gstack-egress verify` (проверка цепочки) и `gstack-egress grants` (постоянные разрешения). Отдельно явно оговорено: «it is not a network firewall» — журнал фиксирует попытки отправки для аудита, не блокирует их.
- Параллельно с журналом отправок есть локальные логи, которые никуда не уходят: `~/.gstack/analytics/skill-usage.jsonl` (использование скиллов), `~/.gstack/projects/<repo>/timeline.jsonl` (старт/финиш скилла с именем ветки), `~/.gstack/sessions/<pid>` (маркеры активных сессий).
- Телеметрия — два уровня (`anonymous`: без ID устройства; `community`: с устойчивым ID устройства + имя скилла/исход/длительность/версия), никогда не включает код/пути/имена репозиториев/ветки/промпты; хранится в Supabase через edge functions со схемой/ограничениями полей.
- Проверка обновлений обращается к GitHub (`git ls-remote`, `raw.githubusercontent.com`, `api.github.com` — GitHub видит IP), а при включённой телеметрии тот же заход дополнительно отправляет версию и ОС в Supabase gstack.
- Windows: нативный `/cso` требует PowerShell и Visual Studio 2022 Build Tools; Windows Smart App Control может блокировать несигнированные скомпилированные бинарники (issue #2595); без Developer Mode установщик использует копирование файлов — после каждого `git pull` нужно заново запускать `./setup`.
- Экосистема выросла за счёт README не упомянутых на странице компонентов: **Capy** (мультиагентный «software factory»-контроллер, `crew/docs/recommended-harness.md`, `capy/README.md`) и **GBrain** (синхронизация памяти между машинами, `docs/gbrain-quick-tour.md`, `docs/gbrain-sync.md`) — оба в докладной таблице README как отдельные продукты рядом с gstack, не разбирались.

Деталь не внесена как факт (риск суммаризации одного захода, не перепроверено вторым запросом): точное число скиллов (~55).
