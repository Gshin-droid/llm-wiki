# Jev (TypeSafe)

Платный облачный API типизированных решений: на вход состояние и вопрос, на выход — выбор, оценка или вероятность. Попал в вики как точка отсчёта, относительно которой измеряет себя открытая локальная [[laya]], и как единственный известный вики сервис этого класса.

**Тип:** сервис / модель (API типизированных решений)
**Актуально на:** 2026-10-03
**Поставщик:** TypeSafe

## Что известно

Сведения взяты из README конкурента ([[laya-local-decision-engine]]) — **не от поставщика**, и это надо держать в уме: сравнение делала соперничающая сторона.

- Закрытый API, тариф $0,042 за 1M токенов.
- Задержка 236–276 мс на вопрос — из них значительную часть съедает сам сетевой запрос.
- Калибровка хуже, чем у Laya (ECE 0,144 против 0,081).
- **Заметно сильнее на больших наборах вариантов**: Banking77 (77 классов) — 0,870 против 0,425.

## Не проверено

Официальная документация TypeSafe не читалась: ни тариф, ни задержки, ни границы применимости первоисточником не подтверждены. Лид в [[gaps-backlog]].

## Допроверка 2026-10-03 — домен заблокирован целиком, запасной путь не нашёлся

Ежедневный процесс закрытия пробелов. Цель — прочитать официальную документацию TypeSafe и подтвердить (или опровергнуть) тариф $0,042/1M, задержку 236–276 мс и границы применимости, известные только со слов конкурента ([[laya-local-decision-engine]]).

**Метод.** Прямой фетч `docs.typesafe.ai/introduction/quickstart`, `docs.typesafe.ai/api` и `typesafe.ai/` — все три `EGRESS_BLOCKED`, домен заблокирован целиком, не точечно. Дополнительно заблокированы `typesafe-ai.github.io` (лендинг компании на GitHub Pages — то есть блокировка здесь похожа на блокировку по ключевому слову/бренду, а не только по домену `typesafe.ai`) и `openrouter.ai` (уже известный нестабильный домен). По правилу «сначала проверить официальный открытый репозиторий» найдена организация `github.com/typesafe-ai` (11 репозиториев, в вики раньше не упоминалась) — прочитаны напрямую через `raw.githubusercontent.com`: README и `docs/changelog.md` официального `typesafe-sdk-python`, исходник `index.html` `typesafe-ai.github.io`.

**Итог — не закрыто, частичная новая находка.** В отличие от Chroma/MINJA/context7/opencode/21st.dev/pi-coding-agent, где открытый репозиторий сам оказывался первоисточником тарифов/лимитов, здесь ни один из трёх прочитанных файлов не содержит ни цифр тарифа, ни задержки, ни границ применимости — SDK README лишь подтверждает аутентификацию через переменную `TYPESAFE_API_KEY` и ссылается обратно на тот же заблокированный `docs.typesafe.ai` за деталями; лендинг — только текст о компании/команде, без технических данных. Новое, чего раньше в вики не было: официальная организация `typesafe-ai` на GitHub существует и поддерживает SDK на двух языках (`typesafe-sdk-python`, `typesafe-sdk-js`) плюс интеграции (n8n, Dagger). Тариф/задержка/границы применимости остаются известны только со слов конкурента — первоисточник для них живёт исключительно на заблокированном `docs.typesafe.ai`, запасного пути не нашлось. Один заход на каждый из названных доменов, повторно в этот и будущие прогоны не пробовать (CLAUDE.md, правило «один заход на заблокированный домен»).

## Связь двух упоминаний установлена (2026-09-22)

Имя «Jev» пришло в инбокс дважды, и это один и тот же сервис. В моде [[jev-skill-suggestion-mod]] для [[claude-code]] Jev выступает классификатором, выбирающим один подходящий скилл на запрос, — карточка мода называет его *«System One decision model»* от TypeSafe, доступной напрямую по API либо через Vercel AI Gateway. Это тот же класс модели, открытой локальной альтернативой которому объявлена [[laya]].

Там же видно, чем Jev платит за облачность и что даёт взамен: во внешний сервис уходит текст запроса пользователя, а возвращается, помимо выбора, **калиброванный коэффициент доверия** — см. [[kalibrovka-uverennosti-resheniy]].

## Экосистема (2026-09-22)

Вокруг модели сложился слой открытых проектов — [[jev-ecosystem-projects]] разбирает подборку из двадцати. Форма применений у всех одна: **модель решений ставится в узкое место конвейера**, где нужно много быстрых однотипных суждений и не нужен текст. Ни один проект не просит её ничего написать.

Четыре из двадцати — обвязка для агентов-кодеров, в том числе два плагина к [[claude-code]]: сжатие контекста удалением вместо пересказа и калиброванное сито результатов инструментов. Есть и обёртки в MCP, дающие агенту типизированные суждения как инструменты.

Оговорка, важная для оценки: доступ к самой модели — **ранний**, и часть проектов имеет запасной путь через обычную языковую модель, честно отмечая, что он **не калиброван**.

## Решение: не используем (2026-09-22)

Пользователь решил **не применять Jev ни в каком виде**, включая верхнюю ступень каскада. Причины: закрытый платный сервис малоизвестного поставщика; в схеме каскада ему уходит содержимое работы; замеренный выигрыш (78% против 57% у локальной [[laya]] на одном домене — [[laya-jev-lab-measurements]]) этого не окупает.

Страница остаётся в вики как точка отсчёта и как объяснение, почему проекты экосистемы устроены именно так: значительная их часть спроектирована вокруг вызова к этому API, и при переносе логики на локальную модель это место придётся менять.

## Третий инструмент того же класса (2026-09-23)

[[openjev-verdict-2]] заявляет 77,10% против 72,70% у TypeSafe Jev 1.13.0 на собственном тестовом наборе автора — не независимая проверка, тот же класс заявления, что и сравнения на этой странице. См. [[openjev-verdict-2-repo-review]].

## Четвёртый инструмент того же класса (2026-09-29)

[[clm-8b]] (Contrastive-LM, Apache 2.0) устроен иначе, чем Jev, Laya и Verdict: ситуацию и варианты кодирует отдельно и сравнивает векторы, поэтому векторы вариантов кэшируются. Заявлено «наравне с Jev» и до 9 раз быстрее — авторский замер, см. [[clm-8b-contrastive-system-one]]. Цена — полноценная Qwen3-8B на видеокарте через vLLM; отдельно авторы пишут, что Jev не справляется с ролью проверяющего на длинных задачах агентов (выбирает хуже первого варианта наугад) — на 38 и 30 задачах, сравнивая с дообученным CLM.
